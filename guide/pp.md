# `.pp` / `.pgame` 格式手册

> **上层索引**：[`../Guide.md`](../Guide.md)（总入口、修改流程、共同铁律）
> **同族接口**：[`ai.md`](ai.md)（AI 导读与流程）、[`rules.yaml`](rules.yaml)（本手册的机读镜像）
>
> **本手册自包含**：`.pp` / `.pgame` 的**全部**顶层键、各节字段、取值域、缺省、降级行为与校验项都在本文件内，**不需要**再翻任何其它文档。
>
> **健全性标准**：仅依据本手册即可写出 / 改动一份合法 `.pp` / `.pgame`，并预知其校验项与降级行为。

## 一、用途与边界

- `.pp` 是**皮肤模组**（zip 容器），只承载**纯渲染**：路径 / 建筑 / 背景 / 音频 / 面板 / 角色 / 页面。**不含任何玩法语义**——素材不改变任何判定，取图必须是纯函数。
- **素材是可选增强，不是必需依赖**：任何一节缺失即**逐级降级**为程序绘制形态（道路脚印 / 圆角矩形 / emoji），**不报错**。兜底永远是「纸张 ＋ 手绘 ＋ 涂鸦」基调，不允许出现观感断裂。
- **不写进 `.psave`**：皮肤是渲染层，不进存档；皮肤名不记录，跨会话偏好属「用户配置」。
- `.pgame` = `.pmod` ＋ `.pp` 的整体分发容器，**不增设计算语义**。

### 1.1 覆盖边界（皮肤**不**负责什么）

| 不负责 | 说明 |
|---|---|
| 构建页的**编辑器控件**（检查器、输入控件、行内菜单、缩放条、面板闸门） | 控件沿用 CSS 手绘风，不接入素材 |
| **Creative 模式自身的编辑器 UI** | 皮肤编辑器长什么样不能依赖皮肤自身，否则自举循环；只有其**预览画布**用素材渲染 |
| 纸面底纹（噪声）与手绘分隔线 | 现已由 CSS 用 data-URI（`feTurbulence` 噪声、波浪 `sketch-line`）生成，**素材不与之重复** |
| 界面字体本身 | 皮肤只能指定**建筑名**的字体文件与字色，不接管界面字体 |
| 玩法语义 | 素材不改变任何判定；取图必须是纯函数 |

**边界内的三处例外（素材确实会进入编辑器场景）**：

| 场景 | 素材范围 |
|---|---|
| build 模式加载 pp | **仅地图视图与预览用的组件**按素材渲染，用于验证「素材与地图是否对得上」；不影响导出的 `.pmod` |
| 组件库与信息视图的图标衬底 | 使用 `item` / `building` 的衬底三元组；衬底在下、`icon` 居中在上 |
| Creative 模式的预览画布 | 等同游玩态渲染 |

## 二、包结构

### 2.1 `.pp` 内部结构

```text
xxx.pp（zip）
├── manifest.json          描述文件（必须在包根）
├── preview.png            可选：皮肤预览图（存在时须在包根）
└── 素材…                  目录名、层级、文件名一律自由
    ├── background/  bg.jpg       ← 以下为推荐目录约定（非强制）
    ├── road/        straight.png …
    ├── role/        hero.png …
    ├── item/        …
    ├── building/    …
    ├── window/      …
    ├── font/        hand.woff2
    └── audio/       bgm.mp3
```

- **强制结构只有两项**：`manifest.json`（**必须在包根**，是唯一入口描述文件，**无 `kind` 类标识键**）与 `preview.png`（**可选**，存在时须在包根）。除此之外**包内不设任何强制目录**。
- 图中 `resource/` 与按节命名的子目录是**推荐约定而非要求**，仅为便于人工核对与校验器定位；**加载器不得依赖它**。
- `preview.png` 存在且可解码时用于皮肤列表；缺失或损坏回退为文件名展示（`KP-6`）。

### 2.2 `.pgame` 内部结构

```text
<name>.pgame（zip）
├── pack.json        容器描述文件（必须在包根）
├── game.pmod        `.pmod` 原文本，条目形式存放
└── skin/            皮肤（就是一份 `.pp` 的内容）
    ├── manifest.json
    └── …             素材：目录名与层级自由（以 `manifest.json` 为准）
```

- **`pack.json` 缺失时**按约定文件名回退（`game.pmod` ＋ `skin/manifest.json`），并在清单提示 `KP-7`。
- **缺少 `skin/`（或其中无 `manifest.json`）时按「无皮肤」处理**，游戏照常启动。

## 三、`manifest.json` 骨架

### 3.1 顶层键总表

| 键 | 主题 | 本手册节 |
|---|---|---|
| `format` | 包格式版本（整数，缺省 `1`） | §六 版本 |
| `name` / `author` / `description` | 皮肤名 / 作者 / 描述（均可选；`name` 缺失时列表显示文件名） | §3.2 |
| `startup` | **APP 欢迎页**（启动画面） | §10.8 |
| `lobby` | **游戏首页 ＋ 出身（选角）页面** | §10.8 |
| `extends` | 可选：继承**包内**另一套皮肤（同系列换色） | §七 |
| `theme` | 全局 token → CSS 变量 | §七 |
| `background` | 画布背景**数组**：下标即地图下标，越界用最后一层，每张地图只渲染一层 | §10.1 |
| `road` | 路径数组：路位模式 / 姿态 / 样式标签优先级 | §10.2 |
| `role` | 角色：玩家棋子 / 职业形象 / 怪物形象 / NPC 形象 `npcs` / 立绘 `portraits`（纯皮肤元素） | §10.3 |
| `item` / `building` | 道具 / 建筑：`icon`、衬底三元组；建筑另有地图贴图与地图名称字体 | §10.6 |
| `window` | 窗体：容器 / 按钮 / 格子 / 条 / 提示框 | §10.4 |
| `misc` | 其他：地图标记 / 建筑节点 / 骰子 / 图标 / 参照线 | §10.5 |
| `audio` | 音频：BGM 与音效（**V1 只解析预留**，V1.1 实现） | §10.7 |

**已废除的顶层键**：`resource`（原「素材根目录声明」）——读到即忽略并提示 `KP-10`。

### 3.2 皮肤名与预览图

- `name`（皮肤名，显示在皮肤列表与开局屏的皮肤选择项）、`author`、`description`；预览图由包根 `preview.png` 承担（**没有** `thumbnail` 字段）。
- 三项均可选；`name` 缺失时在皮肤列表中以**文件名**显示。

### 3.3 顶层骨架样例

```json

  "name": "手绘纸片",
  "author": "无名",

  "lobby":   { "bg": { "img": "resource/lobby/room.jpg" }, "panel": { "img": "resource/lobby/scroll.9.png", "slice": [16,16,16,16] } },
  "background": [ { "img": "resource/bg/map1.jpg", "cellSize": 48 } ],
  "road":   { "straight": "resource/road/straight_n.png", "deadEnd": { "img": "resource/road/dead_end_n.png", "rotate": 0 } },
  "role":   { "player": "resource/role/hero.png", "npcs": { "elder": "resource/role/elder.png" } },
  "item":   { "red_potion": { "icon": "resource/item/red_potion.png" } },
  "building": { "chest_room": { "icon": "resource/building/chest.png", "img": "resource/building/chest_map.png" } },
  "window": { "dialog": "resource/window/dialog.9.png" },
  "misc":   { "start": "resource/misc/flag.png" },
  "audio":  { "bgm": { "map": { "file": "resource/audio/map.mp3" } } }

```

## 四、路径规则：由描述文件指定，相对包根

- 素材路径**从包根写全**，逐条写在 `manifest.json` 的对应字段中——**描述文件是素材位置的唯一权威来源**。
- 加载器**不得推断前缀**：不用「相对 `resource/`」的简写，也不靠字段拼前缀，直接按该路径在包内取条目。
- **路径约束（`KP-4`）**：禁止绝对路径、禁止 `..`、禁止 `http(s)://` 等外部地址——产物必须**离线可用**（纯静态约束）。
- 推荐命名：`<元素>_<变体>.<ext>`，变体名与分型表短名一致（如 `dead_end_n.png`、`tee_corner_nw.png`）。
- 推荐格式：`png`（含透明）优先；`jpg` 用于无透明大图（背景）；矢量手绘可用 `svg`。
- **方向基准（全局）**：素材一律按**上北下南、左西右东**绘制一次——世界坐标的正方向即屏幕的**右＝东、下＝南**。同一元素需要其它朝向时**由其复用机制推出**（首选旋转，§5.2），**不为每个朝向单独出图**。
- **单格素材按 `CELL × CELL` 正方形绘制、图形居中**（`CELL` 现为 48px）——**这是旋转复用的前提**。**立绘不适用本行**：立绘按**窗口尺度 `W`** 的比例缩放、不要求正方形。
- **可缩放素材的原图尺寸可以很小**：随容器伸缩的素材（窗体 / 面板 / 按钮 / 建筑 / 色块）由九宫格或整图拉伸铺满，**不按屏幕断点出多套图**。窄屏不产生额外素材需求。

## 五、素材字段的三种写法与复用四件套

### 5.1 三种写法（按复用粒度选用）

```json
"deadEnd": "resource/road/dead_end_n.png"                          // 一张，引擎按朝向旋转
"deadEnd": { "img": "resource/road/dead_end_n.png", "rotate": 90 } // 一张 + 硬性角度纠偏
"deadEnd": ["…/dead_end_n.png", "…/dead_end_e.png",
            "…/dead_end_s.png", "…/dead_end_w.png"]               // 四张，不旋转
```

- **数组顺序固定 N / E / S / W**，**不得省略中间项**（缺哪向即整节降级为程序绘制）。
- `rotate` 用于**素材基准朝向与规范基准朝向不一致时的纠偏**，**不用于表达"这一格该朝哪"**——朝向由引擎按连通关系计算。

### 5.2 复用四件套

| 手段 | 生效条件 | 限制 |
|---|---|---|
| **旋转**（主线省图手段） | 素材旋转不变 ＋ 正方形且图形居中 | 若必须画方向光则放弃旋转、按 4 向全画 |
| **镜像** | **必须显式声明** | **不默认启用**（手绘笔画走向镜像后会变观感） |
| **九宫格** | 素材**带 `slice`** 才成立（DOM 层已落地；SVG 层仍为拉伸） | 没配 `slice` 即整图拉伸；末带 `fill`、不写 `borderWidth` |
| **平铺** | 素材四边可无缝拼接 | **不与拉伸混用**；当前唯一落点是**坐标参照线**（分隔线已裁决不走平铺） |

- **旋转**三前提缺一不可：① 素材本身旋转不变（无方向性光影 / 高光 / 纹理、无与重力相关的元素）；② 正方形且图形居中；③ 非正方形或带出血的素材，旋转后按绕心旋转处理，必要时裁切。
- **九宫格切片顺序固定为 `[上, 右, 下, 左]`**（顺时针、从顶部开始）。**九宫格由素材自己声明**：配了 `slice` 就走九宫格、没配即整图拉伸——**同一个键可以今天拉伸、明天九宫格**，老素材不用改。规范要求：**没配 `slice` 的素材必须在纯拉伸下不难看**。
- **九宫格落地范围**：**DOM 层**（面板 / 弹窗 / 按钮 / 格子 / 条 / 提示条 / 分隔线）已走 CSS `border-image`；**SVG 层**（道路 / 地图 / 画布 / 棋子）仍按 `preserveAspectRatio` 出图，要走九宫格得另起切块拼装。
- **分隔线走单轴九宫格**（上下切片给 0），**不引入 `tile`**。**平铺**当前只用于**坐标参照线（定位线）**；纸面底纹与手绘分隔线默认由 CSS 生成、不由素材接管，若素材要接管必须显式提供且不得与 CSS 版本叠加。
- **定位线是辅助层**：地图上每 10 格那条细线叠在地图之上、只作读数定位用；**道路 / 背景 / 格子等贴图本身不含任何间距与分割线**。

### 5.3 调用方接口：贴图渲染器（改素材时不需要知道）

- **禁止在业务代码中判断素材类型**（不写 `if (is9Patch)`）。所有绘制统一走一层抽象：

```
drawTexture(target, src, box, opts)
  opts = { mode: 'stretch' | 'nine' | 'tile', slice?: [t, r, b, l], rotate?, flip? }
```

| 策略 | 生效条件 |
|---|---|
| `stretch`（V1 缺省） | 直接拉伸铺满盒 |
| `nine` | **策略 ＋ `slice` 同时成立**才生效；只写 `mode: 'nine'` 而没给 `slice` 回落 `stretch` |
| `tile` | 独立成立（不需切片）；唯一候选是定位线 |

- 适用范围：道路 / 建筑素材、面板与弹窗底图、按钮底图、色块——**凡是需要拉伸的一律走此接口**。
- 取图必须是**纯函数**、**确定性**：同一格子状态任何时刻取到同一张素材；并列情况有明确兜底顺序。
- 素材缺位返回 `undefined`，调用方改画程序图形——**逐节点降级**由此成立。

## 六、三层优先级、降级与版本

```
游戏配置（本局 .pp / .pgame 携带）＞ 用户配置（用户本地全局 pp）＞ 缺省配置（程序绘制）
```

- **降级粒度是单个素材节点**，不是整节：某槽位缺图则取用户皮肤同名节点，再缺则回退程序绘制形态。「同屏混用素材与程序绘制」是正常状态，不得视为缺陷。
- **「用户配置」** = 用户在本机设置的全局 pp（随设备走、不随这一局走）。
- **版本（`format`）**：整数，缺省视为 `1`；读到**高于**实现版本时照常渲染可识别字段并警告一次（`KP-3`）。
- **「一次只解压一套」**：任一时刻内存只保留当前生效皮肤的解压结果，切换皮肤先释放再解压。**不设体积硬上限**，仅对超大单图提示。
- **皮肤库**：用户**导入过**的 `.pp` 各记一条条目（名称 / 作者 / 来源 / 导入时间 / 是否启用），包体保持**原始 zip 不落地解压**（条索引走 `localStorage` 键 `poprpg_skins`，二进制走 IndexedDB）。**游戏自带皮肤（`.pgame` 内的 `skin/`）不入库**。

## 七、`extends` 与 `theme`

### 7.1 `extends`：包内继承

- 值为**包内**、相对包根的 manifest 路径（如 `"extends": "variant/base/manifest.json"`）；被继承者另有素材时，其路径同样相对**本包**包根书写。
- 加载顺序：先基座、后本包，**逐节点覆盖**；允许多级链式继承。
- **只允许包内继承，禁止跨包引用**（跨包会破坏自包含与离线可用）。路径不存在或成环即 `KP-8`：忽略继承、只按本包渲染。

### 7.2 `theme`：全局 token → CSS 变量

```json
"theme": { "--paper": "#f2ece0", "--ink": "#33302a", "--line": "#c9b795" }
```

允许的键（现有主题变量名）：

| 族 | 变量 |
|---|---|
| 纸面 | `--paper` / `--paper-deep` / `--paper-card` |
| 墨色 | `--ink` / `--ink-soft` / `--ink-faint` |
| 线条 | `--line` / `--line-soft` |
| 语义色 | `--red` / `--amber` / `--green` / `--blue` |
| 圆角 | `--radius` / `--radius-rough` |
| 字体族 | `--font-hand` / `--font-cn` |

- 加载时以**最高优先级**注入 `:root`；卸载皮肤时**还原**缺省值。
- **只允许改观感 token**；布局 token（`--gap` / `--topbar-h` / `--play-topbar-h`）**不可覆盖**（`KP-9`）。未知 token 名忽略并提示（`KP-9`）。

## 八、`.pgame` 的 `pack.json`

| 键 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `format` | 整数 | 容器格式版本 | `1` |
| `kind` | 字符串 | 固定 `"poprpg.pgame"`，用于识别包类型 | 无（缺失即按 `KP-7` 回退探测） |
| `name` | 字符串 | 该整体分发的显示名 | 文件名 |
| `pmod` | 字符串 | `.pmod` 条目路径（相对包根） | `game.pmod` |
| `skin` | 字符串 | 皮肤目录（相对包根，其内为一份 `.pp` 内容） | `skin/` |
| `entry` | 字符串 | 入口标识 | 留空即走默认开局流程 |

- `.pgame` **只声明「内含哪些文件」**，不给自身增设计算语义；容器版本与 `pmod` / `manifest` 的版本号**不合并计**。
- 皮肤部分的校验沿用 `.pp` 规则；**`.pmod` 格式不因本模块改动**（`.pgame` 内以条目形式存放 `.pmod` 原文本）。

## 九、校验项（构建页「清单」，**均为提示、不阻断导出**）

### 9.1 包级 `KP-*`

| 编号 | 检查 | 处理 |
|---|---|---|
| `KP-1` | `manifest.json` 不在包根 / 无法解析 | 该 `.pp` **整体被忽略**，全部降级为用户配置 |
| `KP-2` | 素材路径在包内不存在 | 列出全部无效路径；该项**逐节点降级** |
| `KP-3` | `format` 高于实现版本 | 提示可能读不出新增字段 |
| `KP-4` | 路径含绝对路径 / `..` / 外部地址 | 违反纯静态约束，禁止 |
| `KP-5` | `item` / `building` / `road` / `role` 等节的键不在本局启用的组件 id 内 | 无效键，忽略并提示 |
| `KP-6` | 包根无 `preview.png`，或其无法解码 | 皮肤列表回退为文件名显示 |
| `KP-7` | `.pgame` 缺少 `pack.json` | 按约定文件名回退加载 |
| `KP-8` | `extends` 路径不存在或形成环 | 忽略继承，只按本包渲染 |
| `KP-9` | `theme` 含未知 token 名，或试图覆盖布局 token | 忽略该键，其余主题照常注入 |
| `KP-10` | `manifest.json` 含已废除的 `resource` 键 | 忽略该键，路径一律以各字段自身为准 |

> **不校验项**：皮肤体积**不设硬上限**；仅对超大单图提示，不阻断。

### 9.2 各节子编号总表

## 十、各节字段清单

### 10.1 画布背景 `background`

`background` 是**数组**：一张皮肤可携带多套背景，**数组下标即地图下标**——第 `i` 张地图用 `background[i]`，**不需要任何匹配 key**。

```json
"background": [
  { "img": "resource/bg/plain.jpg", "cellSize": 25, "startX": 256, "startY": 256, "color": "#F2ECDD" },
  { "img": "resource/bg/cave.jpg",  "cellSize": 25, "startX": 200, "startY": 200, "color": "#3A352C" }
]
```

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `img` | 字符串 | 背景图，路径**相对包根** | 该项不绘制 |
| `cellSize` | 正整数 | **背景图上一个游戏格占多少像素**，把地图坐标换算到图片坐标；**同时也是道路等地图层素材的出图基准** | 该项不绘制 |
| `startX` | 整数 | 图片上该点与地图格 `[0,0]` 的**中心**对齐（横向） | `0` |
| `startY` | 整数 | 同上（纵向） | `0` |
| `color` | 颜色 | **图片边界之外**的填充色；**每层各自携带**，取**实际被采用的那一层**的值 | 全局主题色（纸面底色） |

**取值规则（每次只取一层渲染、不需要匹配 key）**：

1. **下标匹配**：第 `i` 张地图（`i` 从 0 起）取 `background[i]`；
2. **越界降级**：`i ≥ 数组长度` 时，**降级为使用最后一张** `background[数组长度 − 1]`；
3. **每张地图只绘制这一层**，命中即停、不再叠加；该层不可用时（`img` / `cellSize` 缺失或路径取不到）向**更靠前的层**回退（`i−1`, `i−2`, …）；
4. `background` 缺失、为空数组，或全部层都不可用 → 本节视为**未接管**，按皮肤整体优先级继续降级，最终落到程序绘制的纸面底纹；
5. **颜色不降级**：被采用层写了 `color` 就用它、没写**直接**用全局主题色，**不会**沿 `i−1` / `i−2` 回退找色 → **每层都要求显式写出 `color`**。

**兼容写法**：只写一个对象（`"background": { … }`）时视为**单元素数组**，所有地图都取它。

**坐标映射**（格坐标以 `[0,0]` 为原点、`col` 向右、`row` 向下，单位是格）：

```
图片坐标点 (startX, startY)  ≡  地图格 [0,0] 的中心
格 [col, row] 的中心像素      =  (startX + col × cellSize, startY + row × cellSize)
地图像素原点（格 [0,0] 左上）  =  (startX − cellSize ÷ 2, startY − cellSize ÷ 2)
```

- **负格坐标合法**：`col < 0` 或 `row < 0` 的格子落在图片左上之外，按 `color` 填充。
- **缩放**：图片按 `屏幕每格像素 ÷ cellSize` 等比缩放（即 `cellSize` 个图片像素显示为 1 格）。
- **与地图层素材的共同基准**：道路贴图等地图层素材的出图基准同样是 `cellSize`、显示倍率相同，与背景图共用同一坐标变换——「素材与背景严格对齐、倍率一致」由此成立。**道路贴图不设背景色**，透明区直接透出背景图；未配背景时地图层素材回退为按屏幕 `CELL` 出图。
- 绘制顺序：① `color` 填充（画布全域）→ ② 背景层（只绘制被采用那一层）→ ③ 参照线 → 道路贴图 → 建筑节点 → 标记 → 角色。

`KB-*` 校验项：

| 编号 | 检查 | 提示 |
|---|---|---|
| `KB-1` | `cellSize` 缺省或 ≤ 0 | 无法对齐，该项不绘制 |
| `KB-2` | `img` 路径在包内不存在 | 该项不绘制 |
| `KB-3` | `startX` / `startY` 落在图片之外 | 图片与地图完全错位，需重新标定 |
| `KB-4` | 背景图覆盖不到整张地图 | 边缘将露出 `color` 填充色，提示可接受或补图 |
| `KB-5` | 背景图分辨率低于 `地图格数 × cellSize` | 放大后模糊，提示提高分辨率 |
| `KB-6` | 某张地图**没有任何可用背景** | 该地图降级为程序绘制的纸面底纹 |
| `KB-7` | `background` 层数**多于** pmod 地图数 | 末尾若干层永远不会被采用 |
| `KB-8` | **被采用的那一层**没有写 `color`（含越界降级后落到的那一层） | 该地图图片之外直接露出全局主题色 |
| `KB-9` | **相邻下标的两层**（相邻地图各取其一）`cellSize` / `startX` / `startY` 不一致 | 切换到相邻地图时背景会跳变，建议统一基准 |

### 10.2 道路 `road`

道路格由**两层信息**决定，互不干扰：

| 层 | 决定因素 | 决定什么 |
|---|---|---|
| ① 样式集 | 道路格的 `tags` | 用哪一套素材（如石路 / 土路 / 铁轨） |
| ② 槽位素材 | 四邻连通关系 | 用这一套里的哪一张 |

**连通判定与样式无关**：只要相邻两格同为道路件，即视为连通（标签不参与连通判定）。

#### 10.2.1 位模式与查表

每格考察周围 **8 格**（一圈），以 8 位标记为一个整数 `flag`，位序为**从左上角起顺时针**：

| 位 | 方向 | 含义 |
|---|---|---|
| `bit0` | 左上（西北） | 该角有路 |
| `bit1` | 中上（北） | 该边有路 |
| `bit2` | 右上（东北） | 该角有路 |
| `bit3` | 右中（东） | 该边有路 |
| `bit4` | 右下（东南） | 该角有路 |
| `bit5` | 中下（南） | 该边有路 |
| `bit6` | 左下（西南） | 该角有路 |
| `bit7` | 左中（西） | 该边有路 |

- **256 种原始组合**（2^8）在构建期展开为查表：`flag → 槽位 → 基准朝向`。运行期每格只做一次查表，**不跑 if-else 链**。
- 查表结果与「样式集」无关：**先按 `flag` 定姿态，再按 `tags` 选样式集**，顺序不可颠倒。

#### 10.2.2 槽位分型表（15 槽位 / 47 姿态 / 15 张素材）

连通关系由**四条边**（N / E / S / W 是否有路）与**四个角**（夹角角块是否有路）构成：

| 边数 `n` | 夹角角块 `c` | 槽位名 | 姿态数 | 需画素材数 |
|---|---|---|---|---|
| 0 | — | `isolated` | 1 | 1 |
| 1 | — | `dead_end` | 4 | **1** |
| 2（相对） | — | `straight` | 2 | **1** |
| 2（相邻） | 0 | `bend` | 4 | **1** |
| 2（相邻） | 1 | `corner` | 4 | **1** |
| 3 | 0 | `tee` | 4 | **1** |
| 3 | 1（西北侧夹角角块） | `tee_corner_nw` | 4 | **1** |
| 3 | 1（东北侧夹角角块） | `tee_corner_ne` | 4 | **1** |
| 3 | 2 | `tee_full` | 4 | **1** |
| 4 | 0 | `cross` | 1 | **1** |
| 4 | 1 | `cross_one_corner` | 4 | **1** |
| 4 | 2（相邻） | `cross_adjacent` | 4 | **1** |
| 4 | 2（相对） | `cross_diagonal` | 2 | **1** |
| 4 | 3 | `cross_three_corners` | 4 | **1** |
| 4 | 4 | `plaza` | 1 | 1 |
| | | **合计** | **47** | **15** |

**读法**：47 种姿态只需 15 张素材——每张基准素材通过 0° / 90° / 180° / 270° 覆盖它那一行的姿态；`straight` 只需 2 种（旋转 180° 等于自身），完全对称的槽位无需旋转。

#### 10.2.3 角位判定：只在夹角处生效

- **夹角角块**：某角的**两侧边都有路**，它就是夹角角块——有路即计入角数 `c`、无路记 0。
- **外侧角**：只挨着一条路的角，**一律不参与判定**，其有无路不影响取图结果。
- **后果**：某格外侧角有路、而相邻侧边无路时，素材不向该角延伸，接缝处出现视觉断开。

| 边数 `n` | 夹角角块 | 判定 |
|---|---|---|
| 0 / 1 | 无（不构成夹角） | 只按边数取 `isolated` / `dead_end` |
| 2（相邻） | 1 个，即两边的交角 | 有路 → `corner`；无路 → `bend` |
| 3 | 2 个（缺边两侧的角） | 0 个有路 → `tee`；1 个 → `tee_corner_*`；2 个 → `tee_full` |
| 4 | 4 个（四边俱全，四角全是夹角） | `cross` 系按 0 / 1 / 2（相邻、相对）/ 3 / 4 个有路分型 |

#### 10.2.4 基准朝向（素材就照这个画）

**世界坐标上北下南、左西右东**——屏幕上方＝北、下方＝南、左＝西、右＝东。每张基准素材**只按自己的基准朝向画一次**，其余朝向由引擎**绕格心旋转 90° 的整数倍**得到。

| 槽位 | 基准朝向 | 覆盖姿态 |
|---|---|---|
| `isolated` | 无朝向（孤立） | 1 |
| `dead_end` | **连通面朝南**（＝缺口朝北，即 `dead_end_n`） | 4 |
| `straight` | **南北向**（`straight_ns`） | 2 |
| `bend` / `corner` | **连北 ＋ 连东**（`_ne`） | 4 |
| `tee` / `tee_full` | **缺口朝北**（唯一无路的那条边在北） | 4 |
| `tee_corner_nw` / `tee_corner_ne` | **缺口朝南**（此时两个夹角分别落在西北与东北侧） | 4 |
| `cross_one_corner` | **西北角有路** | 4 |
| `cross_adjacent` | **北侧两角（西北 ＋ 东北）有路** | 4 |
| `cross_diagonal` | **主对角（西北 ＋ 东南）有路** | 2 |
| `cross_three_corners` | **缺西南角**（其余三角有路） | 4 |
| `cross` / `plaza` | 无朝向（完全对称） | 1 |

- **旋转量 ＝ 基准到目标的顺时针角差**。
- 三写法里的**数组写法按 `N / E / S / W` 顺序给四张实图、不旋转**（§5.1）：即放弃旋转复用时，四张图仍按本表的**世界方向**画。
- 旋转复用的三条约束（同 §5.2）：素材旋转不变；素材为 `cellSize × cellSize` 正方形、图形居中；绕格心旋转、非正方形需配合裁切。

#### 10.2.5 样式选取规则

道路格的标签集合记为 `R`，样式集条目的标签记为 `s.tags`。

```
候选 = { 样式 s | s.tags 为空 }  ∪  { 样式 s | s.tags ∩ R ≠ ∅ }
```

**排序（逐级比较，前者优先）**：

| 序 | 规则 | 说明 |
|---|---|---|
| ① | `s.tags` 非空者优先于为空者 | 空标签是**通配底样**，不参与竞争 |
| ② | `\|s.tags ∩ R\|` 降序 | 命中标签数多者优先：`ABC` 胜 `AB`，`AB` 胜 `A` |
| ③ | 素材表中的声明顺序 | 前声明者优先，保证结果确定 |

- 默认语义为「**命中任意一个即可**」；若需要「必须全部命中」，样式条目另加 `mode: all`。
- 规则 ③ 是兜底而非设计意图：当两条样式在 ①② 上完全同分时，清单应提示作者消歧。

#### 10.2.6 字段与示例

`road` 由 **`styles`（样式集数组）** 与 **`tiles`（15 个槽位的文件名字典）** 组成：

```json
"road": {
  "styles": [
    { "tags": [],              "base": "road/dirt" },
    { "tags": ["石子"],         "base": "road/stone" },
    { "tags": ["石子", "官道"],  "base": "road/stone_wide" }
  ],
  "tiles": {
    "isolated":            "isolated.png",
    "dead_end":            "dead_end_n.png",
    "straight":            "straight_ns.png",
    "bend":                "bend_ne.png",
    "corner":              "corner_ne.png",
    "tee":                 "tee_n.png",
    "tee_corner_nw":       "tee_corner_nw_n.png",
    "tee_corner_ne":       "tee_corner_ne_n.png",
    "tee_full":            "tee_full_n.png",
    "cross":               "cross.png",
    "cross_one_corner":    "cross_one_corner_n.png",
    "cross_adjacent":      "cross_adjacent_n.png",
    "cross_diagonal":      "cross_diagonal_n.png",
    "cross_three_corners": "cross_three_corners_n.png",
    "plaza":               "plaza.png"
  }
}
```

- `styles[]` 字段：`tags`（字符串数组，空数组＝通配底样）、`base`（**目录前缀**，相对包根；带不带尾斜杠都合法，拼接时按需补 `/`）、可选 `mode`（`all` 时才需全匹配）。
- `tiles` 的键**必须与 §10.2.2 槽位名逐字一致**，缺键即该槽位回退为脚印。值为**相对文件名**（不含目录），目录由选中样式集的 `base` 给出；**只有样式集缺省 `base` 时**，值才写成相对包根的**完整路径**。
- 素材名里的方向尾缀**只描述那张图的基准朝向**（§10.2.4）：`_n` ＝ 缺口朝北（尽端路即连通面朝南）、`_ns` ＝ 南北向、`_ne` ＝ 连北 ＋ 连东。
- **道路贴图不设背景色**：透明区直接透出背景图，`road` 节不提供任何颜色 / 填充字段。

`KS-*` 校验项：

| 编号 | 检查 | 提示 |
|---|---|---|
| `KS-1` | `tiles` 键与槽位分型表不一致 | 列出缺失与多余的键名 |
| `KS-2` | 素材路径在包内不存在 | 列出全部无效路径 |
| `KS-3` | 两条样式在规则 ①② 上完全同分 | 提示按规则 ③ 取前者，建议显式消歧 |
| `KS-4` | 素材非正方形（宽高不等） | 提示放弃旋转复用或补全 4 向素材 |
| `KS-5` | 以 `.9.png` 命名但未提供 `slice` | 按普通拉伸处理 |
| `KS-6` | 素材尺寸与背景 `cellSize` 不成整倍数 | 缩放后会出现半像素模糊 |
| `KS-7` | `road` 节里出现颜色类字段 | 道路不设背景色，该字段被忽略 |

### 10.3 形象与立绘 `role`

**形象不带朝向**：游玩态不存在朝向状态（移动为正交四邻），形象素材**不设旋转轨道、不要 4 向素材**。需要「左右相对」的场合由立绘的可选 `flip` 显式声明镜像，**不引入** `n` / `e` / `s` / `w` 槽位。

#### 10.3.1 棋子形象节点

```json
"role": {
  "player": "resource/role/player.png",
  "classes":  { "warrior": "resource/role/class_warrior.png" },
  "monsters": { "goblin":  "resource/role/monster_goblin.png" },
  "npcs":     { "elder":   "resource/role/npc_elder.png" }
}
```

| 键 | 取值 | 缺失时回退 |
|---|---|---|
| `player` | 单节点直接取图（接受三写法） | 职业 `icon` emoji → `🙂` |
| `classes.<组件 id>` | 按职业 id 查表 | 该职业 `icon` emoji |
| `monsters.<组件 id>` | 按怪物 id 查表 | 该怪物 `icon` emoji |
| `npcs.<组件 id>` | 按 NPC id 查表 | 该 NPC `icon` emoji |

- 四组**不跨组借用**（`player` 与 `classes` 是两条独立的链）。
- `classes` / `monsters` / `npcs` **不允许数组**（无朝向，数组无意义）。
- 键一律是组件 `id`。
- **尺寸与锚点**：`player` 画成 `CELL × CELL`、**四周留白 10%**（图形占中心约 80%）；锚点一律为**格中心**，不得依赖「底边贴格」。

#### 10.3.2 立绘 `portraits`

**立绘 = 角色 / 怪物的半身或全身大图，是纯皮肤元素**：`.pmod` 不设任何字段，只存在于 `.pp` 的 `role.portraits` 下；**无皮肤时整块不出现**（不渲染、不占位）。

```json
"portraits": {
  "player":   { "img": "resource/role/hero_stand.png" },
  "classes":  { "warrior": "resource/role/hero_warrior_stand.png" },
  "monsters": { "goblin": { "img": "resource/role/goblin_stand.png", "flip": true } },
  "npcs":     { "elder":  "resource/role/elder_stand.png" }
}
```

| 键 | 取值 | 缺失时回退 |
|---|---|---|
| `portraits.player` | 单节点：`img` ＋ 可选 `flip` / `hurt` | 该落点回退程序绘制形态 |
| `portraits.classes.<组件 id>` | 按职业 id 查表 | **先回退 `portraits.player`**，再回退程序绘制 |
| `portraits.monsters.<组件 id>` | 按怪物 id 查表 | 该落点不渲染（**不**跨怪物借用） |
| `portraits.npcs.<组件 id>` | 按 NPC id 查表 | 该落点不渲染（**不**跨 NPC 借用） |

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `img` | 字符串 | 立绘图，路径**相对包根** | 该立绘不渲染 |
| `flip` | 布尔 | **显式**左右镜像：写 `true` 才翻转 | `false` |
| `hurt` | 字符串 | **受击图**（可选）：受击瞬间改显示这一张 | 缺省 → **改用形变**（§10.3.4） |

- 立绘**不接受数组**。
- `flip` 只翻图、不翻布局：翻转后仍与容器**底边对齐**，且**不改变**左右站位（主角恒在左、怪物 / NPC 恒在右）。

**落点（5 处）**：

| # | 落点 | 规则 | 无立绘时 |
|---|---|---|---|
| 1 | 地图底栏（hp / mp 条左侧） | 主角立绘**替代整个 `hud-face`**；**底边对齐** | **原样保留** `hud-face`；立绘位不进 DOM、不占宽 |
| 2 | 对战对话框（标题之下、怪物状态之上） | 新增 **VS 区**：**任意一方有立绘即渲染整个 VS 区**，主角左、怪物右，中间「VS」为**文字**；缺的一侧留空、不补占位、不回退 emoji；两侧底边对齐 | 双方都无 → 整个 VS 区不渲染 |
| 3 | NPC 对话弹层 | **不设立绘区**（对话是"文字在说话"的地方，`[主角] VS [NPC]` 是交锋语汇）；NPC 在游玩态只占**标题栏那一格 `icon`**（`role.npcs` 的落点） | 恒无 |
| 3′ | 遭遇 / 商店弹层 | **仍为规范预留**（这两个弹层没有主体 id），V1 不渲染 | 恒为不渲染 |
| 4 | 状态面板 / 角色详情头部 | 与落点 1 **同源同图**、规则一致 | 原样保留 |
| 5 | 选角页出身卡（`.class-icon` 位） | 该**职业**立绘**放大替代** `icon` emoji、**居中**（唯一不底边对齐的落点） | 回退职业 `icon` emoji |

**尺寸与对齐**：

- **立绘不使用 `CELL` 基准**、也不写死像素档：取**窗口短边** `W = min(视口宽, 视口高)`，立绘高度＝`W` 的固定比例，**窗口一变、立绘等比跟着变**。
- 高度档（占 `W` 的比例）：底栏 / 状态面板头部 `6%`；对战 VS 区 `18%`；出身卡 `10%`。
- **宽度**由素材**宽高比**推出、**不拉伸变形**；并受**可用宽度 25%** 上限约束，超出即整体等比缩小。
- **默认底边对齐**（立绘"站"在容器底线上）；**仅出身卡居中**。
- 素材必须**自带透明留白**，本节不提供内边距 / 尺寸字段。
- 不加 `@media` 断点——`W` 是唯一尺寸来源。

**回退与占位**：

- 立绘**不是棋子形象的替代品**，与之**不共用回退链**。
- 立绘缺位一律**逐落点降级**，且**整个立绘容器按条件渲染**——「**没有立绘则不占用空间**」（落点 2 的例外：另一方有立绘时 VS 区照常渲染，缺的一侧为空）。
- 立绘**不含动画**（唯一动态是受击形变）、**不套手绘滤镜**、**不参与点击命中**。

#### 10.3.3 受击表现：素材优先，无素材则形变

受击反馈**两条路，优先用素材、缺了才形变**——**棋子形象与立绘（含 NPC）同一套规则**：

| 素材情况 | 表现 |
|---|---|
| **提供了受击图**（立绘写 `hurt`） | 受击瞬间**改显示受击图**，持续到本次受击动作结束 |
| **没有受击图**（默认） | **图形拉伸 / 压缩**（squash & stretch）：横向 ×1.15、纵向 ×0.9，约 `120ms` 回弹 |

- **形变是程序行为、不是素材**：不占皮肤字段、不需额外出图；幅度与时长由引擎给初值（×1.15 / ×0.9、约 120ms）。
- **形变基准点**：棋子形象以**格中心**为基准；立绘以**底边**为基准。
- 棋子形象**没有 `hurt` 字段**，故**恒走形变**。
- **败北 / 倒下不设素材**：形变只表达"挨了一下"，不表达倒下。

`KR-*` 校验项：

| 编号 | 检查 | 提示 |
|---|---|---|
| `KR-1` | **棋子形象**素材非正方形 | 会按中心缩放宽高不一致（**立绘不适用**） |
| `KR-2` | `classes` / `monsters` / `npcs` 的键不在本局存在的组件 id 内 | 无效键，回退 emoji |
| `KR-3` | `classes` / `monsters` / `npcs` 写成数组 | 形象无朝向，数组写法无效 |
| `KR-4` | 图形贴满四边（未留白） | 地图上相邻格会互相压边 |
| `KR-5` | **立绘**素材**宽 ≥ 高**（非竖构图） | 按 `W` 比例缩放后比例失衡，通常应出竖版 |
| `KR-6` | `portraits.*` 的键不在本局存在的组件 id 内 | 无效键，该落点回退 / 不渲染 |
| `KR-7` | `portraits.*` 写成数组 | 立绘无四向，变体也不写成数组 |
| `KR-8` | 立绘**不带透明通道**（四角不透明） | 会盖住底栏 / 对话框的纸面 |
| `KR-9` | 受击图 `hurt` 与 `img` 的宽高比不一致 | 受击瞬间画面会跳变，应同比例出图 |
| `KR-10` | **NPC 立绘与主人公立绘是同一张图** | NPC 立绘缺位的语义是"不渲染"，不是"复用主人公" |

### 10.4 窗体与控件 `window`

`window` 管**带底纹或边框、且尺寸由内容或视口决定的元素**，以及按钮、格子、条、提示条、分隔线。

**四族划分**（决定拉伸方式）：

| 族 | 判定 | 策略 | 元素 |
|---|---|---|---|
| **随视口** | 尺寸由窗口决定 | 九宫格 `slice` | 对话框、抽屉、气泡、页面卡片 |
| **随内容** | 尺寸由文字或条目数决定 | **禁止拉伸**（九宫格或纯 CSS） | 按钮、徽章、芯片、提示条、角标、列表行 |
| **固定** | 像素写死 | 整图等比拉伸 | 技能格 54×54、奖励卡 92、部位标签 44、菜单按钮 44 |
| **单向** | 一端固定一端伸缩 | 单轴九宫格（只给左右或只给上下） | 血蓝条轨道与填充、分隔线、进度条 |

**切片规范**：顺序 `[上, 右, 下, 左]`；随视口族建议四角各 `12`，单向族建议 `6`；**任一维切片之和必须小于该元素最小渲染尺寸**，否则四角重叠（`KW-2`）。

```json
"window": {
  "surfaces": {
    "dialog":  { "img": "skin/window/paper.png", "slice": [12, 12, 12, 12] },
    "drawer":  { "img": "skin/window/paper.png", "slice": [12, 12, 12, 12] },
    "popover": { "img": "skin/window/pop.png",   "slice": [10, 10, 10, 10] }
  },
  "buttons": {
    "primary": {
      "normal":   "skin/window/btn_primary.png",
      "hover":    "skin/window/btn_primary_hover.png",
      "active":   "skin/window/btn_primary_active.png",
      "disabled": "skin/window/btn_primary_disabled.png"
    },
    "plain":  "skin/window/btn_plain.png",
    "danger": "skin/window/btn_danger.png",
    "ghost":  "skin/window/btn_ghost.png",
    "small":  "skin/window/btn_small.png",
    "icon":   "skin/window/btn_icon.png",
    "close":  "skin/window/btn_close.png"
  },
  "slots": {
    "skill":      "skin/window/slot_skill.png",
    "reward":     "skin/window/slot_reward.png",
    "bag":        "skin/window/slot_bag.png",
    "equipLabel": "skin/window/slot_equip_label.png"
  },
  "bars": {
    "hp": { "track": "skin/window/bar_track.png", "fill": "skin/window/bar_hp.png" },
    "mp": { "track": "skin/window/bar_track.png", "fill": "skin/window/bar_mp.png" }
  },
  "hints": { "ok": "…", "warn": "…", "error": "…" },
  "rules": { "line": "skin/window/rule.png" }
}
```

#### 10.4.1 六个键族的定键原则

**键一律按「元素在界面里干的事」定，不按类名定**——同一个 `.btn small` 可以是 `small` / `icon` / `close`。

| 族 | 键 | 元素角色 |
|---|---|---|
| `surfaces` | `dialog` / `drawer` / `popover` | 对话框 / 抽屉 / 气泡，各查自己的键 |
| `buttons` | `plain` / `primary` / `danger` / `ghost` / `small` / `icon` / `close` | 中性按钮 / 本屏主行动 / 危险动作 / 低强调（虚线边） / 行内小动作 / 纯图形按钮 / 关闭 |
| `slots` | `skill` / `reward` / `bag` / `equipLabel` | 技能格 54×54 / 奖励卡 92 / 背包格 / 部位标签 44 |
| `bars` | `hp` / `mp` | 生命条 / 法力条，**一档两张**（`track` 轨道、`fill` 填充） |
| `hints` | `ok` / `warn` / `error` | 成功确认（绿）/ 警告有代价（黄）/ 失败危险（红） |
| `rules` | `line` | 手绘分隔线 |

- **各节一律「各查自己的键、不跨键借用」**：对话框没配就**用不回**抽屉的图；`hints.warn` 没配也不会借用 `hints.ok`；`bars` 只配 `track` 不配 `fill` 是合法的（轨道归素材、填充仍是 CSS 实色）。
- **键名允许自定义**：引擎只读上表这些键，**其余键配了静默搁置**——不报错，也不回退到别的键。
- **`hints` 没有中性档**：不带语气修饰的中性提示（「箱内无物品」「不触发任何效果」）**不设键、也不借用任何键**，全由 CSS 表现。左侧那道 3px 竖线**不归素材**，素材只铺底纹。
- **同一个元素可以一格多档**：例如遭遇的判定框是一个提示条按判定结果换三种配色（`success` → `ok`、`blocked` → `warn`、`fail` → `error`），三档**全部先取**、再挑一份。
- **背包格是唯一的交叠处**：`.bag-cell` 同时是道具衬底位（§10.6 的 `item.background`）。取「**道具衬底优先、`slots.bag` 兜底**」——道具配了 `background` 就整格归它，没配才铺 `slots.bag`，**同一个格子上只会出现一层**。

#### 10.4.2 按钮四态

按钮可写四态对象，也可写单张字符串（**等价于只写 `normal`**）。

| 态 | 语义 | 素材缺省时的回退 |
|---|---|---|
| `normal` | 常态；**唯一必填** | 该条缺失即**整颗按钮算没配**（三态写了也一并作废） |
| `hover` | 指针悬停 | 回落 `normal` ＋ CSS 表现 |
| `active` | 按下 | 回落 `normal` ＋ CSS 表现 |
| `disabled` | 不可用 | 回落 `normal` ＋ 现状的 `opacity` 表达 |

- **四态各自独立**：某态没写、或该态的图不在包里，就**回落 `normal`**；`normal` 缺位即整颗按钮走程序绘制。
- 因此**老包 / 手写配置不会因为只写了 `hover` 就凭空多出一张底图**。

#### 10.4.3 信息图标（道具 / 建筑的展示组合）

物品信息视图与建筑信息视图中的图标，按**类似应用图标**的方式叠三层：

| 层 | 来源 |
|---|---|
| 衬底（在下） | `item` / `building` 的 `background` 三元组（§10.6） |
| 图标（在上、居中） | 组件的 `icon` |
| 名称与说明文字 | **窗体自身**的字体与字色，与素材配置无关 |

- **不存在交叉配置**：§10.6 只回答「图标与衬底怎么画」，本节回答「容器与文字怎么画」。本节**不读** `building.font` / `fontColor`——那两个字段只作用于**地图上**的建筑名称。
- 衬底缺省时回退组件 `color`（再缺则主题色）；图标缺省时回退组件定义中的 `icon`。

**窗材一律出「可缩放素材」**：窗体 / 面板 / 按钮这一族**原图尺寸可以很小**，运行期由九宫格或整图拉伸铺满——**素材只需画对形与边界**，不需要按目标渲染尺寸出图，也**不为窄屏单独出一套「宽面板」**。

**V1 的底纹口径**：V1 只把素材当**纸面底纹**铺，边框仍由 CSS / SVG 绘制，因此交付素材须满足「**无边框、四边可自由拉伸**」；带硬边框的完整面板图留给后续版本，届时调用方接口不变。

`KW-*` 校验项：

| 编号 | 检查 | 提示 |
|---|---|---|
| `KW-1` | 随视口族素材无 `slice` | 将整体拉伸，边框圆角会变形 |
| `KW-2` | 任一边切片之和 ≥ 该元素最小渲染尺寸 | 四角会重叠，需减小切片或放弃九宫格 |
| `KW-3` | 随内容族素材含可拉伸中段 | 该族禁止拉伸，需改为九宫格或保持 CSS 绘制 |
| `KW-4` | 固定族素材非正方形 | 会按容器比例压缩变形，需提供等比尺寸 |
| `KW-5` | 素材路径不存在 | 回退程序绘制形态 |
| `KW-7` | 按钮四态素材尺寸不一致 | 悬停或按下时会出现位移、缩放跳变 |

### 10.5 标记、骰子与图标 `misc`

`misc` 收容**不属于形象（`role`）、不属于容器（`window`）的其余全部可见图形**。

```json
"misc": {
  "marks": { "start": "…", "end": "…", "footprint": "…" },
  "nodes": { "building": { "img": "…", "slice": [12, 12, 12, 12] } },
  "dice": {
    "body": "…",
    "face": { "d1": "…", "d2": { "img": "…", "flip": "x" }, "d6": { "img": "…", "rotate": 90 } },
    "numeric": "…"
  },
  "icons": { "Sword": "…" }
}
```

| 键 | 尺寸 / 策略 | 兜底 |
|---|---|---|
| `marks.start` | 1 格，整图，居中，**不旋转** | 程序绘制三角旗 |
| `marks.end` | 1 格，整图，居中，**不旋转** | 程序绘制藏宝图 X |
| `marks.footprint` | 1 格，整图 | 程序绘制脚印；**只在 `road` 素材缺失的格子上顶替**，该格有道路图就轮不到它 |
| `nodes.building` | **随格数 `w × h` 拉伸**，须九宫格 | 圆角矩形（描边 100% alpha ＋ 填充 30% alpha） |
| `dice.body` | 三档尺寸共用一张，**等比缩放、不拉伸** | 程序绘制骰盒 |
| `dice.face.d1`–`d6` | 随本体；**>6 面一律走 `numeric`** | 程序点阵；`numeric` 缺则数字文本 |
| `dice.numeric` | 随本体 | 数字文本 |
| `icons.<图标名>` | 按该图标的 `size` 占 `size × size` 盒，等比内缩 | 原样回退内置矢量图标 |

- **`marks.start` / `marks.end` 有明确的手绘程序形态**（起点旗、终点藏宝图 X），**可用素材覆盖**；两者**均不使用 emoji**。
- **`nodes.building` 是唯一会随格数拉伸的地图图形**，必须按九宫格交付，否则多格建筑的圆角会变形（`KM-1`）。

**骰面复用是镜像的正式例外**（镜像默认不启用，见 §5.2）：骰面点阵须**显式**声明镜像与旋转，合计 **6 张**覆盖全部骰面朝向：

| 面 | 复用方式 |
|---|---|
| `d1` / `d4` / `d5` | 自身对称，各 1 张 |
| `d2` / `d3` | 主对角 ↔ 副对角，镜像 1 张 |
| `d6` | 竖列 ↔ 横列，旋转 90° |

**图标与兜底**：

- **内置矢量图标**允许按**图标名**提供替换素材（`misc.icons.<图标名>`）：配了该名就换素材，没配 / 缺图一律原样回退。
- **内容 emoji**（职业 / 道具 / 怪物 / 技能的 `icon`）：由组件定义驱动，游玩态**直接以文本绘制、无独立衬底**；替换顺序为「专用素材 → emoji」。
- **兜底字形**：`🙂`（玩家）、`✦`（技能）、`❔`（奖励）、`🎲`（骰子）、`🔒`（门槛徽章）。**兜底字形不可被素材覆盖**——它是素材缺失时的最终保底，可覆盖即失去保底意义。

**定位线（每 10 格坐标参照线）**：属**平铺**而非拉伸，是**叠在地图之上的辅助层、不属于任何贴图**——道路 / 背景 / 格子等贴图本身**不含间距与分割线**。若改用素材，素材必须**四边可无缝拼接**（`KM-2`）。

`KM-*` 校验项：

| 编号 | 检查 | 提示 |
|---|---|---|
| `KM-1` | `nodes.building` 未提供九宫格切片 | 多格建筑的圆角会随格数拉伸变形 |
| `KM-2` | 定位线素材四边不可拼接 | 平铺后出现可见接缝 |
| `KM-3` | 骰面少于 6 张且未声明复用方式 | 按上表的镜像 / 旋转关系补齐 |

### 10.6 道具 `item` 与建筑 `building`

两节字段近似同构，但**场景不同、不合并**：`item` **在地图上没有图形**，`building` **地图节点本身要贴图**。

```json
"item": {
  "red_potion": { "icon": "", "background": { "fill": "#FF0000", "stroke": "#8B0000", "img": "" } }
},
"building": {
  "blacksmith": {
    "icon": "",
    "img": "bld/blacksmith.9.png",
    "background": { "fill": "#FF0000", "stroke": "#8B0000", "img": "" },
    "fontColor": "#FFFFFF",
    "font": "font/hand.ttf"
  }
}
```

| 字段 | 类型 | 适用 | 含义 | 缺省 |
|---|---|---|---|---|
| `icon` | 字符串 | 两者 | 覆盖组件定义中的 `icon`（emoji / 字形） | 组件定义的 `icon` |
| `img` | 字符串 | 建筑 | 地图节点的整体贴图；普通图直接拉伸，`.9.png` 建议配 `slice` | §10.5 的 `nodes.building`，再缺则程序绘制圆角矩形 |
| `background` | 颜色 **或** 对象 | 两者 | 图标 / 格子**衬底**；字符串＝`fill` 简写 | 组件定义的 `color`，再缺则主题色 |
| `background.fill` | 颜色 | 两者 | 衬底的背景填充色 | 同上 |
| `background.stroke` | 颜色 | 两者 | 衬底描边色；**独立设置项，未给即不绘制描边** | 无（不描边） |
| `background.img` | 字符串 | 两者 | 衬底背景图；**优先级高于 `fill`**（`fill` 作其透明区的兜底） | 无 |
| `fontColor` | 颜色 | 建筑 | **地图上**建筑名称的文字颜色 | 主题的次级墨色 |
| `font` | 字符串 | 建筑 | **地图上**建筑名称的字体：包内字体文件路径（相对包根）**或**内置字体名（如 `"serif"`） | CSS 默认 |

**两条硬规则**：

1. `item` **不得**出现 `img` / `font` / `fontColor`（写了忽略并提示，`KIB-6`）。
2. `building` 的 `font` / `fontColor` **只作用于地图上的名称文字**；对话框内的文字一律用窗体（§10.4）的字体与字色——避免同一处文字两套配置互相打架。

**其它口径**：

- **键一律为组件 `id`**（不用显示名，`KIB-5`）。
- `background` 是「填充色 ＋ 描边色 ＋ 背景图」三元组；**背景图存在时不绘制 `fill`，仍绘制 `stroke`**（若 `stroke` 有值）。
- **描边是独立设置项**：只写 `fill` 而不写 `stroke` 时**不绘制描边**——既不跟随 `fill`，也不保留组件色；`"stroke": "transparent"` 与省略等价。
- 这条规则只作用于**素材接管**的情形：某元素整节未接管时，仍按程序绘制形态渲染，即**保留现有组件色描边**。
- `font` 指向包内文件时由加载器注入字体，**族名取文件名去扩展名**；文件无效则回退内置字体（`KIB-4`）。**内置字体名原样交给 CSS、不注入**。
- **道具的 `background` 主落点是格子衬底**（含背包格、穿戴格、更换气泡候选）；**`item` 不影响地图**。
- **物品 / 建筑信息视图**只消费本节两个输入（衬底 ＋ `icon`），名称与说明文字归窗体；**`building.font` / `fontColor` 不作用于此处**。

`KIB-*` 校验项：

| 编号 | 检查 | 提示 |
|---|---|---|
| `KIB-1` | 键不在本局启用的组件 id 内 | 无效键，忽略 |
| `KIB-2` | `img` 带 `.9.png` 后缀但未提供 `slice` | 按普通拉伸处理 |
| `KIB-3` | `img` 尺寸与格数不成整倍数 | 多格建筑上会拉伸变形，建议按「格数 × 单格边长」出图 |
| `KIB-4` | `font` 指向包内文件但路径无效 | 回退内置字体 |
| `KIB-5` | 用显示名（`name`）而不是 `id` 作键 | 可能因重名或改名失效 |
| `KIB-6` | `item` 写了 `img` / `font` / `fontColor`；或 `background` 对象含未知键 | 忽略该字段 |
| `KIB-7` | `background.stroke` 与 `fill` 都为透明，或整节只有 `img` 且该图全透明 | 衬底不可见，确认是否有意 |
| `KIB-8` | 写了 `fill` 但未写 `stroke` | **不绘制描边**属正常用法，仅在观感可能与程序绘制形态不同时提示确认 |

### 10.7 音频 `audio`

`audio` 覆盖**背景音乐**与**操作音效**两类，全部为包内素材，逐节点降级。

```json
"audio": {
  "bgm": {
    "home":   { "file": "resource/audio/home.mp3",   "loop": true, "volume": 0.5 },
    "map":    { "file": "resource/audio/map.mp3",    "loop": true, "volume": 0.5 },
    "battle": { "file": "resource/audio/battle.mp3", "loop": true, "volume": 0.6 }
  },
  "sfx": {
    "dice_roll": "resource/audio/dice_roll.ogg",
    "dice_land": "resource/audio/dice_land.ogg",
    "hit":       "resource/audio/hit.ogg",
    "pickup":    "resource/audio/pickup.ogg",
    "coin":      "resource/audio/coin.ogg",
    "open":      "resource/audio/open.ogg",
    "close":     "resource/audio/close.ogg",
    "error":     "resource/audio/error.ogg"
  }
}
```

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `bgm.<场景>.file` | 字符串 | 背景音乐文件，路径相对包根 | 无声（该场景静音） |
| `bgm.<场景>.loop` | 布尔 | 是否循环 | `true` |
| `bgm.<场景>.volume` | 0–1 | 该曲默认音量（**可被用户偏好覆盖**） | `0.5` |
| `sfx.<事件>` | 字符串 **或** 对象 | 音效文件；对象写法为 `{ "file": …, "volume": … }` | 静默 |
| `sfx.<事件>.volume` | 0–1 | 该音效默认音量 | `0.8` |

**BGM 场景键**（与现有一一对应，**各查自己的键、不跨键借用**——配了 `battle` 不会让 `map` 有曲）：

| 场景键 | 对应界面 |
|---|---|
| `home` | 欢迎页 / 出身选择页 |
| `map` | 地图探索（游玩态主界面） |
| `battle` | 战斗 / 遭遇 |

**音效事件键**（键名即**唯一契约**，改名视为不兼容变更）：

| 事件键 | 触发时机 |
|---|---|
| `dice_roll` | 掷骰开始（掷骰动画期间） |
| `dice_land` | 骰子落定 |
| `hit` | 战斗造成伤害 |
| `pickup` | 获得道具 / 奖励 |
| `coin` | 买 / 卖成交 |
| `open` / `close` | 面板、对话框、抽屉开合 |
| `error` | 操作被拒（背包已满、点数不够等） |

**播放约束**：

- **本节在 V1 只做解析与校验**：识别 `audio` 键、校验路径与取值、在清单中给出提示；**不加载、不解码、不播放**，也不产生任何音频行为。字段与事件键在 V1 即定稿，后续版本不再变动。
- **不自动播放**：浏览器禁止无用户手势的播放，BGM 在**首次用户交互后**才启动。
- 素材必须来自**包内**条目，不请求外部地址。
- 推荐 `mp3`（兼容面最广）＋ `ogg`（体积）；同一素材可**顺序**声明多个文件由引擎择一。
- **音量与静音的用户偏好属于用户配置**，优先级高于本节给出的默认音量；本节不接管。
- 场景切换的默认行为是**淡出旧曲 → 淡入新曲**（各 600ms），同一场景重复进入不重启曲目。
- 同一帧内的多次相同事件**合并为一次播放**，避免叠音。
- 音频**不参与任何渲染**，与视觉各节无耦合；也不做频谱可视化。

`KA-*` 校验项：

| 编号 | 检查 | 提示 |
|---|---|---|
| `KA-1` | 音频路径在包内不存在 | 该条静音，其余正常；**不单列**，由包级通用缺失收集（按扩展名认音频）判定 |
| `KA-2` | `sfx` 的事件键不在上表内 | 无效键，忽略 |
| `KA-3` | `volume` 超出 0–1 | 截断并提示 |
| `KA-4` | 单个音频文件体积过大（暂以 > 2 MB 提示） | 首次播放会有明显延迟；同一个文件只报一次 |
| `KA-5` | 声明了 BGM 但 `loop: false` 且曲目过短（< 3s） | 会明显听出停止 |

### 10.8 欢迎页与首页 `startup` / `lobby`

覆盖**进入游戏之前**的两屏，**两屏均可整体缺省**（不设置即整屏走降级），不报错。

| 键 | 屏 |
|---|---|
| `startup` | **应用欢迎页**（启动画面 / 封面主页） |
| `lobby` | **游戏首页 / 选角页面**（世界简介 ＋ 出身选择） |

```json
"startup": {
  "bg":    { "img": "resource/home/bg.jpg", "fit": "cover" },
  "title": { "img": "resource/home/title.png" },
  "cover": { "img": "resource/home/cave.png" },
  "dice":  { "img": "resource/misc/die.png" }
},
"lobby": {
  "bg":    { "img": "resource/start/bg.jpg", "fit": "cover" },
  "card":  { "img": "resource/start/card.9.png", "slice": [14, 14, 14, 14],
             "selected": { "stroke": "#B4552F" } },
  "panel": { "img": "resource/start/scroll.9.png", "slice": [16, 16, 16, 16] }
}
```

**`startup`**：

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `bg` | 素材对象 | 全屏背景（**即该屏的封面图**） | 纸面底纹（CSS） |
| `title` | 素材对象 | 标题图形，**只替换字形、不改文案** | 文字标题 |
| `cover` | 素材对象 | 主视觉图形 | 程序绘制的洞穴主视觉 |
| `dice` | 素材对象 | 主视觉上的装饰骰子贴图；**本键只给骰子本体**，骰面复用 §10.5 的 `dice.face` | 程序绘制骰子 |

**`lobby`**：

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `bg` | 素材对象 | 同 `startup.bg` | 纸面底纹 |
| `panel` | 素材对象 | 「这一局的世界」正文面板的底 | 现纸面 |
| `card` | 素材对象 | **出身卡片**底，按内容高度拉伸 | 现手绘卡片 |
| `card.selected` | 对象 | 选中态差异：`{ img, slice, stroke }`；`img` 缺省时**只改描边** | 现选中描边 |

**整屏背景的 `fit` 三档**：`cover`（裁切铺满，**缺省**，非法值也回落此档）/ `contain`（完整可见，两侧留主题底色）/ `tile`（平铺）。

**其它口径**：

- **每个字段独立降级**：只给 `startup.bg` 时，标题仍是文字、主视觉仍是程序绘制——**半素材化是正常状态**。
- **封面图归皮肤侧**：`.pmod` **不设**封面图字段，与「`.pmod` 不含任何 UI 定义」的分工一致。
- 封面标语 / 副标题 / 版本号 / 警告条**均为文字**：文案不随皮肤改变，字体与字色沿用主题，本节**不提供字色字段**。
- 两屏的按钮、徽章、提示条**直接复用 §10.4**，不在本节重复定义；卡片内的**职业图标与立绘**归 §10.3，本节不接管。
- **「其它开始方式」里的皮肤选择入口**由程序绘制，**不受皮肤控制**——否则会出现「必须先选皮肤才能显示出选皮肤的界面」的循环；它只消费包描述文件的顶层 `name` / `author` 与包根预览图。

`KPG-*` 校验项：

| 编号 | 检查 | 提示 |
|---|---|---|
| `KPG-1` | `bg.fit` 取值非法 | 回退 `cover` |
| `KPG-2` | `card` 给了 `img` 但未给 `slice` | 按普通拉伸处理 |
| `KPG-3` | `title.img` 尺寸与标题区比例不符（高宽比偏离约 `6:1`） | 会被压缩，建议按该比例出图 |
| `KPG-4` | `dice.img` 给了图但 `dice.face` 未给骰面 | 主视觉有骰子外壳、内部仍是程序绘制点数 |
| `KPG-5` | 本节出现 `buttons` / `chips` / 字体类字段 | 本节不接管，应写到 `window` / 主题侧；忽略 |
| `KPG-6` | 出现旧键 `pages` | 已拆为 `startup` / `lobby`，旧键忽略并提示迁移 |

## 十一、最小完整示例

一个只覆盖背景与角色、其余全部回退程序绘制的最小 `.pp`：

```text
demo.pp（zip）
├── manifest.json
└── resource/
    ├── bg/map1.jpg
    └── role/hero.png
```

`manifest.json`：

```json
{
  "format": 1,
  "name": "最小皮肤",
  "theme": { "--paper": "#f5efe2" },
  "background": [ { "img": "resource/bg/map1.jpg", "cellSize": 48 } ],
  "role": { "player": "resource/role/hero.png" }
}
```

- 未列出的节（`road` / `window` / `item` …）**全部回退程序绘制**，属正常状态。

## 十二、直接修改检查清单

1. `manifest.json` **在包根**、是合法 JSON（无尾逗号、无注释）。
2. 只出现**顶层键总表**内（§3.1）的键；未用到 `resource`（`KP-10`）。
3. **`name` 若给，则在皮肤列表可读**；`preview.png`（如有）**在包根**且可解码。
4. 每条素材路径**相对包根写全**，不出现绝对路径 / `..` / `http(s)://`（`KP-4`）。
5. 路径**确实存在于包内条目**（`KP-2`）——尤其改目录名后逐条核对。
6. 数组型素材字段**顺序为 N / E / S / W 且不缺项**（§5.1）。
7. 需要旋转复用的素材**正方形且图形居中**；需要九宫格的素材**已给 `slice`**。
8. `item` / `building` / `road` / `role` 的键名**是本局 `.pmod` 里实际启用的组件 id**（`KP-5`）。
9. `theme` 只改**观感 token**，不碰布局 token、不用未知 token（`KP-9`）。
10. `extends` 指向**包内**路径且**不成环**（`KP-8`）。
11. 素材缺失**不报错、逐节点降级**——不用担心"少一张图会崩"，但也别指望它会报错提示。
12. 改的是**观感**；任何"改玩法数值 / 改判定"的诉求都应回到 `.pmod`（见 [`pmod.md`](pmod.md)）。
