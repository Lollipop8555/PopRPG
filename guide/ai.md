# AI 规则读取入口（`ai.md`）

> **用途**：让人用自然语言描述玩法，由 AI 落地成 `.pmod` / `.pp` / `.pgame` 改动。
> **上层索引**：[`../Guide.md`](../Guide.md)（总入口、修改流程、共同铁律）
> **同族接口**：格式手册 [`pmod.md`](pmod.md) / [`pp.md`](pp.md)、机读结构定义 [`rules.yaml`](rules.yaml)

AI 不必通读全部文档：按下面两节取用即可，**凡涉及字段名、取值域、缺省、校验编号，一律以格式手册为准**，`rules.yaml` 只是同一批事实的机读形态。

## 一、读什么、按什么顺序

| 步骤 | 读 | 取什么 |
|---|---|---|
| 1 | 本文件 | 边界、流程、映射表 |
| 2 | [`../Guide.md`](../Guide.md) | 文件类型分工、修改流程、共同铁律、校验家族 |
| 3 | [`rules.yaml`](rules.yaml) 的 `pmod:` / `pp:` 段 | 结构骨架、字段名与取值域、校验编号 —— **定位用** |
| 4 | 目标格式手册的对应章节 | 字段语义、必填 / 可省、缺省、降级行为 —— **落笔用** |
| 5 | 目标格式手册的校验项与检查清单 | 自查用 |

- **只写不读不够**：字段名对不代表语义对。例如 `## Rules` 只给默认骰，难度写在组件上；`give` 而不是 `items` 才是交付清单。
- **章节定位**：`.pmod` → [`pmod.md`](pmod.md) 的 §三–§八（骨架 / 组件 / Rules / Pool / Maps / 校验）；`.pp` → [`pp.md`](pp.md) 的 §五–§十（路径 / 复用 / 优先级 / 各节字段）。

## 二、四条不可越界的铁律

1. **不发明字段**。`rules.yaml` 与手册里没有的键一律不写；不确定时先读手册，不要用"看起来合理"的名字。
2. **不发明取值**。`kind` / `encounter` / `dim` / `op` / `algo` 这类枚举只取手册列出的值；`algo` 没有 `all`。
3. **不越界分工**。玩法内容进 `.pmod`（**不含 UI 定义**，封面图、字体、按钮一律不进）；观感进 `.pp`（**不含玩法语义**，碰不到属性、规则、地图）。
4. **不改已确认的结构**。结构标题必须英文、`.pmod` 必须含 BOM 与 `<!-- charset: utf-8 -->`、`id` 一经给定不回收；这些是往返一致与校验的前提。

## 三、自然语言需求 → 文件改动映射

| 用户说法 | 改哪 | 落笔位置 |
|---|---|---|
| 加一只怪 / 改怪物强度 | `.pmod` | `Monsters` 组新增或改 `stats` 区间、`attack_weights` |
| 加一件装备 / 药水 | `.pmod` | `Items` 组：`kind` 决定 `slots` ＋ `modifiers` 还是 `usable` ＋ `effects` |
| 加一种建筑 / 改开箱奖励 | `.pmod` | `Buildings` 组按 `encounter` 分支配 `reward_pool` / `monster_pool` / `event` / `stock` |
| 加一条路 / 路要难走 | `.pmod` | `Roads` 组改 `cost` / `gate` |
| 加职业 / 改初始属性 | `.pmod` | `Classes` 组；再在 `Rules.class_pool` 登记 |
| 加技能 / 改伤害公式 | `.pmod` | `Skills` 组的 `dim` / `vs` / `bonus` / `apply` / `effects` |
| 让 NPC 说话 / 加对话分支 | `.pmod` | `NPCs` 组 `dialogs` 下的对话树；再在地图节点 `npcs` / `dialog` 挂上 |
| 加一张地图 / 挪建筑位置 | `.pmod` | `Maps` 段新增 `### 地图名` 或改 `nodes` |
| 加全局规则 / 加回合效果 | `.pmod` | `Rules` 十四项；带条件与效果的按回合逻辑写 `Pool` 的 `checks` |
| 记一个全局变量 / 记是否开过门 | `.pmod` | `Pool` 的 `pool` 段声明，使用时写规范全名 `usr-xxx` |
| 换背景 / 换地图贴图 | `.pp` | `background` 段（按地图下标） |
| 换怪物 / 主角形象 | `.pp` | `role` 段（键为组件 id） |
| 换对话框 / 按钮样式 | `.pp` | `window` 段（各查自己的键） |
| 换骰子 / 标记 / 图标 | `.pp` | `misc` 段 |
| 加音乐音效 | `.pp` | `audio` 段（场景键 / 事件键） |
| 换欢迎页 / 选角页 | `.pp` | `startup` / `lobby`（旧键 `pages` 已废除） |
| 把游戏和皮肤一起发出去 | `.pgame` | `pack.json` ＋ `game.pmod` ＋ `skin/` |

**用户描述里缺的参数不要编**：区间、权重、概率、骰子这类数值若用户没说，取手册的缺省值并在交付说明里点出「用了缺省」。

## 四、改动流程（六步 ＋ 交付）

1. **认类型**：先判定改的是 `.pmod`、`.pp` 还是 `.pgame`（见上表）。跨两类的需求拆成两次改动。
2. **读手册**：打开目标手册的骨架与限制，再读目标模块那一节。**先读后写，不要边猜边写**。
3. **定位**：确认目标字段的必填 / 可省、取值域、缺省。
4. **落笔**：结构标题、缩进、围栏、键名保持原样；新增实体按 ID 规则取 id；引用写规范全名。
5. **自查**：过手册末尾的检查清单；对 `.pmod` 额外核 `Pool` 家族编号（`K20`–`K37`）。
6. **核校验**：确认没有触发阻塞项 —— `.pmod` 只有 `K30`（回合判定依赖成环）阻塞；`.pp` 全部提示不阻断。

**交付时必须说明**（缺一项视为未交付）：

- 改了哪个文件的哪个结构段；
- 新增 / 修改的 `id` 清单与它们的取值来源；
- 用到的缺省值（未由用户指定者）；
- 触发或规避的校验编号；
- 若涉及观感，说明素材路径写法（相对包根、四张数组顺序 `N/E/S/W`）。

## 五、结构化定义取用

[`rules.yaml`](rules.yaml) 的顶层结构与用途：

| 段 | 内容 |
|---|---|
| `common` | 编码、版本键、自包含、纯静态、校验家族 |
| `pmod.id_rules` / `inclusion` | 预设与自建的 id 形态、哪些实体随文件带走 |
| `pmod.blocks` / `components` / `effects` / `pools` | 结构骨架与八类组件字段、效果算子、池结构 |
| `pmod.rules` | `## Rules` 十四项（key / 形状 / 说明） |
| `pmod.pool` | 状态池三段、读算子与写算子、键匹配 |
| `pmod.maps` | 地图骨架与节点字段 |
| `pmod.codecs` / `validations` | 编码兼容策略、`K20`–`K37` 与提示级校验 |
| `pp.manifest_top_keys` / `paths` / `reuse` / `priority` | 顶层键、路径规则、复用四件套、三层优先级 |
| `pp.sections` | 各节字段与缺省（`background` / `road` / `role` / `window` / `misc` / `item` / `building` / `audio` / `startup` / `lobby`） |
| `pp.validations` | `KP-*` 与各节子编号 |
| `pgame` | 容器条目与 `pack.json` 字段 |

- 程序侧同样读取本文件：应用内 Guide 阅读页（`#/guide`）用它渲染字段速查表。
- **冲突处理**：`rules.yaml` 与格式手册不一致时，**以手册为准**，并把差异回改到 `rules.yaml`，在交付说明里点出。

## 六、常见失误清单

| 失误 | 后果 |
|---|---|
| 用中文结构标题（`## 组件`） | 匹配不上，该段组件被**静默丢弃** |
| `.pmod` 漏 BOM 或漏 `charset` 注释 | 中文地图名与散文可能乱码 |
| 把 NPC 写进 `Buildings` 的定义里 | NPC 不挂在建筑定义上，只挂地图节点的 `npcs` / `dialog` |
| 对话交付清单写成 `items` | 交付清单是 `give`；`items` 是子节点 |
| 条件同写 `value` 与 `ref` | 只认 `ref`（`K37`） |
| `add_tag` 漏 `duration` | 必填，缺失**禁止保存** |
| 回合判定互相 `deps` 成环 | `K30`，唯一阻塞项 |
| `.pp` 写绝对路径或外部地址 | 违反纯静态约束（`KP-4`） |
| 四张朝向数组省掉中间项 | 顺序固定 `N/E/S/W`，不得省略 |
| 期待 `.pp` 能改玩法数值 | `.pp` 是纯渲染，不含任何玩法语义 |
| 期待 `.pmod` 能带封面图 | 封面图归皮肤侧，`.pmod` 不含 UI 定义 |
