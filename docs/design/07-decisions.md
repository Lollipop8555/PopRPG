## 8. 已确认决策记录

| 项 | 决策 |
|---|---|
| 技术栈 | React + TS + Vite + Zustand + lucide/Emoji |
| 文件格式 | 混合：散文 Markdown 正文 + 结构化 ```yaml 围栏 |
| 存档分离 | `.pmod` 仅场景定义；进度存独立 `.psave`（后续） |
| MVP 范围 | 先构建闭环（编辑器 + 套件 + 地图 + 导出/导入） |
| 建筑宝箱怪物 | 宝箱屋的可选 `mimic` 属性（概率伪装怪物，战胜有奖） |
| 图标来源 | lucide 矢量 + Emoji 占位（手绘后续） |
| 预设范围 | 最小可用预设先跑通闭环，后期专项补充 |
| 项目管理 | 先单项目（localStorage 单例） |
| 数值体系 | **6 个属性 = 两条资源（`hp` / `mp`）+ 四条能力（`patk` / `matk` / `pdef` / `mdef`）**；装备占 头手脚身武 槽；消耗品改数值 |
| 部署目标 | GitHub Pages 纯静态；无后端/无服务端；仅用可打包进静态产物的库 |
| 视觉风格 | 纸张质感 + 手绘风格（暖色纸纹、手绘线条、手写体，尽量不引额外库） |
| **信息架构** | 两层：**组件库 Library（系统预设 ＋ 用户自建，同一份列表、同一地位）→ 游戏内容 Content（启用 ＋ 铺设）= 一局游戏** |
| **组件库定位** | 库是**工具来源**，像笔刷库：用户自建的和系统预设一样躺在库里，能改 / 删 / 复制 / 反复用；库不因某个项目而生，也不随某个项目而亡 |
| **组件生效** | 地图件（道路/建筑）：**铺到地图格才算内容**；非地图件（消耗品/装备/怪物/职业）：**显式启用才算内容** |
| **组件分类** | 按"在内容里怎么出现"分：**地图件**（道路 / 建筑）vs **道具／内容**（消耗品 / 装备 / 怪物 / 职业 / **技能**）；两类**永不在同一层混排**。起点/终点是画布内建标记，不占库名额 |
| **`.pmod` 自包含** | 只装本局真正用到的组件（启用 + 铺设），定义快照随文件带走；导入时并入本地组件库。**没有来源标记字段** |
| **预设 vs 自建** | **不存字段**，由 `id` 形状当场派生（§3.2）：id 命中内置预设表 = `预设`，否则 = `自建`。**八大类一视同仁**——用户能自建怪物 / 道具 / 建筑 / 道路 / 职业 / **技能** / **NPC**（裁决 26），判定方式完全一样 |
| **库与项目的关系** | 项目只记 `enabledIds` + 地图铺设，**不存组件定义**；改库 = 所有用到它的局一起变（这正是"库是工具来源"该有的行为） |
| **图层** | 「图层」= 项目的**多张地图列表**，在左栏管理（切换 / 新建 / 重命名 / 排序 / 删除）；顶栏**不再放地图 Tab** |
| **工具模式** | 只有 **6 个模式**（选择 / 放置 / 连线 / 框选 / 擦除 / 标记），入口唯一在画布左上「模式条」；顶栏不放工具 |
| **批量操作** | 拖框选区 → 浮动条 → **批量删除**（一轮做）；批量替换 / 批量移动标 P1 |
| **三层边界** | **硬规则**（§4.8.0，写死、不应列入）→ **前置配置**（§4.8.6，每场景一套算法）→ **内容**（组件上只有池和数值） |
| **配置纪律** | **配置里出现的每个字段都必须是代码已实现的**；不给"本来就该如此"的东西做开关（`move.allow_back` / `move.diagonal` 全删）。有疑问的字段一律不写 |
| **硬规则** | 正交四邻移动、不可斜走、可原路返回；**一回合 = 一次推进时间的行动（一次交锋 / 一次移动走完全部步数）**；`target: opponent` 时 `本力值 ≥ 对方防值` 命中；伤害 = `max(1, 本力值−防值)`、治疗 = `本力值`；**1 点=+1 / 不可洗点 / 余点保留**；技能要付自己的 `cost`；**任何状态必须有 `duration` 且不超上限**（§4.8.0） |
| **状态必有上限** | 任何状态都必须带 `duration`，且不超过 `state.max_duration`（默认 10）。**不存在永久状态**——没有解法的状态就是死局（§4.8.10） |
| **点数给多少 = 职业设定** | `ClassDef.base_stats`（初始属性）+ `ClassDef.free_points`（开局自由点）**都是职业自己的字段**。**不设上限**——`free_points: 300` 完全合法（§4.2.3） |
| **分配规则 = 硬规则** | **1 点 = 该属性 +1**；可分配到 6 属性任意项；**任意时刻**都能加；**不可洗点**；**剩余自由点保留**。这一层引擎写死（§4.2.2） |
| **点数会持续进账** | 怪物 / 建筑上的 `point_reward`（默认 0）在结算时把点数加进剩余自由点——**这是玩家变强的主渠道**，固定值不掷骰（§4.8.8） |
| **属性来源两侧不对称** | **玩家 = `base_stats` ＋ 分配出的确定值**（不能被骰子改）；**怪物 = `stats` 区间登场摇定**（有波动）。玩家可控、敌人随机——故意的（§4.0.2 / §4.8.2） |
| **小怪 / 精英** | **不加字段**：靠 `stats` 区间拉开档（小怪 `hp 6~12` / 精英 `hp 24~40`），精英再打 `tags: [精英]`，怪物池直接 `filter: { tags: [精英] }` 就能做精英房（§4.1 / §6.1.1） |
| **`mp` 是正式属性** | 两条资源之一：玩家能分配点到它、**有成本的技能消耗它**（如 `cost: { mp: 3 }`；**保底对 `basic_attack` / `basic_magic` 都不花 mp**）、蓝瓶回它、地形 `cost` 能扣它。**要么没有 mp，要么成套**——现在是成套（§4.0.1 / §4.8.3） |
| **消耗 vs 权限** | 道路 / 建筑有**两个正交维度**：`cost`（消耗：步数 / 血量 / 法力）与 `gate`（权限：标签匹配）。**消耗只让路变贵，权限才决定能不能过**——两者任意组合（§4.5.1） |
| **标签驱动通行** | `gate.tags` 对 `capabilities = ⋃(穿戴中装备.tags) ∪ 当前职业.tags` 做匹配（`any` / `all`）；不满足时 `block`（走不进去）或 `penalty`（能走但加罚）。**引擎不认识"渡河""火抗"这些词，用户造新标签就自动有新区块**（§4.5.2 / §4.5.3） |
| **能力的三个来源** | `capabilities = ⋃(穿戴中装备.tags) ∪ 当前职业.tags ∪ **身上状态.tags**`。装备是**长期**钥匙（5 个槽位有限，"带火抗鞋就带不了小船"正是玩点）；状态是**临时**钥匙（御火符顶 3 回合）。**同一个 `tags` 字段身兼三职**（§4.3 / §4.5.2 / §4.8.10） |
| **`cost` / `gate` 是地图件公共字段** | 道路和建筑**共用同一套**：建筑加 `gate` 就是一扇上锁的门，机制完全复用，不另发明（§4.4） |
| **力值合成链** | `力值 = floor( ( (已结算属性值 + 装备 modifiers + **状态 modifiers** + **技能 bonus**) × 职业 buffs% + 骰子叠加 ) × 骰子倍率 )`。**属性 / 加值（加法环：装备＋状态＋技能）/ 职业（乘法）/ 骰子（叠加 or 倍率）四环全在链上，不是只看骰子**（§4.8.2） |
| **技能决定维度** | `skill.dim` 决定"取哪一维属性当基准"，`skill.vs` 决定"对手拿哪一维对抗"（`auto` 物理族对物理族、法术族对法术族）。**引擎不再写死"物攻→物防、魔攻→魔抗"**（§4.8.3） |
| **基础积木只有三个** | `rollRange`（骰点→区间取值）、`rollSteps`（骰点→档位倍率）、`rollSum`（骰点直接相加）；全篇不另起第二套公式（§4.8.1） |
| **技能 = 取一维 + 攻击目标** | 技能是**组件库第七类**，只回答三件事：**`dim`（取哪一维属性）／ `target`（攻击目标）／ `effects`（附带什么）**。**攻击、治疗、增益、诅咒全是这三种选择的组合，不是四套代码**（§4.8.3） |
| **两个 0 加成基准** | `普通攻击`（`patk`/`opponent`/`bonus: 0`）与 `普通法术`（`matk`/`opponent`/`bonus: 0`）——**纯粹靠属性值攻击对手，技能只是载体**；**两者 `cost` 都为空（保底对）** |
| **`auto` 自动配对** | `dim = patk` → `vs = pdef`；`dim = matk` → `vs = mdef`。**引擎不再写死"物攻→物防"**，那只是两个预设技能的选择 |
| **技能来源** | **玩家 ← 后天学**（技能书 `learn_skill` / 事件 / 商店 / 战利品）；**怪物 ← `attack_weights` 的键**（键就是技能 id）。**职业不限定技能**，**默认模板角色**开局只有保底对 `basic_attack` ＋ `basic_magic`（§4.8.3，作者可移除） |
| **skill 的两个分支** | `target: opponent` **对抗、会落空**（不命中则 `effects` 也不生效）；`target: self` **不对抗不落空，但仍掷骰**（骰子定治疗/加成的量） |
| **战斗骰子** | `stat_dice` 属性结算骰；`pick_dice` 怪物挑技能骰；`atk_roll` / `def_roll` **施放方与对抗方各一组力值骰**（`add_dice` / `mult` 可省）。**没有 `combat.attacks`**（§4.8.3 / §4.8.6） |
| **回合 = 推进时间** | 只有两类行动算一回合：**① 一次交锋**（玩家【点攻击】＋ 怪物【电脑掷骰】反击，§4.8.3）**② 一次移动**（掷骰得 N 步，**走完全部才算一个回合**）。**状态与地形 `cost` 在回合【开始】先判存活、再 tick 一次**（§4.8.0） |
| **移动为什么算整次** | 若"走一格 = 一回合"，摇 6 就 tick 6 次、摇 1 只 tick 1 次——**摇 6 反而更不利**，掷骰失去意义 |
| **道具不占回合** | 使用道具是**回合内的自由动作**，不推进时间、不 tick——所以使用药水随时可用。**这是它比技能强的地方** |
| **技能占回合** | **施放任何技能 = 一次交锋 = 一个回合**——所以"治疗术"花一回合、"红瓶"不花，**道具即时但数值小、技能消耗回合但数值大**（§4.8.10） |
| **技能有成本** | 技能自己的 `cost`（如 `{ mp: 3 }`）——**选它之前先查，不够就选不了**；`mp` 不进力值链，它是"入场券"。`cost` 省略 = 免费（§4.8.3） |
| **技能两侧不对称** | **玩家自己选**（从**自己学到的**技能栏里挑，有取舍）；**怪物掷 `pick_dice` 按 `attack_weights` 随机**——否则玩家只提升单一维度防御就无敌（§4.8.3） |
| **职业＝先天** | 职业只给 **`base_stats`（属性起点）+ `buffs`（优劣百分比）+ `inventory_size`（背包）+ `starting_items`（家当）**。**没有 `skills`**——**技能一律后天学**（§4.2.3） |
| **先天改不了、后天自己选** | `buffs` 的百分比**永远生效**（法师 `patk: 80` 物理攻击终生按 ×0.8 计算）。**"带着先天减益成长"就是靠这一条**——你可以用后天的选择去对抗先天获得的配置，但**抹不掉它** |
| **技能书 = 消耗品** | 技能靠 `op: learn_skill` 传播。**因为书就是道具，所有现有"给东西"的机制自动都能给技能**——奖励池 / 事件 / 商店 / 战利品，一处都不用改（§4.8.3 / §4.8.10） |
| **学过 ≠ 状态** | 学会技能是**永久的**（只能被 `forget_skill` 拿走）；状态是**限时的**（必带 `duration`）。**两者不是一回事**（§4.8.10） |
| **技能的"启用"≠"谁会"** | "启用" = 这一局世界里**存在这一招**；"谁会"是**游玩态数据**（进 `.psave` 不进 `.pmod`）。未启用的技能不能被学、不能被怪物用（§4.8.3） |
| **怪物属性登场摇定** | **怪物**登场时用 `stat_dice` 把 6 属性区间摇成具体值，**本场固定**；**玩家不摇**（`base_stats` ＋ 分配）。战斗中的随机性只来自力值链的 ⑤叠加 / ⑥倍率（§4.8.2） |
| **怪物不写死** | 怪物房用 `monster_pool`（池 + 权重 + 掷骰抽），**单只 = 单元素池**；抽到后再摇它的属性（§4.8.5⑥） |
| **奖励算法** | 池（组件上）：`source: ids` 手选 / `source: filter` 按条件筛整个组件库，条目可带 `weight`。算法（前置配置）：`treasure` / `loot` 各一套 `pick`（`tiers` 档位含空箱 / `count` 区间）+ `copies`（`fixed` / `value` / `multiplier`）；**件数恒被 `\|池\|` 夹住**（§4.8.5） |
| **没有 `all`** | `pick.algo: all` 已删除——池来自 filter 时会把上百件全部给予玩家。要"全给"就写显式 ids 给个大 `n`（§4.8.5 ④） |
| **移动** | `rules.move` **只有 `dice` 一个字段**：每回合掷它定步数。其余是硬规则（§4.8.4） |
| **组件覆盖** | 怪物可覆盖 `atk_roll` / `def_roll` / `stat_dice` / `reward_pool` / `pick` / `copies` / **它的技能表 `attack_weights`**；建筑可覆盖 `reward_pool` / `monster_pool` / `pick` / `copies` / **`event.check`** / **`stock`** / **`price`**。**技能与消耗品不覆盖配置**——它们的内容本身就是字段（§4.8.7） |
| **建筑有五种行为** | `encounter: empty / treasure / monster / **event** / **shop**`。**给东西 / 打架之外，终于能"提要求"和"做交易"**（§4.4 / §4.8.9 / §4.8.11）。**（裁决 26 增补第六种 `talk`，见 §8.2）** |
| **事件 = 门槛 + 手艺** | ① `gate` 标签门槛（**能否参与**）；② `check` 判定（**做不做得成**）。两层都可省，**全省 = 纯叙事块**。判定复用力值链，所以**提升属性 / 换装备能提高成功率**（§4.8.9） |
| **骰子是核心，不是运气** | 编辑器必须把**必成 / 必败区间**算出来摆在眼前：必成提示"必然成功"，必败提示"现在做纯属徒劳，先去提升属性"。**不做"必须掷出 6"这种纯概率门**（§1.1 / §4.8.9） |
| **状态 = 标签 + 回合数** | `{ tag, duration, per_turn? }`；每回合 tick 一次；`duration` 必填且不超上限。状态 tag **进能力集合**，所以"临时通行"成立（§4.8.10） |
| **商店不发明货币** | **货币就是一件普通道具**（`tags: [货币]` 只是给编辑器筛选用），"捡钱"就是普通产出。商店 = `stock`（上架池，与奖励池同构）+ `price`（复用 `rollRange` **掷骰定价**），形态与宝箱屋并列（§4.8.11） |
| **背包 = 职业的一个数字** | `inventory_size`（默认 50，`0` = 无限），按 `{ id, count }` **条目数**算，同一种道具占 1 格。它是**内容**（所以不同职业可以背得不一样多），(§4.2.4) |
| **技能已落地（第三轮）** | 技能被收敛成"**取哪一维属性 + 攻击目标 + 附带什么**"（§4.8.3），**不新增判定**——仍是一条力值链、一个命中公式、一个伤害公式。**冷却 / 蓄力 / 范围多目标只是后续扩展方向**，都不破坏现有结构（§7.5） |
| **职业＝先天、技能＝后天** | **`ClassDef.skills` 删除**。职业只给先天的属性配置：`base_stats` + `buffs` + `inventory_size` + `starting_items`。**技能一律后天学**（技能书 / 事件 / 商店 / 战利品）——**角色是先天获得的配置，路线由玩家自己决定**（§4.2.3 / §4.8.3） |
| **保底对** | **默认模板角色**技能栏含 `basic_attack` ＋ `basic_magic`，两个 `cost` 都为空（免费安全网）。**"无技能可用"与"因法力不足陷入死局"两种死局在默认模板下被堵死**；免费 ≠ 无差别——差别在 `dim`（取哪一维），先天的 `buffs` 百分比照样起作用（§4.8.3）。**作者可在设计里移除 / 改 `cost`，这是玩法的一部分** |
| **技能的学习与失去** | 学会靠 `op: learn_skill`（**技能书就是一件普通消耗品**——所以所有"给东西"的机制自动都能给技能，零新增通道）；`op: forget_skill` 能**夺走**技能。**学会是永久的，状态是限时的**（§4.8.3 / §4.8.10） |
| **跑团哲学** | **不做多结局 / 条件通关 / 剧情分支树**——跑团是未知的自由探索，走到终点就是完成，**用任何方式到都算**（§1.1） |
| **编辑器不下定义** | **不做难度评估、不做平衡性警告**。引擎只校验"会不会卡死"（引用悬空 / 死路 / 必败），**不评判好不好玩**（§1.1） |
| **布局对齐** | 全页**一层** padding + 唯一间距 token；**面板一律不许自带 margin**；顶栏不换行 |

### 8.1 素材皮肤（skin）决策（2026-09-29 追加）

| 项 | 决策 |
|---|---|
| **素材定位** | 素材是**可选增强**：素材缺位即回退到程序绘制形态（道路脚印 / 建筑圆角矩形 / emoji），不阻断渲染与导出。规范见 [`skin.md`](skin.md) |

|---|---|
| **设定 1 · NPC 触发时机** | **NPC 触发在「玩家进入建筑之后、该建筑的建筑事件之前」**执行：踩到建筑 → ① **NPC 触发**（实例有 `npcs` 就抽人 / 抽方案、跑对话树；没有就跳过）→ ② **建筑事件**（该建筑自己的 `encounter` 行为）。因此 **`npcs` 与 `encounter` 正交**——`npcs` 不再只限 `talk` 建筑（原「挂了 NPC 却不是对话建筑 → 不生效」的校验随之作废）；**`encounter: talk` ＝ 建筑事件阶段留空、以对话为主体**的建筑。见 [`02-data-model.md`](02-data-model.md) §4.9.3、[`03-engine.md`](03-engine.md) §4.8.12、[`04-editor.md`](04-editor.md) §5.6 / §5.7 |
| **设定 2 · 只在「进入建筑」时触发一次** | NPC 触发**只在玩家从建筑外的格子踏入该建筑（任意一格）那一次**发生；**已经在建筑内部移动（多格建筑里从一个格走到另一个格）不再触发**。多格建筑是**同一座**（同一节点 key），只在**首次踏入**时算"进入"。**首次进入一定走对话流程**。 |
| **设定 3 · 重入先弹「选择对话框」** | 该实例**触发过一次对话之后**，再次进入**不直接进对话**，先弹**选择对话框**：列出**这位（已锁定的）NPC 的名字**（点它 ＝ **重看**该对话）＋「**直接进入**」（跳过对话，直接跑建筑事件 / 离开）。**掷定即锁死不变**——列表**不提供换人、不重掷**；已交付（`prop` 终态）的实例点名字只回放**交付节点的 `message`**。 |
| **设定 4 · 空宝箱 ＋ NPC ≠ 空** | `treasure` 建筑**没配奖励池**（或池抽到 0 件）**但配了 NPC** → 进入时**不再提示"什么也没有 / 已经空了"**：**NPC 就是它的内容物**，玩家看到的是一次对话。 |
