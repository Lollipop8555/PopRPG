## 5. 编辑器设计（构建态）

> 本节是**唯一的交互标准**。任何组件的任何操作都必须能在这张表里找到出处；
> 找不到出处的交互一律不加，先改本节再加代码。

### 5.0 信息架构（见 §4.0）

```text
① 组件库 Library      左栏一个面板、一份列表。系统预设 + 用户自建，地位相同。
        │ 启用（消耗品 / 装备 / 怪物 / 职业 / 技能）
        │ 铺设（道路 / 建筑，铺到某张图的格子上）
        ▼
② 游戏内容 Content    = 启用的组件 + 地图上的铺设 + 起终点。导出成 .pmod。
```

**两条铁律：**

- **L1 —— 库是工具来源，内容是实际构建出的产物。** 用户自建组件和系统预设**地位完全相同**，都躺在库里，都能改 / 删 / 复制 / 反复用。库不因某个项目而生，也不随某个项目而亡。所以**没有"本局组件"这个概念**——左栏永远是那一个组件库，只是每条上面标着"在本局里用没用"。
- **L2 —— 组件不落到"内容"上就不生效。** 非地图件（消耗品 / 装备 / 怪物 / 职业 / 技能）要**显式启用**才进奖励池 / 背包 / 开局候选；地图件（道路 / 建筑）要**铺到地图格**才存在；**NPC 两样都不是**——它的生效条件是**被建筑实例引用**（节点的 `npcs`，§4.9.3）。没启用的、没铺的、没挂的，都只是躺在库里待用。

### 5.0.1 组件分类：按"在内容里怎么出现"分

| 大类 | 分区 | 占地图格 | 成为"内容"的条件 | 被谁消费 |
|---|---|---|---|---|
| **地图件** | 道路 | 是 | 铺到地图格 | 网格移动 |
| | 建筑 | 是（可多格） | 铺到地图格 | 踩到触发遭遇 |
| **道具／内容** | 消耗品 | 否 | **启用** | 建筑奖励池、玩家使用 |
| | 装备 | 否 | **启用** | 建筑奖励池、玩家穿戴 |
| | 怪物 | 否 | **启用** | 怪物房 `monster_pool`、宝箱怪物 `mimic.monster` |
| | 职业 | 否 | **启用** | 开局 `class_pool`；**只给先天的属性配置**（属性 / 百分比 / 背包，§4.2.3） |
| | **技能** | 否 | **启用** | **玩家的技能栏靠"学会"（技能书 / 事件 / 商店）；怪物用 `attack_weights` 引用** |
| | **NPC** | 否 | **被建筑实例引用**（节点的 `npcs`） | **建筑对话 `encounter: talk`**——**NPC 只能出现在建筑里**，不能独立存在（§4.9） |
| **全局** | 背景 | 否 | 始终 | 游玩开场展示 |

> 起点 / 终点**不在这个表里**：它们是画布内建标记（每图一个、无属性），由模式条上的「标记」模式放置，
> 不占组件库名额，也不参与"启用 / 铺设"的讨论。

> 这一条直接回答"局内道具和建筑道具混在一起"：**建筑只装"内容"，内容只被建筑引用**，两者永远不在同一层混排——建筑在地图件区，它装的东西在道具／内容区，靠属性面板里的"奖励池"关联。
>
> **技能也一样**：它是"内容"，被**职业**（玩家会什么）和**怪物**（它会什么）引用，
> **不占地图格**——所以它和道具同类，永远不和地图件混排。

### 5.1 布局：单一栅格 + 一套间距 token

```text
┌─ 顶栏：项目名 · 撤销/重做 · 导入/导出   （不放工具、不放地图 Tab） ─┐
├───────────────┬─────────────────────────────────┬─────────────────┤
│ 左栏 280px    │ 中栏 地图画布 (1fr)             │ 右栏 320px      │
│ ① 图层块      │ ┌─ 模式条（模式 + 当前提示）   │ 右栏三页        │
│ ② 组件库      │ └─                              │ 组件/实例/规则  │
│   筛选+搜索   │              缩放控件（右下）   │                 │
│   分区×9      │                                 │                 │
└───────────────┴─────────────────────────────────┴─────────────────┘
```

**对齐铁律（问题 1 的直接处方）：**

- 全页只有**一层**内边距：`.app-shell { padding: var(--gap) }`；`--gap: 10px` 是唯一间距 token。
- **任何面板、任何子组件都不允许自带 `margin`**（现在 `Toolbar`/`KitPanel`/`Inspector` 各自写内联 margin 是错位的根因，全部删除）。
- 顶栏**不换行**（`flex-wrap: nowrap`）：内容放不下就收进"⋯"溢出菜单，绝不改用换行改变行高。行高恒定为 `--topbar-h`。
- 左 / 右栏都是 `display:flex; flex-direction:column; min-height:0`，**滚动只发生在内部滚动区**（`overflow:auto`），滚动条内缩 2px，不撑破栅格。
- 所有面板共用同一个 `.panel` 类：同圆角、同边框、同内边距 `10px`、同 `min-height:0`。**禁止逐面板写 inline style 打补丁。**
- 手绘风的"不规则圆角"只用于**内层卡片 / 按钮**；栅格容器用规整圆角，避免视觉错位被放大。
- 中栏 `position: relative`：模式条贴左上（8px），缩放控件贴右下（8px），底部提示条贴左下，三块互不重叠。
- `≤880px`：中栏全屏；左 / 右栏改成左右抽屉；模式条改为**底部横排**（拇指可达），缩放控件移到右上。

### 5.2 图层块（左栏 ①）

> 决策：**图层 = 本项目的多张地图**。顶栏那一排地图 Tab 全部挪到这里，顶栏随之清空。

- 列表逐行显示一张地图：`序号 · 名称 · N 节点 · 状态点`；点击即切换当前地图。
- 状态点：起点 / 终点缺失时显示红点（悬停提示"缺少起点"）。
- 行内操作：双击重命名 · 上移 / 下移（排序）· 删除（仅当地图数 ≥ 2 时可删）。
- 底部：`+ 新建地图`。
- **可折叠**：收起态只留一行 `图层 · 共 N 张 · 当前「名字」▸`，点击展开。

### 5.3 组件库面板（左栏 ②）

> **只有一个面板、一份列表。没有"本局组件 / 素材库"两个 Tab。**
> 用户自建的组件和系统预设躺在同一个列表里，地位完全相同——就像图形设计工具里的笔刷面板，
> 你自己造一支笔刷，它就在库里待着，反复可用，不会"用一次就没了"。

**分区**（标题行：`▾ 分区名 · 计数 · [+ 新建]`，每个分区独立可折叠）：

`道路` · `建筑` · `消耗品` · `装备` · `怪物` · `职业` · **`技能`** · **`NPC`** · `背景`
（前两个是**地图件**，中间六个是**道具／内容**——其中 **NPC 只被建筑引用**、**没有"启用"开关**，最后一个是全局——顺序即 §5.0.1 的分类）

**顶部工具条**：筛选 `[全部] [本局已用]` ＋ 名称搜索框。

**每行**：`图标 · 名称 · 徽章组 · ⋯菜单`

| 徽章 | 出现位置 | 含义 |
|---|---|---|
| `预设` / `自建` | **全部条目（八大类一视同仁）** | 拿 `id` 查内置预设表：查得到 = `预设`，查不到 = `自建`（§3.2）。不存字段 |
| ☑ `已启用` / ☐ `未启用` | 消耗品 / 装备 / 怪物 / 职业 / **技能**（**NPC 没有这个开关**，见下一行） | 本局是否启用（= 这条算不算游戏内容）。未启用行降透明 |
| `已引用` / `未引用` | **NPC** | 是否被**某个建筑实例的 `npcs`** 引用（＝ 这一局里会不会遇到它）。**未引用的 NPC 行降透明**，`⋯` 菜单里的「启用 / 停用」对它**不可用**（§4.9.3） |
| `已铺设 ×N` / `未铺设` | 道路 / 建筑 | 在本局地图上的铺设次数（0 就没进内容） |
| `被引用 ×N` | **全部条目** | 被几处引用（道具 ← 奖励池；怪物 ← 怪物房 / 宝箱怪物；**技能 ← 技能书的 `learn_skill` / 怪物 `attack_weights`**；**NPC ← 建筑实例的 `npcs`**；建筑 ← 地图节点…） |

> **技能的"启用"= 这个世界里有没有这一招**，**不是"谁会"**——
> 谁会**靠后天学**（技能书 / 事件 / 商店，§4.8.3）。未启用的技能不能被学、不能被怪物用、写成技能书也是死引用（§5.7）。

> 徽章把"哪些是预设、哪些在这局里真用上了"一次说清：
> **左半是库的身份（派生），右半是这一局的状态。**

**每行操作**：行内独立按钮 `编辑` · `复制` · `启用 / 停用`（仅"启用型"非地图件；**NPC 不适用**，它没有这个开关），
行尾 `⋯` 菜单：**`复制成新组件`** · `删除` · `恢复默认`
（行内 `复制` 与菜单里的 `复制成新组件` 是**同一个动作**，两个入口都保留：一条是常规路径，一条与 `删除` / `恢复默认` 同处）
（`恢复默认` 仅对 `预设` 条目显示：拿 id 去内置预设表取原始定义覆盖回来）
（**NPC 的 `⋯` 菜单多一项**：`编辑对话` —— 直接跳到「NPC 模组」面板并选中它，§5.6）

**选中行为分两种：**

- 选中**地图件** → 可立即到地图上用「放置 / 连线」模式落子；
- 选中**非地图件**（含 **NPC**）→ 只打开右栏属性表单，**不再提供拖拽到地图**
  （现在"所有条目外观一致、均可拖拽"正是混乱来源之一）。
  > **NPC 的"摆放"不走画布**：它只能**挂到建筑实例上**——先在画布选中建筑节点（实例页），再在实例页里挑 NPC（§5.6 实例页 / §4.9.3）。

**新建 / 复制：**

- `+ 新建` —— 从零建一条库组件（`自建`）。
- `⋯ → 复制成新组件`（或行内 `复制`）—— 以现有条目为起点派生一条新库组件（`自建`），原条目**不受影响**。
  **复制整条**：新组件带上原条目的全部字段——**NPC 连它的整套对话方案（`dialogs` 里所有方案与整棵树）一起带走**，
  复制出来的是一条可以独立改、独立挂到建筑上的完整 NPC。
  > 这就是"从预设起步、改成自己的"的正统做法：**预设本身要不要改随你**；
  > 想留住原版就复制一份再改，不想留就直接改原条目（还能 `恢复默认`）。
  > **重名以本地优先**：预设定义固定、改过的版本在本地，播种时本地已有同名条目则**不再补入该预设**（§6.1 ①）。
- 删除被本局引用（铺设 / 启用 / 被奖励池引用）的组件时，先提示"被 N 处使用"再确认；
  确认后那些引用会变成悬空，按 §5.7 处理。

### 5.4 操作模式标准表（本轮核心）

**工具只有 6 个模式，全部收进画布左上「模式条」；顶栏、右栏、说明文字里一律不再放第二个入口。**

| # | 模式 | 前提 | 单击 | 拖拽 | 中间态 / 结束 |
|---|---|---|---|---|---|
| 1 | **选择** | — | 点节点 = 选中；点空白 = 取消选中 | 空白 = 平移；节点 = 移动；节点角柄 = 缩放（建筑） | 常驻；`Esc` 清选中 |
| 2 | **放置** | 左栏选中一个**地图件** | 在空格放下该组件（点哪放哪） | 划过的格子连续放置 | `Esc` / 再点模式条退出 |
| 3 | **连线** | 左栏选中一条**道路** | 第 1 次 = 起点，第 2 次 = 终点 → 自动正交折线铺满（对角自动拐角）；再点可继续接续下一段 | — | 实时预览到光标；`Esc` / 双击结束 |
| 4 | **框选** | — | 点空白 = 清空选区 | 拖出矩形 = 选中范围内**全部**节点 | 选区非空时弹出浮动操作条 |
| 5 | **擦除** | — | 单击删除该格组件（多格建筑整块删） | 划过 = 连续删除 | `Esc` / 再点模式条退出 |
| 6 | **标记** | — | 放置该标记（每图唯一；已存在则**移动**而非新建） | — | 放置后自动回「选择」 |

> **（2026-09-27 修订）** 起点 / 终点**仍然不是组件、不进组件库**（§5.0.1），入口也**不常驻模式条**
> （一张图各一个、放一次就完事，不值得长期占用工具栏位置）：
> - **按需出现**：图层面板里，哪张图缺起点 / 终点，那一行就给对应的「放起点 / 放终点」按钮；
>   不缺就不显示。新建地图时提示补放。
> - **快捷键**：`S` 放起点、`F` 放终点；按下后模式条才临时显示当前放置的是哪一个（仅作状态提示）。
> - **移动**：已有标记可在「选择」模式下直接拖动（实例页也能改坐标）。

**通用铁律 G1–G6：**

- **G1** 拖空白 = 平移，**任何模式都一致**。
- **G2** `Esc` = 回到「选择」并清掉所有中间态（连线起点、框选、待放组件）。
- **G3** 入口唯一：一个模式在地图上**只有一个开关**。（现在"铺路"同时存在于顶栏语义、面板说明文字、右栏表单按钮三处，是三套规则打架的直接原因。）
- **G4** 当前模式 + 操作提示显示在**模式条右侧**一行；**所有面板底部的长段说明文字全部删除**。
- **G5** 一次连续操作 = **一步撤销**（整条线 / 整次框选删除 / 一次画笔拖刷 / 一次擦除拖刷）。
- **G6** 快捷键：`V` 选择 · `B` 放置 · `L` 连线 · `M` 框选 · `E` 擦除 · `S` 起点 · `F` 终点；`Delete` 删除选中；`Ctrl/Cmd+D` 复制；`Ctrl/Cmd+Z` / `Shift+Z` 撤销·重做；方向键微调 1 格。
- **G7（2026-09-29 追加）** 本节管的是**画布上的 6 个模式**。**整页面板**（顶栏「规则」、「NPC 模组」）**不占模式条、不适用上面的模式表**——规则面板是纯表单；**「NPC 模组」是思维导图**，其交互单独定义在 §5.6.1。**这条保证"任何交互都能在本节找到出处"仍然成立。**

**框选浮动条（模式 4）**——这就是"选起点终点范围 → 自动计算 → 批量移除"：

- **批量删除（N 个）** —— 一键移除范围内全部节点。计入一步撤销。
- P1（本轮不做）：批量替换为…（整批换成另一个地图件）、批量移动（整体平移 N 格）。

### 5.5 画布基础（沿用，不重做）

- 网格 + **每 10 格加粗**；中心 `[0, 0]`；坐标域 `[-10000, 10000]`；视口虚拟化只渲可见格。
- **初始视口把当前地图摆在正中**（`camera.x/y` 是视口左上角的世界坐标，需减半屏）：
  起点常在 `[0,0]`，若把 `[0,0]` 顶在左上角，左边与上方的格子就全在屏幕外。
  换图时重新摆一次；之后用户自行平移缩放，不再自动干预。缩放控件里的「摆回正中」按钮可随时重新居中。
- 缩放：滚轮 / 按钮，锚点跟随光标；**平移只有"拖空白"一种**。
- 起 / 终点有专属图形，**不靠文字标签**：起点 = **手绘三角旗**，终点 = **藏宝图手绘 X**
  （均为 SVG 路径 + 手绘滤镜，详见 00b-style；构建页画布与游玩页地图共用）。

### 5.6 属性编辑（右栏）

右栏只有**两个**页签：**组件** / **实例**。

> **（2026-09-27 修订）** 规则**不进右栏** —— 它是整局共用的一套算法，跟选中哪一条组件无关，
> 和组件编辑挤在一起会让人以为「选中建筑后右边显示的规则是这条建筑的」。
> 入口改到**顶栏「规则」按钮**，点开是一整页面板（关掉回到画布）。

**规则面板**（= 这一局的前置配置，对应 `project.rules`，字段清单见 §4.8.6，**不多一个**）：

- **移动**：只有一个字段 `dice`。面板上写说明：**"每回合掷 `1D6` 决定能走几步；走完全部步数算一个回合"**。
  下方一句提示："每格的**消耗与权限**由那一格的**道路 / 建筑组件**决定（`cost` / `gate`），不在这里配。"
- **战斗**：
  - **没有 `attacks`**——攻击方式已升级为**技能组件**（左栏「技能」分区）。
    这里只留一句指路：**"这一局用哪些技能、每个技能取哪一维攻击目标，都在 `技能` 分区里配"**。
  - `stat_dice` 属性结算骰 + `pick_dice` 怪物挑技能骰。
  - `atk_roll` / `def_roll`：**施放方与对抗方各一组**，每组 `add_dice`（可留空）/ `mult`（可留空，留空即不乘倍率）。
- **开箱 `treasure` / 战利品 `loot`**：各一组 `pick`（`algo` = `tiers` 档位表 / `count` 区间）与 `copies`（`fixed` / `value` / `multiplier`）。
- **状态 `state`**：`max_duration` 一个数字框。旁注："**任何状态都不会超过这么多回合**——避免没有解药时被耗死。"
- **商店 `shop`**：默认定价 `price`（`currency` 选一件道具当钱 ＋ `algo` = `fixed` / `value` ＋ 骰子与区间）。旁注："没写定价的商店都用这一套。"
- **事件 `event`**：默认判定骰 `dice`。旁注："**难度值与后果写在事件组件上**（那是内容），这里只给默认骰。"
- **对话 `talk`**：对话骰 `dice`。旁注："**建筑里的 NPC 是随机遇到的**——候选多位时掷这颗骰抽一位；某位 NPC 有多套对话方案时也用它抽一套。**踩到时抽定，整场不再变**（§4.9.3）。"
- **开局职业池**：只列**已启用**的职业；开局作为**卡片供玩家挑选**——长度 1 = 直接选定，>1 = 玩家手选，想交给运气就自己点「掷骰决定出身」。
- **每个字段旁给一句说明**，把骰子和它的用途绑在一起：
  - 移动 → "每回合掷 1D6 走几格；**走完全部步数算一个回合**（不是每格一回合）"
  - 属性结算 → "登场时掷 1D6 把 `物攻[3~6]` 摇成 `5`，本场固定"
  - 战斗 → "力值 = 物攻 5（已摇定）+ 铁剑(+5) + 技能加成(0)，× 职业 100%，+ 1D4 叠加，× 1D6 倍率"
  - 开箱 → "掷 1D6：1~2 空箱，3~4 一件，5~6 两件；每件再掷 1D6 定 1~3 份"
  - 怪物挑技能 → "掷 1D6 按 `普通攻击 3 : 毒牙 1` 挑，玩家须兼顾两维防御"
- **预览按钮**：每个算法旁给「模拟 10 次」按钮，直接看产出分布（避免"配完了不知道是什么效果"）。

**NPC 模组面板**（顶栏「NPC 模组」按钮，整页 —— 与「规则」并列的**第二个整页入口**，**不进右栏**）：

> **它的主业是对话分支构建。** NPC 的**名称 / 图标 / 标签**在组件页；**描述**与**颜色**这两个公共字段本页也放了一份
> （本页盖住整屏、组件页根本看不见，改这两个字段不该逼人先关页面再回左栏找这条 NPC）；主业仍是**对话树**（§4.9 / 裁决 26）。

- **布局**：左侧＝**NPC 列表**（列出**库里的全部 NPC**；被引用者带 `被引用 ×N`，未被引用者降透明并标「未引用」）；右侧＝**思维导图画布**。**引用数只是本局状态标注，不是能否撰写对话的前提**——未被引用的 NPC 同样可选中、同样可写对话树（引用关系随时可以再补）。
- **NPC 自身的字段**：右侧顶部依次是**名字**、**方案行**（方案下拉 ＋ `[+ 方案]` / 改名 / 删方案）、**描述 ＋ 颜色**（文本框 ＋ 取色器 ＋ 随机 / 清除）——与组件页写的是**同一份定义**（`desc` / `color` 是 `ComponentBase` 公共字段）。
- **方案（Mod）**：右侧顶部一个方案下拉（`Mod1` / `Mod2` …）＋ `[+ 新建方案]` / 重命名 / 删除。
  一个 NPC **可以有多套方案**；用哪一套由**实例 ＋ 骰子**决定（§4.9.3）——**面板不写权重**（多套等权，想控制就多写几套）。
- **卡片＝一条记录，全树同构**（§4.9.2）：自上而下**五段**，**每一段的段名都直接写在段间的分隔线上**
  （`— 答复 —` / `— 台词 —` / `— 赠予道具 —` / `— 后续项 —`），卡片自身即可看清哪块是哪块，不必回头翻窗口说明：
  **命中**（这条记录在哪些点数上轮到 —— **行内标签**，它在卡片第一行、上面没有分隔线；根卡片没有上一级，故不显示）
  → **答复**（`result`，玩家可见的选项文本；根卡片不显示，它只在"作为上一级的选项"时有意义）
  → **台词**（`message` 的**多行台词列表**，一行一条、可拖动排序）
  → **赠予道具**（`give`，走到这一条赠予什么 —— 写在本条记录自身，不属于子树）
  → **后续项**（`items`：答复骰子 ＋ 命中覆盖提示）。
  卡片**底部**另有一行（**同排、不再分行**）：**「＋ 选项」**（直接新增一条后续项）＋ **连接端口**（拖出后续项）＋ **折叠箭头**——自左至右就是这个次序，三者都只作用于后续项；
  这三枚**同一款式、同一尺寸**（等宽等高的一排小按钮，取色器式的端口不再是"另一个尺寸的小框"），只把端口的光标换成十字以示可拖；
  卡片**右上角**并排两颗按钮：**`断开`** 在左、**`删除`** 在右——**断开**与**删除**都不属于任何一段内容，故不占正文行。
  **一张卡片上不该有无名之段**：段与分隔线一一对应（§5.6.1 的用例锁住这一点）。
- **答复骰子**：**「后续项」这一段的第一行**，一个**可选 `dice` 下拉**（如 `1D6`，默认「无」）。它管的是**它下面**那些答复，
  故**置于自家后续项之上**（上一级的骰子落在上一级卡片底部，正好贴着本卡片顶部的「命中」）。
  **填了 → 本卡片的后续列表改为掷骰命中**（每行出现 `hit` 区间输入框，并在下方实时提示**覆盖情况**，§5.7）；
  **留空 → 本卡片后续列表直接可点**（`hit` 输入框隐藏、导出时自动剔除，§4.9.2）。
- **连线**＝后续关系：从卡片底部端口**拖到另一张卡片**，后者即成为它的后续项（**树状、只能向下**）。
  **落点以松手时的光标位置为准**：松手处没有卡片（包括"只是划过、随后又移开"）→ **取消连线、不改数据**；指向自身或其后续项时**拒绝并提示**——不能有回环（§4.9.2）。

#### 5.6.1 NPC 模组面板的操作（思维导图模式）

> **G7 的落地点**：本页面**不使用 §5.4 的画布模式条**，交互一律以下表为准。

| 操作 | 手势 | 结果 |
|---|---|---|
| 新建 NPC | 左栏「全部 NPC」标题行的「＋ 新建」；**库中一条 NPC 都没有时，同一按钮直接给在空态提示框内** | 建出一条空 NPC（与组件库「＋ 新建」同一构造：名称「新建 NPC」、`dialogs` 为空）并**立即选中**，随后在此写它的对话树；**删除**仍在组件库中进行（与其它组件一致） |
| 新建节点 | 双击画布空白 | 落一张空白卡片（**一步撤销**）——就是一条记录（`message` 起手） |
| 连接 | 从卡片**底部端口**拖到目标卡片 | 目标成为当前卡片的**后续项**（写进当前卡片的 `items`）；**落点以松手位置为准**——松手处没有卡片就取消（只是划过不算）；**拖向自身 / 上一级时拒绝并提示**——不能有回环（§4.9.2） |
| 断开 | 卡片**右上角、紧邻「删除」左侧**的「断开」，或选中连线按 `Delete` | 移除该条后续关系，该分支**移至右侧「未连接」**（内容保留，重新连接即可，不静默删除） |
| 加后续项 | 卡片**底部一行、连接端口左侧**的「＋ 选项」 | 新增一条后续项（`result` 文本 ＋ 台词） |
| 赠予道具 | 卡片内「＋ 赠予道具」 | 在**当前这条记录**上加 **`give`**（**道具多选**，写进 `give` 字段——**不是 `items`**，§8.3 设定 8；**同一道具可重复添加 ＝ 多份**）。**`give` 与后续项可并存**：先赠予道具，再按 `items` 继续；**没有 `items` 就到此结束**（§4.9.2） |
| 设答复骰子 | 卡片上（**后续项之上**）的 `dice` 下拉 | 选一枚骰（如 `1D6`）→ 本卡片的后续列表**改为掷骰命中**，各行出现 `hit` 输入框；选「无」→ 回到**直接点选**（§4.9.2）。**游玩态这里不是"藏起选项只给一个掷骰按钮"**——后续各行照旧全部列出（各标命中区间），只是不可点、改由骰子定 |
| 设命中区间 | 选项行的 `hit` 输入框 | 填 `"1-2"` / `"3-4"` / 单点 `"6"`；**实时显示覆盖情况**——已覆盖哪些点数、还剩哪些空档（见 §5.7，只提示不拦截） |
| 编辑台词 | 直接改行文本；`Enter` 换行、空行 `Backspace` 即删除 | 写回 `message` 数组 |
| 移动 / 缩放画布 | 拖空白平移、滚轮缩放（锚点跟随光标，与 §5.5 一致） | — |
| 选中 / 多选 | 点卡片；`Shift` 加选 | 选中后 `Delete` ＝ 删除节点**连同其后续项**（先提示"该记录含 N 条后续项，将一并删除"） |
| 撤销 / 重做 | `Ctrl/Cmd+Z` / `Shift+Z` | 与构建页**同一套撤销栈**；整棵树的增删改各算**一步** |
| 折叠 | 卡片**底部连接端口右侧**的箭头 | 折叠该卡片的后续项（**只影响显示**，不影响导出） |
| 改描述 / 颜色 | 右侧顶部的「描述」文本框与「颜色」取色器（＋ 随机 / 清除） | 写回当前 NPC 的 `desc` / `color`（公共字段，与组件页同一份定义） |

> **面板只提供"树"，不提供"条件 / 跳转 / 循环"**：字段只有 `result` / `message` / `dice` / `hit` / `items` / `give` 六个（§4.9.2）。
> 「赠予道具」的下拉**只列已启用道具**，可重复添加；引用失效时按 §5.7 标红。
> **命中覆盖检查（只提示不拦截）**：节点填了 `dice` 后，面板实时统计各 `hit` 的覆盖并标出**未覆盖的点数**——
> "掷到 `4` 没有任何选项命中，运行时会要求重掷"；**重叠**也提示（"`3` 同时命中 A 和 B"）。**这不会阻止保存 / 导出**（§5.7）。

**组件页**（在左栏组件库里选中一条 → 编辑的是**库里的组件定义**）：

- 公共：名称、图标（Emoji）、描述、标签 `tags`、来源徽章（`预设` / `自建`，只读、由 id 派生）、
  `预设` 条目带「恢复默认」（拿 id 去内置预设表取原始定义覆盖回来）。
- 本局状态：启用开关（仅非地图件）＋ 铺设次数 / 被引用次数（只读，说明它在本局算不算内容）。
- **怪物**：**6 个属性的区间**（`hp` / `mp` / `patk` / `matk` / `pdef` / `mdef`，属性结算输入）、
  **`attack_weights` 技能权重表**（**从已启用技能里多选 + 各自权重**，
  旁边提示"掷 1D6 按 `普通攻击 3 : 毒牙 1` 挑，玩家须兼顾两维防御"）、
  可选 **`effects`**（命中玩家时施加，**用与消耗品同一套控件**）、
  可选 `atk_roll` / `def_roll` / `stat_dice` 覆盖、`point_reward`（打赢给几点）、可选**战利品池**（`source: ids|filter`）+ 可选覆盖 `pick` / `copies`。
  > 界面上给个**档位对照**："小怪 `hp 6~12` / 精英 `hp 24~40`"（§6.1.1），并提示可用 `tags: [精英]` 标注。
- **技能**（§4.8.3）：**选一维 + 选个对象 + 加个效果**，五个下拉/数字框：
  - `dim` **基准维度**（6 属性下拉）→ `target` **作用对象**（`opponent` 攻击对手 / `self` 对己）
  - `vs` **对手拿哪一维对抗**（`auto` / `none` / 具体维）→ `bonus` **技能加成**（数字，默认 0）
  - `apply` **力值作用到哪**（`hp` / `mp` / `none`，默认 `hp`）
  - `cost` 施放成本（默认免费；给法术填 `{ mp: 3 }`）
  - `effects` 附带效果（与消耗品同一套控件，挂 buff / debuff）
  > **面板上直接写说明预览**，让人一眼看出这是"攻击对手"还是"救人"：
  > - `dim: patk` + `target: opponent` → **"用物攻打对方 `pdef`，伤害 = max(1, 力值 − 对方物防)"**
  > - `dim: matk` + `target: self`   → **"不对抗，回自己 力值 点 `hp`"**
  > - `apply: none` + `effects: [力量祝福]` → **"不对抗，给自己挂 3 回合 力量祝福（物攻 +2）"**
  >
  > **编辑器不认识"火球术""治疗术"这些词**——它只显示"取哪一维、攻击目标、挂什么"。
  > **技能页底部还有一块「这一局里谁能学到它」**：列出所有指向它的 `learn_skill`（技能书 / 事件 / 商店），
  > 一个都没有时标黄提示"**已启用，但没有任何地方能学到**"（§5.7）。**技能没有"谁会"这个属性**——
  > **"谁学会"是游玩态数据，编辑器不管**（§4.8.3）。
- **职业**：`base_stats`（6 个属性的**初始属性**，数字输入）+ `free_points`（**开局自由点数**，数字输入）
  ＋ `buffs` 百分比（力值链③）＋ `tags` ＋ **`inventory_size`（背包格数，数字框 ＋「无限」勾选）**
  ＋ **`starting_items`（初始道具多选，只列已启用道具）**——**没有属性区间、也没有 `skills`**。
  > 面板上给三句说明：①"这个职业开局给 **25 点**自由点（想给 300 也行）"；
  > ②"把点数分配在 `matk` 会被 ×1.3，分配在 `patk` 会被 ×0.8——**职业决定怎么分配才最合理**"；
  > ③"**职业只给先天的属性配置，不给技能**——它从哪儿学本事，是这一局里的事（§4.8.3）"。
- **道具**：kind 切换 → 装备（槽位多选 + **6 属性** `modifiers` 加值，力值链②）
  / 消耗品（`usable` + **`effects` 混合列表**，**五选一 `op`**：`add_stat` 改数值 / `add_tag` 挂状态 /
  `remove_tag` 解状态 / **`learn_skill` 学会技能** / **`forget_skill` 忘掉技能**，§4.8.10）。
  > `add_tag` 行必填 `duration`（超过 `state.max_duration` 会被夹到上限），可再勾"每回合结算"填 `per_turn`，
  > 或填 **`modifiers`**（持续期间改属性，如"力量祝福 物攻 +2"）。
  > **`learn_skill` 行选一个已启用技能，旁边实时显示它的说明预览**——"学会：用物攻打对方 `pdef`"。
  > **这就是"技能书"**，也是"后天发育"的唯一载体（§4.8.3）。
  > **消耗品、技能、怪物、事件四处的 `effects` 用的是同一个控件。**
  > 一行一个效果，右侧一个「＋ 加一条效果」按钮。
  > 道具的 `tags` 框旁注："**给编辑器筛选用**（比如 `货币`），引擎不认识这个词。"
- **建筑**：`encounter` **六选一**（`empty` / `treasure` / `monster` / `event` / `shop` / **`talk`**〔＝**建筑事件阶段留空、以对话为主体**；对话本身由实例的 `npcs` 触发，**与 `encounter` 正交**〕），
  **面板只显示选中行为对应的块**——这就是"构建面板终于有逻辑"的落点：
  - `empty` → 只有 `cost` / `gate` / `point_reward` / `desc`
  - `treasure` → 奖励池（`source: ids` 手选 / `filter` 按条件筛，只列已启用项，可设权重）
    ＋ 可选覆盖 `pick` / `copies` ＋ 勾选"宝箱怪物"展开 `mimic`
  - `monster` → 怪物池（同上结构）
  - **`event`** → **门槛 `gate` ＋ 判定 `check`（骰子 / 加值属性 / 目标值）＋ 后果 `on_success` / `on_fail` ＋ `once` 勾选**
    - 门槛复用道路那套标签控件（`tags` / `mode` / `on_missing`），**标签反查提示也共用**
    - 后果块是一个可增删的列表，每项可选 `text` / `cost` / `point_reward` / `grant` / `effects`
    - **判定下方实时显示必成 / 必败区间**（§5.7）
  - **`shop`** → **上架池 `stock`（与奖励池同一套选择器）＋ 定价 `price`（货币下拉 ＋ 固定价 / 掷骰定价）**
  - **`talk`** → **组件页里不配 NPC**：只显示一句指路——"**NPC 挂在建筑实例上**（遇到谁、用哪套对话方案），请到实例页挑"，
    并给一个 `[去实例页配置]` 快捷按钮。**理由**：同一栋建筑铺到多格可以遇到不同的人——NPC 属于**实例**而不是定义（§4.9.3）
  - 通用：`cost` / `gate`（§4.5）＋ `point_reward`
  > 每个选择器旁边实时显示**算出什么**：
  > 奖励池"掷 1D6：1~2 → 空箱，3~4 → 1 件，5~6 → 2 件；每件再掷 1D6 定份数"；
  > 怪物池"命中 12 只，掷 1D6 按权重抽 1 只"；
  > 事件判定"当前加值 8：需掷 ≥ 7，命中率约 58%"；
  > 商店定价"红瓶：每件掷 1D6 → 5 ~ 15 枚 `gold`"。
- **NPC**：公共字段（名称 / 图标 / 描述 / 标签）＋ **对话方案清单**（`dialogs` 的方案名列表，**只读摘要**：
  每个方案显示"节点数 / 最深几层 / 有没有赠予道具 / **有没有掷骰节点**"）＋ 一个 `[编辑对话]` 按钮跳到「NPC 模组」面板（§5.6.1）。
  > **NPC 没有"位置"字段**——它只能被建筑实例引用（§4.9.3）。面板上给一句说明："**NPC 住在建筑里**：去地图上挑一栋
  > `encounter: talk` 的建筑，在**实例页**里选它。"
  > **NPC 也没有"启用"开关**（它不是奖励池内容）；`本局状态` 一行显示 **`被引用 ×N`**，为 0 时降透明提示"还没有建筑用到它"。
- **道路**：名称 / 图标 / 描述 ＋ **消耗 `cost`**（步数 / 血量 / 法力三个数字框，步数默认 1）
  ＋ **权限 `gate`**（标签输入，回车加一个；`mode` any/all；`missing` block/penalty；`penalty` 三个数字框）。
  > **不放"铺设（画线）"按钮**——那是模式 3，入口唯一在模式条。
  > 面板上给一句对照："`step: 1` 正常；`step: 2` 难行；`step: 0` 不耗步"。
  > 权限框旁边**实时列出现在哪些已启用组件带这些标签**——"`火抗`：火抗鞋 ✓ / 炎魔甲 ✓"，
  > 一个都没有时标黄提示"目前没有任何装备带 `火抗`，这条路走不通"，避免造出死路。
- **装备 / 职业**：除 `modifiers` / `buffs` 外，还有 **`tags` 输入框**，旁注
  "这些标签用于**通行权限匹配**（§4.5.2）"，并实时反查"带 `火抗` 可以让玩家通过：火焰山 ×2 处"。

**实例页**（选中地图上的节点）：

- 坐标、类型、引用的组件名；`[编辑该组件定义]` 快捷跳转到组件页。
- 建筑：宽 / 高（格）。
- **建筑实例专有 · NPC / 对话（任何建筑都可以挂；对话在「进入建筑后、建筑事件前」执行，§4.9.3）**：
  - **`npcs` 候选列表**（下拉只列库里的 NPC，可加多条、可删）：
    - **留空** → 提示"**这个建筑不触发对话**，只运行自身的建筑事件"（§4.9.3）
    - **1 位** → 旁注"**只有一位候选，不掷骰，必定遇到该 NPC**"
    - **多位** → 旁注实时算概率："**掷 `talk.dice` 等权抽一位**——当前是 1D6，3 位候选各占 2 面"（§4.9.3）
  - **`dialog` 方案下拉**：列出所选 NPC 的**全部方案**。**留空（默认）＝ 由骰子选一套**（只有一套时面板直接写"只有一套方案，必定用它"）；
    **选中某个方案名 ＝ 写死、不掷骰**（§4.9.3）
  - **「允许重新对话」开关**（方案下拉**下方**，写进实例的 `dialog.retalk`）：**默认开**；关掉 → 重新进入该实例时**不给出【重新对话】**——未走完的只有【继续对话】（且**不弹选项框、直接续上**），已走完的另有【路过】。
    旁注两句：开着说"**重新进入该实例时给出【重新对话】—— 从第 1 条重新播放（已赠予的道具不重复赠予）**"，关着说"**重新进入该实例时不给出【重新对话】—— 未走完的只有【继续对话】，已走完的另有【路过】**"（§4.9.3 / §4.9.2）
  - 底部一句总述：**"先抽人、再抽方案，两次各掷一次骰子；**进入建筑时**抽定，整场不变。"**
  - **触发时机旁注**：**"只在**从建筑外踏入**时触发一次，在建筑内部走动不再触发。**首次进入直接开始对话（不弹选项框）**；**已触发过的实例再次进入时先弹选项框**——未走完的给【继续对话】【重新对话】，**已走完**的另有【路过】；**关闭「允许重新对话」**后不再给出【重新对话】。"**（§4.8.12 / §4.9.2）
- 操作：复制该节点 / 删除该节点。
- 若引用的组件已被删除 → **标红提示**并给出"换成别的组件"快捷操作。

> 这里的编辑**直接改库**，所有用到它的局一起生效（§4.7）。想保住原版就先用 `⋯ → 复制成新组件` 派生一条再改。

### 5.7 校验与提示（每张图）

| 项 | 规则 | 违反时 |
|---|---|---|
| 起 / 终点 | 每图恰好各一个 | 图层面板行显示红点；导出前给 toast 提示，**不阻塞导出**（不把用户锁死） |
| 建筑多格 | **一座建筑 ＝ 一个节点**，多格由节点自带的 `w` / `h` 标记（**缺省 1**；拖拽缩放取整、最小 1）；不与其它节点重叠 | 放置时**直接替换**被压住的节点（计入一步撤销）。**相邻的两座同名建筑就是两个节点、两座**——引擎**绝不**按"相邻同种"合并（§4.9.3） |
| 引用完整性 | `reward_pool` / `monster_pool` / `stock` / `price.currency` / `mimic.monster` / `class_pool` / `starting_items` / **`learn_skill` / `forget_skill` 的 `skill`** / **`attack_weights` 的键** / **建筑实例 `npcs` 的 NPC**（**无「启用」要求**）/ **建筑实例 `dialog.mod` 的方案名**（须在该 NPC 的 `dialogs` 里）/ **对话树 `give` 的道具** / 事件 `grant` 只能指向已存在且**已启用**的组件（**NPC 例外：只要在库里存在即可**，它没有"启用"开关，§4.9.3） | 右栏标红 + 快捷修复；悬空引用导出时自动剔除并提示（**`dialog` 例外：不剔除**，见下行） |
| **技能指向失效** | 某个 `learn_skill` / `forget_skill` / `attack_weights` 指向**已停用 / 已删**的技能 | 标红 + 快捷修复（换成别的技能）。**停用的技能不被任何书 / 怪物引用**——它们的世界里不存在这一招（§4.8.3） |
| **技能无法获得** | 这一局**没有任何途径**能让玩家学到某个已启用技能（既没有技能书、也没有事件给、商店也不卖） | 标黄提示："`火球术` 已启用，但**没有任何地方能学到它**——要不要放一本技能书 / 让某个事件教它？"。**不阻塞导出**（也可能是故意留给纯怪物的技能） |
| **技能自相矛盾** | `target: self` 却写了 `vs:` 具体维；`vs: none` 却指望有伤害；`apply: none` 且 `effects` 为空（**这技能什么都不做**） | 编辑器标黄说明后果，并给一句建议（如"`apply: none` 且没有 `effects`，这个技能放出来没有任何效果"） |
| **池筛空** | `source: filter` 的条件可能筛出 0 项 | 建筑 / 怪物池 / 商店上架池旁实时显示命中数；命中 0 时标黄提示"这个池是空的"（导出前再提示一次） |
| **权限死路** | **道路 / 建筑 `gate.tags`、事件 `gate.tags`** 里的标签**没有任何已启用组件带** | 编辑器标黄："没有任何已启用装备 / 职业带 `火抗`，这条路走不通"；**不阻塞导出**（用户可能是先铺路、装备还没做） |
| **事件必成 / 必败** | 事件判定按当前配置算出的命中率是 100% 或 0% | 必成 → 提示"这个判定对当前配置是必然成功的"；必败 → 标黄"**现在做这个纯属徒劳，先提升属性 / 换装备**"。**不阻塞导出** |
| **状态无上限** | `effects.add_tag` 的 `duration` 缺失或超过 `state.max_duration` | `duration` **必填**，缺失时禁止保存（状态必须有限期）；超过上限时**直接夹到上限**并提示 |
| **商店缺货币** | `price.currency` 指向的道具没启用，或它在全图里没有任何产出 | 标黄："`gold` 没有出现在任何奖励池 / 事件产出里，玩家买不起东西" |
| **说了要对话，却没配人** | 建筑定义是 `encounter: talk`，但实例的 `npcs` 为空 | 实例页标黄："**这个建筑没有对话**——要么加 NPC，要么把行为改回 `empty`"（§4.9.3）。不阻塞导出 |
| **空宝箱 ＋ NPC** | `treasure` 建筑的奖励池为空（没配 / 筛出 0 项）**但实例配了 `npcs`** | **不报"宝箱是空的"**——**NPC 就是内容物**，进入时会走对话（§4.8.5⑥ / [`07-decisions.md`](07-decisions.md) §8.3 设定 4）。这是**合法配置**，不标黄 |
| **空宝箱（且无 NPC）** | `treasure` 奖励池为空**且实例没有 `npcs`** | 建筑页标黄："这个宝箱**什么都没装**——配个奖励池，或给它挂一位 NPC"（不阻塞导出） |
| ~~挂了 NPC 却不是对话建筑~~（**V2.0 起作废**） | ~~实例写了 `npcs`，但该建筑定义不是 `talk`~~ | **不再报错**：`npcs` 与 `encounter` **正交**——任何建筑实例都可以挂 NPC，对话在**进入建筑后、该建筑的建筑事件之前**执行（[`07-decisions.md`](07-decisions.md) §8.3 / [`03-engine.md`](03-engine.md) §4.8.12） |
| **`dialog.mod` 方案名悬空** | 实例写了 `dialog.mod`，但该方案名**不在所抽到 NPC 的 `dialogs` 里** | 实例页该行**标红**（"`Mod9` 这个方案不存在"）＋ 方案下拉供改选；进「清单」。**导出时【不剔除】该字段**（剔除会把它变成"留空 → 掷骰"，语义正好相反）——**运行时跳过对话、当该实例没有 NPC**（[`07-decisions.md`](07-decisions.md) §8.3 设定 5） |
| **`road` / `start` / `end` 带了大小** | 非建筑节点写了 `w` / `h` ≠ 1 | **标红并归一为 1×1**（这些件**恒为单格**）；导入老档 / 手改文件时**静默归一 + 提示一句**（[`01-pmod.md`](01-pmod.md) §3.1 / §8.3 设定 6） |
| **建筑 `w` / `h` 非法** | `w` / `h` 不是 **≥ 1 的整数**（`0` / 负数 / 小数） | 输入框与拖拽缩放本就限制在 ≥ 1；导入老档 / 手改文件时**归一为 1** 并提示一句（运行时按 `w`×`h` 覆盖） |
| **地图名重复** | 两张地图同名 | 图层行**标黄**："同名地图会让**建筑实例 key** 撞车（对话抽取结果 / 进度标记被串用）——**导出与开局时会自动改成 `名字 (2)`**，建议直接改名免得存档对不上"；**不阻塞导出**（§8.3 设定 6） |
| **空对话** | 某个方案的根节点 `message` 与 `items` **都为空** | 模组面板标黄："这个方案点开就结束了，玩家什么都看不到"（§4.9.2） |
| **赠予悬空** | `give` 里出现未启用 / 已删的道具 | 模组面板该行标红，并只列已启用道具供替换；导出时剔除（§4.9.2 / §5.7） |
| **根层写了 `result`** | 根层数组的元素带了 `result`（它只在作为上层选项时有意义） | 标黄提示"根层的 `result` 不展示"，导出时剔除（§4.9.2） |
| **命中覆盖不全** | 节点写了 `dice`，但各 `hit` 的**并集没盖满**该骰子的全部点数 | 模组面板该节点标黄："掷到 `4` 没有任何选项命中，运行时会要求重掷"；**只提示、不拦截**保存 / 导出（§4.9.2 / §5.6.1） |
| **`hit` 重叠** | 同一节点内两个 `hit` 区间**有交集** | 标黄："`3` 同时命中 A 与 B——运行时会取**先出现的那个**"，给一键改区间的快捷操作 |
| **`hit` 无所属** | 节点**没写 `dice`**，但选项带了 `hit` | 标黄："该节点没有骰子，`hit` 会被忽略"；导出时自动剔除（§4.9.2） |
| **`hit` 越界 / 非法** | `hit` 不是合法区间，或点数**超出该骰子的范围**（如 `1D6` 写了 `7-9`） | 该行标红："`7-9` 超出 `1D6` 的点数范围"，并提示改为合法区间 |
| **多套方案但没写 `dialog`** | 该 NPC 方案数 > 1，且实例没有写 `dialog` | **不算错**，面板提示"**将由骰子抽一套**（`talk.dice`）"；想要固定就写下 `dialog`（§4.9.3） |
| **背包容量** | 职业的 `inventory_size` 小于开局要发的道具条目数 | 提示但不拦（设计者可能故意做"精简背包流"） |
| 道路引用 | 地图上的 `road` 节点必须带 `ref` | 缺失时右栏标红；旧档里没有 `ref` 的路节点**回退到默认 `cost: { step: 1 }` 且无 `gate`**，不报错 |
| **"清单"一键自检** | 构建页提供一个 **「清单」按钮**，一键跑上面 **全部 K1~Kn 校验**并**汇总成一张清单**（哪些通过、哪些标红 / 标黄、各自定位） | 让构建者在导出 / 试玩前**一口气查漏补缺**——比逐条散在面板里更省心；不阻塞导出，只是汇总视图 |

> **「清单」按钮**是 §5.7 所有校验的"总开关"：它不引入新规则，只是把 K1~Kn 的结果集中展示，构建者一眼看到全图的健康度。
