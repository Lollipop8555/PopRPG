## 6. MVP 范围：构建闭环

### 纳入
- A. **脚手架**：React+TS+Vite，栅格布局骨架（§5.1）
- B. **信息架构**：**组件库（预设 + 自建）→ 游戏内容（启用 + 铺设）** 打通（§4.0 / §5.0）
- C. **左栏**：图层块（多地图管理，§5.2）+ **组件库面板**（单一列表、分区折叠、筛选、徽章，§5.3）
- D. **画布**：网格 / 十格粗线 / `[0,0]` / 平移缩放 / 6 个操作模式 / 框选批量删除 / 校验（§5.4 / §5.5）
- E. **属性编辑**：右栏三页（组件 / 实例 / **规则**）；奖励池 / 怪物池（`ids` / `filter`）+ 可选覆盖 `pick` × `copies` + mimic（§5.6）
- F. **消耗与权限**：道路 / 建筑可编 `cost`（含 `mp`）+ `gate`；装备 / 职业可编 `tags`；编辑器提供**双向反查**（§4.5 / §5.6）
- G. **6 属性体系**：`hp` / `mp`（资源）+ `patk` / `matk` / `pdef` / `mdef`（能力）；装备 `modifiers`、消耗品 `effects`、怪物 `stats` 全部按 6 属性走（§4.0.1）
- H. **前置配置 `rules`**：完整可编辑并写入 `.pmod`——`move.dice`、`combat` 的 `stat_dice` / `pick_dice` / `atk_roll` / `def_roll`、
  `treasure` / `loot` 两套抽取算法、**`state.max_duration` / `shop.price` / `event.dice`**、`class_pool`；**字段清单严格等于 §4.8.6（共 13 项），不多一个**
  > **注意没有 `combat.attacks`**——攻击方式已升级为技能组件（见 K）。
- I. **职业＝先天**（§4.2.3）：职业可编 `base_stats`（初始属性）+ `free_points`（开局自由点数）+ `buffs`（优劣百分比）
  + **`inventory_size`（背包格数）** + **`starting_items`（出生家当）**——**职业不给技能**；
  怪物 / 建筑可编 `point_reward`（打赢 / 开箱给几点）（§4.2.3 / §4.2.4 / §4.8.8）
- J. **五种建筑行为**：`empty` / `treasure` / `monster` / **`event`** / **`shop`**——右栏**按选中行为只显示对应的块**（§4.4 / §5.6）
- K. **技能系统**（§4.8.3）：技能是**组件库第七类**，字段 `dim` / `target` / `vs` / `bonus` / `apply` / `cost` / `effects`；
  编辑器**只用下拉与数字框**把"取哪一维 + 打谁 + 挂什么"配出来，并给人话预览
- K2. **后天学技能**（§4.8.3 / §4.8.10）：`effects` 支持 **`learn_skill` / `forget_skill`**，
  于是**技能书就是一件普通消耗品**——**推箱 / 事件 / 商店 / 战利品，凡能给道具的地方都能给技能，零新增通道**。
  **技能无职业限制**：法师能学盾击、战士能学治疗术；玩家开局只有保底对 `basic_attack` ＋ `basic_magic`
- K3. **技能可获取性校验**（§5.7）：已启用但**没有任何途径能学到**的技能 → 编辑器标黄提示（不阻塞导出）
- L. **事件系统**：门槛 `gate` ＋ 判定 `check` ＋ 后果 `on_success` / `on_fail` / `once`；编辑器**实时显示必成 / 必败区间**（§4.8.9 / §5.7）
- M. **状态与持续效果**：`effects` **五种 `op`**（`add_stat` / `add_tag` / `remove_tag` / **`learn_skill`** / **`forget_skill`**）；状态带 `duration`（有上限）、
  `per_turn`（每回合增减）、**`modifiers`（持续改属性，进力值链 ②）**；**tag 进能力集合**（§4.8.10）
- N. **商店**：上架池 `stock`（与奖励池同构）＋ 定价 `price`（货币 = 一件道具，复用 `rollRange` 掷骰定价）（§4.8.11）
- O. **背包容量**：职业 `inventory_size`（默认 50，`0` = 无限），按条目数算（§4.2.4）
- P. **回合引擎**：*一次交锋*（技能 + 对手反击）与 *一次移动*（走完全部步数）各算一回合；**道具不占回合**（§4.8.0）
- Q. **数值标定**：预设数值全部落在 §6.1.1 的基线内（预设职业总量约 35 点 / 小怪低区间 / 精英高区间）
- R. **序列化**：导出 / 导入 `.pmod`（自包含组件快照 + `rules`，round-trip 无损，§3.3）
- S. **内置预设**：见 6.1

### 6.1 内置预设最小清单（开箱即玩）

- **技能**（第七类，**全套七条刚好把"取哪一维 × 打谁 × 挂什么"演示完**，§3.1 有完整 yaml）：
  `普通攻击`（`patk`/`opponent`/0 加成）、`普通法术`（`matk`/`opponent`/0 加成，**`cost` 同样为空**）、
  **`治疗术`（`matk`/`self`/`apply: hp`——只改 `target` 就从打人变救人）**、
  **`力量祝福`（`self` + `apply: none` + `modifiers`——对自己上增益）**、
  **`虚弱诅咒`（`opponent` + `apply: none` + 减益——对对手上 debuff）**、
  `盾击`（`patk` + `bonus`，给骑士）、**`毒牙`（伤害 + 挂 `中毒`）**
- **小怪**：哥布林（`hp [6,12]`，`point_reward: 1`，`attack_weights: { basic_attack: 3, basic_magic: 1 }`）、
  史莱姆（`hp [6,10]`，`point_reward: 1`，只会 `basic_attack`、抗魔法）
- **精英怪**：哥布林王（`hp [24,40]`，`point_reward: 5`，`tags: [精英]`，带战利品池，会 `basic_attack` + `basic_magic`）、
  伪装宝箱（`hp [18,28]`，`point_reward: 3`，`tags: [精英]`，带战利品池）
- 道具：铁剑（weapon, `patk +5`）
- **恢复道具**：红瓶（`self hp +5`）、蓝瓶（`self mp +5`）—— 量级按基线，各约 1/6 预算
- **能力件**：火抗鞋（`tags: [火抗]`，脚槽）、小船（`tags: [渡河]`，手槽，`patk -1`）、**撬锁工具（`tags: [撬锁]`，手槽）**
  —— 让"火焰山 + 火抗鞋""河流 + 小船""石门 + 撬锁工具"开箱即玩就能碰出来
- **状态用品**：御火符（`add_tag: 火抗, duration: 3`——**临时通行**）、解毒剂（`remove_tag: 中毒`——**解药**）
- **货币**：金币（`tags: [货币]`，`usable: []`）—— 商店的钱，靠奖励池 / 事件产出
- 建筑：宝箱屋（treasure + mimic + `pick: tiers` 含空箱档 + `copies: multiplier`，`point_reward: 1`）、
  怪物房（`monster_pool` 池里放哥布林 + 史莱姆，**不是写死一只**）
- **事件建筑**：上锁的石门（`event`，`gate: [撬锁]` + `check: 2D6 + patk ≥ 15`；成功给 2 点 + 红瓶，
  失败掉 3 血并挂 `扎伤` 3 回合）—— 把"门槛 ＋ 判定 ＋ 后果"三件套演示一遍
- **商店建筑**：流浪商人（`shop`，`stock` 按标签筛消耗品，`price: 1D6 → 5~15 枚金币`）
- **会下毒的怪**：毒牙哥布林（`attack_weights: { poison_bite: 1 }`，
  **技能 `poison_bite` 自带 `effects: [中毒]`**）—— 演示"怪物会下毒"＋"解毒剂能解"的闭环，
  且**靠的是技能，不是怪物身上的特殊字段**（§4.8.3）
- **道路：小路（`step: 1`）、沼泽（`step: 2`）、河流（`gate: [渡河]` + `block`）、火焰山（`gate: [火抗]` + `penalty hp: 5`）**
  —— 四条路刚好把"纯消耗 / 硬权限 / 软权限"三种形态各演示一遍
- **职业**：骑士 / 法师，各带 `base_stats`（初始属性）+ `free_points: 25` + `buffs`（优劣）+ `starting_items`（家当）：

| 职业 | `base_stats` | `free_points` | `buffs` | `starting_items` | `inventory_size` |
|---|---|---|---|---|---|
| 骑士 | `{ hp: 5, mp: 0, patk: 3, matk: 0, pdef: 2, mdef: 0 }` | `25` | `{ hp: 110, patk: 120, pdef: 110, matk: 80 }` | `[red_potion]` | `50` |
| 法师 | `{ hp: 3, mp: 4, patk: 0, matk: 3, pdef: 0, mdef: 2 }` | `25` | `{ hp: 90, matk: 130, mdef: 120, patk: 80 }` | `[blue_potion, scroll_of_fireball]` | `30` |

> **职业之间只差"先天的牌面"，不差"会什么"**：法师出生带一本《火球术》——
> 但那只是**家当**，能丢能卖，**不是"法师专属技能"**。他要是把书扔了、去捡《盾击》，那他就是个战士（§4.2.3）。
- **技能书**：`scroll_of_fireball`（`learn_skill: fireball`）——**后天发育的载体**，放在宝箱屋的奖励池里、商店的货架上、或事件后果里都行。

> 两个预设职业的 `base_stats` 总和分别是 10 / 12，加上 `free_points: 25` 后总量约 35~37——
> **这就是 §6.1.1 那把尺子的来源**。想要更硬核的局，把 `free_points` 调小即可；**这是职业设定，引擎不管**。

### 6.1.1 数值标定基准（预设职业的尺子）

**这把尺子来自预设职业，不是引擎硬规则**：预设职业的 `base_stats` 总量约 10，`free_points: 25`，
所以开局玩家大约有 **35 点属性**可分（§4.2.1）。1 点 = 1 属性值，所以：

| 对象 | `hp` | `mp` | `patk` | `matk` | `pdef` | `mdef` |
|---|---|---|---|---|---|---|
| **玩家**（预设职业约 35 点） | 5 ~ 30 | 0 ~ 25 | 0 ~ 30 | 0 ~ 30 | 0 ~ 30 | 0 ~ 30 |
| **小怪** | `[6, 12]` | `[0, 2]` | `[2, 4]` | `[0, 2]` | `[1, 2]` | `[1, 2]` |
| **精英怪** | `[24, 40]` | `[4, 8]` | `[6, 10]` | `[4, 8]` | `[4, 6]` | `[4, 6]` |
| **装备**（普通 / 强力，单维加值） | 0 / +2 | 0 / +3 | +1~2 / +4~6 | 同左 | 同左 | 同左 |
| **消耗品**（单次 delta） | 红瓶 +5 | 蓝瓶 +5 | — | — | — | — |

- **尺子在玩家这边**：一件强力装备 `+5` ≈ 1/7 的点数预算；超过它就该是"传说"级别。
- **怪物不在同一把尺子上**：它是**区间**且**小怪 / 精英跨度很大**（`hp` 从 6 到 40）。
  想让某只怪"难缠"，加宽区间或抬高档位即可——**不需要新字段**。
- **`point_reward` 是成长曲线**：预设里小怪 1 点 / 精英 5 点。玩家打完一张图的收益大致可以推算，
  这就是"变强"的节奏。
- 这只是一张**参考基线**，不是硬约束。你完全可以把预设职业的 `free_points` 改成 300，
  那时**这张表就作废了**——**这是你的设计自由**。

> 开箱时有**两件独立的事**，别混：
> ① **系统预设**（上面这批）在新用户首次打开时**播种一次**进组件库（标 `预设`），此后就是用户的资产；
> ② **新建一局游戏**时，项目是**空的**（一张空地图 + 空背景）——需要什么就从库里勾选启用 / 铺到图上；
> ③ 不预置任何现成关卡：要玩什么，就在构建页把库里的组件**启用并铺到图上**，自己搭出来。

### 6.2 验收标准
1. **对齐**：顶栏、左栏、中栏、右栏四条边在任意窗口宽度下都落在同一条栅格线上；面板无自带 margin。
2. **图层**：左栏能看到全部地图，可切换 / 新建 / 重命名 / 排序 / 删除；顶栏不再有地图 Tab。
3. **可辨识**：任一组件都能一眼看出**库身份**（`预设` / `自建`）与**本局状态**（`已启用` / `未启用`、`已铺设 ×N` / `未铺设`、`被引用 ×N`）；非地图件不会被误以为能拖到地图上。
4. **操作模式**：6 个模式各自行为与 §5.4 表一致；"铺路"只有一个入口；`Esc` 在任意模式都能干净退回「选择」。
5. **框选批量**：拖框选中范围内全部节点后，可一键批量删除，且只占**一步**撤销。
6. **奖励算法**：宝箱屋能配 `reward_pool`（`source: ids` 手选 / `source: filter` **按条件筛整个组件库**，可带权重）
   ＋ `pick`（`tiers` 档位表含空箱档 / `count` 数值区间）＋ `copies`（`fixed` / `value` **数值** / `multiplier` **倍率**）；
   面板上能直接读到"掷 1D6：1~2 空箱，3~4 一件，5~6 两件"这类预览。**没有 `all`**：件数永远被 `|池|` 夹住。
7. **力值链可验证**：一次施放的**本力值 / 对方防值**都能拆开看到
   **已结算属性值 ＋（装备加值 ＋ 状态加值 ＋ 技能 `bonus`）＋ 职业百分比 ＋ 骰子叠加 ＋ 骰子倍率** 五环，
   不是"只有骰子点数"；换装备 / 挂状态 / 换职业 / 换个技能会立刻反映到力值上。
7a. **技能就是"取一维 + 打谁"**：用**同一个技能编辑器**（五个下拉/数字框）能造出这五类，且**不改一行代码**——
   `普通攻击`（`patk`/`opponent`/0 加成）、`治疗术`（**只把 `target` 改成 `self`**）、
   `力量祝福`（`apply: none` + `modifiers`）、`虚弱诅咒`（`opponent` + 减益）、`毒牙`（伤害 + 挂 `中毒`）。
   **编辑器不认识"火球术""治疗术"这些词**——它只显示"取哪一维、打谁、挂什么"。
7b. **两种技能走两条路**：`target: opponent` 会**对抗、会落空**（不命中则 `effects` 也不生效）；
   `target: self` **不对抗、不落空**，但**仍然掷骰**（骰子决定治疗 / 加成的量）。
7c. **技能不绑职业**：把某职业的 `starting_items` 改成不含技能书、或干脆删空——**他不会因此少会任何技能**；
   把一本《盾击》放进宝箱屋，**法师开箱照样学会**；`forget_skill` 又能把它拿走。
7c2. **"存在"与"谁会"是两件事**：技能页能**反查**"哪些书 / 哪些怪物在用我"，但**不显示"谁会"**（那是游玩态数据）；
   一个技能都没启用的世界里，玩家只有保底对 `basic_attack` ＋ `basic_magic`。
7c3. **"法师练成战士"能跑通**：法师把点数全砸 `patk` + 学到 `shield_bash` + 抢到铁剑，**确实能当战士打**——
   但 `buffs.patk: 80` **永远不消失**（先天的牌面改不了，这正是"顶着 debuff 努力向前"）。
7c4. **技能书就是道具**：把 `scroll_of_fireball` 放进奖励池 / 事件 `grant` / 商店 `stock` 三处任一，
   玩家都能学会——**没有任何一处需要为"教技能"新增通道**。
7d. **回合定义可验证**：掷出 3 步走 3 格**只 tick 一次状态**（不是 3 次）；一次交锋结束 tick 一次；
   **用道具不 tick**——同一场战斗里连嗑两瓶药，状态剩余回合数**一点不减**。
7b. **6 属性贯通**：`mp` 能在五处一致工作——分配点数能加它、法术 `cost` 扣它、蓝瓶回它、地形 `cost` 扣它、怪物 `stats.mp` 有它。**不允许出现"半套 mp"**。
7c. **两边的属性来源不对称**：玩家属性来自 职业 `base_stats` ＋ 分配（**不被骰子改**）；怪物属性来自 `stats` 区间**登场摇定**。
7d. **小怪 / 精英可辨**：预设里两者 `stats` 区间档位明显不同；精英靠 `tags: [精英]` 标注，怪物池能 `filter` 出来。
7e. **点数由职业决定、规则由引擎决定**：把某职业的 `free_points` 改成 `300` 能直接生效（**引擎不拦**）；
    但"1 点 = +1""不可洗点""余点保留"这三条**改不了**（是硬规则）。
7f. **战斗能加点**：怪物 / 建筑上的 `point_reward` 在结算时把点数加进玩家的剩余自由点，
    且**溢出到下个场景仍然有效**（不是临时加点）。
8. **规则可配**：「规则」面板（顶栏入口，不进右栏）的字段与 §4.8.6 清单**严格一致（共 13 项，不多一个）**，且**没有 `combat.attacks`**；
   每个字段旁有人话预览，如"每回合掷 1D6 走几格，**走完全部步数算一个回合**"、
   "力值 = 物攻[3~6] 摇出 5 + 铁剑(+5) + 技能加成(0)，× 职业 100%，+ 1D4，× 1D6 倍率"。
9. **来源派生**：**七大类**（怪物 / 道具 / 建筑 / 道路 / 职业 / 技能 / 背景）都能自建，
   且「预设 / 自建」徽章**判定方式完全相同**——没有哪一类多一个字段。
10. **消耗与权限可配**：道路 / 建筑能编 `cost`（步数 / 血量 / 法力）与 `gate`（标签 + `any|all` + `block|penalty` + `penalty`）；
    装备 / 职业能编 `tags`；编辑器里能**双向反查**——"这条路要 `火抗`，谁带这个标签？""这双鞋的 `火抗` 能过哪些路？"
11. **标签驱动、不写死**：造一条 `gate.tags: [飞行]` 的路 + 一件 `tags: [飞行]` 的装备，**不改一行代码就能走通**——
    编辑器不认识"飞行""渡河""火抗"这些词。
11b. **事件能跑通**：造一个 `encounter: event` 的建筑，能配 `gate`（标签门槛）+ `check`（骰子 / 加值属性 / 目标值）
    + `on_success` / `on_fail` / `once`；编辑器**实时显示命中率与必成 / 必败**——
    把目标值调到必败时会提示"**现在做这个纯属浪费时间**"。
11c. **状态闭环**：中毒能挂上（带 `duration`）、每回合掉血、**解毒剂能解**、`duration` 到点自动消失；
    且 `duration` 超过 `state.max_duration` 时被夹到上限；**造不出永久状态**。
11d. **临时通行**：吃御火符获得 `火抗` 3 回合，期间能过火焰山，3 回合后过不去——
    **全靠状态 `tags` 进能力集合，引擎不写死任何标签**。
11e. **商店能跑通**：造一个 `encounter: shop` 的建筑，配 `stock`（按标签筛）+ `price`（掷骰定价）；
    能验证"**货币就是一件普通道具**"——整个系统里不存在独立的货币字段。
11f. **背包上限生效**：把职业 `inventory_size` 设成 `1`，捡第二件**不同**道具时被拒绝并提示；
    同种道具叠加仍占 1 格；设成 `0` 则不限制。
11g. **五种行为面板分明**：同一栋建筑切换 `encounter` 五选一时，右栏**只显示对应的块**（不把奖励池 / 事件 / 商店糊在一起）。
11h. **跑团立场可验证**：编辑器里**找不到**"难度评估""平衡性警告""多结局""条件通关"这类入口（§1.1 / §7.4）。
12. **round-trip**：导出 `.pmod` → 重新导入，启用集合、铺设节点、地图顺序、组件定义与 **`rules` 全部一致**。
13. **持久化**：刷新页面数据不丢失。
