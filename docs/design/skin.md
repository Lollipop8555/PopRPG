## 一、定位：素材是可选增强，不是必需依赖

- **素材缺位即回退，不报错。** 任何一节整体缺失时，元素仍按 `00b-style.md` 描述的程序绘制形态渲染：道路用脚印（`src/ui/Footprint.tsx`）、建筑用圆角矩形、其余用 emoji 图标。
- 因此本模块的规范是**叠加层**：先定义逻辑元素，再定义它可能对应哪些素材；不允许出现「必须先有素材才能渲染」的元素。
- 素材回退遵循「逐级降级」：专用素材 → 通用素材 → 程序绘制形态。

### 1.1 三层优先级（原始需求 ＋ 裁决 5）

```
游戏配置（本局 .pp / .pgame 携带）＞ 用户配置（用户本地设置的全局 pp）＞ 缺省配置（程序绘制）
```

- 「用户配置」= **用户在本机设置的全局 pp**（随设备走、不随这一局走）：本局 pp 未覆盖的节点仍从全局 pp 取。
- 降级粒度是**单个素材节点**，不是整节——同屏混用素材与程序绘制是正常状态。包结构与加载入口以**上位规范** [`00a-formats.md`](00a-formats.md) §二–§四 为准；皮肤包视角的说明见 [`skin/00-package.md`](skin/00-package.md) §四。

### 1.2 覆盖边界（本模块**不**负责什么）

| 不负责 | 归属 | 说明 |
|---|---|---|
| 构建页的**编辑器控件**（检查器、输入控件、行内菜单、缩放条、面板闸门） | [`02-data-model.md`](02-data-model.md)、[`04-editor.md`](04-editor.md) | 控件沿用现有 CSS 手绘风，不接入素材 |
| **Creative 模式自身的编辑器 UI** | [`skin/09-creative.md`](skin/09-creative.md) §一 | 皮肤编辑器长什么样不能依赖皮肤自身，否则自举循环；只有其**预览画布**用素材渲染 |
| 纸面底纹（噪声）与手绘分隔线 | 现在是 CSS 生成 | `theme.css` 已用 data-URI（`feTurbulence` 噪声）实现底纹与 `sketch-line`，**素材不与之重复**（见 §3.4、[`skin/03-window.md`](skin/03-window.md) §五） |
| 字体本身 | `00b-style.md` | 皮肤可指定**建筑名**的字体文件与字色（[`skin/06-item-building.md`](skin/06-item-building.md)），但不接管界面字体 |

## 二、存放与引用

- **目录**：素材放在 `.pp` 包内的 **`resource/`** 目录（见 [`skin/00-package.md`](skin/00-package.md) §二）。包内自包含，**纯静态约束**（见 [`08-deploy.md`](08-deploy.md)）：不请求外部地址，不依赖在线接口。
- **引用路径**：manifest 内一律写**相对 `resource/` 的路径**（`"img": "bg.jpg"`，不写 `resource/bg.jpg`），禁用绝对路径、`..` 与外部地址。
- **建议子目录**：`resource/<节>/`，与分节同名（`road/`、`role/`、`window/`、`misc/`、`component/`），便于人工核对与校验器报错定位。
- **命名**：`<元素>_<变体>.<ext>`，变体名使用与分型表一致的短名（如 `dead_end_n.png`、`tee_corner_nw.png`）。
- **格式**：`png`（含透明）优先；`jpg` 用于无透明需求的大图（背景）；矢量手绘可用 `svg`。
- **尺寸**：单格素材按 `CELL × CELL` 正方形绘制，图形居中——**这是旋转复用的前提**（见 3.1）。`CELL` 为游玩态的每格屏幕像素（现为 48，见 [`02-role.md`](skin/02-role.md) §四）。

## 三、复用机制（四件套：旋转 / 镜像 / 九宫格 / 平铺）

### 3.1 旋转（主要省图手段）

一张基准素材按 90° 步进复用，覆盖 4 种朝向姿态。

**三个前提，缺一不可**：

1. **素材本身旋转不变**：无方向性光影 / 高光 / 纹理，无与重力相关的元素（如飘向、落影方向）。
2. **素材为正方形且图形居中**（见 §二），旋转即绕格子中心旋转。
3. **非正方形或带出血**的素材，旋转后按 `<g transform="rotate(a cx cy)">` 处理，必要时配合裁切。

若素材必须画方向光，则该元素放弃旋转复用，按 **4 向全画**。

### 3.2 镜像

镜像仅用于**素材本身左右对称、仅朝向不同**的情形，且必须显式声明——**不默认启用**，因为手绘素材的笔画走向在镜像后会改变观感。

### 3.3 九宫格（预留，V1 不实现）

带「可拉伸区域」的素材（面板底图、按钮底图、长条色块）以 `.9.png` 命名预留，切片顺序固定为 `[上, 右, 下, 左]`（顺时针，从顶部开始）。

**V1 一律按普通拉伸处理**，不解析九宫格；V1.1 增加九宫格策略。因此规范要求：**V1 交付的素材必须在纯拉伸下不难看**，否则该素材推迟到 V1.1。

### 3.4 平铺

用于沿一个或两个方向重复的纹理：坐标参照线、分隔线、纸纹底。素材必须**四边可无缝拼接**，否则会出现可见接缝。平铺与拉伸不可混用在同一元素上。

**现状（重要）**：纸面底纹与手绘分隔线**已由 CSS 用 data-URI SVG 生成**（`theme.css` 的 `feTurbulence` 噪声底纹与波浪 `sketch-line`）。因此这两项**默认不由素材接管**——`tile` 策略当前只用于坐标参照线与可选的面板底纹；若素材要接管，必须显式提供且不得与 CSS 版本叠加（否则出现双层纹理）。

## 四、调用方接口：贴图渲染器

**禁止在业务代码中判断素材类型**（不写 `if (is9Patch)`）。所有需要绘制素材的位置统一调用一层抽象：

```
drawTexture(target, src, box, opts)
  opts = { mode: 'stretch' | 'nine' | 'tile', slice?: [t, r, b, l], rotate?, flip? }
```

| 版本 | 策略 | 实现 |
|------|------|------|
| V1 | `stretch` | `<image preserveAspectRatio="none">` 直接拉伸 |
| V1.1 | `nine` | 按 `slice` 切成九块拼装：四角原样、四边单向拉伸、中心双向拉伸 |

- **SVG 内无原生 `border-image`**，九宫格必须在 SVG 内切块拼装；DOM 层（面板 / 弹窗）可直接用 CSS `border-image` 实现同一策略。**两侧实现可以不同，调用方接口必须相同。**
- 适用范围：道路 / 建筑素材、面板与弹窗底图、按钮底图、色块——**凡是需要拉伸的一律走此接口**。

## 五、素材字段的三种写法

同一元素字段接受三种形态，按复用粒度选用：

```json
"deadEnd": "skin/road/dead_end_n.png"                      // 一张，引擎按朝向旋转
"deadEnd": { "img": "skin/road/dead_end_n.png", "rotate": 90 }   // 一张 + 硬性角度纠偏
"deadEnd": ["n.png", "e.png", "s.png", "w.png"]            // 四张，不旋转（顺序固定 N/E/S/W）
```

- **数组顺序固定为 N / E / S / W**，不得省略中间项（缺哪向就整节降级为程序绘制）。
- `rotate` 用于素材基准朝向与规范基准朝向不一致时的纠偏，**不用于表达「这一格该朝哪」**——朝向由引擎按连通关系计算。

## 六、跨节通用约定

- **取图必须是纯函数**：`(格子状态, 素材表) → 素材标识或回退形态`，无副作用，可单测（遵守 [`00c-guidelines.md`](00c-guidelines.md) §三 引擎与 UI 分离）。
- **确定性**：同一格子状态在任何时刻必须取到同一张素材；一切并列情况都要有明确的兜底顺序（各节自行规定，见 `skin/01-road.md` §四）。
- **校验**：素材表缺失、路径不存在、变体数量与分型表不符，均在构建页「清单」（K 系列校验，见 [`04-editor.md`](04-editor.md) §5.7）中列为提示项，**不阻断导出**。

## 九、原始需求的手误修正记录（已直接修正，无需确认）

整理原始需求时发现以下**笔误**，已在各分节按语义修正；此处留档以免后续反复质疑：

|---|---|---|
