## 二、结构决定：形象不带朝向

游玩态**不存在朝向状态**（移动为正交四邻，组件定义无面向字段），因此形象素材不设旋转轨道、不向美术索要 4 向素材；本节不重复 [`../skin.md`](../skin.md) §3.1 的旋转前提。

**裁决 24 确认**：**暂不考虑四个方向的图**——棋子与立绘**均不设 4 向槽位**。需要「左右相对」的场合（对战 VS 区、对话框）由立绘的**可选 `flip` 字段显式声明**镜像（§四），**不引入** `n` / `e` / `s` / `w` 槽位。

**裁决 25 确认 · 单人游戏、唯一主人公**：本引擎是**单人游戏**，**只有一位主人公**——因此：

- **立绘就是"唯一形象"**：**不存在队伍、队友、多角色切换**。`portraits.player` ＝ 主人公本人的立绘；`portraits.classes.<id>` ＝ **各出身职业**对应的主人公立绘（选角页与状态面板用它区分"你选的是谁"）。
- **不需要"角色 × 多角色"的槽位矩阵**，也就不需要为立绘设计批量命名 / 槽位约定——一人一张（每职业各一张）而已。
- 相对地，**怪物与 NPC 才是"多立绘"的来源**：怪物按组件 `id` 查表；**NPC 按 `name` 查表 ＋ 通配 `"*"`**（**V2.4**，裁决 66）（§三 / §4.1）。

## 三、棋子形象节点

```json
"role": {
  "player": "skin/role/player.png",
  "classes":  { "warrior": "skin/role/class_warrior.png" },
  "monsters": { "goblin":  "skin/role/monster_goblin.png" },
  "npcs":     { "长老":    "skin/role/npc_elder.png", "*": "skin/role/npc_generic.png" }
}
```

| 键 | 取值 | 缺失时回退 |
|---|---|---|
| `player` | 单节点直接取图 | 职业 `icon` emoji → `🙂` |
| `classes.<组件 id>` | 按职业 id 查表 | 该职业 `icon` emoji |
| `monsters.<组件 id>` | 按怪物 id 查表 | 该怪物 `icon` emoji |
| **`npcs.<NPC 的 name>`** | **按 NPC 的 `name` 查表**（**V2.4 起**，**裁决 66**） | 依次：**通配 `npcs."*"`** → 该 NPC `icon` emoji |
| **`npcs."*"`** | **通配形象**：所有**没被精确 `name` 命中**的 NPC 都用它（**V2.4**） | 该 NPC `icon` emoji |

四者均接受 [`../skin.md`](../skin.md) §五 的三种写法；`classes` / `monsters` / **`npcs`** **不允许数组**（无朝向，数组无意义，见校验项 `KR-3`）。

> **`npcs` 的键是 `name`、不是 `id`**（**V2.4**，**裁决 66**）：NPC 的 `id` 是**随机串**（`n_5t2w`）、玩家不可见，做美术约定的键很难用；改用**作者在编辑器里看得见的 `name`** —— 再配一个**通配键 `"*"`** 兜住"没单独出图的 NPC"。**命中顺序：精确 `name` → `"*"` → 该 NPC 的 `icon` emoji。**
> 这与 `classes` / `monsters` 仍按**组件 `id`** 查表**不同**，属有意为之（那两类的 id 是可读词 / 玩家不可见）。

> **NPC 的落点有两个**（V2.4）：① **对话弹层标题栏**那一格 `icon`（本节的 `npcs` 素材照旧能用在这儿）；② **地图上建筑格里的槽位标记**——**有皮肤画皮肤、无皮肤画槽位色圆环**（§4.1 **落点 6**）。

## 四、立绘 `portraits`（裁决 24 / 25 / 26）

**立绘 = 角色 / 怪物的半身或全身大图，是纯皮肤元素**：**`.pmod` 不设任何字段、不新开组件概念**（在 pmod 设计之外），只存在于 `.pp` 的 `role.portraits` 下；同一份 `.pmod` 换皮肤即可换立绘，**无皮肤时整块不出现**（不渲染、不占位）。

```json
"role": {
  "player": "skin/role/player.png",
  "classes":  { "warrior": "skin/role/class_warrior.png" },
  "monsters": { "goblin":  "skin/role/monster_goblin.png" },
  "npcs":     { "长老":    "skin/role/npc_elder.png", "*": "skin/role/npc_generic.png" },
  "portraits": {
    "player":   { "img": "skin/role/hero_stand.png" },
    "classes":  { "warrior": "skin/role/hero_warrior_stand.png" },
    "monsters": { "goblin": { "img": "skin/role/goblin_stand.png", "flip": true } },
    "npcs":     { "长老":   "skin/role/elder_stand.png", "*": "skin/role/npc_stand_generic.png" }
  }
}
```

| 键 | 取值 | 缺失时回退 |
|---|---|---|
| `portraits.player` | 单节点：`img` ＋ 可选 `flip` / `hurt` | 该落点回退程序绘制形态（§4.3） |
| `portraits.classes.<组件 id>` | 按职业 id 查表 | **先回退 `portraits.player`**（主人公立绘），再回退程序绘制 |
| `portraits.monsters.<组件 id>` | 按怪物 id 查表 | 该落点不渲染（**不**借用其它怪物或通用怪物图） |
| **`portraits.npcs.<NPC 的 name>`** | **按 NPC 的 `name` 查表**（**V2.4**，**裁决 66**；与 §三 的 `npcs` **同一键口径**） | 依次：**通配 `portraits.npcs."*"`** → 该落点**不渲染**（**不**跨 NPC 借用，同 `monsters`）。**立绘通配是显式配置，不算"借用"** |

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `img` | 字符串 | 立绘图，路径**相对包根**（同 §三） | 该立绘不渲染 |
| `flip` | 布尔 | **显式**左右镜像：写 `true` 才翻转 | `false`（不翻转——遵守 [`../skin.md`](../skin.md) §3.2「镜像不默认启用」） |
| `hurt` | 字符串 | **受击图**（可选，裁决 25）：受击瞬间改显示这一张 | 缺省 → **改用形变**（拉伸 / 压缩），见 §4.4 |

- 立绘**不接受数组**（无四向；变体也**不写成数组**——V1 只有一个具名变体字段 `hurt`，见校验项 `KR-7`）。
- `flip` 只翻图、不翻布局：翻转后仍与容器**底边对齐**，且**不改变**左右站位（主角恒在左、怪物 / NPC 恒在右）。

### 4.2 尺寸与对齐

- **立绘不使用 `CELL` 基准**（那是地图棋子的基准），**也不写死像素档**：**展示尺寸基于窗口大小缩放**——取**窗口短边**为尺度 `W = min(视口宽, 视口高)`，立绘高度＝`W` 的固定比例，**窗口一变、立绘等比跟着变**。故 §五 的正方形要求**不适用于立绘**。
- **高度档（占 `W` 的比例，裁决 25 初值，实现后按观感微调）**：

| 落点 | 高度 | 直觉校验（以 900×600 窗口 → `W = 600` 为例） |
|---|---|---|
| 底栏 / 状态面板头部 | `6% W` | ≈ 36px，与 `hud-face` 同量级 |
| 对战对话框 VS 区 | `18% W` | ≈ 108px，约对话框可用高度的 1/3 |
| 出身卡 | `10% W` | ≈ 60px，约卡内图标位高度 |

- **宽度**由素材**宽高比**推出，**不拉伸变形**；并受**可用宽度 25%** 上限约束——超出即整体等比缩小，避免挤占底栏技能格与对话框正文（校验项 `KR-5`）。
- **默认底边对齐**（立绘"站"在容器底线上）；**仅出身卡居中**。
- 素材必须**自带透明留白**，本节不提供内边距 / 尺寸字段（思路同取舍 `S-11`）。
- **窗口极端长宽比时**（竖屏手机 / 超宽屏），立绘随 `W` 缩放而**地图格仍是固定 48px**，两者比例会不一致（取舍 `S-31`）——实现时**以 `W` 为唯一尺寸来源**，不要再给立绘加 `@media` 断点。

### 4.3 回退与占位

- 立绘**不是棋子形象的替代品**，与之**不共用回退链**：`player` 棋子 emoji 与 `portraits.player` 相互独立。
- 立绘缺位一律**逐落点降级**，且**整个立绘容器按条件渲染**——「**没有立绘则不占用空间**」，不渲染空盒、不保留占位宽高（落点 2 的**例外**：另一方有立绘时 VS 区照常渲染，缺的一侧为空）。
- 职业立绘缺位时**先取 `portraits.player`** 再回退 emoji；怪物立绘缺位**不**跨怪物借用。
- 立绘**不含动画**（V1 单帧静态；**唯一的动态是 §4.4 的受击形变**）、**不套手绘滤镜**、**不参与点击命中**。
- **NPC 立绘**缺位时该落点**不渲染**（与 `monsters` 一致，**不**回退 emoji）——注意与**棋子形象**（§三）相反：`role.npcs` 缺位才回退 `icon` emoji。
- **地图上 NPC 槽位（落点 6）的兜底是圆环**（**V2.4**，**裁决 66**）：`role.npcs` **未命中**（含通配 `"*"` 也没配）→ 画 **槽位色圆环** —— **颜色与构建页该槽位行的颜色一致**（构建页槽位色**按槽号从固定调色板分配**，[`../04-editor.md`](../04-editor.md) §5.6）。圆环按格尺寸绘制、以**格中心**为基准。**不**回退 `icon` emoji —— 圆环是"这里有一位 NPC、但还没皮肤"的**占位语汇**。
- **`icon` emoji 仍用于对话弹层标题栏**（§三 的回退链），两处**各司其职、不冲突**。

### 4.4 受击表现：素材优先，无素材则形变（裁决 25）

受击反馈**两条路，优先用素材、缺了才形变**——**棋子形象与立绘（含 NPC）同一套规则**：

| 素材情况 | 表现 |
|---|---|
| **提供了受击图** | 受击瞬间**改显示受击图**（立绘写 `hurt`，§四字段表），持续到本次受击动作结束 |
| **没有受击图**（默认） | **图形拉伸 / 压缩**（squash & stretch）：受击瞬间**横向 ×1.15、纵向 ×0.9**，约 `120ms` 回弹到原尺寸 |

- **形变是程序行为、不是素材**：不占用皮肤字段、不需要美术额外出图；幅度与时长由引擎给初值，**V1 不做逐素材配置**（取舍 `S-32`）。
- **形变的基准点**：棋子形象以**格中心**为基准（同 §五锚点）；立绘以**底边**为基准（否则会"陷进地板"）。
- **败北 / 倒下仍不设素材**：形变只表达"挨了一下"，不表达倒下——`dead` 变体不在 V1（待确认 2）。

## 五、尺寸、锚点与留白（棋子形象）

> 本表只适用于 §三 的**棋子与形象**；**立绘**见 §4.2。

| 节点 | 尺寸基准 | 锚点 |
|---|---|---|
| `player` | 1 格（地图格 48px） | 格中心 |
| `classes.*` / `monsters.*` | 沿用现有 CSS 尺寸 | 中心 |
| **`npcs.*`（地图槽位，V2.4）** | **1 格（同地图格 48px）**；按槽号色圆环兜底时同此 | **格中心** |

- **四周留白 10%**：`player` 素材画成 `CELL × CELL`，图形占中心约 80%，避免相邻格互相压边。
- **锚点一律为中心**，与 [`04-misc.md`](04-misc.md) 的地图标记一致；素材不得依赖「底边贴格」。

## 六、复用

不启用旋转、不启用镜像（无朝向）；无拉伸需求，九宫格不适用；**不套手绘滤镜**（素材已是手绘位图，见 [`04-misc.md`](04-misc.md) §六）。

立绘同此：不旋转（无四向）、不启用九宫格；**`flip` 是唯一的镜像开关，且必须显式声明**（§四）。**受击形变不属于"复用"**（它是程序行为，见 §4.4）——**也不要对受击图做九宫格 / 滤镜处理**。

## 七、状态与叠加不在本节

状态芯片（「中毒 ×3」）、门槛徽章（`🔒`）、属性徽章均为**文本元素**，外观归 [`03-window.md`](03-window.md) 的自适应宽度族。**受击表现见 §4.4**（受击图优先、缺了用形变）；**败北 / 倒下仍不改素材**——`dead` 变体不在 V1（待确认 2）。

## 十一、实现落点（2026-09-30）

> **本节全部落地**：棋子形象（§三）、立绘（§四 及 §4.1 四落点）、受击表现（§4.4）均已接入。§4.4 的幅度 / 时长仍按 `S-32` 写死。

### 取图与渲染件

- **取图**：[`src/engine/skin/lookup.ts`](../../../src/engine/skin/lookup.ts) 的 `roleSprite(role, kind, id)`（§三 四组，**不跨组借用**）与 `portraitOf(role, kind, id)`（§四 回退链：职业缺位先取 `portraits.player`、怪物**不**跨怪物借用、NPC 不回退）；`spriteRef()` / `textureRef()` 归一三写法（立绘不收数组）。两者都只出形状、不碰 IO；**键一律是组件 `id`**（玩家职业取 `player.cls.id`）——**唯一例外是 `npcs`：按 NPC 的 `name` 查表、并支持通配 `"*"`**（**V2.4**，裁决 66；`roleSprite` / `portraitOf` 需多接一个"按名查 ＋ 通配兜底"的入口）。
- **渲染件**：形象格 [`src/ui/RoleGlyph.tsx`](../../../src/ui/RoleGlyph.tsx)、立绘 [`src/ui/Portrait.tsx`](../../../src/ui/Portrait.tsx)，都借**行内层** `InlineTexture` 出图（只吃 `src` / `flip`，尺寸交给 CSS），取不到图即降级——形象格回 emoji、立绘返回 `null`（整块不渲染）。

### 棋子形象（§三）

- **地图棋子**（[`src/play/MapView.tsx`](../../../src/play/MapView.tsx)）：`role.player` → `textureProps(..., {x: 格x × CELL, y: 格y × CELL, w: CELL, h: CELL})`（整格大小 ＋ 锚点格中心，故左上角即格左上角，**四周留白 10% 由素材自己画**）→ SVG 层 `SvgTexture`；**路径取不到图才回到方框 ＋ 职业 `icon` emoji**。绿色定位环是「你在这儿」的标记、与棋子形象无关，故出图时**照旧画**。
- **四处文字落点**走 `RoleGlyph`：出身卡职业图标与状态面板标题、底栏（`role.classes.<职业 id>`）、对战弹层标题（`role.monsters.<怪物 id>`）、对话弹层标题（`role.npcs.<NPC name>`）——只换掉 `icon` 那一格，尺寸跟着所在处字号走（`.inline-texture` 的 `1em`），非正方形素材按 `object-fit: contain` 等比内缩（`KR-1` 只提示、不改行为）。
- **`player` 与 `classes` 是两条独立的链**：地图棋子**只认 `player`**，不会去借 `classes.<职业>` 的图——这是 §三 回退表的字面执行；若要做「按职业出棋子」需先改规范（与 §十 待确认 2 一并议）。

### 立绘（§四，四个落点）

- **尺寸全在 CSS**（§4.2 的「不写死像素档」）：`W = min(视口宽, 视口高)` 正好就是 `100vmin`，故三个高度档即 `.portrait-hud` `6vmin` / `.portrait-vs` `18vmin` / `.portrait-card` `10vmin`；图片只给 `height: 100%; width: auto`，**宽度由素材宽高比推出**，**不加任何 `@media` 断点**（`S-31`）。
- **可用宽度 25% 上限**：实现为 `.portrait { max-width: 25% }`，基数就是**该立绘所在容器的可用宽度**（CSS 百分比的自然解析）；撞上限时由浏览器的替换元素规则**按比例整体回缩**，故绝不拉伸变形。**遗留**：基数是「所在容器」还是「整个底栏 / 对话框」（§4.2 的意图更偏后者）等观感定（§十 待确认 6）。
- **对齐**：`.portrait { align-items: flex-end }` 即 §4.2 的底边对齐；出身卡加 `.portrait-center` 改居中（本表唯一例外）。
- **四个落点**：① 底栏 `.hud-vitals` 内、hp / mp 条左侧（两条血蓝条包进 `.hud-vitals-main` 与之底边对齐）；④ 状态面板 `.panel-head`（与 ① 同源同图：同一张 `portraits.player`）；② 对战弹层 `.vs-area`——**任一方画得出来即整块渲染**，两个 `.vs-side` 恒在（主角左、怪物右），缺的一侧是空 `<div>`、**不补 emoji / 占位图**；⑤ 出身卡 `.class-card-head` 内替代 `.class-icon`（逐张卡按职业查表，缺位先回退 `portraits.player`）。
- **缺位即不占位**（§4.3）：`portraitTile()` 给 `undefined` 时 `Portrait` 返回 `null`；落点 ① / ④ 是**显式二选一**（有立绘渲染立绘，否则渲染原样 `hud-face` / emoji ＋ 名称），落点 ② 是整块条件渲染——"没立绘不占宽高"因此是字面成立的。
- **NPC 立绘**：按 §4.1 落点 3 **不渲染**（配了 `portraits.npcs` 也不出图）；对话弹层里的 NPC 形象只有标题栏那一格 `icon`。
- **地图上的 NPC 槽位**（**V2.4 新增，落点 6**）：`MapView` 在建筑节点上按实例各槽的 `at` 画槽位标记 —— `roleSprite(role, 'npcs', npc.name)`（**按 `name` ＋ 通配 `"*"`**，§三）取到图就画图，取不到就画**槽位色圆环**（颜色 = 构建页该槽位行颜色，槽号 → 调色板，[`../04-editor.md`](../04-editor.md) §5.6）；**不**回退 `icon` emoji（§4.3）。锚点格中心、1 格大小（§五）。**绘制层在棋子层之下**（玩家踩到重叠格时，主角压在 NPC 上）。

### 受击表现（§4.4）

- **「受击瞬间」怎么判**：结算全在纯函数里（会话里**没有**「正在挨打」这个字段），故信号取自 **`hp` 掉下来的那一帧**——谁掉血谁受击，掉多少、谁打的都不问。实现为 [`src/ui/useHitPulse.ts`](../../../src/ui/useHitPulse.ts) 的 `useHitPulse(anchor, key?)`（`HIT_MS = 120`）：回血 / 原地不动不发作，`key`（怪物 id 之类）一变只挪基准——**换了怪物不算挨打**。
- **两条路在渲染件里收口**：`Portrait` 收 `hurt` ＋ `hit`——有 `hurt` 素材且正挨打就**改显示那张图**，没有就挂 `.portrait-hit` 走**形变**；`portraitHurtTile()` 只认对象写法（§四字段表），`flip` 跟着主图走。**棋子**没有 `hurt` 字段（§三 的写法里没有这一项），故**恒走形变**——与 §4.4 表里「提供了受击图（立绘写 `hurt`）」的字面一致。
- **一次受击动作 = 这一拍**：§4.4 说受击图「持续到本次受击动作结束」，实现里把「一次动作」定为 `HIT_MS`（`120ms`，与形变回弹同值）；形变是「受击瞬间瞬间压下去、离开这一拍时约 `120ms` 弹回」，故**先瞬时后回弹**，与 §4.4 的措辞同向。
- **基准与幅度全在 CSS**（[`src/styles/theme.css`](../../../src/styles/theme.css)）：`.portrait` 以 **`50% 100%`（底边）** 为变换基准、约 `120ms` 回弹，`.portrait-hit` 是 `scale(1.15, 0.9)`；棋子那一层是 `.piece-hit`，用 **`transform-box: fill-box` ＋ `transform-origin: 50% 50%`** 把基准钉在**格中心**（SVG 里按元素自身外框算，故与格大小无关）。
- **接线**：对战弹层两侧**各管各的**（主角锚 `player.resources.hp`、怪物锚 `monster.resources.hp` ＋ `monster.id`）；底栏、状态面板、地图棋子看的是**同一个主角 `hp`**（地图上看得到的场合是回合开始的持续效果扣血）。地图棋子的形变层**只包形象**——绿色定位环在它外面，不跟着压扁。
- **不做的**：形象格的**文字落点**（`RoleGlyph`：出身卡图标 / 底栏与面板标题 / 两个弹层标题）不做受击形变——它们没有「格」也没有「底边」这个基准；**NPC 立绘本就不渲染**，故天然不受影响；`dead` 变体仍不设（待确认 2）。
