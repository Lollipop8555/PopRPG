## 二、结构决定：形象不带朝向

游玩态**不存在朝向状态**（移动为正交四邻，组件定义无面向字段），因此形象素材不设旋转轨道、不向美术索要 4 向素材；本节不重复 [`../skin.md`](../skin.md) §3.1 的旋转前提。

**裁决 24 确认**：**暂不考虑四个方向的图**——棋子与立绘**均不设 4 向槽位**。需要「左右相对」的场合（对战 VS 区、对话框）由立绘的**可选 `flip` 字段显式声明**镜像（§四），**不引入** `n` / `e` / `s` / `w` 槽位。

**裁决 25 确认 · 单人游戏、唯一主人公**：本引擎是**单人游戏**，**只有一位主人公**——因此：

- **立绘就是"唯一形象"**：**不存在队伍、队友、多角色切换**。`portraits.player` ＝ 主人公本人的立绘；`portraits.classes.<id>` ＝ **各出身职业**对应的主人公立绘（选角页与状态面板用它区分"你选的是谁"）。
- **不需要"角色 × 多角色"的槽位矩阵**，也就不需要为立绘设计批量命名 / 槽位约定——一人一张（每职业各一张）而已。
- 相对地，**怪物与 NPC 才是"多立绘"的来源**：它们各自按组件 id 查表（§三 / §4.1）。

## 三、棋子形象节点

```json
"role": {
  "player": "skin/role/player.png",
  "classes":  { "warrior": "skin/role/class_warrior.png" },
  "monsters": { "goblin":  "skin/role/monster_goblin.png" },
  "npcs":     { "elder":   "skin/role/npc_elder.png" }
}
```

| 键 | 取值 | 缺失时回退 |
|---|---|---|
| `player` | 单节点直接取图 | 职业 `icon` emoji → `🙂` |
| `classes.<组件 id>` | 按职业 id 查表 | 该职业 `icon` emoji |
| `monsters.<组件 id>` | 按怪物 id 查表 | 该怪物 `icon` emoji |
| **`npcs.<组件 id>`** | **按 NPC id 查表**（裁决 26） | 该 NPC `icon` emoji |

四者均接受 [`../skin.md`](../skin.md) §五 的三种写法；`classes` / `monsters` / **`npcs`** **不允许数组**（无朝向，数组无意义，见校验项 `KR-3`）。

> **`npcs` 没有"多角色"问题**：NPC 只出现在建筑对话里（[`../02-data-model.md`](../02-data-model.md) §4.9），地图上不画它，因此 **NPC 形象的唯一落点是对话弹层**（§4.1 落点 3）。

## 四、立绘 `portraits`（裁决 24 / 25 / 26）

**立绘 = 角色 / 怪物的半身或全身大图，是纯皮肤元素**：**`.pmod` 不设任何字段、不新开组件概念**（在 pmod 设计之外），只存在于 `.pp` 的 `role.portraits` 下；同一份 `.pmod` 换皮肤即可换立绘，**无皮肤时整块不出现**（不渲染、不占位）。

```json
"role": {
  "player": "skin/role/player.png",
  "classes":  { "warrior": "skin/role/class_warrior.png" },
  "monsters": { "goblin":  "skin/role/monster_goblin.png" },
  "npcs":     { "elder":   "skin/role/npc_elder.png" },
  "portraits": {
    "player":   { "img": "skin/role/hero_stand.png" },
    "classes":  { "warrior": "skin/role/hero_warrior_stand.png" },
    "monsters": { "goblin": { "img": "skin/role/goblin_stand.png", "flip": true } },
    "npcs":     { "elder":  "skin/role/elder_stand.png" }
  }
}
```

| 键 | 取值 | 缺失时回退 |
|---|---|---|
| `portraits.player` | 单节点：`img` ＋ 可选 `flip` / `hurt` | 该落点回退程序绘制形态（§4.3） |
| `portraits.classes.<组件 id>` | 按职业 id 查表 | **先回退 `portraits.player`**（主人公立绘），再回退程序绘制 |
| `portraits.monsters.<组件 id>` | 按怪物 id 查表 | 该落点不渲染（**不**借用其它怪物或通用怪物图） |
| **`portraits.npcs.<组件 id>`** | **按 NPC id 查表**（裁决 26） | 该落点不渲染（**不**跨 NPC 借用，同 `monsters`） |

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `img` | 字符串 | 立绘图，路径**相对包根**（同 §三） | 该立绘不渲染 |
| `flip` | 布尔 | **显式**左右镜像：写 `true` 才翻转 | `false`（不翻转——遵守 [`../skin.md`](../skin.md) §3.2「镜像不默认启用」） |
| `hurt` | 字符串 | **受击图**（可选，裁决 25）：受击瞬间改显示这一张 | 缺省 → **改用形变**（拉伸 / 压缩），见 §4.4 |

- 立绘**不接受数组**（无四向；变体也**不写成数组**——V1 只有一个具名变体字段 `hurt`，见校验项 `KR-7`）。
- `flip` 只翻图、不翻布局：翻转后仍与容器**底边对齐**，且**不改变**左右站位（主角恒在左、怪物 / NPC 恒在右）。

### 4.1 落点（裁决 24）

### 4.2 尺寸与对齐

- **立绘不使用 `CELL` 基准**（那是地图棋子的基准），**也不写死像素档**：**展示尺寸基于窗口大小缩放**——取**窗口短边**为尺度 `W = min(视口宽, 视口高)`，立绘高度＝`W` 的固定比例，**窗口一变、立绘等比跟着变**。故 §五 的正方形要求**不适用于立绘**。
- **高度档（占 `W` 的比例，裁决 25 初值，实现后按观感微调）**：

| 落点 | 高度 | 直觉校验（以 900×600 窗口 → `W = 600` 为例） |
|---|---|---|
| 底栏 / 状态面板头部 | `6% W` | ≈ 36px，与 `hud-face` 同量级 |
| 对战 / NPC 对话 VS 区 | `18% W` | ≈ 108px，约对话框可用高度的 1/3 |
| 出身卡 | `10% W` | ≈ 60px，约卡内图标位高度 |

- **宽度**由素材**宽高比**推出，**不拉伸变形**；并受**可用宽度 25%** 上限约束——超出即整体等比缩小，避免挤占底栏技能格与对话框正文（校验项 `KR-5`）。
- **默认底边对齐**（立绘"站"在容器底线上）；**仅出身卡居中**。
- 素材必须**自带透明留白**，本节不提供内边距 / 尺寸字段（思路同取舍 `S-11`）。
- **窗口极端长宽比时**（竖屏手机 / 超宽屏），立绘随 `W` 缩放而**地图格仍是固定 48px**，两者比例会不一致（取舍 `S-31`）——实现时**以 `W` 为唯一尺寸来源**，不要再给立绘加 `@media` 断点。

### 4.3 回退与占位

- 立绘**不是棋子形象的替代品**，与之**不共用回退链**：`player` 棋子 emoji 与 `portraits.player` 相互独立。
- 立绘缺位一律**逐落点降级**，且**整个立绘容器按条件渲染**——「**没有立绘则不占用空间**」，不渲染空盒、不保留占位宽高（落点 2 的**例外**：另一方有立绘时 VS 区照常渲染，缺的一侧为空）。
- 职业立绘缺位时**先取 `portraits.player`** 再回退 emoji；怪物立绘缺位**不**跨怪物借用。
- 立绘**不含动画**（V1 单帧静态；**唯一的动态是 §4.4 的受击形变**）、**不套手绘滤镜**、**不参与点击命中**。
- **NPC 立绘**缺位时该落点**不渲染**（与 `monsters` 一致，**不**回退 emoji）——注意与**棋子形象**（§三）相反：`role.npcs` 缺位才回退 `icon` emoji。

### 4.4 受击表现：素材优先，无素材则形变（裁决 25）

受击反馈**两条路，优先用素材、缺了才形变**——**棋子形象与立绘（含 NPC）同一套规则**：

| 素材情况 | 表现 |
|---|---|
| **提供了受击图** | 受击瞬间**改显示受击图**（立绘写 `hurt`，§四字段表），持续到本次受击动作结束 |
| **没有受击图**（默认） | **图形拉伸 / 压缩**（squash & stretch）：受击瞬间**横向 ×1.15、纵向 ×0.9**，约 `120ms` 回弹到原尺寸 |

- **形变是程序行为、不是素材**：不占用皮肤字段、不需要美术额外出图；幅度与时长由引擎给初值，**V1 不做逐素材配置**（取舍 `S-32`）。
- **形变的基准点**：棋子形象以**格中心**为基准（同 §五锚点）；立绘以**底边**为基准（否则会"陷进地板"）。
- **败北 / 倒下仍不设素材**：形变只表达"挨了一下"，不表达倒下——`dead` 变体不在 V1（待确认 2）。

## 五、尺寸、锚点与留白（棋子形象）

> 本表只适用于 §三 的**棋子与形象**；**立绘**见 §4.2。

| 节点 | 尺寸基准 | 锚点 |
|---|---|---|
| `player` | 1 格（地图格 48px） | 格中心 |
| `classes.*` / `monsters.*` | 沿用现有 CSS 尺寸 | 中心 |

- **四周留白 10%**：`player` 素材画成 `CELL × CELL`，图形占中心约 80%，避免相邻格互相压边。
- **锚点一律为中心**，与 [`04-misc.md`](04-misc.md) 的地图标记一致；素材不得依赖「底边贴格」。

## 六、复用

不启用旋转、不启用镜像（无朝向）；无拉伸需求，九宫格不适用；**不套手绘滤镜**（素材已是手绘位图，见 [`04-misc.md`](04-misc.md) §六）。

立绘同此：不旋转（无四向）、不启用九宫格；**`flip` 是唯一的镜像开关，且必须显式声明**（§四）。**受击形变不属于"复用"**（它是程序行为，见 §4.4）——**也不要对受击图做九宫格 / 滤镜处理**。

## 七、状态与叠加不在本节

状态芯片（「中毒 ×3」）、门槛徽章（`🔒`）、属性徽章均为**文本元素**，外观归 [`03-window.md`](03-window.md) 的自适应宽度族。**受击表现见 §4.4**（受击图优先、缺了用形变）；**败北 / 倒下仍不改素材**——`dead` 变体不在 V1（待确认 2）。

## 八、校验项（清单提示，不阻断导出）

| 编号 | 检查 | 提示 |
|---|---|---|
| KR-1 | **棋子形象**（§三）素材非正方形 | 形象会按中心缩放宽高不一致（**立绘不适用**，见 §4.2） |
| KR-2 | `classes` / `monsters` / **`npcs`** 的键不在本局存在的组件 id 内 | 无效键，回退 emoji |
| KR-3 | `classes` / `monsters` / `npcs` 写成数组 | 形象无朝向，数组写法无效 |
| KR-4 | 图形贴满四边（未留白） | 地图上相邻格会互相压边 |
| KR-5 | **立绘**素材**宽 ≥ 高**（非竖构图） | 按 `W` 比例缩放后比例失衡，通常应出竖版（§4.2） |
| KR-6 | `portraits.*`（含 **`npcs`**）的键不在本局存在的组件 id 内 | 无效键，该落点回退程序绘制形态 / 不渲染 |
| KR-7 | `portraits.*` 写成数组 | 立绘无四向，变体也不写成数组（只有一个具名 `hurt`），数组写法无效 |
| KR-8 | 立绘**不带透明通道**（四角不透明） | 会盖住底栏 / 对话框的纸面，须抠图后出图 |
| KR-9 | **受击图 `hurt` 与 `img` 的宽高比不一致** | 受击瞬间画面会跳变（两张图按同一显示宽缩放），应**同比例**出图（§4.4） |
| KR-10 | **NPC 立绘与主人公立绘是同一张图** | NPC 立绘缺位的语义是"**不渲染**"，不是"复用主人公"——别拿 `hero_stand.png` 冒充 NPC（§4.3） |
