## 一、三件套的分工

| 文件 | 后缀 / 形态 | 承载 | 现状 |
|---|---|---|---|
| 游戏模组 | `.pmod`，**单文件 Markdown**（散文 ＋ ` ```yaml ` 围栏） | 地图、组件、规则、玩法——**不含任何 UI 定义** | 已实现（`src/io/pmod.ts`，`PMOD_VERSION = 1`） |
| 皮肤模组 | `.pp`，**zip 容器** | 纯渲染：路径 / 建筑 / 背景 / 音频 / 面板 / 提示框 / 角色等 | 新增 |
| 整体分发 | `.pgame`，**zip 容器** | `pack.json` ＋ `.pmod` ＋ 皮肤（`skin/` 子目录），作为整体分发与加载 | 新增 |

- 后缀 `.pp` 取自 pop pack。
- **`.pmod` 格式不因本模块改动**：`.pgame` 内直接以条目形式存放 `.pmod` 原文本，二者均可单独导出 / 单独加载。
- 皮肤**不是必需依赖**：没有 `.pp` 时游戏照常渲染（见 [`../skin.md`](../skin.md) §一）。

## 二、包结构

### 2.1 `.pp` 内部结构

```text
xxx.pp（zip）
├── manifest.json          描述文件（必须在包根）
├── preview.png            可选：皮肤预览图（皮肤列表与选择皮肤时展示，须在包根）
└── 素材…                  目录名、层级、文件名一律自由
    ├── background/  bg.jpg       ← 以下为推荐目录约定（非强制）
    ├── road/        straight.png …
    ├── role/        hero.png …
    ├── item/        …
    ├── building/    …
    ├── window/      …
    ├── font/        hand.woff2
    └── audio/       bgm.mp3
```

- **强制结构只有两项**（裁决 22）：`manifest.json`（**必须在包根**，是 `.pp` 唯一的入口描述文件，无 `kind` 类标识键）与 `preview.png`（**可选**，存在时须在包根）。除此之外**包内不设任何强制目录**——目录名（`resource/` 等）、层级、文件名与扩展名**一律自由**。
- **素材位置以 `manifest.json` 内各字段所写的路径为准**（§2.2）：加载器按描述文件逐条取包内条目，**不推断、不假设任何目录约定**。因此调整目录结构不需要改动加载代码，扩展性与兼容性最好。
- `preview.png`：存在且可解码时用于皮肤列表与皮肤选择项；缺失或损坏回退为文件名展示（校验项 `KP-6`）。
- 上图中的 `resource/` 与按分节命名的子目录（`road/`、`role/`、`window/`、`misc/` 等）是**推荐约定而非要求**，仅为便于人工核对与校验器报错定位；**加载器不得依赖它**。

### 2.2 路径规则：由**描述文件**指定，相对**包根**

素材路径**从包根写全**，并逐条写在 `manifest.json` 的对应字段中（裁决 19 / 22）——**描述文件是素材位置的唯一权威来源**：

```json
"img": "resource/road/straight.png"   // 仅为示例写法；目录名与层级自由
```

- 加载器**不得推断前缀**：既不用「相对 `resource/`」的简写，也不靠任何字段拼前缀，直接按该路径在包内取条目。
- 草案曾有的 `resource` 键（原「素材根目录声明」）**已废除**（裁决 22）——目录名既不强制，该键便不再携带信息；读到即忽略并提示（校验项 `KP-10`）。
- 路径约束（校验项 `KP-4`）：禁止绝对路径、禁止 `..`、禁止 `http(s)://` 等外部地址——与 [`../08-deploy.md`](../08-deploy.md) 的纯静态约束一致：**产物必须离线可用**。

### 2.3 `.pgame` 内部结构

```text
<name>.pgame（zip）
├── pack.json        容器描述文件（必须在包根）
├── game.pmod        `.pmod` 原文本，条目形式存放
└── skin/            皮肤（就是一份 `.pp` 的内容）
    ├── manifest.json
    └── …             素材：目录名与层级自由（以 `manifest.json` 为准）
```

`pack.json` 的键（裁决 19）：

| 键 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `format` | 整数 | 容器格式版本 | `1` |
| `kind` | 字符串 | 固定 `"poprpg.pgame"`，用于识别包类型 | 无（缺失即按 `KP-7` 回退探测） |
| `name` | 字符串 | 该整体分发的显示名 | 文件名 |
| `pmod` | 字符串 | `.pmod` 条目路径（相对包根） | `game.pmod` |
| `skin` | 字符串 | 皮肤目录（相对包根，其内为一份 `.pp` 内容：`manifest.json` ＋ 自由布局的素材） | `skin/` |
| `entry` | 字符串 | 入口标识 | 留空即走默认开局流程（首页 → 出身选择 → 首个场景）；取值语义见 §七 待确认 2 |

- `.pgame` 只声明「内含哪些文件」，不给自身增设计算语义；容器版本与 `pmod` / `manifest` 的版本号**不合并计**（§五）。
- 皮肤部分的校验沿用 `.pp` 的规则；**缺少 `skin/`（或其中无 `manifest.json`）时按「无皮肤」处理**，游戏照常启动。
- **`pack.json` 缺失时**按约定文件名回退（`game.pmod` ＋ `skin/manifest.json`），并在清单提示 `KP-7`。

## 三、`manifest.json` 顶层结构

定稿的顶层键为（裁决 19：`version` 改名 `format`；`meta` 三键上提为顶层；缩略图改用包根 `preview.png`；`pages` 拆为 `startup` / `lobby`；裁决 22：废除 `resource` 键）：

| 键 | 主题 | 规范位置 |
|---|---|---|
| `format` | 包格式版本（整数，缺省 `1`） | 本节 §五 |
| `name` / `author` / `description` | 皮肤名 / 作者 / 描述 | 本节 §3.1 |
| `startup` | **APP 欢迎页**（启动画面） | [`08-pages.md`](08-pages.md) |
| `lobby` | **游戏首页 ＋ 出身（选角）页面** | [`08-pages.md`](08-pages.md) |
| `extends` | 可选：继承**包内**另一套皮肤（同系列换色） | 本节 §3.2 |
| `theme` | 全局 token → CSS 变量 | 本节 §3.3 |
| `background` | 画布背景**数组（逐图清单：下标即地图下标，越界用最后一层，每张地图只渲染一层）**：多地图适配、对齐、`cellSize`、图外填充色 | [`05-canvas.md`](05-canvas.md) |
| `road` | 路径数组：路位模式 / 姿态 / 样式标签优先级 | [`01-road.md`](01-road.md) |
| `role` | 角色：玩家棋子、职业形象、怪物形象、**NPC 形象 `npcs`**，**立绘 `portraits`**（纯皮肤元素，`.pmod` 不设字段——裁决 24 / 26） | [`02-role.md`](02-role.md) |
| `item` / `building` | 道具 / 建筑：`icon`、衬底三元组；建筑另有地图贴图与地图名称字体 | [`06-item-building.md`](06-item-building.md) |
| `window` | 窗体：容器、按钮、格子、条、提示框 | [`03-window.md`](03-window.md) |
| `misc` | 其他：地图标记、建筑节点、骰子、图标、参照线 | [`04-misc.md`](04-misc.md) |
| `audio` | 音频：BGM 与音效（**V1 只解析预留**；播放已落 **V2.2**） | [`07-audio.md`](07-audio.md) |

**已废除的顶层键（裁决 22）**：`resource`（原「素材根目录声明」）——目录名不强制，素材位置一律由各字段自身的路径给出（§2.2），读到即忽略并提示 `KP-10`。

> **与原始需求的一致与差异**：
> ① 原始需求「道具」`item` 与「建筑」`building` **保持两节**（2026-09-29 裁决 4：场景不同——道具无地图层、不设字体）；
> ② 原始需求将「路径」写成 `role` 键，与「角色」节撞名——定稿用 `road`，`role` 专指角色；
> ③ `startup` / `lobby`（原 `pages` 节）为原始需求未列出、按裁决 5 补充、按裁决 20 拆分的新节；
> ④ `extends` / `theme` 为原始需求已提出、本轮补全规范（§3.2 / §3.3）。

### 3.1 皮肤名与预览图

`name`（皮肤名，显示在皮肤列表与开局屏的皮肤选择项）、`author`、`description`；预览图由包根 `preview.png` 承担（不再有 `thumbnail` 字段）。

- 三项均可选；`name` 缺失时在皮肤列表中以**文件名**显示。

### 3.2 `extends`：包内继承

用于「同系列换色」：一套皮肤只写与基座不同的节点，其余继承。

- 值为**包内**、相对包根的 manifest 路径（如 `"extends": "variant/base/manifest.json"`）；被继承者另有素材时，其素材路径同样相对**本包**包根书写。
- 加载顺序：先基座、后本包，**逐节点**覆盖（与 §4.2 的降级粒度一致）；允许多级链式继承。
- **只允许包内继承，禁止跨包引用**——跨包会让皮肤不再自包含，破坏纯静态与离线可用。按皮肤名继承本地已安装的另一套皮肤列为待确认（§七 3）。
- 校验 `KP-8`：`extends` 路径不存在或形成环时，忽略继承、只按本包渲染并提示。

### 3.3 `theme`：全局 token → CSS 变量

键为现有主题变量名（[`04-editor.md`](04-editor.md) 与 `src/styles/theme.css` 的 `:root`）：纸面族 `--paper` / `--paper-deep` / `--paper-card`、墨色族 `--ink` / `--ink-soft` / `--ink-faint`、线条族 `--line` / `--line-soft`、语义色 `--red` / `--amber` / `--green` / `--blue`、圆角 `--radius` / `--radius-rough`、字体族 `--font-hand` / `--font-cn`。

```json
"theme": { "--paper": "#f2ece0", "--ink": "#33302a", "--line": "#c9b795" }
```

- 加载时以**最高优先级**注入 `:root` 覆盖缺省值；卸载皮肤时**还原**为缺省值。
- **只允许改观感 token**；布局 token（`--gap` / `--topbar-h` / `--play-topbar-h`）**不可覆盖**——布局不随皮肤变化（取舍 `S-23`），越权写入忽略并提示（`KP-9`）。
- 未在 `:root` 中出现的键名视为未知 token，忽略并提示（`KP-9`）。

## 四、加载与降级

### 4.1 加载入口

| 入口 | 行为 |
|---|---|
| 加载 `.pmod` | 只加载游戏本身（现有行为，不变） |
| 加载 `.pgame` | 同时加载 `.pmod` 与皮肤，作为整体启用 |
| **首页手动选择皮肤** | 为当前这一局指定皮肤；不改变文件加载顺序。该交互本身由**程序绘制**，否则会形成「必须先选皮肤才能显示出选皮肤的界面」的循环（[`08-pages.md`](08-pages.md) §三） |
| **build 模式加载 `.pp`** | **仅用于预览**：地图视图按素材渲染，用于验证「素材与地图是否对得上」；不改变导出的 `.pmod`（[`09-creative.md`](09-creative.md) §一） |
| **Creative 模式打开 `.pp`** | 新建／编辑／导出 `.pp`；可加载 `.pmod` 作为**靶子**做命中检查（[`09-creative.md`](09-creative.md) §二） |

- 现有 `pickTextFile`（`src/io/download.ts`）**只读文本**；`.pp` / `.pgame` 是 zip 二进制，需新增 zip 读写能力——**裁决 14：引入 `fflate`**（依赖边界见 [`../08-deploy.md`](../08-deploy.md) §9）。
- 后两条入口只影响**渲染与编辑**：皮肤编辑器自身的 UI 不接管素材（自举循环，[`09-creative.md`](09-creative.md) §一）。

### 4.2 优先级（逐节点降级）

```
游戏配置（当前 .pp / .pgame 携带）＞ 用户配置（用户本地皮肤库中启用的全局 pp）＞ 缺省配置（程序绘制）
```

- 「用户配置」的确义（裁决 5）：**用户在本机设置的全局 pp**——它随设备走、不随这一局走；一局里指定了 pp 时，本局 pp 覆盖它，而未被覆盖的节点仍从全局 pp 取。
- 降级粒度是**单个素材节点**，不是整节：某槽位在游戏皮肤中缺图，则取用户皮肤的同名节点，再缺则回退程序绘制形态（道路脚印 / 圆角矩形 / emoji）。
- 因此「同一屏内一部分是素材、一部分是程序绘制」是正常状态，不得视为缺陷。

### 4.3 不写进 `.psave`

皮肤是**渲染层**，不进入存档语义域（[`../02-data-model.md`](../02-data-model.md) §4.0：`.psave` 只存进度）。**`.psave` 不记录皮肤名**（裁决 15）；皮肤选择在会话内有效，跨会话的皮肤偏好属「用户配置」，由皮肤库承担。

### 4.4 皮肤库与「一次只解压一套」（裁决 15 / 19）

- **入库范围**：用户**导入过**的 `.pp` 各记为一条皮肤条目（名称 / 作者 / 来源 / 导入时间 / 是否启用）。**游戏自带皮肤（`.pgame` 内的 `skin/`）不入库**——它只随该局加载，不进入皮肤列表、不单独记录。
- **存储形态**：条目携带的素材保持 **`.pp` 原始包体**（不落地解压目录、不逐文件保存）。
  - 条目索引（小型 JSON）走 `localStorage`，键 `poprpg_skins`；**包体（二进制）走 IndexedDB**。
  - 理由：`.pp` 为二进制 zip，体积远超 `localStorage` 约 5 MB 的配额，且 `localStorage` 只能存字符串（需 base64，额外膨胀三分之一）。这是对本项目「数据只走 `localStorage`」约定的一处**扩展**（[`../08-deploy.md`](../08-deploy.md) §9）：仍为纯客户端、离线可用，不引入任何服务端能力。
- **一次只解压一套**：任一时刻内存中**只保留当前生效皮肤**的解压结果（条目名 → 字节内容）。**切换皮肤时先释放当前解压结果，再解压目标包**；不常驻多套，不缓存历史皮肤的解压产物。
- **不设体积硬上限**（裁决 15）：加载不因包大而拒绝；仅在「清单」中对超大单图给出提示，不阻断加载与导出。
- **实现落点（2026-09-30）**：「一次只解压一套」由 [`../../../src/io/skin-runtime.ts`](../../../src/io/skin-runtime.ts) 承担（两层输入按**素材节点**降级合成一套生效皮肤）；素材地址由 [`../../../src/io/skin-assets.ts`](../../../src/io/skin-assets.ts) 按需建、`release()` 一次撤；界面侧统一从 [`../../../src/store/skin.ts`](../../../src/store/skin.ts) 取——`activateLayers()` 整体换两层（本局 `.pp` ＋ 用户全局 pp）、`refresh()` 重取用户启用的全局皮肤、`release()` 回到全部程序绘制。**未启用皮肤时素材源对一切路径回 `undefined`**，各屏据此逐节点回退，调用方不必判空。

## 五、版本与迁移

- `manifest.json` 的 `format` 为整数，缺省视为 `1`（原 `version` 键改名为 `format`，裁决 19）。
- 读到**高于**当前实现的版本时：照常渲染可识别字段，并在控制台给出一次警告（与 `.pmod` 的处理一致，`src/io/pmod.ts` 的 `PMOD_VERSION` 检查）。
- `.pgame` 的 `pack.json.format` 为**容器**版本，只声明「内含哪些文件」，不与 `pmod` / `manifest` 的版本号合并计。

## 六、校验项（构建页「清单」，均为提示不阻断导出）

| 编号 | 检查 | 提示内容 |
|---|---|---|
| KP-1 | `manifest.json` 不在包根 / 无法解析 | 该 `.pp` 整体被忽略，全部降级为用户配置 |
| KP-2 | 素材路径在包内不存在 | 列出全部无效路径；该项逐节点降级 |
| KP-3 | `format` 高于实现版本 | 提示可能读不出新增字段 |
| KP-4 | 路径含绝对路径 / `..` / 外部地址 | 违反纯静态约束，禁止 |
| KP-5 | `item` / `building` / `road` / `role` 等节的键不在本局启用的组件 id 内 | 无效键，忽略并提示（明细见各节 `KIB` / `KS` / `KR` 等） |
| KP-6 | 包根无 `preview.png`，或其无法解码 | 皮肤列表回退为文件名显示 |
| KP-7 | `.pgame` 缺少 `pack.json` | 按约定文件名（`game.pmod` ＋ `skin/manifest.json`）回退加载 |
| KP-8 | `extends` 路径不存在或形成环 | 忽略继承，只按本包渲染 |
| KP-9 | `theme` 含未知 token 名，或试图覆盖布局 token | 忽略该键，其余主题照常注入 |
| KP-10 | `manifest.json` 含已废除的 `resource` 键 | 忽略该键，路径一律以各字段自身为准（裁决 22） |

> **不校验项**：皮肤体积**不设硬上限**（裁决 15）；仅对超大单图提示，不阻断。

## 七、待确认

1. **`.pmod` 是否也要支持并入 `.pp`**（即反向：皮肤包内挂一个默认游戏）？当前不允许。
2. **`pack.json.entry` 的取值语义**：指向 `.pmod` 内的场景 id、还是某个页标识？当前留空即走默认开局流程（首页 → 出身选择 → 首个场景）。
