## 一、渲染目标：从「一个图标」到「按连通关系拼出的路形」

道路组件当前以**脚印**（`src/ui/Footprint.tsx`）渲染，每格独立、不表达连通关系。
本节的规范是把道路格升级为**按四邻连通关系取图**：格子与哪个方向相邻的道路连通，素材就在哪个方向延伸。

**素材缺位时回退为脚印**，观感仍成立（见 [`../skin.md`](../skin.md) §一）。

## 二、取图分两层，互不干扰

| 层 | 决定因素 | 决定什么 | 规范位置 |
|----|----------|----------|----------|
| ① 样式集 | 道路格的 `tags` | 用哪一套素材（如石路 / 土路 / 铁轨） | §六 |
| ② 槽位素材 | 四邻连通关系 | 用这一套里的哪一张 | §三 / §四 / §五 |

**同一条道路的多个实例可能命中不同样式集，但连通判定与样式无关**：只要相邻两格同为道路件，即视为连通（标签不参与连通判定；若需「同标签才连通」，见 §九 待确认 1）。

### 2.1 位模式与查表（原始需求）

每格考察周围 **8 格**（一圈），以 8 位标记为一个整数 `flag`，位序为**从左上角起顺时针**：

| 位 | 方向 | 含义 |
|---|---|---|
| `bit0` | 左上（西北） | 该角有路 |
| `bit1` | 中上（北） | 该边有路 |
| `bit2` | 右上（东北） | 该角有路 |
| `bit3` | 右中（东） | 该边有路 |
| `bit4` | 右下（东南） | 该角有路 |
| `bit5` | 中下（南） | 该边有路 |
| `bit6` | 左下（西南） | 该角有路 |
| `bit7` | 左中（西） | 该边有路 |

- 原始需求的排列与此**逐字一致**（「左上、中上、右上、右中、右下、中下、左下、左中」），本节只是补足位号。
- **256 种原始组合**（2^8）在构建期展开为查表：`flag → 槽位 → 基准朝向`。运行期每格只做一次查表，**不跑 if-else 链**（原始需求明确要求）。
- 8 位折叠到 15 槽位 / 47 姿态的规则：按 §五 的夹角口径，`n ≤ 3` 时**只把夹角角块计入角数 `c`**，外侧角忽略；`n = 4` 时四角全是夹角，全部计入（`cross` 系）。因此 256 个值映射到 47 种姿态，多种 `flag` 共用同一张姿态素材。
- 查表结果与「样式集」无关：**先按 `flag` 定姿态，再按 `tags` 选样式集**（§六），顺序不可颠倒。

## 三、槽位分型表（15 槽位 / 47 姿态 / 15 张素材）

连通关系由两条信息构成：**四条边**（N / E / S / W 是否有路）与**四个角**（夹角角块是否有路，见 §五）。

| 边数 `n` | 夹角角块 `c` | 槽位名 | 覆盖的姿态数 | 旋转轨道数（需画的素材数） |
|---|---|---|---|---|
| 0 | — | `isolated` | 1 | 1 |
| 1 | — | `dead_end` | 4 | **1** |
| 2（相对） | — | `straight` | 2 | **1** |
| 2（相邻） | 0 | `bend` | 4 | **1** |
| 2（相邻） | 1 | `corner` | 4 | **1** |
| 3 | 0 | `tee` | 4 | **1** |
| 3 | 1（西北侧夹角角块） | `tee_corner_nw` | 4 | **1** |
| 3 | 1（东北侧夹角角块） | `tee_corner_ne` | 4 | **1** |
| 3 | 2 | `tee_full` | 4 | **1** |
| 4 | 0 | `cross` | 1 | **1** |
| 4 | 1 | `cross_one_corner` | 4 | **1** |
| 4 | 2（相邻） | `cross_adjacent` | 4 | **1** |
| 4 | 2（相对） | `cross_diagonal` | 2 | **1** |
| 4 | 3 | `cross_three_corners` | 4 | **1** |
| 4 | 4 | `plaza` | 1 | 1 |
| | | **合计** | **47** | **15** |

**读法**：47 种姿态（几何上互不相同的外观），只需 15 张素材——每张基准素材通过 0° / 90° / 180° / 270° 覆盖它那一行的 4 种姿态；`straight` 只需 2 种（旋转 180° 等于自身），`isolated` / `cross` / `plaza` 等完全对称的槽位无需旋转。表中的 `c` **只数夹角角块**（§五），外侧角不参与，15 槽位因此恰好覆盖全部 47 种姿态。

### 3.1 命名约定（裁决 2）

- 三岔口用**绝对角名**：`tee_corner_nw` / `tee_corner_ne`，语义为**该夹角角块有路**（西北侧 / 东北侧），沿用「角上有路为正」的正向表述。`cross` 系同法：角位槽位一律以**西北角起、顺时针**为基准姿态，再按 §四 旋转复用。
- 原始需求把这两个槽位写作 `teeLeft`（「T 字型左侧夹角**没有**道路」）与 `teeRight`（右侧无路），是**相反方向**的表述；**以本节的正向命名为准**（2026-09-29 裁决 2）。
- 原始需求对 `teeLeft` / `teeRight` / `teeFull` 的释义「入口 / 出口 / 边缘」与形态无关，属笔误，见 [`../skin.md`](../skin.md) §九。

## 四、旋转复用的前提

旋转能省下 32 张素材，代价是三条约束（通用前提见 [`../skin.md`](../skin.md) §3.1）：

1. **素材旋转不变**：无方向性光影、无与重力相关的元素。美术若坚持画方向光，则该套样式放弃旋转复用，按 47 张全画。
2. **素材为 `cellSize × cellSize` 正方形、图形居中**——尺寸基准是**背景图的每格像素数**，与背景图共用同一变换（裁决 3，见 [`05-canvas.md`](05-canvas.md) §3.1）。未配置背景时回退为屏幕 `CELL × CELL`。
3. **旋转是绕格子中心旋转**，非正方形或带出血的素材需配合 `<g transform="rotate(a cx cy)">` 与裁切。

**基准朝向**统一为**缺口朝北**（即素材表中「朝北」列的语义），其余朝向由引擎旋转得到。带**唯一缺口**的形态（`dead_end` / `tee`）按此定义；角位槽位以**角位本身**定位（§3.1），`tee_corner_nw` / `tee_corner_ne` 的基准姿态为**缺口朝南**（此时两个夹角分别落在西北与东北侧），否则「西北 / 东北」这对绝对角名无法区分这两行。

## 五、角位判定：只在夹角处生效（已确认）

**规范**：角位（四个角）**只在该角处于两条相邻路的夹角中时**参与判定。某角的**两侧边都有路**，它就是**夹角角块**：有路即计入角数 `c`，无路记 0；只挨着一条路的角是**外侧角**，一律不参与判定，其有无路不影响取图结果。

**判定口径**（`c` 只数夹角角块）：

| 边数 `n` | 夹角角块 | 判定 |
|---|---|---|
| 0 / 1 | 无（不构成夹角） | 只按边数取 `isolated` / `dead_end` |
| 2（相邻） | 1 个，即两边的交角 | 有路 → `corner`；无路 → `bend` |
| 3 | 2 个（缺边两侧的角） | 0 个有路 → `tee`；1 个 → `tee_corner_*`；2 个 → `tee_full` |
| 4 | 4 个（四边俱全，四角全是夹角） | `cross` 系按 0 / 1 / 2（相邻、相对）/ 3 / 4 个有路分型 |

**后果**：当某格外侧角有路、而相邻侧边无路时，素材不向该角延伸，接缝处出现视觉断开。

**理由**：夹角角块落在两条路的转角内，漏掉即是实打实的缺口，必须计入；外侧角若一并计入，`n ≤ 3` 的槽位将从 8 个膨胀到 20 个以上，素材量与判定复杂度显著上升，收益仅为少数接缝的观感改善。

本条已登记为 [`../skin.md`](../skin.md) §七 的 `S-3`。

## 六、样式选取规则（已确认）

道路格的标签集合记为 `R`，样式集条目的标签记为 `s.tags`。

**候选条件**：

```
候选 = { 样式 s | s.tags 为空 }  ∪  { 样式 s | s.tags ∩ R ≠ ∅ }
```

空标签的样式集是**通配底样**：对所有道路生效。

**排序（逐级比较，前者优先）**：

| 序 | 规则 | 说明 |
|---|---|---|
| ① | `s.tags` 非空者优先于为空者 | 通配底样不参与竞争 |
| ② | `\|s.tags ∩ R\|` 降序 | 命中标签数多者优先：`ABC` 胜 `AB`，`AB` 胜 `A`，任何非空者胜 `[]` |
| ③ | 素材表中的声明顺序 | 前声明者优先，保证结果确定 |

**语义归属**：默认「命中任意一个即可」（`any`），与 [`../02-data-model.md`](../02-data-model.md) §4.5.1 道路 `gate.mode` 的命名保持一致。若后续需要「必须全部命中」，样式条目另加 `mode: all`，此时规则 ①② 仍然成立。

> **与原始需求的差异（裁决 1）**：原始需求写作「只有 tag 全匹配的情况下，才会表示命中道路样式」，而**以本节的「空标签通配 ＋ 命中任意一个 ＋ 命中数降序」为准**（2026-09-29 裁决 1：「按现有的」）。需要全匹配时用 `mode: all` 表达，默认不启用。

**确定性要求**：规则 ③ 是兜底而非设计意图。当两条样式在 ①② 上完全同分时，构建页／Creative 模式「清单」应给出提示，要求作者消歧（见 §八）。

## 七、素材表字段与示例

字段形态见 [`../skin.md`](../skin.md) §五（字符串 / 对象 / 数组三写法）。

**路径定义（重申）**：`styles[].base` 是**目录前缀**，`tiles` 的值是**相对文件名**——两者拼接即该素材的路径，全部相对**包根**（裁决 19；[`00-package.md`](00-package.md) §2.2）。因此 `base` 与 `tiles` 各司其职：**目录写一次**（换样式集只改 `base`），**文件名写 15 条**。`base` 带不带尾斜杠都合法，拼接时按需补一个 `/`；样式集缺省 `base` 时，`tiles` 的值按**相对包根的完整路径**处理。

```json
{
  "road": {
    "styles": [
      { "tags": [],               "base": "road/dirt" },
      { "tags": ["石子"],          "base": "road/stone" },
      { "tags": ["石子", "官道"],   "base": "road/stone_wide" }
    ],
    "tiles": {
      "isolated":            "isolated.png",
      "dead_end":            "dead_end_n.png",
      "straight":            "straight_ns.png",
      "bend":                "bend_ne.png",
      "corner":              "corner_ne.png",
      "tee":                 "tee_n.png",
      "tee_corner_nw":       "tee_corner_nw_n.png",
      "tee_corner_ne":       "tee_corner_ne_n.png",
      "tee_full":            "tee_full_n.png",
      "cross":               "cross.png",
      "cross_one_corner":    "cross_one_corner_n.png",
      "cross_adjacent":      "cross_adjacent_n.png",
      "cross_diagonal":      "cross_diagonal_n.png",
      "cross_three_corners": "cross_three_corners_n.png",
      "plaza":               "plaza.png"
    }
  }
}
```

- `tiles` 的键**必须与 §三 槽位名逐字一致**，缺键即该槽位回退为脚印。值为**相对文件名**（不含目录），目录由选中样式集的 `base` 给出；只有样式集缺省 `base` 时，值才写成相对包根的**完整路径**。
- 素材名中的 `_n` 表示基准朝向为缺口朝北；`_ns` / `_ne` 表示该素材已覆盖的方向组合。
- **道路贴图不设背景色**（裁决 3）：素材的透明区**直接透出背景图**，`road` 节不提供任何颜色／填充字段，与 [`05-canvas.md`](05-canvas.md) §3.1 的「地图层素材与背景共用基准」一致。

## 九、明确不做

- **不做单向路**：与 [`../02-data-model.md`](../02-data-model.md) §4.5.4 一致，道路不表达通行方向，因此槽位表不含方向箭头。
- **不做道路踩踏触发**：道路只回答消耗与权限两个问题，「一踩就出事」由建筑承担。
- **不在组件定义内写素材路径**：素材归属项目级配置，组件定义与素材分离。
- **不在业务代码判断素材类型**：一律走贴图渲染器接口（[`../skin.md`](../skin.md) §四）。
- **不做「按标签连通」**：连通只看是否为道路件（见 §九 待确认 1）。

## 十、待确认

1. **连通判定是否看标签**：当前规范为「相邻格同为道路件即连通，标签只决定样式集」。若设计意图是「只有同标签的道路才互相连通」，需在连通判定中引入标签匹配，槽位计算随之改变。
2. **`straight` 的两张素材**：现行规范只要求一张（旋转 180° 复用）。若手绘素材在任何角度下都带方向感，则需补第二张。
3. **素材与脚印的混用**：是否允许同一张地图内部分道路有素材、部分回退脚印（当前规范允许，逐格降级）。
