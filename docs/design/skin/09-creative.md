# PopRPG 设计文档 — skin 分节：Creative 模式（构建 `.pp`）

> **上层索引**：[`../skin.md`](../skin.md)　**包结构**：[`00-package.md`](00-package.md)
> **设计依据**：2026-09-29 裁决 9 / 10（build 模式可加载 pp 预览地图；新增 Creative 模式用于构建 pp）＋ 裁决 21（内置**九宫格切分工具**；字体**不做**额外处理）
> **状态**：新增（含 1 处待确认）

## 一、定位

Creative 模式是**第三个顶层模式**，与既有两模式并列：

| 模式 | 编辑对象 | 产物 | 与 pp 的关系 |
|---|---|---|---|
| build | `.pmod`（地图、组件、规则、玩法） | `.pmod` | 可**加载 pp 预览**：地图视图按素材渲染，用于验证「素材与地图是否对得上」 |
| **Creative** | **`.pp`（皮肤）** | `.pp` / `.pgame` | 编辑与导出皮肤；可**加载 `.pmod` 作为靶子** |
| play | 无 | 存档 `.psave` | 消费 pp 渲染游玩态 |

- build→Creative 的分工与 build→play 一致：**build 编游戏，Creative 编皮肤**，两者共享地图视图、组件库与检查器范式。
- Creative 的**编辑器 UI 自身不被任何 pp 覆盖**（同 [`08-pages.md`](08-pages.md) 取舍 `S-13`）——否则「皮肤编辑器长什么样」会依赖皮肤自身，形成自举循环。
- 只有预览画布与预览用的游玩态组件（地图、卡片、面板、按钮）使用素材渲染。

## 二、核心能力

### 2.1 新建 / 打开 / 导入

| 动作 | 行为 |
|---|---|
| 新建 | 从空白骨架开始；或**从 `.pmod` 生成骨架**：读出该局启用的全部组件与地图用到的全部道路 flag，为每个槽位生成占位条目（值为空字符串），形成「待填清单」 |
| 打开 | 打开 `.pp`（zip 容器）或本地目录 |
| 导入 | 与本地用户皮肤合并（同名槽位以导入者为准，逐节点） |
| 导出 | 导出 `.pp`；或**导出 `.pgame`**（当前 `.pmod` ＋ 当前 `.pp` 打包） |

### 2.2 素材绑定

- 支持拖入图片文件；按 [`../skin.md`](../skin.md) §二 的命名约定（`<元素>_<变体>.<ext>`）**自动匹配槽位**，未识别者进入「未绑定素材」暂存区。
- 绑定即写回 manifest 的对应字段，不复制文件内容（导出时按推荐约定写入 `resource/<节>/` 子目录，manifest 中记**相对包根**的完整路径——素材位置以描述文件为准，目录名不构成约束，裁决 19 / 22）。
- 绑定后立即在同一屏内显示**预览缩略图**与「原始尺寸 / 目标尺寸 / 是否成整倍数」。

### 2.3 九宫格切分工具（裁决 21）

针对 `.9.png` 的「黑边浏览器读不到」问题，Creative 提供**切分工具**：

| 步骤 | 行为 |
|---|---|
| 导入 | 取一张整图（`.9.png` 或普通图），显示原始像素尺寸 |
| 定线 | 拖出**四根参考线**（上 / 右 / 下 / 左），实时预览九宫格分区与四角、四边、中心各自的范围 |
| 写入 | 一键把 `slice: [上, 右, 下, 左]` 写回该素材所在的 manifest 字段 |
| 导出切片 | 可选：把九张切片另存为独立素材写进包内（便于人工核对或交给外部工具继续处理） |

- **不改变 V1 的渲染规则**：V1 仍按普通拉伸绘制（取舍 `S-1`）；本工具产出的是**参数与可选切片**，供 V1.1 的 `nine` 策略消费。
- 工具只做「按参考线切分」，不做抠图、改色、重绘（取舍 `S-16`）。

### 2.4 命中检查（本模式的核心价值）

加载一份 `.pmod` 作为靶子，遍历其地图与道路，输出三类清单：

| 类 | 含义 | 处置建议 |
|---|---|---|
| **已命中** | 该槽位有专用素材 | 无需动作 |
| **走通用** | 无专用素材，回退到通用素材（如 `misc.nodes.building`） | 提示可补专用图 |
| **程序绘制** | 无任何素材，仍用脚印／圆角矩形／emoji | **列为缺图清单**，并给出建议文件名 |

- 道路部分另提供 **flag 矩阵视图**：以 `16 × 16` 网格呈现 `256` 个组合（[`01-road.md`](01-road.md) §二 位序），每格显示其命中的姿态与素材；空格即为缺图位置，可直接在其中绑定素材。
- 清单与各分节的 `KR/KS/KW/KM/KIB/KPG` 校验项合并显示；**导出前提示但不阻断**（与 build 一致）。

### 2.5 预览

- 预览画布 = 被编辑的 `.pp` ＋ 靶子 `.pmod`，即「导出后 play 会看到的实际效果」。
- 提供「只看素材」（隐藏程序绘制）开关，用于快速发现漏配。
- 道路预览可切「按 flag 展示」与「按姿态展示」两种视图，后者用于确认旋转复用是否正确（[`01-road.md`](01-road.md) §四）。

## 三、存储与版本

- 编辑中的工程（manifest ＋ 素材引用）与 build 模式的项目同级存放于本地；素材本身以 blob 引用保存，导出时才打包。
- **打包/解包统一走 zip 库**（裁决 14：`fflate`）：打开 `.pp` / `.pgame` 为解包，导出为打包；不在本项目内自实现 deflate。
- **导入才入库**：用户通过「导入」动作加入的 `.pp` 进入本地皮肤库（包体进 IndexedDB，条目索引进 `localStorage`，裁决 15）；**导出产物不自动入库**，需要入库须再执行导入。
- 打开高版本 `manifest.format` 的包时：可识别字段照常编辑，保存时**不降级**该版本号（由用户决定是否回退版本，见 [`00-package.md`](00-package.md) §五）。

## 四、取舍登记

| 编号 | 取舍 | 后果 |
|---|---|---|
| S-16 | Creative 只做**绑定、切分与预览**，不内置其它图片编辑（裁剪构图、抠图、改色、生成 `.9.png` 黑边） | 素材仍须在外部工具完成，本模式不做美术生产（九宫格切分工具是唯一例外，裁决 21） |
| S-17 | 命中检查以**单一靶子 pmod** 为单位 | 跨多份 pmod 的通用性需逐个加载验证，不提供批量报告 |
| S-18 | Creative 自身 UI 不接管素材 | 编辑器观感固定为程序绘制手绘风 |
| S-27 | **字体不做子集化**（裁决 21）：包内字体原样打包 | 字库体积由作者负责，超大字体只提示不裁剪（校验项 `KA-4` 同族提示） |
