# PopRPG 设计文档 — skin 分节：画布背景 `background`

> **上层索引**：[`../skin.md`](../skin.md)（引用与复用、贴图渲染器接口）　**包结构**：[`00-package.md`](00-package.md)
> **设计依据**：原始需求「背景」配置节 ＋ 2026-09-29 裁决 3 / 8（采纳 `cellSize`；`{}` 升级为 `[{},{}]` 以适配多地图；道路贴图同基准）
> **状态**：新增（含 2 处待确认）

## 一、渲染目标

游玩态的地图是一块**连续画布**：背景图铺在底层，道路上叠贴图与标记。本节只定义**背景图与地图坐标的对齐关系**、**多地图的适配方式**，以及图片边界之外露出的填充色。

素材缺位时回退为程序绘制的纸面底纹（[`../skin.md`](../skin.md) §一）。

## 二、字段

`background` 是**数组**（裁决 8）：一张皮肤可携带多套背景，按 `maps` 命中当前地图的那一套生效。

```json
"background": [
  {
    "maps": ["cave_1", "cave_2"],
    "img": "bg/cave.jpg",
    "cellSize": 25,
    "startX": 200,
    "startY": 200,
    "color": "#000000"
  },
  {
    "img": "bg/plain.jpg",
    "cellSize": 25,
    "startX": 256,
    "startY": 256,
    "color": "#F2ECDD"
  }
]
```

| 字段 | 类型 | 含义 | 缺省 |
|---|---|---|---|
| `maps` | 字符串数组 | 本项**适用哪些地图**（地图 `id`）；**省略即适用全部地图**（兜底项） | 适用全部 |
| `img` | 字符串 | 背景图，路径相对 `resource/` | 无（本项降级为纸面底纹） |
| `cellSize` | 正整数 | **背景图上一个游戏格占多少像素**，把地图坐标换算到图片坐标；**同时也是道路等地图层素材的出图基准**（§3.1） | 无（缺省则不渲染背景图） |
| `startX` | 整数 | 图片上该点与地图格 `[0,0]` 的**中心**对齐（横向） | 无 |
| `startY` | 整数 | 同上（纵向） | 无 |
| `color` | 颜色 | **图片边界之外**的填充色，避免边缘穿帮 | 纸面底色（沿用主题） |

**取值规则**：数组**按顺序求值，取第一个 `maps` 命中的项**；顺序因而具有语义——无条件项应放在**最后**作为兜底。

> **边界约定**：本节的 `color` 是**画布级**（图片之外的填充），[`06-item-building.md`](06-item-building.md) 的 `background` 是**组件级**（图标／格子衬底）。两者同名但层级不同，**画布级保留 `color` 原名**（裁决 3 未采纳改为 `outsideColor`），组件级则升级为 `{ fill, stroke, img }` 三元组以示区别。

### 2.1 由 `{}` 升级为 `[{},{}]` 的兼容写法（裁决 8）

- 只写一个对象（`"background": { ... }`）时，视为**单元素数组**，等价于无条件兜底项。
- 单项**不带 `maps`** 时即「所有地图共用一张」——这覆盖了升级前的全部用法。
- 判定「多地图适配是否生效」的检查见 `KB-6`。

### 2.2 改名决议

| 原字段 | 决议 | 说明 |
|---|---|---|
| `dpi` | **采纳 `cellSize`** | 原字段实际语义是「每格像素数」，与 `dpi` 的通行含义（每英寸点数）无关 |
| `color` | **保留原名** | 见 §二 边界约定；组件级另用三元组区分 |

## 三、坐标映射（规范定义）

地图格坐标以 `[0,0]` 为原点、`col` 向右、`row` 向下，单位是**格**。

```
图片坐标点 (startX, startY)  ≡  地图格 [0,0] 的中心
格 [col, row] 的中心像素      =  (startX + col × cellSize, startY + row × cellSize)
地图像素原点（格 [0,0] 左上）  =  (startX − cellSize ÷ 2, startY − cellSize ÷ 2)
```

- 原始需求「采用中心对齐的方式」与「图片此位置与 [0,0] 对齐」两句互相冲突（既说中心对齐、又说指定点对齐）。裁决为：**指定的图片点 = 格 `[0,0]` 的中心**，统一为前式。
- **负格坐标合法**：`col < 0` 或 `row < 0` 的格子落在图片左上之外，按 `color` 填充。
- **缩放**：图片按 `屏幕每格像素 ÷ cellSize` 等比缩放后绘制（即 `cellSize` 个图片像素显示为 1 格）。`cellSize` 只影响清晰度与对齐，不改变格数语义。

### 3.1 与地图层素材的共同基准（裁决 3）

- **道路贴图与其它地图层素材的出图基准同样是 `cellSize`**，显示倍率同为 `屏幕每格像素 ÷ cellSize`，与背景图共用同一个坐标变换。
- 由此得到「素材与背景严格对齐、且缩放倍率一致（要么一起清晰、要么一起模糊）」的效果——这正是「道路贴图为了适配背景」的含义。
- **道路贴图不设背景色**：素材的透明区透出背景图，道路节不提供任何颜色／填充字段（[`01-road.md`](01-road.md) §五）。
- 若未配置背景（无 `cellSize`），地图层素材回退为按屏幕 `CELL` 出图（即纯屏幕像素基准）。

## 四、绘制顺序

```
① color 填充（画布全域，兜住图片之外）
② 背景图（按 §二 取首个命中项，按 §三 缩放与偏移放置）
③ 参照线 → 道路贴图 → 建筑节点 → 标记 → 角色
```

- 背景图**不套手绘滤镜**（[`04-misc.md`](04-misc.md) §六）。
- 背景图**不参与点击命中**（不作交互层）。

## 五、校验项（构建页／Creative 模式「清单」，提示不阻断导出）

| 编号 | 检查 | 提示 |
|---|---|---|
| KB-1 | `cellSize` 缺省或 ≤ 0 | 无法对齐，该项降级为纸面底纹 |
| KB-2 | `img` 路径在包内不存在 | 降级为纸面底纹 |
| KB-3 | `startX` / `startY` 落在图片之外 | 图片与地图完全错位，需重新标定 |
| KB-4 | 背景图覆盖不到整张地图 | 边缘将露出 `color` 填充色，提示可接受或补图 |
| KB-5 | 背景图分辨率低于 `地图格数 × cellSize` | 放大后模糊，提示提高分辨率 |
| KB-6 | 某张地图**没有任何项命中**（且无兜底项） | 该地图将无背景图，只剩纸面底纹 |
| KB-7 | 前面某项的 `maps` 完全覆盖了后面某项 | 后者永远不会生效，提示可能写错顺序 |

## 六、取舍登记

| 编号 | 取舍 | 后果 |
|---|---|---|
| S-7 | 每项背景仍是**单张整图**，不做分块 / 多分辨率切换 | 大地图需要超高分辨率单图，体积与内存随地图面积平方增长 |
| S-8 | 背景图跟随 `cellSize` 缩放，不提供「按屏幕像素」模式 | 换设备（不同 DPR）时清晰度变化，需美术按最大目标分辨率出图 |
| S-19 | 数组语义是**择一命中**，不是多层叠加 | 无法用「地形层 ＋ 光影层」两张图叠出背景 |

## 七、待确认

1. **数组是否需要「叠加」语义**：即同一地图是否允许两层背景（如地形层 ＋ 阴影层）。当前按**择一命中**撰写（取舍 `S-19`）。
2. **是否需要动画背景**：当前背景只有一张静态图，无视差 / 滚动 / 帧动画。
