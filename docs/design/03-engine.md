### 4.8 规则：前置配置 + 硬规则 + 每个场景的算法

> 这一节只回答一件事：**骰子在每个场景里到底怎么参与结算。**
>
> 分三层，边界必须清楚：
> 1. **硬规则**（§4.8.0）—— 玩法骨架，**写死在引擎里，不进配置，也不给开关**
> 2. **前置配置**（`## 规则配置`，完整清单见 §4.8.6）—— 每个场景**一套算法**，写进 `.pmod`
> 3. **内容**（组件上）—— 只有"池"和"数值"，不含算法
>
> **铁律：配置里出现的每一个字段，都必须是代码已经实现的。** 没有实现承诺的字段不许写进文档。

#### 4.8.0 硬规则（不应列入置）

| 硬规则 | 内容 |
|---|---|
| **移动机制** | 只能走**正交四邻**（上下左右）；**不可斜走**；**可原路返回** |
| **移动代价** | 每进一格的消耗**由踩进去的那一格组件决定**（道路 `cost`，默认 `{ step: 1 }`）。机制是硬的，"代价多少"是内容 |
| **通行权限** | 每格可要求标签（`gate`）；匹配靠 `capabilities = ⋃(穿戴中装备.tags) ∪ 当前职业.tags ∪ 身上状态.tags`（§4.5.2）。**标签是自由文本，引擎不认识任何具体的词** |
| **回合（世界心跳）** | **一回合 = 一次"推进时间"的行动**，只有两类：**① 一次交锋**（玩家攻击回合 ＋ 怪物反击回合）**② 一次移动**（掷骰得 N 步，**整次算一个回合**）。**所有按回合结算的东西（状态、地形 `cost`）都在回合【开始】先判定、再 tick 一次**（见下方"回合开始时序"）——这样玩家在任何回合开头都有操作空间（如中毒扣到 0 也能先吃药救活） |
| **为什么移动算整次** | 若"走一格 = 一回合"，摇到 6 就要 tick 6 次、摇到 1 只 tick 1 次——**摇 6 反而比摇 1 更不利**，掷骰就失去了意义。所以**一次移动 = 一个回合** |
| **道具不占回合** | **使用道具是"回合内的自由动作"，不推进时间、不 tick**。所以探索和战斗时使用药水都是随时可以——**这正是它比技能强的地方** |
| **技能占回合** | **玩家施放一次技能（交锋的攻击回合）＋ 怪物反击（交锋的反击回合）= 一次交锋 = 一个回合**。所以"治疗术"要花一回合，而"红瓶"不花——**道具即时但数值小，技能消耗回合但数值大**，两者的取舍就立住了 |
| **状态必有上限** | 任何状态都必须带 `duration`（剩余回合数），且**不得超过 `state.max_duration`**（§4.8.6）。**不存在永久状态**——没有解法的状态 = 死局（§4.8.10） |
| **技能决定维度** | 技能用 `dim` 指定"取哪一维属性"，用 `vs` 指定"对手拿哪一维对抗"（`auto` 时物理族对物理族、法术族对法术族）。**引擎不再写死"物攻→物防、魔攻→魔抗"**——那只是 `basic_attack` / `basic_magic` 两个**预设技能**的选择（§4.8.3） |
| **谁定技能** | **玩家侧：自己选**（从**自己学到的技能栏**里挑——技能栏靠后天学，§4.8.3）。**怪物侧：掷骰按权重随机**（否则玩家只提升单一维度就无敌） |
| **命中** | `target: opponent` 时 **本力值 ≥ 对方防值** 即命中；`target: self` 或 `vs: none` 时**不对抗、不落空** |
| **伤害 / 治疗** | 伤害 = **`max(1, 本力值 − 防值)`**；治疗 = **`本力值`**（不对抗，不乘算第二遍） |
| **属性点分配规则** | **1 点 = 该属性 +1**；可分配到 6 属性任意项；**任意时刻**都能加；**不可洗点**；**剩余自由点保留**。（**给多少点是职业设定，不是硬规则**，见 §4.2.1） |
| **属性来源** | **玩家 = 职业 `base_stats` ＋ 分配出的自由点**（确定值，不被骰子改）；**怪物 = `stats` 区间在登场时摇定**（§4.8.2 第一步） |
| **技能各有成本** | 选一个技能要先付它自己的 `cost`（如 `{ mp: 3 }`）；**不够就不能选**——不扣、不掷。**但两个保底技能 `cost` 为空 = 永远免费**（§4.8.3），所以**绝不存在"没蓝就陷入死局"** |
| **资源归零** | **玩家 `hp ≤ 0` → 不在伤害 / buff 作用时即时死，而是在"回合开始存活判定"才败北**（给一回合缓冲吃药）；**怪物 `hp ≤ 0` → 伤害作用时即时败北**（立场在主角的设计，死亡规则不对称，见 §4.8.3 交锋结构）。**`mp` 不够 → 只是放不了"贵技能"，保底对照样能打**（保底对免费时） |

- **移动机制 vs 移动代价**是两个层次：机制（四邻 / 不斜走 / 可回头）写死在引擎；代价是那一格**组件自己的属性**，
  所以"小路"和"沼泽"是两个不同的道路组件，而不是一个全局开关。
- **技能的两侧不对称是故意的**：玩家主动选 = 有取舍；怪物掷骰随机 = 逼玩家把物防 / 法防都堆起来。
- **属性来源的两侧不对称也是故意的**：玩家点数分配（可控、可规划）；怪物区间摇定（有波动、小怪精英自然拉开档）。
- **回合开始时序（硬规则，两步）**：每个回合【开始】先 `(1) 存活判定` 再 `(2) 状态 tick`，然后才进入本回合行动——
  - ① **存活判定**：玩家 `hp ≤ 0` → 败北；怪物 `hp ≤ 0` → 即时败北（不再参与本回合）。
  - ② **状态 tick**：对所有在场单位执行 `per_turn` 增减、`duration -= 1`（归零移除）。**本回合中刚挂上的状态不参与本次 tick，下回合开始才首次生效**。
  - 为什么先判血再算 buff：玩家 1 滴血、中毒每回合 `-1`——回合开始先判"1 > 0 存活"，再 tick 毒扣到 0，但本回合玩家仍存活、可吃药救活；若把判定放在 tick 之后就会当场暴毙，失去操作空间。
  - 移动回合也走同一套开始时序（移动时踩到的场景 buff / 身上 debuff 同样在开头结算），所以"统一移到开头"才公平。

- **回合是全篇唯一的时间轴**：交锋与移动都走同一条轴，所以"中毒 3 回合"在任何场景下都指
  **再过 3 次推进时间的行动**（走完 N 步算一次，一次交锋算一次），不需要为战斗和探索各定义一套计时（§4.8.10）。
- **"推进时间"和"自由动作"的区别只此一条**：**占回合的**（移动 / 技能）会 tick 状态、会吃到地形的每格 `cost`；
  **不占回合的**（用道具）不会。**没有第三种。**

> 这些是玩法骨架，**不给配置项**。想改就是改玩法，不是改某张地图的配置。

#### 4.8.1 基础积木（三个纯函数，全篇复用）

**① `rollRange(range, dice)` —— 把骰点映射到区间**（取属性值 / 取件数 / 取份数）

```text
t     = (roll − diceMin) / (diceMax − diceMin)          # 归一化到 0 ~ 1
value = min + round( t × (max − min) )
其中  diceMin = count × 1 ,  diceMax = count × faces     # 1D6 → 1..6 · 2D6 → 2..12
```

- `min === max` → 直接取该值，不掷骰。
- 例：`patk: [3, 6]` + `1D6` → 掷 1 → 3，掷 3 → 4，掷 6 → 6。

**② `rollSteps(steps, dice)` —— 骰点查档位表，得到倍率**

```text
idx  = round( (roll − diceMin) / (diceMax − diceMin) × (steps.length − 1) )
mult = steps[idx]
```

例：`steps: [0.5, 1, 1, 1.5, 2, 3]` + `1D6`

| 掷出 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 倍率 | 0.5× | 1× | 1× | 1.5× | 2× | 3× |

**③ `rollSum(dice)` —— 骰子点数直接相加**（作力值的叠加项）

```text
add = 各骰点数之和        # 1D4 → 1..4 · 2D4 → 2..8
```

#### 4.8.2 属性结算 + 力值合成链

**第一步：属性结算（每个单位只做一次）**

**两边不一样，这是故意的**（§4.0.2）：

```text
怪物：登场时（遭遇开始）把 stats 区间摇成具体值
      statValue[k] = rollRange(单位.stats[k], stat_dice)
                        # k ∈ hp / mp / patk / matk / pdef / mdef
                        # stat_dice 来自前置配置（如 1D6）

玩家：职业给了起点，其余靠分配，全程不摇
      statValue[k] = 职业.base_stats[k] + 已经加到这一项上的自由点
```

- 玩家侧的属性**随时可能因为加点而变**（加点不可逆、可发生在任意时刻），但它**永远不是骰子决定的**。

- 例：哥布林 `patk: [2, 4]` + `1D6` → 掷 1~2 → `patk = 2`，掷 5~6 → `patk = 4`；
  **这只哥布林这一场就固定是那个数**。
- `hp` / `mp` 也这样摇定，作为**当前值 = 上限**。
- **"摇骰子摇出它的属性"只发生在这里**，一次摇定、本次遭遇内不再重摇。
- 玩家侧之所以不摇：玩家的属性是他自己一点一点分出来的，**不能被骰子改掉**（§4.2.1）。

**第二步：力值链（每次判定时）**

**攻值和防值都走同一条链**，只是取的属性维不同：

```text
① 属性值     stat  = 已结算的具体值（上一步得到的，这里不再掷骰）
② 加值       plus  = Σ装备.modifiers[维] + Σ状态.modifiers[维] + 技能.bonus   ← 加法
③ 职业加成   prof  = 职业.buffs[维] / 100                                    ← 乘法，默认 100 → ×1
④ 基础力值   base  = (stat + plus) × prof
⑤ 骰子叠加   add   = rollSum(add_dice)                                       ← 可省；省略 = 0
⑥ 骰子倍率   mult  = rollSteps(mult_dice)                                    ← 可省；省略 = 1
──────────────────────────────────────────────────────────────
   力值 = floor( (base + add) × mult )
```

**五类来源各占一环，谁也不能顶替谁：**

| 环 | 来源 | 形态 | 玩家 | 怪物 |
|---|---|---|---|---|
| ① 属性 | 已结算的属性值 | 具体数字 | **`base_stats` ＋ 分配点** | **`stats` 区间摇出来的** |
| ② 加值 | 装备 `modifiers` ＋ 状态 `modifiers` ＋ **技能 `bonus`** | **固定加值** | 铁剑 `patk +5`；力量祝福 `patk +2`；重击技能 `bonus: 3` | 0（怪物不穿装备、不挂增益） |
| ③ 职业 | 单位的 `buffs` | **百分比** | 法师 `matk: 130` | 1（怪物没职业） |
| ④ 骰子 | 前置配置的 `add_dice` / `mult` | 叠加 / 倍率 | `1D4` / `1D6` 查表 | 同左（可用 `atk_roll` 覆盖） |

> **注意 ① 是"已结算的值"而不是"再摇一次"**：属性一旦定下来就固定了，
> 每次判定重摇会让 `hp` 之类失去意义。战斗中的随机性来自 ⑤⑥ 两枚骰。

- **② 是"加法环"——三样东西都往这里塞**：装备（长期）、状态（限时）、技能（本次施放的加成）。
  **"0 加成的普通攻击"就是 ② 里技能那一项为 0**（§4.8.3）——它能攻击对手，全靠 ① 的属性值。
- **加法和乘法位置不同，不能互换。** 这就是"装备 / 状态 / 技能 / 职业都要吃进去"的落点。
- **骰子在链上可插两处**：**⑤ 加法（叠加到力值上）** 与 **⑥ 乘法（力值倍率）**——
  即"骰子可以拿来做攻击力或者防御力的叠加，也可以算作倍速"。
- **无骰时骰子项取"中性值"**：不掷骰则 ⑤ 加法 = `0`、⑥ 乘法 = `1`——也就是只用**固有数值**（属性值 ① ＋ 装备 ② ＋ 职业% ③ ＋ 状态 mod ④）。
  这正是"玩家反击回合不点击防御"的落点：不防御 ≠ 防值为 0，而是**少了骰子的浮动，仍按身上固有数值计算**（固有部分不受主观动作改变）。
- **怪物**没有装备和职业 → ② = 0、③ = 1，只走 ①④⑤⑥；**玩家**没穿装备 → ② = 0，没选职业 → ③ = 1。
- **取哪一维、和谁对抗，由技能决定**（`skill.dim` / `skill.vs`，§4.8.3）——力值链本身不关心维度的含义。

#### 4.8.3 技能：取哪一维属性、打哪个对象

> **技能不是新机制，它是力值链的一次"参数化调用"。** 一个技能只回答三件事：
> **① 用哪一维属性当基准（`dim`）② 作用到谁（`target`）③ 附带什么（`effects`）**。
> **攻击、治疗、增益、诅咒全是这三种选择的组合——不是四套代码。**

**保底对：两个 0 加成的基础技能（一切的参照系，且永远免费）**

| 技能 | `dim` | `target` | `bonus` | `cost` | 含义 |
|---|---|---|---|---|---|
| **普通攻击** | `patk` | `opponent` | `0` | **空** | **纯粹依靠物攻属性攻击对手**，技能本身不提供额外加值 |
| **普通法术** | `matk` | `opponent` | `0` | **空** | **纯粹依靠魔攻属性攻击对手**，技能本身不提供额外加值 |

> **这两个是"保底对"，是我们预设模板按理想化设计给所有职业的兜底技能，且都免费**（§4.8.3 保底规则）：
> - **只给物理** → 敌人法抗低你也没辙，一个维度打到底
> - **若把"普通法术"也设成要花 `mp`** → **`mp` 花完就只能靠 `basic_attack`**，
>   但只要保底对（`basic_attack` + `basic_magic`）的 `cost` 保持为空，就**永远有免费技能可打**，不会陷入死局
>
> 所以（**默认模板角色**）：**开局技能栏 = `[basic_attack, basic_magic]`，两个 `cost` 都是空**——
> "无技能可用"和"没蓝陷入死局"这两种死局同时被堵死。
> **这是给"模板 / 内建角色"的默认安全网**：自创角色或作者可以在游戏设计里移除保底对（或改其 `cost`），
> 不阻止——删了 / 改了之后两边（玩家技能栏、怪物回退）都可能失去攻击手段，是否出现死局由作者负责，这是玩法的一部分。
>
> **免费 ≠ 无差别**：两者差别在 **`dim`**（用哪一维属性）——对法师来说 `matk` 高，
> 对战士来说 `patk` 高，**先天的百分比差异照样起作用**（§4.2.3）。
> **有成本的技能是"更强"，不是"能不能打"**（花 `mp` 买的是 `bonus` / `effects` / 倍率）。

**技能的全部字段**

```yaml
- id: basic_attack
  name: 普通攻击
  icon: ⚔️
  dim: patk              # ① 基准维度：力值链取哪一维属性（这就是"技能表示维度"）
  target: opponent       # ② 作用对象：opponent（攻击对手）| self（对己）
  vs: auto               # ③ 对手用哪一维对抗：auto = 按 dim 自动配对 | none = 不对抗，直接生效 | 具体维
  bonus: 0               # ④ 技能自身加值（"0 加成" = 纯粹依靠属性，技能只是个载体）
  apply: hp              # ⑤ 力值作用到哪：hp（伤 / 治）| mp | none（只挂效果）
  cost: {}               # ⑥ 施放成本（默认免费；**保底对必须留空**）
  effects: []            # ⑦ 附带效果：挂 buff / debuff（§4.8.10，与消耗品同一套）

- id: basic_magic
  name: 普通法术
  icon: ✨
  dim: matk              # ← 与普通攻击的唯一结构差别：换一维
  target: opponent
  vs: auto               # matk → mdef
  bonus: 0
  apply: hp
  cost: {}               # ← **一样是空的**：没 mp 也能放，不会陷入死局
```

**`auto` 的配对规则（硬规则，不给配置）**

```text
dim = patk / pdef  →  vs = pdef / patk      物理族对物理族
dim = matk / mdef  →  vs = mdef / matk      法术族对法术族
```

**"自然演化"——同一套字段，七种技能**

| 想要什么 | `dim` | `target` | `vs` | `apply` | `effects` | 力值链怎么走 |
|---|---|---|---|---|---|---|
| **物理攻击** | `patk` | `opponent` | `auto`→`pdef` | `hp` | — | 与对手 `pdef` 对抗 |
| **法术攻击** | `matk` | `opponent` | `auto`→`mdef` | `hp` | — | 与对手 `mdef` 对抗；**是否付 `mp` 由该技能自己的 `cost` 决定**（保底对 `basic_magic` 的 `cost` 设为空，故免费） |
| **治疗自己** | `matk` | **`self`** | `none` | `hp` | — | **不对抗、不落空**，回血量 = 力值 |
| **对自己上增益** | `patk` | **`self`** | `none` | `none` | `add_tag: 力量` | 不对抗，只挂状态 |
| **对对手上减益** | `matk` | `opponent` | `auto` | `none` | `add_tag: 虚弱` | **命中才挂，不中不挂** |
| **吸血 / 毒击** | `patk` | `opponent` | `auto` | `hp` | `add_tag: 中毒` | 打中 + 附带状态 |
| **回蓝** | `matk` | `self` | `none` | `mp` | — | 回自己 `mp`（**`cost` 由作者定，可含 `mp`——例如花 1 回 5，净赚；自由度交给制作者**） |

> **这就是"允许挂 buff"**：`effects` 用的就是 §4.8.10 那套五个 `op`（`add_stat` / `add_tag` / `remove_tag` / `learn_skill` / `forget_skill`）——
> **消耗品、技能、事件三处共用全部五 `op`，怪物命中只用其中三种**（不可教 / 夺技能，见 §4.1），不另发明。
>
> 用户造一个新技能，就是**选一维 + 选个对象 + 加个效果**，编辑器不需要认识"火球术"这个词。

**谁会什么技能——职业不管这个，全靠后天**

> **铁律：职业不限定技能。** 角色是**先天**的（职业给属性起点与优劣百分比，§4.2.3），
> 但**长成什么样是玩家自己塑造的**——学什么技能，由**事件与环境**决定，不由出生决定。

| 谁 | 技能从哪来 |
|---|---|
| **玩家（默认模板）** | **后天学会的**。开局只有**保底对 `basic_attack` ＋ `basic_magic`**（内建，不算组件，是默认模板的安全网），其余全靠 `op: learn_skill`（§4.8.10）： |
| | · **技能书**——一件**普通消耗品**，`effects: [{ op: learn_skill, skill: fireball }]`。**开箱、事件、商店、战利品，凡能给道具的地方都能给技能** |
| | · **事件后果**（`on_success.effects`）——"石碑上传你一招""老人临终托付" |
| | · **怪物战利品**（`reward_pool` 里放一本技能书）——"打赢它，捡到它的功法" |
| **怪物** | **`attack_weights` 的键就是技能 id**（§4.1）——`{ basic_attack: 3, poison_bite: 1 }` |
| **保底对** | **默认模板角色**技能栏**包含 `basic_attack` ＋ `basic_magic`，两个 `cost` 都为空**（免费）——**既不会"无技能可用"，也不会"没蓝就陷入死局"**。**职业不给技能；保底对是给模板角色的默认安全网，作者可在设计里移除或改 `cost`（自创角色不受影响）**——但移除后要保证角色仍有可打的技能 |
| **失去** | `op: forget_skill` 能**夺走**技能——**环境和运气不好，真的会把你的本事拿走** |

> **零新增通道**：因为技能书就是道具，**所有现有"给东西"的机制自动都能给技能**——
> 奖励池（§4.8.5）、事件后果（§4.8.9）、商店（§4.8.11）、战利品，一个都不用改。

**"法师练成战士"是被允许的，而且取舍真实可见：**

```text
起点（先天）    法师：patk 0，职业 patk 百分比 ×0.8      ← 物理天生按 ×0.8 计算
后天（自己的）  属性点全部分配给 patk  →  在废墟里捡到《盾击》 →  又把铁剑抢到手
结果            他确实能发动物理攻击了，但永远承受那个 ×0.8 的折扣
```

> **这就是"带着先天减益成长"**：职业的 `buffs` 百分比是**先天的属性配置**（§4.2.3），
> **它不会因为你努力就消失**。玩家的乐趣正是**用后天的选择去对抗先天获得的配置**——
> 出一个"靠后天硬拗成战士的法师"，比出一个"按模板长的法师"有意思得多。

**"已学会哪些技能"是游玩态数据，不进 `.pmod`：**

| 数据 | 存在哪 | 说明 |
|---|---|---|
| 技能**定义** | **组件库 / `.pmod` 的 `## 设定`** | 这一局**世界里存在**这个技能（可被学、被怪物用、被写成书） |
| "谁**已学会**它" | **`.psave`** | 玩家技能栏是进度，不是场景（§7.3） |

> **技能的"启用"= 这一局世界里有没有这招**，不是"谁会"。
> 未启用的技能：不能被学、不能被怪物用、写进技能书里也是死引用（§5.7 会标红）。

> **技能是组件库的第七类（§4.0），不是前置配置。**
> 它有名字、图标、维度、目标、效果，和道具 / 怪物一样需要 DIY 与管理，也该有"启用 / 未启用"。
> **因此前置配置里不再有 `combat.attacks`**（§4.8.6）——技能表已升级为组件。

**一次施放的结算（6 步）**

```text
① 选技能      玩家自己选 / 怪物掷 pick_dice 按 attack_weights 加权随机（见下）
② 查成本      不够 → 不能选（不扣、不掷）；够 → 扣掉
③ 算本力值    力值 = 力值链(施放者, atk_roll, skill.dim) + skill.bonus      ← §4.8.2
④ 判定分支
     target = self 或 vs = none  →  跳过判定，直接进 ⑤
     target = opponent           →  对手掷 防值 = 力值链(对手, def_roll, skill.vs)
                                    命中 = 本力值 ≥ 防值；**不命中 → 本次施放不造成作用、不挂 effects（⑤⑥ 不执行）**，
                                    但交锋仍进入对手的反击回合（见下）
⑤ 作用        apply = hp   → 伤：对手扣 max(1, 本力值 − 防值) / 治：自己回 本力值
              apply = mp   → 同上，作用在 mp 上
              apply = none → 跳过（纯 buff 技能）
⑥ 附带效果    逐个执行 effects（**只有命中才执行**）
```

**一次交锋 = 两个半回合（玩家攻 → 怪物反击），双方各掷骰，玩家攻 / 防都主动点击：**

```text
① 玩家攻击回合（玩家主动）
   - 玩家选技能 → 查 cost（不足不能选）
   - 玩家【点击"攻击"】→ 引擎掷 atk_roll（add_dice + mult）→ 本力值
   - 怪物由电脑掷 def_roll → 防值；判定 / 作用 / 挂 effects
       · 不命中 → 本次施放不生效，但交锋仍进入 ②（不终止）
       · 命中且把怪物打到 hp≤0 → 怪物即时败北（伤害作用时即死），交锋直接结束，不进入 ②（怪物不会"死后再反击"）

② 怪物反击回合（换防，电脑出手）
   - 怪物由电脑掷 pick_dice 按 attack_weights 选技能 → 查 cost
       · 选到的技能 cost 不足（如 mp 不够）→ 回退该怪物 attack_weights 中 cost 为空的技能，再无则本次反击跳过（若怪物根本没配 `attack_weights`，则用引擎内建 `basic_attack`——cost 为空、与玩家保底对组件无关，作者删组件不影响怪物兜底，见 §4.1）
   - 怪物由电脑掷 atk_roll → 本力值
   - 玩家【点击"防御"】（主动动作）→ 引擎掷 def_roll → 防值；判定 / 作用 / 挂 effects
       · 玩家**主动选"不防御"** → 不掷 def_roll，防值 = 固有数值（属性值＋装备＋职业%＋状态 mod，无骰浮动），仍按此计算

③ 整次交锋结束 → 无额外 tick（tick 已在回合开始做过一次，见 §4.8.0）
```

- **所有"电脑掷骰"（怪物 atk / def / pick）结果都必须在战斗 UI 公示**——玩家能看到怪物掷了什么、为什么这么打。
- **玩家攻 / 防都是主动点击，引擎会等待**：这是单人游戏，**除非特殊场景设计，否则没有倒计时**——玩家不点攻击 / 防御，回合就停在那等他，不会因"没操作"而超时跳过。
  - 点"防御" → 引擎掷 `def_roll` 获得骰浮动减伤；
  - 玩家**主动选择"不防御"** → 不掷 `def_roll`，防值走**固有数值**（属性值 ①＋装备 ②＋职业% ③＋状态 mod ④，无骰浮动）。**不是 0，只是少了骰子的浮动**。攻 / 防两个点击（或"不防御"抉择）构成一次交锋里玩家的主动操作。
- **怪物登场（每次遭遇实例化时摇一次，绝非每回合重摇）**：玩家每次踩到怪物格、生成出一只具体的怪物实例时，先掷"选怪骰"从 `monster_pool` 抽哪只，再用 `stat_dice` 把它的属性区间摇成具体值（波动、不锁死）。
  - **同一只怪物的整场战斗不再重摇**（我们反对的是"每回合都摇怪物属性"）；
  - **但不同遭遇各自独立摇**——场景 A 的哥布林摇过一次，场景 B 再遇到哥布林是另一只实例，**同样要重新随机**。不是"全局只摇一次"；
  - 属性浮动默认共用 `stat_dice`；进阶可给各属性分别配独立骰子（多个骰子分别摇各属性区间），都是"实例化时摇一次、整场不重摇"。

- **`target: self` 的技能不对抗、不会落空**，但**仍然掷骰**——因为骰子决定治疗量 / 加成量（力值链 ⑤⑥）。
- **伤害恒为 `max(1, 本力值 − 防值)`，治疗恒为 `本力值`**，两者都不再乘算第二遍。
- `mp` **不参与力值链**——它是"选这个技能的入场券"，不是攻防数值（§4.0.1）。

**谁能挑技能？—— 两侧故意不对称**

| 侧 | 怎么定 | 为什么 |
|---|---|---|
| **玩家** | **自己选**（从**自己学到的技能栏**里挑，§4.8.3） | 有取舍才有策略 |
| **怪物** | **掷骰按权重随机** | 若怪物会什么就固定用什么，玩家只要堆对应那一维防御就无敌了 |

**怪物的技能权重表**（写在怪物组件上，键 = 技能 id）：

```yaml
attack_weights:
  basic_attack: 3        # 权重 3
  poison_bite: 1         # 权重 1（一个自带 `中毒` 的 `effects` 的技能）
```

**选法（加权轮盘，复用 §4.8.1 的积木）**：

```text
① 掷 pick_dice → roll
② t = rollRange([1, Σ权重], pick_dice)                ← 把点数映射到 1..总权重
③ 按 attack_weights 的书写顺序累加，第一个让「累计权重 ≥ t」的技能被选中
```

- 只有一项（`{ basic_attack: 1 }`）时不必掷骰，直接用。
- 玩家侧若也想随机（AI / 懒惰模式），同一套选法即可，权重表挂在玩家身上。

**掷骰次数**：一次施放 = **2 组力值骰**（自己 1 组、对手 1 组）；
`target: self` 时只用 **1 组**；怪物还有多项技能时再加 **1 次 `pick_dice`**。

> **旧模型的对应关系**：`combat.attacks.phys` → 技能 `basic_attack`；
> `attacks.magic` → 技能 `basic_magic`；`attacks[x].cost` / `roll` → 技能自己的 `cost` / `roll`。
> **技能只是把"攻击方式"从配置里搬进了组件库，判定结构一点没变。**

#### 4.8.4 移动

```yaml
move:
  dice: 1D6            # 每回合掷这枚骰，点数就是本回合可走的格数
```

**配置就这一个字段。** 移动机制（正交四邻 / 不可斜走 / 可原路返回）是硬规则（§4.8.0）。

**每格的消耗与权限**都不在这里配——它们是**那一格上组件自己的属性**（道路 `cost` / `gate`，§4.5）。

**走一格的完整判定（3 步）**

```text
① 权限检查   capabilities = ⋃(穿戴中装备.tags) ∪ 当前职业.tags          ← §4.5.2
             这一格组件有 gate 吗？
               没有           → 直接过
               有且满足        → 过
               有且不满足      → missing: block   → 走不进去，这一步作废
                                 missing: penalty → 过，但要额外付 penalty
② 扣消耗     从本回合步数里扣 cost.step（默认 1）
             cost.hp → 扣血；cost.mp → 扣蓝
③ 结算该格   若该格是 building → ① NPC 触发（§4.8.12：**仅从建筑外踏入时**；重入先弹选择对话框）→
             ② 再按 encounter 触发（treasure → §4.8.5；monster → §4.8.3；
             event → §4.8.9；shop → §4.8.11；mimic 先按 chance 判定）
```

**回合流程**

1. 开局站在 `start`
2. 每回合掷 `move.dice` → 得本回合步数
3. 按上面 3 步走格（一次一格，只能走正交四邻）
4. 走到 `end` → 本张图通关，进入下一张图（起点自动接上一张终点）
5. 步数用完 → 回合结束

> **消耗 vs 权限是两个独立开关**：沼泽是纯消耗（走得慢），河流是硬权限（没船过不去），
> 火焰山是软权限（没火抗也能强行通过，但每格掉血）。三者组合出来的地形，用户自己造。

#### 4.8.5 开箱与战利品：池 + 抽取算法

**算法在前置配置里定**（`treasure` / `loot` 各一套），**池在组件上写**。

**① 池（写在建筑 / 怪物组件上）—— 三种池共用同一个结构**

```yaml
# 奖励池（宝箱 / 战利品）
reward_pool:
  source: ids                 # ids = 手选 | filter = 从整个组件库里筛
  ids: [{ id: red_potion, weight: 5 }, { id: iron_sword, weight: 1 }]
  filter:                     # source=filter 时生效
    itemKind: consumable      # 限定 消耗品 / 装备
    tags: [common]            # 限定标签

# 怪物池（怪物房用）：踩到就从池里抽一只出来打
monster_pool:
  source: filter              # 例如"全部洞穴怪"
  filter: { tags: [cave] }
```

- `source: ids` —— 池就是列出来的这几项（**只保留其中"已启用"的**）。**单只怪物就是一个元素的池**，不用再单独开一个"固定怪物"字段。
- `source: filter` —— 遍历组件库里**所有已启用**的对应类型，留下满足 `filter` 的。
  **上百来个道具 / 几十只怪物的大地图就靠这个**，不用手动一件件挑。
- 池里每项可带 `weight`：`{ id: goblin, weight: 3 }`；写纯 id 视为权重 1。**权重越大越容易被抽到。**
- 三个字段名固定：`reward_pool`（奖励）/ `monster_pool`（怪物），结构完全相同。

**② 抽取算法（写在前置配置里，`treasure` 与 `loot` 各一套）**

```yaml
treasure:                              # 开箱
  pick:
    algo: tiers                        # tiers = 骰点落档 | count = 掷骰映射到区间
    dice: 1D6
    tiers:
      - { upto: 2, n: 0 }              # 1~2 → 空箱
      - { upto: 4, n: 1 }
      - { upto: 6, n: 2 }
  copies:
    algo: multiplier                   # multiplier = 骰点查档 | value = 掷骰映射到区间 | fixed = 固定
    dice: 1D6
    steps: [1, 1, 1, 2, 2, 3]          # → 每件 1~3 份
```

**③ 完整算法（5 步，一步都不能省）**

```text
① 定池      source=ids    → ids 里"已启用"的那几件
            source=filter → 组件库里"已启用"且满足 filter 的全部道具
            |池| = 0 → 直接结束，产出为空（游玩态提示"这箱子是空的"）

② 定件数 n  掷 pick.dice → 从上往下找第一个 upto ≥ 点数的档 → n
            pick.algo=count 时改为 n = rollRange(range, dice)
            （该档可以写 0，就是空箱）

③ 夹紧      n = min(n, |池|)        ← 件数永远不会超过池的大小

④ 抽件      按 weight 加权、不放回，从池里抽 n 件

⑤ 定份数    每件掷 copies.dice：
              fixed      → n
              value      → rollRange(range, dice)
              multiplier → rollSteps(steps, dice)
            产出 = [{ itemId, count: 份数 }, ...]
```

**④ 为什么没有 `all`**

早期草案里有 `pick.algo: all`（池里全给）。**已删除**：
池一旦来自 `source: filter`（比如"全部消耗品"上百件），`all` 会把整个仓库全部给予玩家。

想要"全给"就把池写成显式 `ids`、`n` 给一个足够大的数——**反正第 ③ 步会把它夹到 `|池|`**。

**⑤ 战利品与开箱的关系**

- **算法内核完全相同**（同一套 `pick` + `copies`），但**两套独立配置**：
  `treasure`（踩到建筑触发）与 `loot`（战斗胜利触发）。
- 分开的理由：开箱可以"开出空箱"，战利品一般不会；两者档位也往往不一样。
- **空箱 ＋ NPC ＝ 不空**：`treasure` 建筑**没配池（或抽到 0 件）但配了 NPC** → 进入时**不再提示"什么也没有 / 已经空了"**——**NPC 就是它的内容物**，玩家看到的是一次对话（§4.8.12；[`07-decisions.md`](07-decisions.md) §8.3 设定 4）。
- **组件可覆盖**：建筑 / 怪物上写自己的 `pick` / `copies`（§4.8.7），不写就用对应场景的前置配置。

**⑥ 怪物池怎么抽（怪物房用）**

怪物房不写死一只怪。踩到时走**同一套加权抽取原语**，只是抽取数量固定为 1：

```text
① 定池      monster_pool（ids 手选 / filter 筛全库，只留已启用怪物）
            |池| = 0 → 空房间，不触发战斗
② 掷骰      t = rollRange([1, Σ权重], combat.pick_dice)      ← 复用 §4.8.1① 与 §4.8.3 的加权轮盘
③ 选出      按书写顺序累加权重，第一个「累计权重 ≥ t」的那只被选中
④ 属性结算  对选中的怪掷 stat_dice 摇出 6 属性具体值（§4.8.2 第一步）
⑤ 开打      §4.8.3
```

- **"摇骰子随机选怪 → 摇骰子摇出它的属性"两步都在这里**，一次遭遇各摇一次。
- 想让怪物房固定出哥布林 → 池里只放哥布林（`ids: [goblin]`），第 ② 步只有一个候选，等价于不掷。

#### 4.8.6 前置配置完整清单（`.pmod` 的 `## 规则配置`）

**这就是全部，一个不多：**

```yaml
## 规则配置
move:
  dice: 1D6                      # 每回合掷骰定步数（每格的消耗与权限看那格道路的 cost / gate）
combat:
  # 没有 attacks —— "攻击方式"已升级为**技能组件**（见 `## 设定 → 技能`，§4.8.3）
  stat_dice: 1D6                 # 属性结算骰：怪物登场时把区间摇成具体值（一次摇定）
  pick_dice: 1D6                 # 怪物随机挑技能时掷的骰
  atk_roll:                      # 攻方力值链上的骰子
    add_dice: 1D4                # 可省
    mult:                        # 可省
      dice: 1D6
      steps: [0.5, 1, 1, 1.5, 2, 3]
  def_roll:                      # 守方力值链上的骰子
    add_dice: 1D4
treasure:                        # 开箱算法
  pick:   { algo: tiers, dice: 1D6, tiers: [{ upto: 2, n: 0 }, { upto: 4, n: 1 }, { upto: 6, n: 2 }] }
  copies: { algo: multiplier, dice: 1D6, steps: [1, 1, 1, 2, 2, 3] }
loot:                            # 战利品算法
  pick:   { algo: count, dice: 1D6, range: [1, 2] }
  copies: { algo: fixed, n: 1 }
state:                           # 状态上限（§4.8.10）
  max_duration: 10               # 任何状态的 duration 都会被夹到不超过这个值
shop:                            # 商店默认定价（§4.8.11）；组件可用自己的 price 覆盖
  price: { algo: value, dice: 1D6, range: [5, 15] }
event:                           # 事件默认判定（§4.8.9）；组件可用自己的 check 覆盖
  dice: 2D6                      # 只提供默认骰，目标值在事件组件上（那是内容）
talk:                            # 建筑内 NPC 对话（§4.9.3）；选人 / 选方案两次抽取都用它
  dice: 1D6                      # 多选一 NPC ／ 多套对话方案时掷的骰；掷定后本局锁定不变
                                 # 注意：对话「节点内」的选项抽取骰（节点 dice ＋ hit）是内容，不在这里（§4.9.2）
class_pool: [knight, mage]
```

**删掉了哪些字段，以及为什么**

| 删掉的字段 | 原因 |
|---|---|
| `move.mode` / `steps` / `free` | 移动只有"掷骰定步数"一种形态，其它是另行增设的选项 |
| `move.allow_back` / `diagonal` | **本来就是硬规则**（§4.8.0），写死。给了开关就是在问"用户把 `diagonal` 设成 `true`，代码是否实现" |
| `move.cost`（全局每格代价） | 每格代价是**那一格组件自己的属性**（`Road.cost`），属于内容，不是全局配置；全局配一个就等于所有路一个样 |
| `dice.available` / `dice.default` | **全局兜底骰**是隐式默认，删掉——每个场景算法**自己带骰子**（`move.dice` / `event.dice` / `talk.dice` / `treasure.pick.dice` …），下拉候选是 UI 的事，不进文件 |
| `hit.success` | 命中恒为"`本力值 ≥ 对方防值`"（`target: opponent` 时） |
| `damage.algo`（`diff` / `subtract` / `multiply`） | 收敛成**一条力值链**（§4.8.2）：骰子插在链的 ⑤加法 与 ⑥乘法 两处，伤害恒为 `max(1, 攻值 − 防值)` |
| `pick.algo: all` | 会倒仓库（§4.8.5 ④） |
| `crit` / 大成功大失败 | **没有实现就不应列入** |
| `monster_ref`（单只） | 换成 `monster_pool`（池 + 权重 + 掷骰抽），**单只 = 单元素池**，不必开两个字段 |

**又加回来了什么（以及为什么）：**

| 加回的字段 | 原因 |
|---|---|
| `event`（事件默认判定） | 上一版以"没实现"为由删掉了 `static` 判定，结果**撬锁 / 陷阱 / 谜题 / 抉择整类玩法做不了**（§4.8.9）。行为种类从 3 种（空 / 给东西 / 打架）扩到 5 种（＋事件 / 商店） |
| `state.max_duration` | 状态必须有上限，否则没有解法就是死局（§4.8.10） |
| `shop`（默认定价） | "卖多少"必须有个全局兜底，否则每个商店都要自己写价格（§4.8.11） |

**配置项总账**：`move` ×1　`combat` ×4（`stat_dice` / `pick_dice` / `atk_roll` / `def_roll`）　`treasure` ×2　`loot` ×2　`state` ×1　`shop` ×1　`event` ×1　`talk` ×1　`class_pool` ×1 —— **共 14 项**。

> **技能不在这一章**：它已升级为**组件库的第七类**（§4.0），因为它有名字、图标、维度、目标、效果，
> 需要 DIY 与管理，也该能"启用 / 未启用"。前置配置只留**力值链的骰子**（`atk_roll` / `def_roll`）与**属性结算骰**。

> **注意 `class_pool` 只是"用哪些职业"，"给多少点"在职业自己身上**（`base_stats` / `free_points`，§4.2.3）——
> 那是**内容**，不是前置配置。所以"开局 300 点"不会混入该清单。

#### 4.8.7 组件可以覆盖什么（+ 组件自己的差异化字段）

**能覆盖前置配置的：**

| 组件 | 能覆盖 | 不能覆盖 |
|---|---|---|
| **怪物** | `atk_roll` / `def_roll`（力值骰）、`stat_dice`、`reward_pool`、`pick` / `copies`、**它自己的技能表 `attack_weights`** | 命中判定、伤害公式（**技能只改"取哪一维、攻击目标"，改不了这两条**） |
| **建筑** | `reward_pool`、`monster_pool`、`pick` / `copies`、**`event.check`**（事件判定骰）、**`price`**（定价）、`stock`（上架池） | 同上 |
| **职业** | —（`base_stats` 是起点、`buffs` 自动进力值链 ③、`tags` 进能力集合、`inventory_size` 定背包、`starting_items` 给家当。**职业完全不碰技能——技能是后天的**） | — |
| **装备** | —（`modifiers` 自动进力值链 ②） | — |
| **道路** | —（**它本来就是内容**：`cost` / `gate`，§4.5） | — |
| **消耗品** | —（`effects` 是内容：改数值 / 挂状态 / 解状态，§4.8.10） | — |
| **技能** | —（`dim` / `target` / `vs` / `bonus` / `apply` / `effects` **全是它自己的内容**，§4.8.3） | 命中判定、伤害公式 |

**各组件自己的差异化字段（这就是每个分组"为什么值得单列"的答案）：**

| 组件 | 差异化字段 | 差异举例 |
|---|---|---|
| **道路** | `cost`（消耗）+ `gate`（权限） | 沼泽（慢）/ 河流（没船过不去）/ 火焰山（没火抗掉血） |
| **建筑** | `cost` + `gate` + `encounter` + `event` + `reward_pool` / `monster_pool` / `stock` + `mimic` | 宝箱屋 / 怪物房 / **事件（上锁的门、陷阱、抉择）** / **商店** / 有宝箱怪物的屋子 |
| **怪物** | `stats`（6 属性区间）+ `attack_weights`（会哪些技能）+ `effects`（命中施状态）+ `reward_pool` + `point_reward` | 小怪（低区间、给 1 点）/ 精英（高区间 + `tags:[精英]`、给 5 点）/ **毒牙哥布林（会 `poison_bite`，打中你 → 中毒）** |
| **技能** | **`dim`（取哪一维）+ `target`（攻击目标）+ `vs`（对手拿哪一维防）+ `bonus`（加值）+ `apply`（作用到 hp/mp/无）+ `effects`（挂啥）** | **普通攻击（0 加成）/ 治疗术（`target: self`）/ 力量祝福（`apply: none` + `modifiers`）/ 虚弱诅咒（`target: opponent` + 减益）/ 吸血（伤害 + 挂状态）** |
| **装备** | `slots` + `modifiers` + `tags` | 铁剑（物攻 +5）/ 火抗鞋（`tags:[火抗]`）/ 小船（`tags:[渡河]`，但占手） |
| **消耗品** | `usable` + `effects` | 红瓶（回 `hp`）/ 蓝瓶（回 `mp`）/ 解毒剂（`remove_tag`）/ 御火符（临时 `火抗`） |
| **职业** | `base_stats` + `free_points` + `buffs`（百分比）+ `tags` + `inventory_size` + `starting_items` | 骑士（`patk:120`，物理向）/ 法师（`matk:130` 且 `patk:80`——**物理攻击终生按 ×0.8 计算**）。**职业没有 `skills`**（§4.2.3） |

- 不覆盖时一律用前置配置里对应场景的那一套（`combat` 的骰子 / `treasure` / `loot` / `event` / `shop`）。
- 例："这只 BOSS 攻骰 2D6、防骰 1D4" = 在怪物上写 `atk_roll` / `def_roll`；
  "这个宝箱只出手选的那几件" = 在建筑上写 `reward_pool.source: ids`；
  "这只怪会普通攻击也会下毒" = 在怪物上写 `attack_weights: { basic_attack: 3, poison_bite: 1 }`。

#### 4.8.8 属性点产出 `point_reward`（"打完怪能加点"）

**这就是"后续战斗也会得到属性点"的落点**——玩家变强的主渠道。

```yaml
# 怪物组件（也可以写在建筑上）
- id: goblin
  # ……
  point_reward: 1        # 打赢给 1 点自由属性点

- id: goblin_king
  tags: [精英]
  # ……
  point_reward: 5        # 精英给 5 点
```

| 项 | 规则 |
|---|---|
| **字段** | `point_reward`（整数，默认 `0`） |
| **挂在哪** | **怪物和建筑的公共可选字段**（打怪、开箱都可能给点），和 `cost` / `gate` 同级 |
| **触发时机** | 战斗胜利 / 开箱结算时 |
| **给到哪** | **直接加进玩家的"剩余自由点"**，玩家随后在任何时候分配（§4.2.2） |
| **掷骰吗** | **不掷**。它是固定值 |

**为什么固定不掷骰**：`point_reward` 是**这一局的节奏设计**（打多久能变多强），
不是"这一次运气如何"。想要不同强度，就设不同档位的怪物给不同点数——
**小怪 1 点 / 精英 5 点**，靠内容拉开，别靠骰子。

> 和 `cost` / `gate` 一样：它是**内容**（组件自己的属性），不是前置配置（§4.8.6 清单里没有它）。

#### 4.8.9 事件判定：门槛 + 手艺（撬锁 / 陷阱 / 谜题 / 抉择）

> **为什么要有这一节**：建筑原来只有 `empty / treasure / monster` 三种行为，"给东西"和"打一架"。
> 石碑、上锁的门、陷阱、商人、剧情抉择全都造不出来。本节补上行为 `event`，
> 并**把 `static` 判定加回判定体系**（§4.8.6 里曾被删掉的那条）。

**事件 = 两层，各自独立：**

| 层 | 字段 | 作用 | 回答的问题 |
|---|---|---|---|
| **① 门槛** | `gate` | **资格**：没带对应标签，连"尝试"的选项都不给 | "你**能不能**碰这件事" |
| **② 判定** | `check` | **手艺**：掷骰 + 加值 vs 固定难度 | "你**做不做得成**" |

**两层都可以单独省。** 只写 `gate` = "有钥匙就能开"；只写 `check` = "谁都能试，看手艺"；
两个都写 = "得先有钥匙，然后还得看手艺"；**两个都不写 = 这就是个纯叙事块**（读一段文本）。

```yaml
- id: stone_door
  name: 上锁的石门
  icon: 🚪
  encounter: event
  event:
    text: 一扇刻着古文字的石门挡住了去路。
    gate:                                  # ① 门槛（可选）
      tags: [撬锁]
      mode: all                            # all = 全都要 | any = 有一个就行
      on_missing: blocked                  # blocked = 不给选项 | penalty = 允许强行尝试，但吃惩罚
    check:                                 # ② 判定（可选；不写 = 过了门槛就必成）
      dice: 2D6
      add: patk                            # 复用哪一维当"手艺"
      target: 15                           # 固定难度（static）
    on_success:
      text: 锁芯"咔"地一声弹开了。
      point_reward: 2
      grant: [{ id: red_potion, count: 1 }]
    on_fail:
      text: 门缝里弹出一排铁针。
      cost: { hp: 3 }
      effects: [{ op: add_tag, tag: 扎伤, duration: 3, per_turn: { hp: -1 } }]
    once: false                            # true = 成功后就变成 empty（门开了就不再是门）
```

**② 判定复用力值链（§4.8.2）——这就是"努力缩小范围"的落点：**

```text
手艺值 = floor( ( (属性[check.add] + 装备加值) × 职业百分比 ＋ rollSum(check.dice) ) × 骰子倍率 )
成功   = 手艺值 ≥ check.target
```

- 走的还是那条链的 **① 属性 → ② 装备 → ③ 职业 → ⑤ 骰子叠加 → ⑥ 骰子倍率**，
  只是这里比的是**固定值**而不是对方的防值。
- **所以提高属性 / 换更好的装备 / 换更对口的职业，都是在提高成功率**——玩家靠经营来压缩运气成分。

**必成 / 必败区间（必须让设计者看见）：**

```text
手艺下限 = 力值(骰子取最小点)      手艺上限 = 力值(骰子取最大点)
必成：手艺下限 ≥ target          必败：手艺上限 <  target
```

例：`target: 15`、`dice: 2D6`（2~12）、加值 5

| 加值 | 需要掷出 | 2D6 命中率 | 状态 |
|---|---|---|---|
| 5 | ≥ 10 | 3/36 ≈ **8%** | 基本靠脸 |
| 8 | ≥ 7 | 21/36 ≈ **58%** | 值得一赌 |
| 13 | ≥ 2 | 36/36 = **100%** | **必成** |

→ **加值够高就必成，加值太低就必败。** 编辑器把这两个区间标出来（§5.7）：
必成时提示"这个判定对当前配置是必然成功的"，必败时提示"现在做这个纯属徒劳，先去提升属性"。
**"投骰子浪费时间"的问题就是靠这个提示解决的**——它把"运气"变成了"经营"。

**后果块 `on_success` / `on_fail` 能做什么**（全部复用已有词汇，不发明新机制）：

| 键 | 作用 |
|---|---|
| `text` | 展示文本 |
| `cost` | 扣资源 `{ hp, mp }`（和道路 `cost` 同形） |
| `point_reward` | 给自由属性点（§4.8.8） |
| `grant` | 给道具 `[{ id, count }]` |
| `effects` | 挂 / 解状态（§4.8.10） |
| `goto` | 传送到某张图的某格（P1） |

- **`on_missing` 两种语义**：`blocked`（干脆不给选项，玩家绕路）/ `penalty`（可以强行尝试，但走 `on_fail` 分支）。
  后者就是"没有撬锁工具就强行破门，多半受伤"。
- **`once`**：成功后把该节点降级为 `empty`，避免反复刷同一个事件。

#### 4.8.10 状态与持续效果（中毒 / 护盾 / 临时通行）

**状态就是一个挂在**单位**身上的标签 + 剩余回合数**——不发明第二套机制，直接复用 `tags`。

```text
状态 = {
  tag: string,                        # 语义，同时作为"临时能力"进 capabilities
  duration: int,                      # 剩余回合数，必填
  per_turn?: Record<StatKey, number>, # 每回合结算的增减（待续 / 回复）
  modifiers?: Record<StatKey, number>, # 持续期间对 6 属性的加值（进力值链 ②）
  source: id                          # 谁挂的（道具 / 技能 / 怪物 / 事件）
}
```

| 项 | 规则 |
|---|---|
| **结算时机** | **每回合【开始】先判存活、再 tick 一次**（见 §4.8.0"回合开始时序"）。回合 = **一次交锋** 或 **一次移动（走完全部步数才算）**。tick 已前置到回合开头，所以回合结束不再 tick |
| **`duration`** | **必填**。剩余回合数每次 tick 减 1，归零自动移除。**本回合中刚挂上的状态，要到下回合开始才首次 tick**（不会当回合就扣） |
| **硬上限** | 任何 `duration` **不得超过 `state.max_duration`**（§4.8.6，默认 10）。**没有永久状态** |
| **`per_turn`** | 可省。每回合对 `hp` / `mp` 结算一次增减（中毒 `hp: -1`、再生 `hp: +1`） |
| **`modifiers`** | 可省。**持续期间对 6 个属性加值**，直接进力值链的 **② 加法环**（§4.8.2）——**这就是"力量祝福 +2 物攻""虚弱 -2 物攻"的落点** |
| **进不进能力集合** | **进**。状态 tag 与装备 `tags`、职业 `tags` **并列**进 `capabilities`（§4.5.2） |
| **来源** | **消耗品 / 技能 / 事件三处共用全部五 `op`**；**怪物命中 与 地形 `gate.penalty` 只用 `add_stat` / `add_tag` / `remove_tag` 三种**（不可教 / 夺技能——地形不能教玩家技能，怪物也不能，见 §4.1） |
| **与"学会技能"的区别** | 状态是**限时的**（必带 `duration`）；学会技能是**永久的**（`learn_skill`，只能靠 `forget_skill` 拿走）——**两者不是一回事，别混** |

**状态 tag 进能力集合 —— 这一条让"临时通行"成立：**

- 负面："中毒（5 回合，每回合 -1 hp）"
- 正面："**御火符 → `火抗` 3 回合**" —— 遇到火焰山时临时使用一张，就过去了。
- 所以**同一套 `tags` 既是永久能力（装备）也是临时能力（状态）**，编辑器不需要区分。

**`effects` 的五个 `op`（§4.3 道具 / 技能 / 事件三处共用全部五 `op`；怪物命中只用其中三种，见 §4.1）：**

```yaml
effects:
  - op: add_stat          # ① 即时改数值
    target: self          # self | opponent
    stat: hp
    delta: 5
  - op: add_tag           # ② 挂状态（buff / debuff 都靠它）
    tag: 中毒
    duration: 5           # 必填；超过 max_duration 会被夹到上限
    per_turn: { hp: -1 }  # 每回合掉血
  - op: add_tag           # 挂"增益"也是同一条 —— 用 modifiers 改属性
    tag: 力量祝福
    duration: 3
    modifiers: { patk: 2 }   # 3 回合内物攻 +2（进力值链 ②）
  - op: remove_tag        # ③ 解状态（**解药**）
    tag: 中毒
  - op: learn_skill       # ④ **学会一个技能**（"这张纸你记住了"）
    skill: fireball
  - op: forget_skill      # ⑤ **忘掉一个技能**（"那一下把你会的东西打散了"）
    skill: shield_bash
```

**`learn_skill` 是"后天发育"的唯一入口**（§4.8.3）：

- **技能书 = 一件普通消耗品**，`effects: [{ op: learn_skill, skill: X }]`。
  所以**开箱、事件、商店、战利品，凡能给道具的地方都能给技能**——**零新增通道**。
- **没有任何职业限制**：法师能学盾击，战士能学治疗术。**职业只管先天**（§4.2.3）。
- `forget_skill` 是它的反面：**环境与运气真的会夺走你的本事**。
- **`skill` 必须指向一个"已启用"的技能**，否则是死引用（编辑器标红，§5.7）。

**"用红瓶强行承受中毒"是怎么成立的：**

- 中毒 5 回合、每回合 `-1 hp` → 不吃解药共掉 5 点
- **红瓶 `+5 hp` 且不占回合**（§4.8.0）——使用药水不会因为"多花了一回合"而多承受一次毒伤
- 所以红瓶正好抵掉中毒，**能够承受但要消耗药水**；想更省就用解毒剂（`remove_tag`，也不占回合）
- **反过来说，"治疗术"这种技能是要花一回合的**（§4.8.3）——施放那一回合中毒照样 tick。
  **这就是"道具即时但数值小、技能消耗回合但数值大"的取舍**
- 想更狠就把 `per_turn` 调大；想更温和就把 `duration` 调小。**两者都在组件上，是内容不是规则**

#### 4.8.11 商店与交易（`encounter: shop`）

> **回答"谁来卖 / 怎么卖 / 卖多少"三个问题：**
> **谁来卖** —— 商店就是一个**建筑**（地图件），铺到哪就在哪开张，和宝箱屋同构；
> **怎么卖** —— 玩家踩到 → 打开面板 → 从 `stock` 里挑 → 付 `price` 算出的数量 → 成交；
> **卖多少** —— `price` 复用 §4.8.1 的 `rollRange`，**掷骰定价**（同一件东西每局价格不同）。
>
> **确实是"和宝箱屋一样的单独子类型"** —— 见 §4.4 的 `encounter: shop`。

**关键设计：不发明"货币系统"，货币就是一件道具。**

```yaml
- id: merchant
  name: 流浪商人
  icon: 🧳
  encounter: shop
  stock:                                  # 卖什么（池结构，与 reward_pool 完全同构）
    source: ids                           # ids = 手选 | filter = 按标签筛整个组件库
    ids: [red_potion, blue_potion, iron_sword]
    # filter: { tags: [消耗品] }
    pick: { algo: count, dice: 1D6, range: [2, 3] }   # 这次上架几件
  price:                                  # 定价（单价算法）
    currency: gold                        # ← "钱"就是一件道具的 id
    algo: value                           # value = 掷骰映射到区间 | fixed = 固定价
    dice: 1D6
    range: [5, 15]
  restock: on_enter                       # 每次进入重新抽货 / never = 固定库存
  desc: 他不问你要去哪，只问你有多少钱。
```

- **货币 = 一件普通道具**（如 `gold`，`tags: [货币]` 只是给编辑器做筛选用，引擎不认识这个词）。
  所以"捡钱"就是普通的 `grant` / `reward_pool` 产出，**零新增机制**。
- **`price.algo: fixed`** 就是明码标价；**`value`** 就是"这件东西今天 5~15 块"。
- **卖出（玩家卖东西给商店）**：标 **P1**，形态是 `sell_ratio`（回收价倍率，默认 `0.5`）+ 反向池。
- **泛化成"合成台 / 以物易物"**：把 `stock + price` 换成 `take`（给玩家的池）+ `give`（玩家付的池），
  就是"3 个红瓶换 1 把铁剑"。这个形态标 **P1**，不强塞进 M1。

> **商店 / 宝箱 / 战利品三者的关系**：**池结构（§4.8.5①）是完全相同的一份**，
> 区别只在"用什么触发"（踩到 / 打开 / 打赢）和"要付什么"（宝箱免费、商店要钱）。

#### 4.8.12 NPC 触发与对话（**进入建筑的第一步**）

> **位置**：**玩家进入建筑之后、该建筑的建筑事件之前**——踩到建筑 → ① 本节（NPC 触发 / 对话）→ ② 该建筑自己的 `encounter` 行为（V2.0 追加设定，[`07-decisions.md`](07-decisions.md) §8.3）。
>
> **回答"和谁说话 / 说哪一套 / 这层选项怎么定"三个问题：**
> **和谁说话** —— 建筑实例的 `npcs`（空 ＝ 不触发、1 位 ＝ 固定、多位 ＝ 掷 `talk.dice` 等权抽一位）；
> **说哪一套** —— NPC 的 `dialogs` 有多套方案，实例的 `dialog` 可写死方案名，留空且多套时掷 `talk.dice` 抽一套；
> **这层选项怎么定** —— 本层记录写了 `dice` 就掷骰按各 `items` 的 `hit` 命中，没写就让玩家直接点选。
>
> **字段定义与编辑器行为见 §4.9.2 / §4.9.3（[`02-data-model.md`](02-data-model.md)）与 §5.6.1（[`04-editor.md`](04-editor.md)）**；
> 本节只定**运行时顺序**与**这两处骰子的用法**。

**触发条件（进入判定）**：**只在玩家从建筑外的格子踏入该建筑（任意一格）时**触发；**已经在建筑内部移动（多格建筑里走位）不再触发**——多格建筑是**同一座**（同一节点 key），只在**首次踏入**算"进入"。**首次进入一定走对话流程**（**不弹框**，从方案根节点开始）；**重入（该实例已触发过对话）先弹「选择对话框」**——只列**已锁定的那位 NPC**，配【**继续对话**】【**重新对话**】＋（**走完过**才出现的）【**路过**】，**不换人、不重掷**。

**运行时顺序（进入建筑时，先于该建筑的 `encounter` 行为）**

| 步 | 做什么 | 掷骰 |
|---|---|---|
| ① 抽人 | `npcs` 空 → **不触发对话**、直接进建筑事件阶段（定义是 `talk` 时该阶段为空 → 等同 `empty`）；1 位 → 取它；多位 → **等权抽一位** | `talk.dice`（仅多位时） |
| ② 抽方案 | `dialog` 写死方案名 → 直接用、**不掷**；留空且 `dialogs` 有多套 → **等权抽一套** | `talk.dice`（仅多套且未写死时） |
| ③ 进入 / 重入 | **首次进入**：从方案**根节点**开始（**一定触发**、不弹框）；**重入**：先弹**选择对话框**——【**继续对话**】＝ 回到 `cursor` 节点接着走（**没有 `cursor`** 或**已交付**时按各自的落点回放）、【**重新对话**】＝ 从根节点完整重播、【**路过**】（**走完过**才有）＝ 跳过对话去跑该建筑的 `encounter` 行为（完整判定见 §4.9.2） | 不掷 |
| ④ 本轮记录 | 展示 `message`（逐条、点击继续）→ **本层带 `dice`**：给「掷骰」按钮、按 `items` 各条的 `hit` 区间命中（**未命中任何 `hit` 就再掷**）；**不带 `dice`**：列出 `items` 供点选 | 本层记录的 `dice` |
| ⑤ 结算 | 选中 / 命中一条记录 → **若它带 `give` 先按重复次数发道具**（受 `inventory_size` 约束）、记 **`deliveredNode`**；再由它的 `items` 决定：**非空 → 回到 ④ 进那一条**，**缺省 / 空 → 结束** | 不掷 |

- **与建筑事件的关系**：①–⑤ 全部跑完（或该实例没有 `npcs`）之后，才执行该建筑**自己的 `encounter` 行为**；**`encounter: talk` 的建筑「建筑事件阶段为空」**（等于"只有对话"）。**`npcs` 与 `encounter` 正交**——任何建筑实例都可以挂 NPC。
- **掷定即锁死**：① ② 两步只要**由骰子定过**，**本局永久不变**——重踩 / 回访不再重掷、不换人、不换方案。锁的是**建筑实例**（同一 NPC 出现在两栋建筑里，各自独立抽）。
- **两级各掷一次、等权**：与"怪物登场掷骰一次摇定"同一原则（§4.8.2）；**抽定结果**与**三个进度标记**同源写进 `.psave`（§7.3），重开新局自然重置。
- **三个标记的写入时机**（§4.9.2）：每进入一条记录 → 更新 **`cursor`**；走到 `items` 缺省 / 空的正常结尾、或交付完那条带 `give` 的记录 → 置 **`talkDone`**；交付 `give` 的同时写下 **`deliveredNode`**。三者都按建筑实例 key 记账，**缺字段的老档视为未触发**。
- **`.psave` 的记账单位 ＝ 建筑实例 key**（§4.9.3）：**key ＝ `<地图名>#<ref>@<锚点>`**，**锚点 ＝ 节点自己的坐标 `(x, y)`**——**一座建筑就是一个节点**，多格由 `w` / `h` 覆盖，从它任意一格进入都是同一座（相邻的两座是两个节点）；`ref` 靠"组件 id 不做顺序编号、永不变"保证稳定；**弱引用**——`.pmod` 改动导致 key 不匹配 → 该实例对话状态**视为未触发**（不报错、不迁移），孤儿 key 忽略。
- **`dialog` 悬空 ＝ 跳过对话**：实例写的方案名**不在所抽到 NPC 的 `dialogs` 里** → **当该实例没有 `npcs`**，直接跑建筑事件；**不做"降级为掷骰"**，编辑器标红 ＋ 进「清单」（[`07-decisions.md`](07-decisions.md) §8.3 设定 5）。
- **对话不掷别的骰**：不发属性点、不做判定、不与力值链发生关系；`message` 逐条展示、**不做打字机 / 逐字动画**（§4.9.2）。
- **记录上的 `dice` 是内容、不进配置**：写在组件里（与事件的 `check.dice` 同类），**不计入 §4.8.6 的 14 项总账**；`talk.dice` 才是前置配置项。
