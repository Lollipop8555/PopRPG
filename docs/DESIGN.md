>
> **本轮（M1）改了什么**：确立 **组件库 → 游戏内容** 两层架构、按"在内容里怎么出现"重排组件分类、
> 把交互收敛成 §5.4 的 6 个操作模式标准表、左栏加「图层」块并让套件分区可折叠、

> **地图件的「消耗 + 权限」双维度与标签匹配机制**（§4.5）——"火焰山 + 火抗鞋"这类玩法由数据碰出来，不由代码写死、
> **属性体系定为"两资源 + 四能力"共 6 个**（`hp` / `mp` / `patk` / `matk` / `pdef` / `mdef`，§4.0.1）、
> **主角成长＝职业给起点 + 玩家分配 + 战斗产出点数**（§4.2 / §4.8.8），
> 怪物走区间摇定并分小怪 / 精英档（§6.1.1）。
>
> **第二轮补充（框架完整性审计）**：把**建筑行为从 3 种扩到 5 种**（＋ **事件** §4.8.9 / **商店** §4.8.11）、
> 加**状态与持续效果** §4.8.10、**背包容量** §4.2.4；并**明确划出不做**的三条（多结局、难度评估、独立货币/背包系统，§1.1 / §7.4）。
>
> **第三轮补充（技能与回合）**：把"攻击方式"（旧 `combat.attacks`）**升级为组件库第七类「技能」**——
> 技能不引入新判定，它只回答 **`dim`（取哪一维属性）+ `target`（打谁）+ `effects`（附带什么）**，
> 于是**攻击 / 治疗 / 增益 / 诅咒全是这三种选择的组合**（§4.8.3）；同时**重定义回合**：
> **一次交锋**或**一次移动（走完全部步数）**才算一回合，**使用道具不占回合**（§4.8.0）。
>
> **第四轮补充（先天与后天）**：**技能彻底脱离职业**——`ClassDef.skills` 删除，**职业只管先天的牌面**
> （`base_stats` / `buffs` / `inventory_size` / `starting_items`）。技能靠 **`op: learn_skill`** 后天学，
> 于是**技能书就是一件普通消耗品**：开箱 / 事件 / 商店 / 战利品，**凡能给道具的地方都能给技能，零新增通道**（§4.8.3 / §4.8.10）。
> **法师可以练成战士，代价是永远背着先天的 `buffs` 折扣**——这就是"顶着 debuff 努力向前"（§1.1 / §4.2.3）。
>
> **实现时主要对照两节**：**§5**（编辑器交互）与 **§4.8**（硬规则、力值链、技能、每场景算法、前置配置清单）。
> 另加 **§4.2.3**（职业＝先天）与 **§4.8.3**（技能＝后天）——**这两条是角色成长的骨架**。
>
> **两条贯穿全场的不对称**：① **玩家精确、敌人随机**（属性：分配 vs 区间摇定）；
> ② **玩家自己选、敌人掷骰随机**（攻击方式）。
>
> **§4.8 的两条纪律**：① 属性 / 装备 / 职业 / 骰子**全都在力值链上**，不存在"只看骰子"的结算；
> ② **配置里出现的每个字段都必须是代码已实现的**，不给"本来就该如此"的东西做开关。
>
> **一条贯穿全篇的设计观**：**骰子是核心，但不是运气游戏**——玩家靠提高属性 / 换装备 / 换职业抬高基数来
> **压缩运气成分**，编辑器负责把"必成 / 必败"摆在眼前（§1.1 / §4.8.9）。
>
> **一条贯穿全篇的克制**：**任何新玩法都必须能回答"它在哪一步生效、用哪颗骰"**。
> 技能能加进来，正是因为它没有自创判定流程，只是给力值链换了个输入（§7.5）。

## 1. 产品定位

PopRPG 是一个**单人跑团（Solo TTRPG）** Web App，整体分为两个阶段：

- **构建（Build）**：像思维导图工具，左栏管理**图层（多张地图）**与**组件库**，把组件按格摆到方格地图上，设定数值区间；
  同时在「规则」里定死这一局的**判定标准、战斗公式与移动规则**（§4.8）——骰子从来不是孤立的，它必须知道自己在跟什么比。
- **游玩（Play）**：消费构建结果，去网格线、只留坐标参照，按 `rules.move` 掷骰定步数前进、按 `rules.combat` 判定战斗、按 §4.8.5 揭晓随机奖励，跑通一场冒险。

核心乐趣 = **"预设套件 + 随机揭晓"**（模式 B+C）：你摆了宝箱屋但不知道里面是药水还是空的，靠骰子 + 奖励池制造惊喜，与"自己画自己玩"结合。

### 1.1 三条立场（决定了什么**不做**）

| 立场 | 含义 | 因此不做 |
|---|---|---|
| **跑团，不是剧情 RPG** | 跑团是**未知的自由探索**和玩家自己定下的未来；剧情 RPG 才是在走设定好的条件 | **不做多结局、不做条件通关、不做剧情分支树**。走到终点就是完成游戏——**用任何方式到都算** |
| **角色是先天的，路子是后天的** | 职业只给**先天的牌面**（属性起点 + 优劣百分比 + 背包容量 + 出生家当），**不给技能**。学什么、变成什么，由**这一局里遇到的事件与环境**决定——**法师可能被逼成战士** | **不做职业专属技能 / 技能树 / 转职系统**。想做"法师"就出生带一本《火球术》，**但那本书能丢能卖**——他随时可以不做法师。**先天的百分比永远生效**，所以"顶着 debuff 努力向前"是有代价的真选择（§4.2.3 / §4.8.3） |
| **骰子是核心，但不是运气游戏** | 玩家投骰的同时，通过**提升属性 / 换装备 / 换职业**抬高基数，**压缩运气成分**；编辑器负责把"必成 / 必败"摆在眼前 | **不做"必须掷出 6 才能撬锁"这种纯概率门**——那不叫玩法，叫浪费时间（§4.8.9） |
| **编辑器不下定义** | 不同的设计**本身就是各自的特色玩法** | **不做难度评估、不做平衡性警告**。引擎只校验"会不会卡死"（引用悬空、死路），**不评判好不好玩** |

- 跨端：手机 + 电脑，响应式。
- 分享：整套场景导出为单个 **`.pmod`** 文件（内部 Markdown），可读、可再编辑、可分享。

## 2. 技术栈

| 关注点 | 选型 | 说明 |
|---|---|---|
| 框架 | React + TypeScript + Vite | 生态最成熟，网格/画布、Markdown 解析资料多 |
| 状态管理 | Zustand | 轻量，适合多面板共享大状态 |
| 图标 | lucide-react + Emoji | 分类/预设用矢量图标；自定义与内容用 Emoji |
| Markdown | 导出模板拼接；导入 remark/轻量解析 | 散文正文 + ```yaml 围栏还原为内存模型 |
| 本地存储 | localStorage（单项目单例） | 编辑自动保存；`.pmod` 仅是导出/分享格式 |
| 地图渲染 | 视口虚拟化（只渲可见格） | 坐标域 ±10000，不能全量渲染 |

> 地图渲染优先 SVG（交互元素易点击），视口外不渲染；缩放改变格像素尺寸 + 组件标识缩放。

## 3. `.pmod` 文件格式

单文件 Markdown，后缀 `.pmod`。**一个 `.pmod` = 一局游戏的全部内容**（"内容"的定义见 §4.0）：

- **一级标题 `#`** = 游戏名
- **二级标题 `##`** = 模块（背景 / 设定 / **规则配置** / 地图）
- **三级标题 `###`** = 分组（怪物 / 道具 / 建筑 / 道路 / 职业 / **技能**）或每张地图
- **散文段**（背景）= 普通 Markdown 正文，游玩时直接渲染
- **结构化数据**（怪物/道具/地图等）= ```` ```yaml ```` 围栏块，保证人读 + 机解析都稳
- **`## 设定` 段 = 组件快照**：这一局用到的组件定义会**随文件一起带走**，所以 `.pmod` **自包含**——别人拿到就能玩，不依赖他本地的组件库。
  导入时这些定义**并入本地组件库**，成为用户自己的组件。

````markdown
### 建筑
```yaml
- id: chest_room
  name: 宝箱屋
  icon: 📦
  encounter: treasure            # empty | treasure | monster | event | shop（五种，§4.4）
  reward_pool:                   # 池（§4.8.5①）：算法走前置配置的 treasure，这里只给"给什么"

    chance: 0.2                  # 概率变成怪物屋
    monster: mimic_chest
    reward_pool: { source: ids, ids: [red_potion] }
  desc: 你不知道里面有什么。
- id: monster_room
  name: 怪物房
  icon: 💀
  encounter: monster
  monster_pool:                  # 怪物池：踩到掷骰抽一只（单只 = 单元素池）
    source: ids
    ids: [{ id: goblin, weight: 3 }, { id: slime, weight: 2 }]
  desc: 里面盘踞着一只怪物，但你不确定是什么。
- id: stone_door
  name: 上锁的石门
  icon: 🚪
  encounter: event               # 第五种行为：门槛 + 判定 + 后果（§4.8.9）
  event:
    text: 一扇刻着古文字的石门挡住了去路。
    gate:                        # ① 门槛：没带 `撬锁` 就不给"尝试"选项
      tags: [撬锁]
      mode: all
      on_missing: blocked        # blocked = 不给选项 | penalty = 允许硬来但吃惩罚
    check:                       # ② 手艺：掷 2D6 + 物攻 ≥ 15（复用力值链，§4.8.9）
      dice: 2D6
      add: patk
      target: 15
    on_success:
      text: 锁芯"咔"地一声弹开了。
      point_reward: 2
      grant: [{ id: red_potion, count: 1 }]
    on_fail:
      text: 门缝里弹出一排铁针。
      cost: { hp: 3 }
      effects: [{ op: add_tag, tag: 扎伤, duration: 3, per_turn: { hp: -1 } }]
    once: false
- id: merchant
  name: 流浪商人
  icon: 🧳
  encounter: shop                # 第五种行为的另一支：用钱换东西（§4.8.11）
  stock:                         # 上架池（与 reward_pool 同一套结构）
    source: filter
    filter: { itemKind: consumable, tags: [common] }
    pick: { algo: count, dice: 1D6, range: [2, 3] }
  price:                         # 定价：货币就是一件普通道具
    currency: gold
    algo: value                  # value = 掷骰映射到区间 | fixed = 明码标价
    dice: 1D6
    range: [5, 15]
  restock: on_enter
  desc: 他不问你要去哪，只问你有多少钱。
```

### 技能
```yaml
# 技能 = 取哪一维属性 + 打谁 + 附带什么（§4.8.3）
# 前两个是"保底对"：人人开局都有，cost 都是空的（免费），保证任何情况下都打得了
- id: basic_attack
  name: 普通攻击
  icon: ⚔️
  dim: patk              # 基准维度：取物攻
  target: opponent       # 打对方
  vs: auto               # auto → 按 dim 配对：patk 对 pdef
  bonus: 0               # 0 加成：纯靠属性，技能自身不加东西
  apply: hp              # 力值作用到对方 hp
  cost: {}               # 免费
- id: basic_magic
  name: 普通法术
  icon: ✨
  dim: matk              # ← 与普通攻击只差一维
  target: opponent
  vs: auto               # matk 对 mdef
  bonus: 0
  apply: hp
  cost: {}               # ← 也免费：没有 mp 也能放，不会等死
- id: heal
  name: 治疗术
  icon: 💚
  dim: matk
  target: self           # ← 只改这一项：从"打人"变成"救人"
  vs: none               # 不对抗、不落空
  bonus: 2
  apply: hp              # 回自己 hp，量 = 力值
  cost: { mp: 3 }
- id: bless
  name: 力量祝福
  icon: 💪
  dim: patk
  target: self
  vs: none
  bonus: 0
  apply: none            # 不伤不治，纯挂状态
  cost: { mp: 2 }
  effects:

      tag: 力量祝福
      duration: 3
      modifiers: { patk: 2 }
- id: weaken
  name: 虚弱诅咒
  icon: 🌀
  dim: matk
  target: opponent       # ← 同一条路：对对手挂减益

- id: poison_bite

  dim: patk
````

### 3.2 实体 ID 与引用规则
- 所有结构化实体（怪物/道具/建筑/道路/职业）都有全局唯一 `id`：定义段里定义一次，地图节点用 `ref` 引用，保证同一建筑可放在多个格子而只维护一份定义。
- **id 形状决定来源**，这是全篇判断"预设还是自建"的**唯一依据**：

| 来源 | id 形状 | 例 |
|---|---|---|
| **预设**（系统自带，七大类都有） | 固定可读词 | `goblin` / `red_potion` / `chest_room` / `path` / `knight` / **`basic_attack`** |
| **自建**（用户自己创建，七大类都能建） | 类型前缀 + 随机串 | `m_a1z2` / `i_7kf0` / `b_3kf9` / **`k_4x8q`** |

- **不做顺序编号**——顺序编号会在删除/重排后错位、破坏地图引用。
- **"预设 / 自建"是派生信息，不存字段、不写进 `.pmod`**：拿 id 去内置预设表里查，查得到就是 `预设`，查不到就是 `自建`。
  好处是**七大类天然一视同仁**，不存在"建筑有、怪物没有"这种事。
- 显示 `name` 与 `id` 分离：`name` 可随时改名而不影响地图引用、也不影响来源判定。
- 高级用户可在编辑器里手动改 `id`（默认隐藏）；**改 id 会同时改变来源判定**（改成随机串就变成 `自建`），这是可接受的——
  id 本来就该是"身份的锚"，改锚就是换了身份。

### 3.3 `.pmod` 里装什么（自包含规则）

`.pmod` 只装**这一局真正用到**的组件：

| 组件类型 | 什么情况下被写进 `.pmod` |
|---|---|
| 消耗品 / 装备 / 怪物 / 职业 / **技能** | 在本局中被**启用** |
| 道路 / 建筑 | 被**铺到某张地图的格子上** |
| 背景 / 规则配置 / 地图 | 始终 |

- 库里那些**没启用、没铺设**的组件，不进 `.pmod`——它们只是待用的工具，不是这局的内容。
- 组件定义原样带出（`id` / `name` / `icon` / `tags` / 各自属性），**没有来源标记字段**；来源由导入方按 §3.2 的 id 形状自行判定。
- **round-trip**：导出 → 导入后，启用集合、铺设节点、地图顺序、组件定义全部一致（无丢失）。

## 4. 数据模型

### 4.0 组件库 vs 游戏内容（全篇总纲）

```text
┌─ 组件库 Library ── 用户的长期资产，自己维护、跨项目复用 ──────────┐
│  道路 · 建筑 · 消耗品 · 装备 · 怪物 · 职业 · 技能 · 背景           │
│  来源：系统预设（可"恢复默认"）  ＋  用户自建（能改能删能复制）    │
└───────────────────────────────────────────────────────────────────┘
        │ 这一局从库里挑出要用的
        ▼
┌─ 游戏内容 Content ── 这一局到底怎么玩 ───────────────────────────┐
│  · 启用的 消耗品 / 装备 / 怪物 / 职业 / 技能                       │
│        → 进奖励池候选、玩家背包 / 穿戴、开局 class_pool、技能栏    │
│  · 铺到地图上的 建筑 / 道路　＋　起终点标记                        │
│        → 出现在地图格上                                            │
└───────────────────────────────────────────────────────────────────┘
        │ 导出
        ▼
   .pmod（自包含：把用到的组件定义一起带走）
```

> **一句话：库是工具来源，内容是干出来的活。**
> 用户自建的组件和系统预设**地位完全相同**，都躺在库里，都能改、能删、能复制、能反复用。
> 库不因某个项目而生（像笔刷库不因某张图而生），也不随某个项目而亡。

**公共字段**（**七大类全都有，一个不多一个不少**：怪物 / 道具 / 建筑 / 道路 / 职业 / 技能 / 背景）：

| 字段 | 必需 | 说明 | 七大类是否一致 |
|---|---|---|---|
| `id` | ✓ | 全局唯一；地图节点用 `ref` 引用；**来源由它的形状决定**（§3.2） | ✓ 都有 |
| `name` | ✓ | 显示名，改名不影响引用、不影响来源判定 | ✓ 都有 |
| `icon` | ✓ | Emoji 或图标名 | ✓ 都有 |
| `desc` | | 描述文本 | ✓ 都有 |
| `tags` | | 标签数组，**三个用途共用同一个字段**：① 奖励池 / 怪物池的 `filter` 筛选（§4.8.5①）；② **通行能力**（§4.5.2）；③ 编辑器里的分组与搜索 | ✓ 都有 |

> **没有"来源"字段。** 预设还是自建，靠 §3.2 的 id 形状**当场判定**（查内置预设表）。
> 这样各类自动一致——怪物能自建，道具能自建，技能也能自建，判定方式完全相同。
> 用户自建的技能和自建的怪物，在库里的待遇没有任何区别。

#### 4.0.1 属性体系：两资源 + 四能力（共 6 个）

**属性一共 6 个，分两类——这两类的行为完全不同，不能混着处理：**

| 类别 | 属性 | 有"当前值" | 会被消耗 / 恢复 | 归零后果 | 用途 |
|---|---|---|---|---|---|
| **资源** | `hp` | ✓ | ✓ | 败北 | 生存 |
| | **`mp`** | ✓ | ✓ | 只是放不了"贵技能" | **技能成本**（§4.8.3）——**不是"法术专属"** |
| **能力** | `patk` | — | — | — | 物理攻击力（力值链 ①） |
| | `matk` | — | — | — | 法术攻击力 |
| | `pdef` | — | — | — | 物理防御 |
| | `mdef` | — | — | — | 法术防御 |

- **`mp` 是正式的第 6 个属性**。早期文档只列了 `hp/patk/matk/pdef/mdef`，却已经在用 `mp`（蓝瓶回蓝、地形扣蓝）——
  **半套 `mp` 是最糟的形态**：要么没有，要么成套。现在成套：
  ① 玩家能分配点到 `mp`；② **有成本的技能**扣它；③ 有恢复道具（蓝瓶）；④ 地形 `cost` 能扣 `mp`。
- **`mp` 消耗完全由技能自己的 `cost` 决定**——跟"是不是法术"无关：一个技能 `cost: { mp: 3 }` 就花 3，
  `cost: {}` 就不花。**我们让保底对 `basic_attack` / `basic_magic` 的 `cost` 设为空，所以它免费**——
  这是**我们对预设模板的设计选择，不是引擎规则**：作者完全可以把某个法术 `cost` 设成 `mp`（它就会真花 mp），
  也可以把保底对的 `cost` 改成非空（那它就不再是"免费保底"）。**物法之别靠的是 `dim`，不靠谁耗蓝**。
- **"不会等死"的保证来自"保底对 `cost` 为空"这个默认设定**：只要保底对免费，即使 `mp = 0` 也能放、也能打；
  若作者把保底对也设成要 `mp`，那保底本身也会受 `mp` 约束——这是作者的设计自由，**引擎不保证不死局**。
- **能力四项永远是"上限值"**，不会被消耗，只在力值链里当输入。
- 下文"五维"的旧叫法一律按 **6 属性**理解（`hp` / `mp` / `patk` / `matk` / `pdef` / `mdef`）。
- **背包不是第 7 个属性**：它不参与任何判定，是**职业上的一个容量数字**（`inventory_size`，§4.2.4）。
  说它"是角色属性"指的是"你这个角色能带多少东西"，和上面这 6 个被力值链消费的属性不是一回事。

#### 4.0.2 两边的属性从哪来（玩家 ≠ 怪物）

| 侧 | 属性来源 | 形态 | 为什么 |
|---|---|---|---|
| **玩家（主角）** | 职业 `base_stats` ＋ **自由点分配**（§4.2.1） | **确定值**，玩家自己分 | 自己的角色要可控、可规划 |
| **怪物** | `stats` **区间 → 登场时摇定**（§4.8.2） | **有波动**，小怪 / 精英靠区间拉开档 | 敌人要有意外性；同一个房间也可能遇到强一点 / 弱一点的 |

> 所以**不是**"双方都摇区间"，也**不是**"双方都用分配"。玩家精确、敌人随机——这是故意的。
> 玩家侧还会**随着战斗不断获得自由点**（`point_reward`，§4.8.8），角色是**长出来**的；怪物一登场就定型。

> **"本局是否启用"不是组件自己的属性**，而是**项目对它的使用状态**（`project.enabledIds`）。
> 同一个哥布林在 A 局启用、在 B 局不启用，库里的哥布林只有一份、不被改动。

**地图件 vs 非地图件：**

| | 地图件 | 非地图件 |
|---|---|---|
| 包含 | 道路、建筑 | 消耗品、装备、怪物、职业、**技能** |
| 是否占地图格 | 是 | 否 |
| 成为"内容"的条件 | **铺到地图格** | **显式启用** |
| 被谁消费 | 网格移动（可走图 = 已铺节点集合） | 建筑奖励池、玩家背包 / 穿戴、怪物房、开局 `class_pool`、**技能栏（学会的）** |

> 起点 / 终点标记是**画布内建工具**（每图各一个、无属性定义），不占组件库名额。

### 4.1 怪物 `monster`
- 属于**非地图件**：不占地图格，需被建筑（怪物房 `monster_pool` / 宝箱怪物 `mimic.monster`）抽出来才出现在游玩里；**未启用的怪物不会进入任何池**。
- `stats`: **6 个属性的区间** `hp / mp / patk / matk / pdef / mdef`，各为 `[min, max]`。
  怪物**用区间**（不是点数分配）：登场时用 `stat_dice` 把区间摇成一个具体值，本场固定（§4.8.2 第一步）。
  区间越宽，这只怪越"没谱"。
- **小怪 / 精英靠区间拉开档，不靠新字段**——精英怪只是区间更高，再打个 `tags: [精英]`：

| 档 | `hp` | `patk` | `matk` | `pdef` | `mdef` | 标注 |
|---|---|---|---|---|---|---|
| **小怪** | `[6, 12]` | `[2, 4]` | `[0, 2]` | `[1, 2]` | `[1, 2]` | — |
| **精英** | `[24, 40]` | `[6, 10]` | `[4, 8]` | `[4, 6]` | `[4, 6]` | `tags: [精英]` |

  > 用 `tags` 而不是新开一个 `rank` 字段：怪物池可以直接 `filter: { tags: [精英] }` 做"精英房"，
  > **机制已经在那儿了，不用再加字段**（§4.8.5①）。
- 怪物**不按玩家那把尺子来设计**——它是另一套标定（§6.1.1 数值标定基准）。
- **`attack_weights`**（可选）：**这只怪会哪些技能、各占多重**——**键就是技能 id**，例 `{ basic_attack: 3, poison_bite: 1 }`。
  出手时掷 `pick_dice` 按权重随机挑一个（§4.8.3）——**这是逼玩家两维防御都堆的关键**。
  省略 = 只用 `basic_attack`（内建基础技能，**与玩家的保底对无关**）。
- `atk_roll` / `def_roll` / `stat_dice`（可选）：**覆盖**前置配置里对应的骰子（§4.8.7）。
- `reward_pool`（可选）：打赢这只怪后的**战利品池**（§4.8.5①）。抽取算法默认用前置配置的 `loot`，可用 `pick` / `copies` 覆盖。
- **`effects`**（可选）：**命中玩家时施加的效果**，结构为 `add_stat` / `add_tag` / `remove_tag` **三种 `op`**（§4.8.10）。
  **怪物不会 `learn_skill` / `forget_skill`**——教 / 夺技能只发生在消耗品、技能、事件三处，怪物命中只改数值、挂状态，
  不做"技能转移"（避免破坏平衡）。
  例：`effects: [{ op: add_tag, tag: 中毒, duration: 3, per_turn: { hp: -1 } }]`——被它打中一次就中毒 3 回合。
  这就是"怪物会下毒"的落点，**不新增任何机制，只是把 `effects` 挂到怪物身上**。
- **`point_reward`**（可选）：打赢给玩家**几点自由属性点**（默认 0）——**玩家变强的主渠道**（§4.8.8）。
  小怪给 1、精英给 5，靠档位拉开，**不掷骰**。
- `desc`: 背景文本

### 4.2 主角：职业给起点，玩家做分配

#### 4.2.1 属性从哪来（三段式）

```text
职业.base_stats      →  初始属性（确定值，不摇）
职业.free_points     →  开局自由点数
战斗 / 开箱的产出     →  后续获得的自由点数（point_reward，§4.8.8）
──────────────────────────────────────────────────────────
玩家属性    = base_stats + 已分配的自由点
剩余自由点  = free_points + Σ point_reward − 已分配的点
```

| 段 | 来源 | 举例 |
|---|---|---|
| **初始属性** | 职业的 `base_stats` | 骑士 `hp 5 / patk 3 / pdef 2` |
| **开局自由点** | 职业的 `free_points` | 骑士 `25` 点 |
| **后续自由点** | 战斗 / 开箱产出的属性点 | 打赢哥布林王 `+3` 点 |

> **"开局给多少点"是职业设定，不是引擎硬规则。** 你可以建一个职业 `free_points: 300`——
> 那是你的设计自由，引擎不拦。**硬规则只管"怎么分"**（§4.2.2）。

#### 4.2.2 分配规则（这一层才是硬规则）

给多少点是职业的自由，**但"怎么分"是引擎写死的**：

| 规则 | 内容 |
|---|---|
| **折算** | **1 点 = 该属性 +1** |
| **可分配到** | 6 个属性的任意一个（`hp` / `mp` / `patk` / `matk` / `pdef` / `mdef`） |
| **时机** | **任意时刻**都能加（战斗外、战斗中都行），没有单独的"升级界面" |
| **洗点** | **不可以**。加进去就是加进去了 |
| **剩余自由点** | **保留**，什么时候想加再加（不过期、不会被没收） |

- **玩家属性不是摇出来的**，是 `base_stats` + 玩家一点一点分出来的**确定值**（§4.0.2）。
- 举例：骑士（`base_stats.hp = 5`、`free_points = 25`），玩家把 25 点分成 `hp +8` / `patk +12` / `pdef +5` →
  最终 `hp 13` / `patk 12` / `pdef 5` / `mp 0` / `matk 0` / `mdef 0`，剩余自由点 0。
- **`mp` 通常初始为 0**（除非职业的 `base_stats` 给了）：想放法术就得先把点分给 `mp`，或者靠装备补。
  **这是"物法之别"的第一道门槛**，也是分配策略的核心取舍之一。
- **剩余点保留**意味着"我现在不确定该加什么"是可以的——但**加错了不能退**，这是设计上的重量。
- **点可以一直攒着**：攒 10 点去打 Boss 前一次性分配，是完全可行的玩法。

#### 4.2.3 职业 `class`：起点 + 放大器

```yaml
- id: knight
  name: 骑士
  icon: 🛡️
  base_stats: { hp: 5, mp: 0, patk: 3, matk: 0, pdef: 2, mdef: 0 }   # 初始属性（先天）
  free_points: 25                                                     # 开局自由点数（先天给你的本钱）
  buffs: { hp: 110, patk: 120, pdef: 110, matk: 80 }                  # 先天优劣（百分比，力值链 ③）
  inventory_size: 50                                                  # 背包格数（省略 = 50；0 = 无限）
  starting_items: [red_potion]                                        # 出生时口袋里有什么（可选）
  desc: 物理见长的近战，血厚防高，法术稀烂。
  # 注意：没有 skills —— 职业不限定你能学什么（§4.8.3）
- id: mage
  name: 法师
  icon: 🧙
  base_stats: { hp: 3, mp: 4, patk: 0, matk: 3, pdef: 0, mdef: 2 }
  free_points: 25
  buffs: { hp: 90, matk: 130, mdef: 120, patk: 80 }                  # ← 这个 80 就是他一辈子背着的物理缺陷
  inventory_size: 30                                                  # 书多的人，背得少
  starting_items: [blue_potion, scroll_of_fireball]                   # 出生带一本《火球术》，但书可以丢可以卖
  desc: 法术见长，血薄，物理几乎打不动人。
```

| 字段 | 作用 |
|---|---|
| **`base_stats`** | **初始属性**（6 个属性的确定值，不摇） |
| **`free_points`** | **开局自由点数**（想给多少给多少，300 也行） |
| `buffs` | 各维**百分比**（默认 100）——力值链第 ③ 环（§4.8.2） |
| `tags` | 通行能力标签（§4.5.2），如"水手"带 `tags: [渡河]` |
| `inventory_size` | **背包格数上限**（默认 `50`，`0` = **无限**）。它是**职业属性**，所以不同职业可以背得不一样多 |
| `starting_items` | **出生时背包里带的东西**（道具 id 列表，可选）。**它是"家当"，不是"本事"**——想给技能就塞一本技能书，但那仍然只是一件可丢可卖的道具 |

**职业 = 先天的牌面。它只决定这几件事，多一件都没有：**

| 先天给什么 | 字段 | 后天呢 |
|---|---|---|
| **属性起点** | `base_stats` | 玩家用挣来的 `point_reward` 继续加（§4.2.1） |
| **优劣百分比** | `buffs` | **改不了**——这就是"顶着 debuff 努力向前"里那个 debuff |
| **背包容量** | `inventory_size` | 改不了 |
| 附带家当 | `starting_items` | 随手就能丢掉、卖掉、送人 |
| ~~技能~~ | **没有 `skills`** | **全靠后天学**（技能书 / 事件 / 商店，§4.8.3） |

> **铁律：职业不限定技能。** 角色是**先天**的，但**长成什么样是玩家自己走出来的**。

- **"法师练成战士"是允许的，而且代价真实**：把点数全砸物攻、学到盾击、抢到铁剑——
  他确实能砍人了，**但永远背着 `patk: 80` 那个八折**。
- **先天改不了、后天自己选** —— 玩家的乐趣正是**用后天的选择去对抗先天发到的牌**。
- **职业与分配配合才成立**：法师把点堆在 `matk`，百分比再放大 30%；
  要是堆在 `patk`，职业的 `patk: 80` 会把它**打八折**——这就是分配该有的取舍。
- 职业**没有 `stats` 区间字段**：玩家属性 = `base_stats` + 分配，职业只负责起点与放大。
- `class_pool`（前置配置里的顶层列表）：控制开局职业；长度 1 = 固定，>1 = 开局随机。
- **装备无职业限制，技能也无职业限制**——任何职业都能用任何装备、学任何技能。

#### 4.2.4 背包 `inventory_size`（"能带几样东西"）

| 项 | 规则 |
|---|---|
| **字段** | `inventory_size`（整数，默认 `50`，**`0` = 无限**） |
| **挂在哪** | **职业**上（所以它是角色属性，是内容，不是前置配置） |
| **算格子还是算堆叠** | 按 **`{ id, count }` 条目数**算——**同一种道具算 1 格**（10 瓶红瓶占 1 格） |
| **超了怎么办** | 拾取时**直接拒绝并提示"背包已满"**（不做自动丢弃，避免误删） |
| **解除状态算不算占格** | 不算。状态挂在身上（§4.8.10），不占背包 |

- **默认 50 是"够用但会满"的量级**：想做成"仓鼠流"就给 `0`（无限），想做成"抉择流"就给 `30`——
  **这是设计者的一句话，引擎不干涉**。
- 编辑器在职业表单里就是一个数字输入框 + 一个"无限"勾选（勾上 = `0`）。

### 4.3 道具 `item`
统一分组，用 `kind` 区分：

**持续性 = 装备 `equipment`**
- `slots`: 占用的槽位，取自 `head / hands / feet / body / weapon`，可多槽
- `modifiers`: 对 **6 个属性**的加值 `{ hp, mp, patk, matk, pdef, mdef }`（任意整数，可正可负，不强制平衡）。
  **这就是力值链第 ② 环**（§4.8.2）——装备的作用是"加"，不是"乘"。
  **加值量级要按 §6.1.1 的基线标定**：普通件 `+1~2`，强力件 `+4~6`——一件装备顶掉 1/7 的点数预算才叫"强力"。
- **`tags`**：装备**最常用来当通行能力**（§4.5.2）——火抗鞋 `tags: [火抗]`、小船 `tags: [渡河]`。
  **"火焰山 + 火抗鞋"就是靠这个碰出来的**，编辑器不需要认识"火抗"这个词。
- **槽位冲突规则**：新装备若与已装备项在任一槽重叠，旧的那件**整体被卸下**
- 只能有 **5 个槽**，所以"带几把钥匙"是有取舍的：**穿火抗鞋就穿不了渡河靴**，这正是玩点。

**一次性 = 消耗品 `consumable`**
- `usable`: `[battle, move]` 子集，表示对战 / 前进时可用
- `effects`: **五种 `op`**，**可混在一个列表里**（完整定义见 §4.8.10）：

| `op` | 参数 | 作用 |
|---|---|---|
| `add_stat` | `target` / `stat` / `delta` | 即时改数值——可加/减 6 属性中任意一项的 `self` 或 `opponent` |
| `add_tag` | `tag` / `duration` / `per_turn?` / `modifiers?` | **挂状态**（中毒、御火符、力量祝福）——`duration` 必填、有硬上限 |
| `remove_tag` | `tag` | **解状态**（解药） |
| **`learn_skill`** | `skill` | **学会一个技能**——**技能书就是这个**（§4.8.3） |
| **`forget_skill`** | `skill` | **忘掉一个技能**——环境夺走你的本事 |

- **`tags`**（可选）：消耗品也能带标签。**`tags: [货币]` 只是给编辑器筛选用**（§4.8.11），引擎不认识这个词。

**技能书 = 一件普通消耗品** —— 「后天发育」的唯一载体（§4.8.3）：

```yaml
- id: scroll_of_fireball
  name: 火球术残卷
  icon: 📜
  kind: consumable
  usable: [move]                 # 走路时读，或者战斗前读
  effects:
    - op: learn_skill            # 读完，这招就跟着你了（永久）
      skill: fireball
  desc: 纸已经脆了，但字还认得。
- id: scroll_of_oblivion
  name: 遗忘之书
  icon: 🕳️
  kind: consumable
  usable: [move]
  effects:
    - op: forget_skill           # 反面：真的会把本事拿走
      skill: shield_bash
```

- **它是道具，所以开箱 / 事件 / 商店 / 战利品，凡能给道具的地方都能给技能**——**零新增通道**。
- **没有任何职业限制**：法师能读《盾击》，战士能读《治疗术》。
  > 编辑器在 `learn_skill` 行旁边显示被指技能的**人话预览**（"学会：用物攻打对方 `pdef`"），并校验它**已启用**。
  > 若玩家**已经会了**，游玩态直接提示"你已经掌握这招了"（书不消耗，避免浪费）。
- **恢复道具就是 `target: self` + `delta` 为正**，两种资源各有一瓶（量级同样按基线）：

| 道具 | `effects` | 在基线里的分量 |
|---|---|---|
| 红瓶 | `[{ target: self, stat: hp, delta: 5 }]` | 约 1/6 的初始点数预算 |
| 蓝瓶 | `[{ target: self, stat: mp, delta: 5 }]` | 同上；`mp` 默认是 0，所以蓝瓶往往比红瓶更"救急" |

- **消耗品现在能做"临时通行能力"了**：`add_tag` + `duration`（如"御火符 → `火抗` 3 回合"，§4.8.10）。
  但它**扛不起长期权限**（走 3 格就失效）；要当常备钥匙，还是做成占槽的装备
- **`mp` 恢复的唯一来源**在 MVP 里就是蓝瓶 + 分配点数：法术是有成本的（§4.8.3）

### 4.4 建筑 `building`
- 属于**地图件**：必须放到地图格才生效；可多格（`w`/`h` 在地图节点上）。
- **`cost` / `gate`**（可选）：和道路**同一套字段**（§4.5.1）——
  建筑加上 `gate: { tags: [钥匙] }` 就是一扇**锁着的门**，`cost` 也能扣血扣蓝。
  机制完全复用，不另发明。
- **`point_reward`**（可选）：结算时给玩家**几点自由属性点**（默认 0）——和怪物共用同一个字段（§4.8.8）。
- `encounter`: `empty | treasure | monster | event | shop`（基础行为，**五种**）

| `encounter` | 玩家踩到时发生什么 | 用哪些字段 |
|---|---|---|
| `empty` | 什么都不发生（纯装饰 / 占位） | — |
| `treasure` | 开箱给东西 | `reward_pool` ＋ `pick` / `copies` ＋ `mimic` |
| `monster` | 抽一只怪开打 | `monster_pool` |
| **`event`** | **门槛 ＋ 判定 ＋ 后果**（撬锁 / 陷阱 / 谜题 / 抉择） | **`event`**（§4.8.9） |
| **`shop`** | **用钱换东西** | **`stock` ＋ `price`**（§4.8.11） |

> **五种行为是并列的，不互相嵌套。** 想表达"锁着的宝箱屋"＝ `encounter: event` 的门槛 + 成功后 `goto`/`grant`；
> 想表达"打怪后开店"属于 P1 的复合事件，M1 不做。

- `event`（`encounter=event` 时）：**事件块** —— 门槛 `gate` ＋ 判定 `check` ＋ 后果 `on_success` / `on_fail`（完整结构见 §4.8.9）
- `stock` / `price`（`encounter=shop` 时）：**上架池 + 定价**（完整结构见 §4.8.11）；不写 `price` 就用前置配置 `shop.price`
- `reward_pool`（treasure 时）：奖励池，可混装备与消耗品（§4.8.5①）：
  ```yaml
  reward_pool:
    source: ids                 # ids = 手选 | filter = 从整个组件库里筛
    ids: [{ id: red_potion, weight: 5 }, { id: iron_sword, weight: 1 }]
    # source: filter 时写 filter: { itemKind: consumable, tags: [common] }
  ```
  **只保留其中"已启用"的道具**。
- `pick` / `copies`（可选）：**覆盖**前置配置的 `treasure` 抽取算法；**算法不写在建筑上**，写在 §4.8.6 的前置配置里。
- **`monster_pool`**（`encounter=monster` 时）：**怪物池，不是单只**（§4.8.5⑥）：
  ```yaml
  monster_pool:
    source: ids                 # ids = 手选 | filter = 从整个组件库里筛
    ids: [{ id: goblin, weight: 3 }, { id: slime, weight: 1 }]
    # source: filter 时写 filter: { tags: [cave] }
  ```
  踩到时**掷骰按权重抽一只**，再摇它的属性，然后开打。**想让房间固定出哥布林就只放哥布林**——单只 = 单元素池，不需要另开字段。
- `mimic`（可选）：`{ chance: 0~1, monster: id, reward_pool }`
  - **宝箱怪物机制**：在宝箱屋（`encounter=treasure`）下勾选后出现；按 `chance` 判定——命中则实为伪装怪物（先战斗），
    战胜后走**战利品算法 `loot`**；未命中走普通 `treasure` 开箱算法。
  - 这里用单只 `monster`（伪装成"这一个箱子里的那只怪"），不用池。
- `desc`

> **算法只在前置配置里定义一次**（§4.8.6 的 `treasure` / `loot`）：建筑和怪物**只提供"池"**，
> 想换算法就覆盖 `pick` / `copies`，不重复发明一套。

### 4.5 道路 `road`

道路是**地形件**：它不触发遭遇（那是建筑的事），它只回答两个问题——
**"走过去要付什么？"（消耗）** 和 **"凭什么能过去？"（权限）**。

#### 4.5.1 两个正交维度

| 维度 | 字段 | 含义 | 回答 |
|---|---|---|---|
| **消耗 `cost`** | 走这一格要付出什么 | 数值型资源扣减 | "走过去有多贵" |
| **权限 `gate`** | 走这一格需要什么 | 标签匹配 | "你有没有资格过去" |

**消耗 `cost`（可扣的资源就这三种）**

| 资源 | 字段 | 例 |
|---|---|---|
| 步数 | `step` | 沼泽 `2`；传送带 `0` |
| 血量 | `hp` | 荆棘路 `3` |
| 法力 | `mp` | 法术结界 `2` |

**权限 `gate`（标签匹配，不写死任何词）**

```yaml
gate:
  tags: [火抗]           # 需要哪些标签（默认"有任一即可"）
  mode: any              # any = 任一即可（默认） | all = 全都要
  missing: penalty       # 不满足时怎么办：block = 走不进去 | penalty = 能走但加罚
  penalty: { hp: 5 }     # missing=penalty 时的额外消耗
```

**完整写法**

```yaml
- id: swamp                  # 纯消耗：难行
  name: 沼泽
  icon: 🟫
  cost: { step: 2 }

- id: river                  # 消耗 + 硬权限：没船过不去
  name: 河流
  icon: 🌊
  cost: { step: 1 }
  gate: { tags: [渡河], missing: block }

- id: volcano                # 消耗 + 软权限：没火抗也能进，但掉血
  name: 火焰山
  icon: 🌋
  cost: { step: 1 }
  gate: { tags: [火抗], missing: penalty, penalty: { hp: 5 } }
```

#### 4.5.2 匹配机制（能力 = 标签集合）

```text
① 算玩家能力      capabilities = ⋃(穿戴中装备.tags) ∪ 当前职业.tags
② 看这一段路      gate = 这条道路的 gate（没写 gate 就直接通过）
③ 匹配            满足 = (gate.tags ∩ capabilities ≠ ∅)        ← mode: any
                        (gate.tags ⊆ capabilities)              ← mode: all
④ 分支            满足    → 按 cost 扣资源，走进这一格
                  不满足  → missing: block   → 走不进去
                            missing: penalty → 按 cost + penalty 一起扣
```

**能力只从"穿戴中装备"和"当前职业"来**（不做背包里带着就算、也不做消耗品当长期钥匙）：

- 想让某样东西当钥匙 → **把它做成装备**。小船占"手"、火抗鞋占"脚"，天然合理。
- 消耗品是一次性的，做不了长期权限，不进能力集合。

#### 4.5.3 为什么用标签，而不是写死"渡河""火抗"

因为**写死就把玩法框死了**。用标签，编辑器**不认识任何具体的词**，但机制照样成立：

| 你想做的 | 道路写 | 玩家需要拿出 |
|---|---|---|
| 河流 | `gate.tags: [渡河]` | 小船（`tags: [渡河]`） |
| 火焰山 | `gate.tags: [火抗]` | 火抗鞋（`tags: [火抗]`） |
| 毒沼 | `gate.tags: [解毒]` | 解毒草囊（`tags: [解毒]`） |
| 天空桥 | `gate.tags: [飞行]` | 羽翼斗篷（`tags: [飞行]`） |
| 魔障 | `gate.tags: [破魔]` | 破魔符（`tags: [破魔]`） |
| 王城大门 | `gate.tags: [王室]`，`mode: all` | 同时要有印章 + 通行令 |

**"火焰山 + 火抗鞋"是数据碰出来的，不是代码写出来的。** 用户造新标签就自动有新区块，编辑器不用改一行。

#### 4.5.4 记忆点

| 组件 | 消耗 | 权限 | 玩法差异 |
|---|---|---|---|
| 小路 `path` | `step: 1` | — | 基准 |
| 沼泽 `swamp` | `step: 2` | — | 走一格吃掉两步，逼你绕路 / 耗光回合 |
| 传送带 `belt` | `step: 0` | — | 不耗步，等于白走 |
| 河流 `river` | `step: 1` | `[渡河]` `block` | 没船就**过不去**，必须绕路或去搞装备 |
| 火焰山 `volcano` | `step: 1` | `[火抗]` `penalty hp:5` | 硬闯也能过，但**每格掉 5 血**，血少就是送死 |

- **不做的（明确记下来，避免又出现"配了没实现"）**：单向路、踩踏触发遭遇 / 传送。
  想"一踩就出事"就**铺一栋建筑在那格**——不要让道路背上遭遇，否则它就成了第二个建筑。
- 道路**不参与**技能 / `stats` / 力值链，它没有任何属性。
- **`cost` / `gate` 不是道路专属**：它们是**地图件（道路 + 建筑）的公共可选字段**——
  建筑加上 `gate: { tags: [钥匙] }` 就是一扇锁着的门，机制完全复用（§4.4）。

### 4.6 地图 `map`
- `name`
- `start: [x, y]`、`end: [x, y]`（每张图强制恰好一个）
- `nodes`: 每格一个映射 `{ x, y, type, ref?, w?, h? }`；`type ∈ start | end | road | building`：
  - `building` **必须带 `ref`** 指向建筑 id；
  - `road` **也必须带 `ref`** 指向道路 id——因为不同道路的 `cost` / `gate` 不同，不记 ref 就不知道这格要付什么、能不能过；
  - `start` / `end` 是画布内建标记，不带 `ref`。
- **建筑大小 `w`/`h`（单位：格，默认 1）放在地图节点上**，因此同一类型建筑可自由设定不同尺寸（如 2×2 仪式感宝箱屋、巨大的 Boss 宫殿）。**建筑与道路一样作为整块判定**，不再区分入口/出口方位。
- **可走图 = 已放置节点集合**（road + building + start + end），未放置格视为不可通行
- 多图有序；导出/游玩时上一张 `end` 自动成为下一张 `start`

### 4.7 项目 `project`（= 一局游戏的"内容"）

- `name`（= 游戏名）
- `background`（散文）
- `enabledIds`: `string[]` —— 本局**启用**的组件 id（消耗品 / 装备 / 怪物 / 职业 / 技能）
  > **注意这里没有"谁会什么技能"**：那是**游玩态数据**，进 `.psave` 不进 `.pmod`（§4.8.3）。
- `rules`: `{ move, combat, treasure, loot, class_pool }` —— **这一局的规则（前置配置）**，
  每个场景一套算法，完整清单见 **§4.8.6**
- `maps`: `map[]`（= 左栏「图层」列表，有序；建筑 / 道路的"铺设"就存在这里）

> **组件库不是 `project` 的一部分。** 库存独立的 localStorage key（`poprpg_library`），跨项目共享、长期存活，
> 里面同时装着系统预设和用户自建。`project` 只记"这一局用了库里的哪些"，**不存组件定义本身**；
> 因此改了库里的哥布林，所有用到它的局都会跟着变——这正是"库是工具来源"该有的行为。
>
> 导出 `.pmod` 时，把**用到的定义快照**嵌进 `## 设定` 段（§3.3），让文件自包含；
> 别人导入后这些定义**并入他自己的组件库**，之后就是他自己的资产了。

### 4.8 规则：前置配置 + 硬规则 + 每个场景的算法

> 这一节只回答一件事：**骰子在每个场景里到底怎么参与结算。**
>
> 分三层，边界必须清楚：
> 1. **硬规则**（§4.8.0）—— 玩法骨架，**写死在引擎里，不进配置，也不给开关**
> 2. **前置配置**（`## 规则配置`，完整清单见 §4.8.6）—— 每个场景**一套算法**，写进 `.pmod`
> 3. **内容**（组件上）—— 只有"池"和"数值"，不含算法
>
> **铁律：配置里出现的每一个字段，都必须是代码已经实现的。** 没有实现承诺的字段不许写进文档。

**场景索引——骰子只会在这 6 个地方出现：**

| # | 场景 | 节 | 用的骰子角色 |
|---|---|---|---|
| 1 | **交锋**（技能施放 / 对方对抗 / 对手反击） | §4.8.3 | 判定 |
| 2 | **移动**（定步数） | §4.8.4 | 数值 |
| 3 | **开箱 / 战利品**（件数 / 份数） | §4.8.5 | 数量 ＋ 数值 / 倍率 |
| 4 | **事件**（撬锁 / 陷阱 / 谜题） | §4.8.9 | 判定（`static`） |
| 5 | **状态**（每回合结算） | §4.8.10 | 不掷骰（纯 tick） |
| 6 | **商店**（定价） | §4.8.11 | 数值 |

#### 4.8.0 硬规则（不配置）

| 硬规则 | 内容 |
|---|---|
| **移动机制** | 只能走**正交四邻**（上下左右）；**不可斜走**；**可原路返回** |
| **移动代价** | 每进一格的消耗**由踩进去的那一格组件决定**（道路 `cost`，默认 `{ step: 1 }`）。机制是硬的，"代价多少"是内容 |
| **通行权限** | 每格可要求标签（`gate`）；匹配靠 `capabilities = ⋃(穿戴中装备.tags) ∪ 当前职业.tags ∪ 身上状态.tags`（§4.5.2）。**标签是自由文本，引擎不认识任何具体的词** |
| **回合（世界心跳）** | **一回合 = 一次"推进时间"的行动**，只有两类：**① 一次交锋**（玩家攻击回合 ＋ 怪物反击回合）**② 一次移动**（掷骰得 N 步，**整次算一个回合**）。**所有按回合结算的东西（状态、地形 `cost`）都在回合【开始】先判定、再 tick 一次**（见下方"回合开始时序"）——这样玩家在任何回合开头都有操作空间（如中毒扣到 0 也能先吃药救活） |
| **为什么移动算整次** | 若"走一格 = 一回合"，摇到 6 就要 tick 6 次、摇到 1 只 tick 1 次——**摇 6 反而比摇 1 更亏**，掷骰就失去了意义。所以**一次移动 = 一个回合** |
| **道具不占回合** | **使用道具是"回合内的自由动作"，不推进时间、不 tick**。所以探索和战斗时嗑药都是随时可以——**这正是它比技能强的地方** |
| **技能占回合** | **玩家施放一次技能（交锋的攻击回合）＋ 怪物反击（交锋的反击回合）= 一次交锋 = 一个回合**。所以"治疗术"要花一回合，而"红瓶"不花——**道具即时但量小，技能费力但量大**，两者的取舍就立住了 |
| **状态必有上限** | 任何状态都必须带 `duration`（剩余回合数），且**不得超过 `state.max_duration`**（§4.8.6）。**不存在永久状态**——没有解法的状态 = 死局（§4.8.10） |
| **技能决定维度** | 技能用 `dim` 指定"取哪一维属性"，用 `vs` 指定"对手拿哪一维对抗"（`auto` 时物理族对物理族、法术族对法术族）。**引擎不再写死"物攻→物防、魔攻→魔抗"**——那只是 `basic_attack` / `basic_magic` 两个**预设技能**的选择（§4.8.3） |
| **谁定技能** | **玩家侧：自己选**（从**自己学到的技能栏**里挑——技能栏靠后天学，§4.8.3）。**怪物侧：掷骰按权重随机**（否则玩家只堆一个维度就无敌） |
| **命中** | `target: opponent` 时 **本力值 ≥ 对方防值** 即命中；`target: self` 或 `vs: none` 时**不对抗、不落空** |
| **伤害 / 治疗** | 伤害 = **`max(1, 本力值 − 防值)`**；治疗 = **`本力值`**（不对抗，不乘算第二遍） |
| **属性点分配规则** | **1 点 = 该属性 +1**；可分配到 6 属性任意项；**任意时刻**都能加；**不可洗点**；**剩余自由点保留**。（**给多少点是职业设定，不是硬规则**，见 §4.2.1） |
| **属性来源** | **玩家 = 职业 `base_stats` ＋ 分配出的自由点**（确定值，不被骰子改）；**怪物 = `stats` 区间在登场时摇定**（§4.8.2 第一步） |
| **技能各有成本** | 选一个技能要先付它自己的 `cost`（如 `{ mp: 3 }`）；**不够就不能选**——不扣、不掷。**但两个保底技能 `cost` 为空 = 永远免费**（§4.8.3），所以**绝不存在"没蓝就等死"** |
| **资源归零** | **玩家 `hp ≤ 0` → 不在伤害 / buff 作用时即时死，而是在"回合开始存活判定"才败北**（给一回合缓冲吃药）；**怪物 `hp ≤ 0` → 伤害作用时即时败北**（立场在主角的设计，死亡规则不对称，见 §4.8.3 交锋结构）。**`mp` 不够 → 只是放不了"贵技能"，保底对照样能打**（保底对免费时） |

- **移动机制 vs 移动代价**是两个层次：机制（四邻 / 不斜走 / 可回头）写死在引擎；代价是那一格**组件自己的属性**，
  所以"小路"和"沼泽"是两个不同的道路组件，而不是一个全局开关。
- **技能的两侧不对称是故意的**：玩家主动选 = 有取舍；怪物掷骰随机 = 逼玩家把物防 / 法防都堆起来。
- **属性来源的两侧不对称也是故意的**：玩家点数分配（可控、可规划）；怪物区间摇定（有波动、小怪精英自然拉开档）。
- **回合开始时序（硬规则，两步）**：每个回合【开始】先 `(1) 存活判定` 再 `(2) 状态 tick`，然后才进入本回合行动——
  - ① **存活判定**：玩家 `hp ≤ 0` → 败北；怪物 `hp ≤ 0` → 即时败北（不再参与本回合）。
  - ② **状态 tick**：对所有在场单位执行 `per_turn` 增减、`duration -= 1`（归零移除）。**本回合中刚挂上的状态不参与本次 tick，下回合开始才首次生效**。
  - 为什么先判血再算 buff：玩家 1 滴血、中毒每回合 `-1`——回合开始先判"1 > 0 存活"，再 tick 毒扣到 0，但本回合玩家仍存活、可吃药救活；若把判定放在 tick 之后就会当场暴毙，失去操作空间。
  - 移动回合也走同一套开始时序（移动时踩到的场景 buff / 身上 debuff 同样在开头结算），所以"统一移到开头"才公平。

- **回合是全篇唯一的时间轴**：交锋与移动都走同一条轴，所以"中毒 3 回合"在任何场景下都指
  **再过 3 次推进时间的行动**（走完 N 步算一次，一次交锋算一次），不需要为战斗和探索各定义一套计时（§4.8.10）。
- **"推进时间"和"自由动作"的区别只此一条**：**占回合的**（移动 / 技能）会 tick 状态、会吃到地形的每格 `cost`；
  **不占回合的**（用道具）不会。**没有第三种。**

> 这些是玩法骨架，**不给配置项**。想改就是改玩法，不是改某张地图的配置。

#### 4.8.1 基础积木（三个纯函数，全篇复用）

**① `rollRange(range, dice)` —— 把骰点映射到区间**（取属性值 / 取件数 / 取份数）

```text
t     = (roll − diceMin) / (diceMax − diceMin)          # 归一化到 0 ~ 1
value = min + round( t × (max − min) )
其中  diceMin = count × 1 ,  diceMax = count × faces     # 1D6 → 1..6 · 2D6 → 2..12
```

- `min === max` → 直接取该值，不掷骰。
- 例：`patk: [3, 6]` + `1D6` → 掷 1 → 3，掷 3 → 4，掷 6 → 6。

**② `rollSteps(steps, dice)` —— 骰点查档位表，得到倍率**

```text
idx  = round( (roll − diceMin) / (diceMax − diceMin) × (steps.length − 1) )
mult = steps[idx]
```

例：`steps: [0.5, 1, 1, 1.5, 2, 3]` + `1D6`

| 掷出 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 倍率 | 0.5× | 1× | 1× | 1.5× | 2× | 3× |

**③ `rollSum(dice)` —— 骰子点数直接相加**（作力值的叠加项）

```text
add = 每颗骰点数之和        # 1D4 → 1..4 · 2D4 → 2..8
```

#### 4.8.2 属性结算 + 力值合成链

**第一步：属性结算（每个单位只做一次）**

**两边不一样，这是故意的**（§4.0.2）：

```text
怪物：登场时（遭遇开始）把 stats 区间摇成具体值
      statValue[k] = rollRange(单位.stats[k], stat_dice)
                        # k ∈ hp / mp / patk / matk / pdef / mdef
                        # stat_dice 来自前置配置（如 1D6）

玩家：职业给了起点，其余靠分配，全程不摇
      statValue[k] = 职业.base_stats[k] + 已经加到这一项上的自由点
```

- 玩家侧的属性**随时可能因为加点而变**（加点不可逆、可发生在任意时刻），但它**永远不是骰子决定的**。

- 例：哥布林 `patk: [2, 4]` + `1D6` → 掷 1~2 → `patk = 2`，掷 5~6 → `patk = 4`；
  **这只哥布林这一场就固定是那个数**。
- `hp` / `mp` 也这样摇定，作为**当前值 = 上限**。
- **"摇骰子摇出它的属性"只发生在这里**，一次摇定、本次遭遇内不再重摇。
- 玩家侧之所以不摇：玩家的属性是他自己一点一点分出来的，**不能被骰子改掉**（§4.2.1）。

**第二步：力值链（每次判定时）**

**攻值和防值都走同一条链**，只是取的属性维不同：

```text
① 属性值     stat  = 已结算的具体值（上一步得到的，这里不再掷骰）
② 加值       plus  = Σ装备.modifiers[维] + Σ状态.modifiers[维] + 技能.bonus   ← 加法
③ 职业加成   prof  = 职业.buffs[维] / 100                                    ← 乘法，默认 100 → ×1
④ 基础力值   base  = (stat + plus) × prof
⑤ 骰子叠加   add   = rollSum(add_dice)                                       ← 可省；省略 = 0
⑥ 骰子倍率   mult  = rollSteps(mult_dice)                                    ← 可省；省略 = 1
──────────────────────────────────────────────────────────────
   力值 = floor( (base + add) × mult )
```

**五类来源各占一环，谁也不能顶替谁：**

| 环 | 来源 | 形态 | 玩家 | 怪物 |
|---|---|---|---|---|
| ① 属性 | 已结算的属性值 | 具体数字 | **`base_stats` ＋ 分配点** | **`stats` 区间摇出来的** |
| ② 加值 | 装备 `modifiers` ＋ 状态 `modifiers` ＋ **技能 `bonus`** | **固定加值** | 铁剑 `patk +5`；力量祝福 `patk +2`；重击技能 `bonus: 3` | 0（怪物不穿装备、不挂增益） |
| ③ 职业 | 单位的 `buffs` | **百分比** | 法师 `matk: 130` | 1（怪物没职业） |
| ④ 骰子 | 前置配置的 `add_dice` / `mult` | 叠加 / 倍率 | `1D4` / `1D6` 查表 | 同左（可用 `atk_roll` 覆盖） |

> **注意 ① 是"已结算的值"而不是"再摇一次"**：属性一旦定下来就固定了，
> 每次判定重摇会让 `hp` 之类失去意义。战斗中的随机性来自 ⑤⑥ 两颗骰。

- **② 是"加法环"——三样东西都往这里塞**：装备（长期）、状态（限时）、技能（本次施放的加成）。
  **"0 加成的普通攻击"就是 ② 里技能那一项为 0**（§4.8.3）——它能打人，全靠 ① 的属性值。
- **加法和乘法位置不同，不能互换。** 这就是"装备 / 状态 / 技能 / 职业都要吃进去"的落点。
- **骰子在链上可插两处**：**⑤ 加法（叠加到力值上）** 与 **⑥ 乘法（力值倍率）**——
  即"骰子可以拿来做攻击力或者防御力的叠加，也可以算作倍速"。
- **无骰时骰子项取"中性值"**：不掷骰则 ⑤ 加法 = `0`、⑥ 乘法 = `1`——也就是只用**固有数值**（属性值 ① ＋ 装备 ② ＋ 职业% ③ ＋ 状态 mod ④）。
  这正是"玩家反击回合不点击防御"的落点：不防御 ≠ 防值为 0，而是**少了骰子的浮动，仍按身上固有数值计算**（固有部分不受主观动作改变）。
- **怪物**没有装备和职业 → ② = 0、③ = 1，只走 ①④⑤⑥；**玩家**没穿装备 → ② = 0，没选职业 → ③ = 1。
- **取哪一维、和谁对抗，由技能决定**（`skill.dim` / `skill.vs`，§4.8.3）——力值链本身不关心维度的含义。

#### 4.8.3 技能：取哪一维属性、打哪个对象

> **技能不是新机制，它是力值链的一次"参数化调用"。** 一个技能只回答三件事：
> **① 用哪一维属性当基准（`dim`）② 作用到谁（`target`）③ 附带什么（`effects`）**。
> **攻击、治疗、增益、诅咒全是这三种选择的组合——不是四套代码。**

**保底对：两个 0 加成的基础技能（一切的参照系，且永远免费）**

| 技能 | `dim` | `target` | `bonus` | `cost` | 含义 |
|---|---|---|---|---|---|
| **普通攻击** | `patk` | `opponent` | `0` | **空** | **纯靠物攻属性打人**，技能本身什么都不加 |
| **普通法术** | `matk` | `opponent` | `0` | **空** | **纯靠魔攻属性打人**，技能本身什么都不加 |

> **这两个是"保底对"，是我们预设模板按理想化设计给所有职业的兜底技能，且都免费**（§4.8.3 保底规则）：
> - **只给物理** → 敌人法抗低你也没辙，一个维度打到底
> - **若把"普通法术"也设成要花 `mp`** → **`mp` 花完就只能靠 `basic_attack`**，
>   但只要保底对（`basic_attack` + `basic_magic`）的 `cost` 保持为空，就**永远有免费技能可打**，不会等死
>
> 所以（**默认模板角色**）：**开局技能栏 = `[basic_attack, basic_magic]`，两个 `cost` 都是空**——
> "打不了架"和"没蓝等死"这两种死局同时被堵死。
> **这是给"模板 / 内建角色"的默认安全网**：自创角色或作者可以在游戏设计里移除保底对（或改其 `cost`），
> 不阻止——删了 / 改了之后两边（玩家技能栏、怪物回退）都可能失去攻击手段，是否出现死局由作者负责，这是玩法的一部分。
>
> **免费 ≠ 无差别**：两者差别在 **`dim`**（用哪一维属性）——对法师来说 `matk` 高，
> 对战士来说 `patk` 高，**先天的百分比差异照样起作用**（§4.2.3）。
> **有成本的技能是"更强"，不是"能不能打"**（花 `mp` 买的是 `bonus` / `effects` / 倍率）。

**技能的全部字段**

```yaml
- id: basic_attack
  name: 普通攻击
  icon: ⚔️
  dim: patk              # ① 基准维度：力值链取哪一维属性（这就是"技能表示维度"）
  target: opponent       # ② 作用对象：opponent（打人）| self（对己）
  vs: auto               # ③ 对手用哪一维对抗：auto = 按 dim 自动配对 | none = 不对抗，直接生效 | 具体维
  bonus: 0               # ④ 技能自身加值（"0 加成" = 纯靠属性，技能只是个载体）
  apply: hp              # ⑤ 力值作用到哪：hp（伤 / 治）| mp | none（只挂效果）
  cost: {}               # ⑥ 施放成本（默认免费；**保底对必须留空**）
  effects: []            # ⑦ 附带效果：挂 buff / debuff（§4.8.10，与消耗品同一套）

- id: basic_magic
  name: 普通法术
  icon: ✨
  dim: matk              # ← 与普通攻击的唯一结构差别：换一维
  target: opponent
  vs: auto               # matk → mdef
  bonus: 0
  apply: hp
  cost: {}               # ← **一样是空的**：没 mp 也能放，不会等死
```

**`auto` 的配对规则（硬规则，不给配置）**

```text
dim = patk / pdef  →  vs = pdef / patk      物理族对物理族
dim = matk / mdef  →  vs = mdef / matk      法术族对法术族
```

**"自然演化"——同一套字段，七种技能**

| 想要什么 | `dim` | `target` | `vs` | `apply` | `effects` | 力值链怎么走 |
|---|---|---|---|---|---|---|
| **物理攻击** | `patk` | `opponent` | `auto`→`pdef` | `hp` | — | 与对手 `pdef` 对抗 |
| **法术攻击** | `matk` | `opponent` | `auto`→`mdef` | `hp` | — | 与对手 `mdef` 对抗；**是否付 `mp` 由该技能自己的 `cost` 决定**（保底对 `basic_magic` 的 `cost` 设为空，故免费） |
| **治疗自己** | `matk` | **`self`** | `none` | `hp` | — | **不对抗、不落空**，回血量 = 力值 |
| **对自己上增益** | `patk` | **`self`** | `none` | `none` | `add_tag: 力量` | 不对抗，只挂状态 |
| **对对手上减益** | `matk` | `opponent` | `auto` | `none` | `add_tag: 虚弱` | **命中才挂，不中不挂** |
| **吸血 / 毒击** | `patk` | `opponent` | `auto` | `hp` | `add_tag: 中毒` | 打中 + 附带状态 |
| **回蓝** | `matk` | `self` | `none` | `mp` | — | 回自己 `mp`（**`cost` 由作者定，可含 `mp`——例如花 1 回 5，净赚；自由度交给制作者**） |

> **这就是"允许挂 buff"**：`effects` 用的就是 §4.8.10 那套五个 `op`（`add_stat` / `add_tag` / `remove_tag` / `learn_skill` / `forget_skill`）——
> **消耗品、技能、事件三处共用全部五 `op`，怪物命中只用其中三种**（不可教 / 夺技能，见 §4.1），不另发明。
>
> 用户造一个新技能，就是**选一维 + 选个对象 + 加个效果**，编辑器不需要认识"火球术"这个词。

**谁会什么技能——职业不管这个，全靠后天**

> **铁律：职业不限定技能。** 角色是**先天**的（职业给属性起点与优劣百分比，§4.2.3），
> 但**长成什么样是玩家自己走出来的**——学什么技能，由**事件与环境**决定，不由出生决定。

| 谁 | 技能从哪来 |
|---|---|
| **玩家（默认模板）** | **后天学会的**。开局只有**保底对 `basic_attack` ＋ `basic_magic`**（内建，不算组件，是默认模板的安全网），其余全靠 `op: learn_skill`（§4.8.10）： |
| | · **技能书**——一件**普通消耗品**，`effects: [{ op: learn_skill, skill: fireball }]`。**开箱、事件、商店、战利品，凡能给道具的地方都能给技能** |
| | · **事件后果**（`on_success.effects`）——"石碑上传你一招""老人临终托付" |
| | · **怪物战利品**（`reward_pool` 里放一本技能书）——"打赢它，捡到它的功法" |
| **怪物** | **`attack_weights` 的键就是技能 id**（§4.1）——`{ basic_attack: 3, poison_bite: 1 }` |
| **保底对** | **默认模板角色**技能栏**包含 `basic_attack` ＋ `basic_magic`，两个 `cost` 都为空**（免费）——**既不会"打不了架"，也不会"没蓝就等死"**。**职业不给技能；保底对是给模板角色的默认安全网，作者可在设计里移除或改 `cost`（自创角色不受影响）**——但移除后要保证角色仍有可打的技能 |
| **失去** | `op: forget_skill` 能**夺走**技能——**环境和运气不好，真的会把你的本事拿走** |

> **零新增通道**：因为技能书就是道具，**所有现有"给东西"的机制自动都能给技能**——
> 奖励池（§4.8.5）、事件后果（§4.8.9）、商店（§4.8.11）、战利品，一个都不用改。

**"法师练成战士"是被允许的，而且代价真实可见：**

```text
起点（先天）    法师：patk 0，职业 patk 百分比 ×0.8      ← 物理天生打八折
后天（自己的）  属性点全砸 patk  →  在废墟里捡到《盾击》 →  又把铁剑抢到手
结果            他确实能砍人了，但永远背着那个 ×0.8
```

> **这就是"顶着 debuff 努力向前"**：职业的 `buffs` 百分比是**先天的牌面**（§4.2.3），
> **它不会因为你努力就消失**。玩家的乐趣正是**用后天的选择去对抗先天发到的牌**——
> 出一个"靠后天硬拗成战士的法师"，比出一个"按模板长的法师"有意思得多。

**"已学会哪些技能"是游玩态数据，不进 `.pmod`：**

| 数据 | 存在哪 | 说明 |
|---|---|---|
| 技能**定义** | **组件库 / `.pmod` 的 `## 设定`** | 这一局**世界里存在**这个技能（可被学、被怪物用、被写成书） |
| "谁**已学会**它" | **`.psave`** | 玩家技能栏是进度，不是场景（§7.3） |

> **技能的"启用"= 这一局世界里有没有这招**，不是"谁会"。
> 未启用的技能：不能被学、不能被怪物用、写进技能书里也是死引用（§5.7 会标红）。

> **技能是组件库的第七类（§4.0），不是前置配置。**
> 它有名字、图标、维度、目标、效果，和道具 / 怪物一样需要 DIY 与管理，也该有"启用 / 未启用"。
> **因此前置配置里不再有 `combat.attacks`**（§4.8.6）——技能表已升级为组件。

**一次施放的结算（6 步）**

```text
① 选技能      玩家自己选 / 怪物掷 pick_dice 按 attack_weights 加权随机（见下）
② 查成本      不够 → 不能选（不扣、不掷）；够 → 扣掉
③ 算本力值    力值 = 力值链(施放者, atk_roll, skill.dim) + skill.bonus      ← §4.8.2
④ 判定分支
     target = self 或 vs = none  →  跳过判定，直接进 ⑤
     target = opponent           →  对手掷 防值 = 力值链(对手, def_roll, skill.vs)
                                    命中 = 本力值 ≥ 防值；**不命中 → 本次施放不造成作用、不挂 effects（⑤⑥ 不执行）**，
                                    但交锋仍进入对手的反击回合（见下）
⑤ 作用        apply = hp   → 伤：对手扣 max(1, 本力值 − 防值) / 治：自己回 本力值
              apply = mp   → 同上，作用在 mp 上
              apply = none → 跳过（纯 buff 技能）
⑥ 附带效果    逐个执行 effects（**只有命中才执行**）
```

**一次交锋 = 两个半回合（玩家攻 → 怪物反击），双方各掷骰，玩家攻 / 防都主动点击：**

```text
① 玩家攻击回合（玩家主动）
   - 玩家选技能 → 查 cost（不足不能选）
   - 玩家【点击"攻击"】→ 引擎掷 atk_roll（add_dice + mult）→ 本力值
   - 怪物由电脑掷 def_roll → 防值；判定 / 作用 / 挂 effects
       · 不命中 → 本次施放不生效，但交锋仍进入 ②（不终止）
       · 命中且把怪物打到 hp≤0 → 怪物即时败北（伤害作用时即死），交锋直接结束，不进入 ②（怪物不会"死后再反手打你一下"）

② 怪物反击回合（换防，电脑出手）
   - 怪物由电脑掷 pick_dice 按 attack_weights 选技能 → 查 cost
       · 选到的技能 cost 不足（如 mp 不够）→ 回退该怪物 attack_weights 中 cost 为空的技能，再无则本次反击跳过（若怪物根本没配 `attack_weights`，则用引擎内建 `basic_attack`——cost 为空、与玩家保底对组件无关，作者删组件不影响怪物兜底，见 §4.1）
   - 怪物由电脑掷 atk_roll → 本力值
   - 玩家【点击"防御"】（主动动作）→ 引擎掷 def_roll → 防值；判定 / 作用 / 挂 effects
       · 玩家**主动选"不防御"** → 不掷 def_roll，防值 = 固有数值（属性值＋装备＋职业%＋状态 mod，无骰浮动），仍按此计算

③ 整次交锋结束 → 无额外 tick（tick 已在回合开始做过一次，见 §4.8.0）
```

- **所有"电脑掷骰"（怪物 atk / def / pick）结果都必须在战斗 UI 公示**——玩家能看到怪物掷了什么、为什么这么打。
- **玩家攻 / 防都是主动点击，引擎会等待**：这是单人游戏，**除非特殊场景设计，否则没有倒计时**——玩家不点攻击 / 防御，回合就停在那等他，不会因"没操作"而超时跳过。
  - 点"防御" → 引擎掷 `def_roll` 获得骰浮动减伤；
  - 玩家**主动选择"不防御"** → 不掷 `def_roll`，防值走**固有数值**（属性值 ①＋装备 ②＋职业% ③＋状态 mod ④，无骰浮动）。**不是 0，只是少了骰子的浮动**。攻 / 防两个点击（或"不防御"抉择）构成一次交锋里玩家的主动操作。
- **怪物登场（每次遭遇实例化时摇一次，绝非每回合重摇）**：玩家每次踩到怪物格、生成出一只具体的怪物实例时，先掷"选怪骰"从 `monster_pool` 抽哪只，再用 `stat_dice` 把它的属性区间摇成具体值（波动、不锁死）。
  - **同一只怪物的整场战斗不再重摇**（我们反对的是"每回合都摇怪物属性"）；
  - **但不同遭遇各自独立摇**——场景 A 的哥布林摇过一次，场景 B 再遇到哥布林是另一只实例，**同样要重新随机**。不是"全局只摇一次"；
  - 属性浮动默认共用 `stat_dice`；进阶可给各属性分别配独立骰子（多个骰子分别摇各属性区间），都是"实例化时摇一次、整场不重摇"。

- **`target: self` 的技能不对抗、不会落空**，但**仍然掷骰**——因为骰子决定治疗量 / 加成量（力值链 ⑤⑥）。
- **伤害恒为 `max(1, 本力值 − 防值)`，治疗恒为 `本力值`**，两者都不再乘算第二遍。
- `mp` **不参与力值链**——它是"选这个技能的入场券"，不是攻防数值（§4.0.1）。

**谁能挑技能？—— 两侧故意不对称**

| 侧 | 怎么定 | 为什么 |
|---|---|---|
| **玩家** | **自己选**（从**自己学到的技能栏**里挑，§4.8.3） | 有取舍才有策略 |
| **怪物** | **掷骰按权重随机** | 若怪物会什么就固定用什么，玩家只要堆对应那一维防御就无敌了 |

**怪物的技能权重表**（写在怪物组件上，键 = 技能 id）：

```yaml
attack_weights:
  basic_attack: 3        # 权重 3
  poison_bite: 1         # 权重 1（一个自带 `中毒` 的 `effects` 的技能）
```

**选法（加权轮盘，复用 §4.8.1 的积木）**：

```text
① 掷 pick_dice → roll
② t = rollRange([1, Σ权重], pick_dice)                ← 把点数映射到 1..总权重
③ 按 attack_weights 的书写顺序累加，第一个让「累计权重 ≥ t」的技能被选中
```

- 只有一项（`{ basic_attack: 1 }`）时不必掷骰，直接用。
- 玩家侧若也想随机（AI / 懒惰模式），同一套选法即可，权重表挂在玩家身上。

**掷骰次数**：一次施放 = **2 组力值骰**（自己 1 组、对手 1 组）；
`target: self` 时只用 **1 组**；怪物还有多项技能时再加 **1 次 `pick_dice`**。

> **旧模型的对应关系**：`combat.attacks.phys` → 技能 `basic_attack`；
> `attacks.magic` → 技能 `basic_magic`；`attacks[x].cost` / `roll` → 技能自己的 `cost` / `roll`。
> **技能只是把"攻击方式"从配置里搬进了组件库，判定结构一点没变。**

#### 4.8.4 移动

```yaml
move:
  dice: 1D6            # 每回合掷这颗骰，点数就是本回合可走的格数
```

**配置就这一个字段。** 移动机制（正交四邻 / 不可斜走 / 可原路返回）是硬规则（§4.8.0）。

**每格的消耗与权限**都不在这里配——它们是**那一格上组件自己的属性**（道路 `cost` / `gate`，§4.5）。

**走一格的完整判定（3 步）**

```text
① 权限检查   capabilities = ⋃(穿戴中装备.tags) ∪ 当前职业.tags          ← §4.5.2
             这一格组件有 gate 吗？
               没有           → 直接过
               有且满足        → 过
               有且不满足      → missing: block   → 走不进去，这一步作废
                                 missing: penalty → 过，但要额外付 penalty
② 扣消耗     从本回合步数里扣 cost.step（默认 1）
             cost.hp → 扣血；cost.mp → 扣蓝
③ 结算该格   若该格是 building → 按 encounter 触发（treasure → §4.8.5；monster → §4.8.3；
             event → §4.8.9；shop → §4.8.11；mimic 先按 chance 判定）
```

**回合流程**

1. 开局站在 `start`
2. 每回合掷 `move.dice` → 得本回合步数
3. 按上面 3 步走格（一次一格，只能走正交四邻）
4. 走到 `end` → 本张图通关，进入下一张图（起点自动接上一张终点）
5. 步数用完 → 回合结束

> **消耗 vs 权限是两个独立开关**：沼泽是纯消耗（走得慢），河流是硬权限（没船过不去），
> 火焰山是软权限（没火抗也能硬闯，但每格掉血）。三者组合出来的地形，用户自己造。

#### 4.8.5 开箱与战利品：池 + 抽取算法

**算法在前置配置里定**（`treasure` / `loot` 各一套），**池在组件上写**。

**① 池（写在建筑 / 怪物组件上）—— 三种池共用同一个结构**

```yaml
# 奖励池（宝箱 / 战利品）
reward_pool:
  source: ids                 # ids = 手选 | filter = 从整个组件库里筛
  ids: [{ id: red_potion, weight: 5 }, { id: iron_sword, weight: 1 }]
  filter:                     # source=filter 时生效
    itemKind: consumable      # 限定 消耗品 / 装备
    tags: [common]            # 限定标签

# 怪物池（怪物房用）：踩到就从池里抽一只出来打
monster_pool:
  source: filter              # 例如"全部洞穴怪"
  filter: { tags: [cave] }
```

- `source: ids` —— 池就是列出来的这几项（**只保留其中"已启用"的**）。**单只怪物就是一个元素的池**，不用再单独开一个"固定怪物"字段。
- `source: filter` —— 遍历组件库里**所有已启用**的对应类型，留下满足 `filter` 的。
  **上百来个道具 / 几十只怪物的大地图就靠这个**，不用手动一件件挑。
- 池里每项可带 `weight`：`{ id: goblin, weight: 3 }`；写纯 id 视为权重 1。**权重越大越容易被抽到。**
- 三个字段名固定：`reward_pool`（奖励）/ `monster_pool`（怪物），结构完全相同。

**② 抽取算法（写在前置配置里，`treasure` 与 `loot` 各一套）**

```yaml
treasure:                              # 开箱
  pick:
    algo: tiers                        # tiers = 骰点落档 | count = 掷骰映射到区间
    dice: 1D6
    tiers:
      - { upto: 2, n: 0 }              # 1~2 → 空箱
      - { upto: 4, n: 1 }
      - { upto: 6, n: 2 }
  copies:
    algo: multiplier                   # multiplier = 骰点查档 | value = 掷骰映射到区间 | fixed = 固定
    dice: 1D6
    steps: [1, 1, 1, 2, 2, 3]          # → 每件 1~3 份
```

**③ 完整算法（5 步，一步都不能省）**

```text
① 定池      source=ids    → ids 里"已启用"的那几件
            source=filter → 组件库里"已启用"且满足 filter 的全部道具
            |池| = 0 → 直接结束，产出为空（游玩态提示"这箱子是空的"）

② 定件数 n  掷 pick.dice → 从上往下找第一个 upto ≥ 点数的档 → n
            pick.algo=count 时改为 n = rollRange(range, dice)
            （该档可以写 0，就是空箱）

③ 夹紧      n = min(n, |池|)        ← 件数永远不会超过池的大小

④ 抽件      按 weight 加权、不放回，从池里抽 n 件

⑤ 定份数    每件掷 copies.dice：
              fixed      → n
              value      → rollRange(range, dice)
              multiplier → rollSteps(steps, dice)
            产出 = [{ itemId, count: 份数 }, ...]
```

**④ 为什么没有 `all`**

早期草案里有 `pick.algo: all`（池里全给）。**已删除**：
池一旦来自 `source: filter`（比如"全部消耗品"上百件），`all` 会把整个仓库倒给玩家。

想要"全给"就把池写成显式 `ids`、`n` 给一个足够大的数——**反正第 ③ 步会把它夹到 `|池|`**。

**⑤ 战利品与开箱的关系**

- **算法内核完全相同**（同一套 `pick` + `copies`），但**两套独立配置**：
  `treasure`（踩到建筑触发）与 `loot`（战斗胜利触发）。
- 分开的理由：开箱可以"开出空箱"，战利品一般不会；两者档位也往往不一样。
- **组件可覆盖**：建筑 / 怪物上写自己的 `pick` / `copies`（§4.8.7），不写就用对应场景的前置配置。

**⑥ 怪物池怎么抽（怪物房用）**

怪物房不写死一只怪。踩到时走**同一套加权抽取原语**，只是抽取数量固定为 1：

```text
① 定池      monster_pool（ids 手选 / filter 筛全库，只留已启用怪物）
            |池| = 0 → 空房间，不触发战斗
② 掷骰      t = rollRange([1, Σ权重], combat.pick_dice)      ← 复用 §4.8.1① 与 §4.8.3 的加权轮盘
③ 选出      按书写顺序累加权重，第一个「累计权重 ≥ t」的那只被选中
④ 属性结算  对选中的怪掷 stat_dice 摇出 6 属性具体值（§4.8.2 第一步）
⑤ 开打      §4.8.3
```

- **"摇骰子随机选怪 → 摇骰子摇出它的属性"两步都在这里**，一次遭遇各摇一次。
- 想让怪物房固定出哥布林 → 池里只放哥布林（`ids: [goblin]`），第 ② 步只有一个候选，等价于不掷。

#### 4.8.6 前置配置完整清单（`.pmod` 的 `## 规则配置`）

**这就是全部，一个不多：**

```yaml
## 规则配置
move:
  dice: 1D6                      # 每回合掷骰定步数（每格的消耗与权限看那格道路的 cost / gate）
combat:
  # 没有 attacks —— "攻击方式"已升级为**技能组件**（见 `## 设定 → 技能`，§4.8.3）
  stat_dice: 1D6                 # 属性结算骰：怪物登场时把区间摇成具体值（一次摇定）
  pick_dice: 1D6                 # 怪物随机挑技能时掷的骰
  atk_roll:                      # 攻方力值链上的骰子
    add_dice: 1D4                # 可省
    mult:                        # 可省
      dice: 1D6
      steps: [0.5, 1, 1, 1.5, 2, 3]
  def_roll:                      # 守方力值链上的骰子
    add_dice: 1D4
treasure:                        # 开箱算法
  pick:   { algo: tiers, dice: 1D6, tiers: [{ upto: 2, n: 0 }, { upto: 4, n: 1 }, { upto: 6, n: 2 }] }
  copies: { algo: multiplier, dice: 1D6, steps: [1, 1, 1, 2, 2, 3] }
loot:                            # 战利品算法
  pick:   { algo: count, dice: 1D6, range: [1, 2] }
  copies: { algo: fixed, n: 1 }
state:                           # 状态上限（§4.8.10）
  max_duration: 10               # 任何状态的 duration 都会被夹到不超过这个值
shop:                            # 商店默认定价（§4.8.11）；组件可用自己的 price 覆盖
  price: { algo: value, dice: 1D6, range: [5, 15] }
event:                           # 事件默认判定（§4.8.9）；组件可用自己的 check 覆盖
  dice: 2D6                      # 只提供默认骰，目标值在事件组件上（那是内容）
class_pool: [knight, mage]
```

**删掉了哪些字段，以及为什么**

| 删掉的字段 | 原因 |
|---|---|
| `move.mode` / `steps` / `free` | 移动只有"掷骰定步数"一种形态，其它是我凭空发明的选项 |
| `move.allow_back` / `diagonal` | **本来就是硬规则**（§4.8.0），写死。给了开关就是在问"用户把 `diagonal` 设成 `true`，你代码写了没" |
| `move.cost`（全局每格代价） | 每格代价是**那一格组件自己的属性**（`Road.cost`），属于内容，不是全局配置；全局配一个就等于所有路一个样 |
| `dice.available` / `dice.default` | **全局兜底骰**是隐式默认，删掉——每个场景算法**自己带骰子**（`move.dice` / `event.dice` / `treasure.pick.dice` …），下拉候选是 UI 的事，不进文件 |
| `hit.success` | 命中恒为"`本力值 ≥ 对方防值`"（`target: opponent` 时） |
| `damage.algo`（`diff` / `subtract` / `multiply`） | 收敛成**一条力值链**（§4.8.2）：骰子插在链的 ⑤加法 与 ⑥乘法 两处，伤害恒为 `max(1, 攻值 − 防值)` |
| `pick.algo: all` | 会倒仓库（§4.8.5 ④） |
| `crit` / 大成功大失败 | **没有实现就不配** |
| `monster_ref`（单只） | 换成 `monster_pool`（池 + 权重 + 掷骰抽），**单只 = 单元素池**，不必开两个字段 |

**又加回来了什么（以及为什么）：**

| 加回的字段 | 原因 |
|---|---|
| `event`（事件默认判定） | 上一版以"没实现"为由删掉了 `static` 判定，结果**撬锁 / 陷阱 / 谜题 / 抉择整类玩法做不了**（§4.8.9）。行为种类从 3 种（空 / 给东西 / 打架）扩到 5 种（＋事件 / 商店） |
| `state.max_duration` | 状态必须有上限，否则没有解法就是死局（§4.8.10） |
| `shop`（默认定价） | "卖多少"必须有个全局兜底，否则每个商店都要自己写价格（§4.8.11） |

**配置项总账**：`move` ×1　`combat` ×4（`stat_dice` / `pick_dice` / `atk_roll` / `def_roll`）　`treasure` ×2　`loot` ×2　`state` ×1　`shop` ×1　`event` ×1　`class_pool` ×1 —— **共 13 项**。

> **技能不在这一章**：它已升级为**组件库的第七类**（§4.0），因为它有名字、图标、维度、目标、效果，
> 需要 DIY 与管理，也该能"启用 / 未启用"。前置配置只留**力值链的骰子**（`atk_roll` / `def_roll`）与**属性结算骰**。

> **注意 `class_pool` 只是"用哪些职业"，"给多少点"在职业自己身上**（`base_stats` / `free_points`，§4.2.3）——
> 那是**内容**，不是前置配置。所以"开局 300 点"不会污染这张清单。

#### 4.8.7 组件可以覆盖什么（+ 组件自己的差异化字段）

**能覆盖前置配置的：**

| 组件 | 能覆盖 | 不能覆盖 |
|---|---|---|
| **怪物** | `atk_roll` / `def_roll`（力值骰）、`stat_dice`、`reward_pool`、`pick` / `copies`、**它自己的技能表 `attack_weights`** | 命中判定、伤害公式（**技能只改"取哪一维、打谁"，改不了这两条**） |
| **建筑** | `reward_pool`、`monster_pool`、`pick` / `copies`、**`event.check`**（事件判定骰）、**`price`**（定价）、`stock`（上架池） | 同上 |
| **职业** | —（`base_stats` 是起点、`buffs` 自动进力值链 ③、`tags` 进能力集合、`inventory_size` 定背包、`starting_items` 给家当。**职业完全不碰技能——技能是后天的**） | — |
| **装备** | —（`modifiers` 自动进力值链 ②） | — |
| **道路** | —（**它本来就是内容**：`cost` / `gate`，§4.5） | — |
| **消耗品** | —（`effects` 是内容：改数值 / 挂状态 / 解状态，§4.8.10） | — |
| **技能** | —（`dim` / `target` / `vs` / `bonus` / `apply` / `effects` **全是它自己的内容**，§4.8.3） | 命中判定、伤害公式 |

**各组件自己的差异化字段（这就是每个分组"为什么值得单列"的答案）：**

| 组件 | 差异化字段 | 差异举例 |
|---|---|---|
| **道路** | `cost`（消耗）+ `gate`（权限） | 沼泽（慢）/ 河流（没船过不去）/ 火焰山（没火抗掉血） |
| **建筑** | `cost` + `gate` + `encounter` + `event` + `reward_pool` / `monster_pool` / `stock` + `mimic` | 宝箱屋 / 怪物房 / **事件（上锁的门、陷阱、抉择）** / **商店** / 有宝箱怪物的屋子 |
| **怪物** | `stats`（6 属性区间）+ `attack_weights`（会哪些技能）+ `effects`（命中施状态）+ `reward_pool` + `point_reward` | 小怪（低区间、给 1 点）/ 精英（高区间 + `tags:[精英]`、给 5 点）/ **毒牙哥布林（会 `poison_bite`，打中你 → 中毒）** |
| **技能** | **`dim`（取哪一维）+ `target`（打谁）+ `vs`（对手拿哪一维防）+ `bonus`（加值）+ `apply`（作用到 hp/mp/无）+ `effects`（挂啥）** | **普通攻击（0 加成）/ 治疗术（`target: self`）/ 力量祝福（`apply: none` + `modifiers`）/ 虚弱诅咒（`target: opponent` + 减益）/ 吸血（伤害 + 挂状态）** |
| **装备** | `slots` + `modifiers` + `tags` | 铁剑（物攻 +5）/ 火抗鞋（`tags:[火抗]`）/ 小船（`tags:[渡河]`，但占手） |
| **消耗品** | `usable` + `effects` | 红瓶（回 `hp`）/ 蓝瓶（回 `mp`）/ 解毒剂（`remove_tag`）/ 御火符（临时 `火抗`） |
| **职业** | `base_stats` + `free_points` + `buffs`（百分比）+ `tags` + `inventory_size` + `starting_items` | 骑士（`patk:120`，物理向）/ 法师（`matk:130` 且 `patk:80`——**物理一辈子打八折**）。**职业没有 `skills`**（§4.2.3） |

- 不覆盖时一律用前置配置里对应场景的那一套（`combat` 的骰子 / `treasure` / `loot` / `event` / `shop`）。
- 例："这只 BOSS 攻骰 2D6、防骰 1D4" = 在怪物上写 `atk_roll` / `def_roll`；
  "这个宝箱只出手选的那几件" = 在建筑上写 `reward_pool.source: ids`；
  "这只怪会普通攻击也会下毒" = 在怪物上写 `attack_weights: { basic_attack: 3, poison_bite: 1 }`。

#### 4.8.8 属性点产出 `point_reward`（"打完怪能加点"）

**这就是"后续战斗也会得到属性点"的落点**——玩家变强的主渠道。

```yaml
# 怪物组件（也可以写在建筑上）
- id: goblin
  # ……
  point_reward: 1        # 打赢给 1 点自由属性点

- id: goblin_king
  tags: [精英]
  # ……
  point_reward: 5        # 精英给 5 点
```

| 项 | 规则 |
|---|---|
| **字段** | `point_reward`（整数，默认 `0`） |
| **挂在哪** | **怪物和建筑的公共可选字段**（打怪、开箱都可能给点），和 `cost` / `gate` 同级 |
| **触发时机** | 战斗胜利 / 开箱结算时 |
| **给到哪** | **直接加进玩家的"剩余自由点"**，玩家随后在任何时候分配（§4.2.2） |
| **掷骰吗** | **不掷**。它是固定值 |

**为什么固定不掷骰**：`point_reward` 是**这一局的节奏设计**（打多久能变多强），
不是"这一次运气如何"。想要不同强度，就设不同档位的怪物给不同点数——
**小怪 1 点 / 精英 5 点**，靠内容拉开，别靠骰子。

> 和 `cost` / `gate` 一样：它是**内容**（组件自己的属性），不是前置配置（§4.8.6 清单里没有它）。

#### 4.8.9 事件判定：门槛 + 手艺（撬锁 / 陷阱 / 谜题 / 抉择）

> **为什么要有这一节**：建筑原来只有 `empty / treasure / monster` 三种行为，"给东西"和"打一架"。
> 石碑、上锁的门、陷阱、商人、剧情抉择全都造不出来。本节补上第五种行为 `event`，
> 并**把 `static` 判定加回判定体系**（§4.8.6 里曾被删掉的那条）。

**事件 = 两层，各自独立：**

| 层 | 字段 | 作用 | 回答的问题 |
|---|---|---|---|
| **① 门槛** | `gate` | **资格**：没带对应标签，连"尝试"的选项都不给 | "你**能不能**碰这件事" |
| **② 判定** | `check` | **手艺**：掷骰 + 加值 vs 固定难度 | "你**做不做得成**" |

**两层都可以单独省。** 只写 `gate` = "有钥匙就能开"；只写 `check` = "谁都能试，看手艺"；
两个都写 = "得先有钥匙，然后还得看手艺"；**两个都不写 = 这就是个纯叙事块**（读一段文本）。

```yaml
- id: stone_door
  name: 上锁的石门
  icon: 🚪
  encounter: event
  event:
    text: 一扇刻着古文字的石门挡住了去路。
    gate:                                  # ① 门槛（可选）
      tags: [撬锁]
      mode: all                            # all = 全都要 | any = 有一个就行
      on_missing: blocked                  # blocked = 不给选项 | penalty = 允许硬来，但吃惩罚
    check:                                 # ② 判定（可选；不写 = 过了门槛就必成）
      dice: 2D6
      add: patk                            # 复用哪一维当"手艺"
      target: 15                           # 固定难度（static）
    on_success:
      text: 锁芯"咔"地一声弹开了。
      point_reward: 2
      grant: [{ id: red_potion, count: 1 }]
    on_fail:
      text: 门缝里弹出一排铁针。
      cost: { hp: 3 }
      effects: [{ op: add_tag, tag: 扎伤, duration: 3, per_turn: { hp: -1 } }]
    once: false                            # true = 成功后就变成 empty（门开了就不再是门）
```

**② 判定复用力值链（§4.8.2）——这就是"努力缩小范围"的落点：**

```text
手艺值 = floor( ( (属性[check.add] + 装备加值) × 职业百分比 ＋ rollSum(check.dice) ) × 骰子倍率 )
成功   = 手艺值 ≥ check.target
```

- 走的还是那条链的 **① 属性 → ② 装备 → ③ 职业 → ⑤ 骰子叠加 → ⑥ 骰子倍率**，
  只是这里比的是**固定值**而不是对方的防值。
- **所以提高属性 / 换更好的装备 / 换更对口的职业，都是在提高成功率**——玩家靠经营来压缩运气成分。

**必成 / 必败区间（必须让设计者看见）：**

```text
手艺下限 = 力值(骰子取最小点)      手艺上限 = 力值(骰子取最大点)
必成：手艺下限 ≥ target          必败：手艺上限 <  target
```

例：`target: 15`、`dice: 2D6`（2~12）、加值 5

| 加值 | 需要掷出 | 2D6 命中率 | 状态 |
|---|---|---|---|
| 5 | ≥ 10 | 3/36 ≈ **8%** | 基本靠脸 |
| 8 | ≥ 7 | 21/36 ≈ **58%** | 值得一赌 |
| 13 | ≥ 2 | 36/36 = **100%** | **必成** |

→ **加值够高就必成，加值太低就必败。** 编辑器把这两个区间标出来（§5.7）：
必成时提示"这个判定对当前配置是白送的"，必败时提示"现在做这个纯属浪费时间，先去提升属性"。
**"投骰子浪费时间"的问题就是靠这个提示解决的**——它把"运气"变成了"经营"。

**后果块 `on_success` / `on_fail` 能做什么**（全部复用已有词汇，不发明新机制）：

| 键 | 作用 |
|---|---|
| `text` | 展示文本 |
| `cost` | 扣资源 `{ hp, mp }`（和道路 `cost` 同形） |
| `point_reward` | 给自由属性点（§4.8.8） |
| `grant` | 给道具 `[{ id, count }]` |
| `effects` | 挂 / 解状态（§4.8.10） |
| `goto` | 传送到某张图的某格（P1） |

- **`on_missing` 两种语义**：`blocked`（干脆不给选项，玩家绕路）/ `penalty`（可以硬来，但走 `on_fail` 分支）。
  后者就是"没有撬锁工具就暴力砸门，多半受伤"。
- **`once`**：成功后把该节点降级为 `empty`，避免反复刷同一个事件。

#### 4.8.10 状态与持续效果（中毒 / 护盾 / 临时通行）

**状态就是一个挂在**单位**身上的标签 + 剩余回合数**——不发明第二套机制，直接复用 `tags`。

```text
状态 = {
  tag: string,                        # 语义，同时作为"临时能力"进 capabilities
  duration: int,                      # 剩余回合数，必填
  per_turn?: Record<StatKey, number>, # 每回合结算的增减（待续 / 回复）
  modifiers?: Record<StatKey, number>, # 持续期间对 6 属性的加值（进力值链 ②）
  source: id                          # 谁挂的（道具 / 技能 / 怪物 / 事件）
}
```

| 项 | 规则 |
|---|---|
| **结算时机** | **每回合【开始】先判存活、再 tick 一次**（见 §4.8.0"回合开始时序"）。回合 = **一次交锋** 或 **一次移动（走完全部步数才算）**。tick 已前置到回合开头，所以回合结束不再 tick |
| **`duration`** | **必填**。剩余回合数每次 tick 减 1，归零自动移除。**本回合中刚挂上的状态，要到下回合开始才首次 tick**（不会当回合就扣） |
| **硬上限** | 任何 `duration` **不得超过 `state.max_duration`**（§4.8.6，默认 10）。**没有永久状态** |
| **`per_turn`** | 可省。每回合对 `hp` / `mp` 结算一次增减（中毒 `hp: -1`、再生 `hp: +1`） |
| **`modifiers`** | 可省。**持续期间对 6 个属性加值**，直接进力值链的 **② 加法环**（§4.8.2）——**这就是"力量祝福 +2 物攻""虚弱 -2 物攻"的落点** |
| **进不进能力集合** | **进**。状态 tag 与装备 `tags`、职业 `tags` **并列**进 `capabilities`（§4.5.2） |
| **来源** | **消耗品 / 技能 / 事件三处共用全部五 `op`**；**怪物命中 与 地形 `gate.penalty` 只用 `add_stat` / `add_tag` / `remove_tag` 三种**（不可教 / 夺技能——地形不能教玩家技能，怪物也不能，见 §4.1） |
| **与"学会技能"的区别** | 状态是**限时的**（必带 `duration`）；学会技能是**永久的**（`learn_skill`，只能靠 `forget_skill` 拿走）——**两者不是一回事，别混** |

**状态 tag 进能力集合 —— 这一条让"临时通行"成立：**

- 负面："中毒（5 回合，每回合 -1 hp）"
- 正面："**御火符 → `火抗` 3 回合**" —— 遇到火焰山时临时吃一张，就过去了。
- 所以**同一套 `tags` 既是永久能力（装备）也是临时能力（状态）**，编辑器不需要区分。

**`effects` 的五个 `op`（§4.3 道具 / 技能 / 事件三处共用全部五 `op`；怪物命中只用其中三种，见 §4.1）：**

```yaml
effects:
  - op: add_stat          # ① 即时改数值
    target: self          # self | opponent
    stat: hp
    delta: 5
  - op: add_tag           # ② 挂状态（buff / debuff 都靠它）
    tag: 中毒
    duration: 5           # 必填；超过 max_duration 会被夹到上限
    per_turn: { hp: -1 }  # 每回合掉血
  - op: add_tag           # 挂"增益"也是同一条 —— 用 modifiers 改属性
    tag: 力量祝福
    duration: 3
    modifiers: { patk: 2 }   # 3 回合内物攻 +2（进力值链 ②）
  - op: remove_tag        # ③ 解状态（**解药**）
    tag: 中毒
  - op: learn_skill       # ④ **学会一个技能**（"这张纸你记住了"）
    skill: fireball
  - op: forget_skill      # ⑤ **忘掉一个技能**（"那一下把你会的东西打散了"）
    skill: shield_bash
```

**`learn_skill` 是"后天发育"的唯一入口**（§4.8.3）：

- **技能书 = 一件普通消耗品**，`effects: [{ op: learn_skill, skill: X }]`。
  所以**开箱、事件、商店、战利品，凡能给道具的地方都能给技能**——**零新增通道**。
- **没有任何职业限制**：法师能学盾击，战士能学治疗术。**职业只管先天**（§4.2.3）。
- `forget_skill` 是它的反面：**环境与运气真的会夺走你的本事**。
- **`skill` 必须指向一个"已启用"的技能**，否则是死引用（编辑器标红，§5.7）。

**"用红瓶硬扛中毒"是怎么成立的：**

- 中毒 5 回合、每回合 `-1 hp` → 不吃解药共掉 5 点
- **红瓶 `+5 hp` 且不占回合**（§4.8.0）——嗑药不会因为"多花了一回合"而多挨一次毒
- 所以红瓶正好抵掉中毒，**扛得过去但要耗瓶子**；想更省就用解毒剂（`remove_tag`，也不占回合）
- **反过来说，"治疗术"这种技能是要花一回合的**（§4.8.3）——施放那一回合中毒照样 tick。
  **这就是"道具即时但量小、技能费力但量大"的取舍**
- 想更狠就把 `per_turn` 调大；想更温和就把 `duration` 调小。**两者都在组件上，是内容不是规则**

#### 4.8.11 商店与交易（`encounter: shop`）

> **回答"谁来卖 / 怎么卖 / 卖多少"三个问题：**
> **谁来卖** —— 商店就是一个**建筑**（地图件），铺到哪就在哪开张，和宝箱屋同构；
> **怎么卖** —— 玩家踩到 → 打开面板 → 从 `stock` 里挑 → 付 `price` 算出的数量 → 成交；
> **卖多少** —— `price` 复用 §4.8.1 的 `rollRange`，**掷骰定价**（同一件东西每局价格不同）。
>
> **确实是"和宝箱屋一样的单独子类型"** —— 见 §4.4 的 `encounter: shop`。

**关键设计：不发明"货币系统"，货币就是一件道具。**

```yaml
- id: merchant
  name: 流浪商人
  icon: 🧳
  encounter: shop
  stock:                                  # 卖什么（池结构，与 reward_pool 完全同构）
    source: ids                           # ids = 手选 | filter = 按标签筛整个组件库
    ids: [red_potion, blue_potion, iron_sword]
    # filter: { tags: [消耗品] }
    pick: { algo: count, dice: 1D6, range: [2, 3] }   # 这次上架几件
  price:                                  # 定价（单价算法）
    currency: gold                        # ← "钱"就是一件道具的 id
    algo: value                           # value = 掷骰映射到区间 | fixed = 固定价
    dice: 1D6
    range: [5, 15]
  restock: on_enter                       # 每次进入重新抽货 / never = 固定库存
  desc: 他不问你要去哪，只问你有多少钱。
```

- **货币 = 一件普通道具**（如 `gold`，`tags: [货币]` 只是给编辑器做筛选用，引擎不认识这个词）。
  所以"捡钱"就是普通的 `grant` / `reward_pool` 产出，**零新增机制**。
- **`price.algo: fixed`** 就是明码标价；**`value`** 就是"这件东西今天 5~15 块"。
- **卖出（玩家卖东西给商店）**：标 **P1**，形态是 `sell_ratio`（回收价倍率，默认 `0.5`）+ 反向池。
- **泛化成"合成台 / 以物易物"**：把 `stock + price` 换成 `take`（给玩家的池）+ `give`（玩家付的池），
  就是"3 个红瓶换 1 把铁剑"。这个形态标 **P1**，不强塞进 M1。

> **商店 / 宝箱 / 战利品三者的关系**：**池结构（§4.8.5①）是完全相同的一份**，
> 区别只在"用什么触发"（踩到 / 打开 / 打赢）和"要付什么"（宝箱免费、商店要钱）。

## 5. 编辑器设计（构建态）

> 本节是**唯一的交互标准**。任何组件的任何操作都必须能在这张表里找到出处；
> 找不到出处的交互一律不加，先改本节再加代码。

### 5.0 信息架构（见 §4.0）

```text
① 组件库 Library      左栏一个面板、一份列表。系统预设 + 用户自建，地位相同。
        │ 启用（消耗品 / 装备 / 怪物 / 职业 / 技能）
        │ 铺设（道路 / 建筑，铺到某张图的格子上）
        ▼
② 游戏内容 Content    = 启用的组件 + 地图上的铺设 + 起终点。导出成 .pmod。
```

**两条铁律：**

- **L1 —— 库是工具来源，内容是干出来的活。** 用户自建组件和系统预设**地位完全相同**，都躺在库里，都能改 / 删 / 复制 / 反复用。库不因某个项目而生，也不随某个项目而亡。所以**没有"本局组件"这个概念**——左栏永远是那一个组件库，只是每条上面标着"在本局里用没用"。
- **L2 —— 组件不落到"内容"上就不生效。** 非地图件（消耗品 / 装备 / 怪物 / 职业）要**显式启用**才进奖励池 / 背包 / 开局候选；地图件（道路 / 建筑）要**铺到地图格**才存在。没启用的、没铺的，都只是躺在库里待用。

### 5.0.1 组件分类：按"在内容里怎么出现"分

| 大类 | 分区 | 占地图格 | 成为"内容"的条件 | 被谁消费 |
|---|---|---|---|---|
| **地图件** | 道路 | 是 | 铺到地图格 | 网格移动 |
| | 建筑 | 是（可多格） | 铺到地图格 | 踩到触发遭遇 |
| **道具／内容** | 消耗品 | 否 | **启用** | 建筑奖励池、玩家使用 |
| | 装备 | 否 | **启用** | 建筑奖励池、玩家穿戴 |
| | 怪物 | 否 | **启用** | 怪物房 `monster_pool`、宝箱怪物 `mimic.monster` |
| | 职业 | 否 | **启用** | 开局 `class_pool`；**只给先天的牌面**（属性 / 百分比 / 背包，§4.2.3） |
| | **技能** | 否 | **启用** | **玩家的技能栏靠"学会"（技能书 / 事件 / 商店）；怪物用 `attack_weights` 引用** |
| **全局** | 背景 | 否 | 始终 | 游玩开场展示 |

> 起点 / 终点**不在这个表里**：它们是画布内建标记（每图一个、无属性），由模式条上的「标记」模式放置，
> 不占组件库名额，也不参与"启用 / 铺设"的讨论。

> 这一条直接回答"局内道具和建筑道具混在一起"：**建筑只装"内容"，内容只被建筑引用**，两者永远不在同一层混排——建筑在地图件区，它装的东西在道具／内容区，靠属性面板里的"奖励池"关联。
>
> **技能也一样**：它是"内容"，被**职业**（玩家会什么）和**怪物**（它会什么）引用，
> **不占地图格**——所以它和道具同类，永远不和地图件混排。

### 5.1 布局：单一栅格 + 一套间距 token

```text
┌─ 顶栏：项目名 · 撤销/重做 · 导入/导出   （不放工具、不放地图 Tab） ─┐
├───────────────┬─────────────────────────────────┬─────────────────┤
│ 左栏 280px    │ 中栏 地图画布 (1fr)             │ 右栏 320px      │
│ ① 图层块      │ ┌─ 模式条（模式 + 当前提示）   │ 右栏三页        │
│ ② 组件库      │ └─                              │ 组件/实例/规则  │
│   筛选+搜索   │              缩放控件（右下）   │                 │
│   分区×8      │                                 │                 │
└───────────────┴─────────────────────────────────┴─────────────────┘
```

**对齐铁律（问题 1 的直接处方）：**

- 全页只有**一层**内边距：`.app-shell { padding: var(--gap) }`；`--gap: 10px` 是唯一间距 token。
- **任何面板、任何子组件都不允许自带 `margin`**（现在 `Toolbar`/`KitPanel`/`Inspector` 各自写内联 margin 是错位的根因，全部删除）。
- 顶栏**不换行**（`flex-wrap: nowrap`）：内容放不下就收进"⋯"溢出菜单，绝不改用换行改变行高。行高恒定为 `--topbar-h`。
- 左 / 右栏都是 `display:flex; flex-direction:column; min-height:0`，**滚动只发生在内部滚动区**（`overflow:auto`），滚动条内缩 2px，不撑破栅格。
- 所有面板共用同一个 `.panel` 类：同圆角、同边框、同内边距 `10px`、同 `min-height:0`。**禁止逐面板写 inline style 打补丁。**
- 手绘风的"不规则圆角"只用于**内层卡片 / 按钮**；栅格容器用规整圆角，避免视觉错位被放大。
- 中栏 `position: relative`：模式条贴左上（8px），缩放控件贴右下（8px），底部提示条贴左下，三块互不重叠。
- `≤880px`：中栏全屏；左 / 右栏改成左右抽屉；模式条改为**底部横排**（拇指可达），缩放控件移到右上。

### 5.2 图层块（左栏 ①）

> 决策：**图层 = 本项目的多张地图**。顶栏那一排地图 Tab 全部挪到这里，顶栏随之清空。

- 列表逐行显示一张地图：`序号 · 名称 · N 节点 · 状态点`；点击即切换当前地图。
- 状态点：起点 / 终点缺失时显示红点（悬停提示"缺少起点"）。
- 行内操作：双击重命名 · 上移 / 下移（排序）· 删除（仅当地图数 ≥ 2 时可删）。
- 底部：`+ 新建地图`。
- **可折叠**：收起态只留一行 `图层 · 共 N 张 · 当前「名字」▸`，点击展开。

### 5.3 组件库面板（左栏 ②）

> **只有一个面板、一份列表。没有"本局组件 / 素材库"两个 Tab。**
> 用户自建的组件和系统预设躺在同一个列表里，地位完全相同——就像图形设计工具里的笔刷面板，
> 你自己造一支笔刷，它就在库里待着，反复可用，不会"用一次就没了"。

**分区**（标题行：`▾ 分区名 · 计数 · [+ 新建]`，每个分区独立可折叠）：

`道路` · `建筑` · `消耗品` · `装备` · `怪物` · `职业` · **`技能`** · `背景`
（前两个是**地图件**，中间五个是**道具／内容**，最后一个是全局——顺序即 §5.0.1 的分类）

**顶部工具条**：筛选 `[全部] [本局已用]` ＋ 名称搜索框。

**每行**：`图标 · 名称 · 徽章组 · ⋯菜单`

| 徽章 | 出现位置 | 含义 |
|---|---|---|
| `预设` / `自建` | **全部条目（七大类一视同仁）** | 拿 `id` 查内置预设表：查得到 = `预设`，查不到 = `自建`（§3.2）。不存字段 |
| ☑ `已启用` / ☐ `未启用` | 消耗品 / 装备 / 怪物 / 职业 / **技能** | 本局是否启用（= 这条算不算游戏内容）。未启用行降透明 |
| `已铺设 ×N` / `未铺设` | 道路 / 建筑 | 在本局地图上的铺设次数（0 就没进内容） |
| `被引用 ×N` | **全部条目** | 被几处引用（道具 ← 奖励池；怪物 ← 怪物房 / 宝箱怪物；**技能 ← 技能书的 `learn_skill` / 怪物 `attack_weights`**；建筑 ← 地图节点…） |

> **技能的"启用"= 这个世界里有没有这一招**，**不是"谁会"**——
> 谁会**靠后天学**（技能书 / 事件 / 商店，§4.8.3）。未启用的技能不能被学、不能被怪物用、写成技能书也是死引用（§5.7）。

> 徽章把"哪些是预设、哪些在这局里真用上了"一次说清：
> **左半是库的身份（派生），右半是这一局的状态。**

**`⋯` 菜单**：编辑定义 · 复制成新组件 · 启用 / 停用（仅非地图件）· 删除 · 恢复默认
（`恢复默认` 仅对 `预设` 条目显示：拿 id 去内置预设表取原始定义覆盖回来）

**选中行为分两种：**

- 选中**地图件** → 可立即到地图上用「放置 / 连线」模式落子；
- 选中**非地图件** → 只打开右栏属性表单，**不再提供拖拽到地图**
  （现在"所有条目长得一样、都能拖"正是混乱来源之一）。

**新建 / 复制：**

- `+ 新建` —— 从零建一条库组件（`自建`）。
- `⋯ → 复制成新组件` —— 以现有条目为起点派生一条新库组件（`自建`），原条目**不受影响**。
  > 这就是"从预设起步、改成自己的"的正统做法：**预设本身要不要改随你**；
  > 想留住原版就复制一份再改，不想留就直接改原条目（还能 `恢复默认`）。
- 删除被本局引用（铺设 / 启用 / 被奖励池引用）的组件时，先提示"被 N 处使用"再确认；
  确认后那些引用会变成悬空，按 §5.7 处理。

### 5.4 操作模式标准表（本轮核心）

**工具只有 6 个模式，全部收进画布左上「模式条」；顶栏、右栏、说明文字里一律不再放第二个入口。**

| # | 模式 | 前提 | 单击 | 拖拽 | 中间态 / 结束 |
|---|---|---|---|---|---|
| 1 | **选择** | — | 点节点 = 选中；点空白 = 取消选中 | 空白 = 平移；节点 = 移动；节点角柄 = 缩放（建筑） | 常驻；`Esc` 清选中 |
| 2 | **放置** | 左栏选中一个**地图件** | 在空格放下该组件（点哪放哪） | 划过的格子连续放置 | `Esc` / 再点模式条退出 |
| 3 | **连线** | 左栏选中一条**道路** | 第 1 次 = 起点，第 2 次 = 终点 → 自动正交折线铺满（对角自动拐角）；再点可继续接续下一段 | — | 实时预览到光标；`Esc` / 双击结束 |
| 4 | **框选** | — | 点空白 = 清空选区 | 拖出矩形 = 选中范围内**全部**节点 | 选区非空时弹出浮动操作条 |
| 5 | **擦除** | — | 单击删除该格组件（多格建筑整块删） | 划过 = 连续删除 | `Esc` / 再点模式条退出 |
| 6 | **标记** | 选起点或终点 | 放置该标记（每图唯一；已存在则**移动**而非新建） | — | 放置后自动回「选择」 |

**通用铁律 G1–G6：**

- **G1** 拖空白 = 平移，**任何模式都一致**。
- **G2** `Esc` = 回到「选择」并清掉所有中间态（连线起点、框选、待放组件）。
- **G3** 入口唯一：一个模式在地图上**只有一个开关**。（现在"铺路"同时存在于顶栏语义、面板说明文字、右栏表单按钮三处，是三套规则打架的直接原因。）
- **G4** 当前模式 + 操作提示显示在**模式条右侧**一行；**所有面板底部的长段说明文字全部删除**。
- **G5** 一次连续操作 = **一步撤销**（整条线 / 整次框选删除 / 一次画笔拖刷 / 一次擦除拖刷）。
- **G6** 快捷键：`V` 选择 · `B` 放置 · `L` 连线 · `M` 框选 · `E` 擦除 · `S` 起点 · `F` 终点；`Delete` 删除选中；`Ctrl/Cmd+D` 复制；`Ctrl/Cmd+Z` / `Shift+Z` 撤销·重做；方向键微调 1 格。

**框选浮动条（模式 4）**——这就是"选起点终点范围 → 自动计算 → 批量移除"：

- **批量删除（N 个）** —— 一键移除范围内全部节点。计入一步撤销。
- P1（本轮不做）：批量替换为…（整批换成另一个地图件）、批量移动（整体平移 N 格）。

### 5.5 画布基础（沿用，不重做）

- 网格 + **每 10 格加粗**；中心 `[0, 0]`；坐标域 `[-10000, 10000]`；视口虚拟化只渲可见格。
- 缩放：滚轮 / 按钮，锚点跟随光标；**平移只有"拖空白"一种**。
- 起 / 终点有专属图形（旗 / ✕），不靠文字标签。

### 5.6 属性编辑（右栏）

右栏三个页签：**组件** / **实例** / **规则**。

**规则页**（= 这一局的前置配置，对应 `project.rules`，字段清单见 §4.8.6，**不多一个**）：

- **硬规则只读展示**：把 §4.8.0 的硬规则（正交四邻 / 不可斜走 / 可原路返回 / **回合 = 一次交锋或一次移动** /
  技能决定维度 / 命中 = 力值 ≥ 防值 / 伤害 = `max(1, 力值−防值)` / 属性登场摇定 / 技能两侧不对称）
  以**只读说明**形式列在最上面——**不做成开关**，因为不给配。
- **移动**：只有一个字段 `dice`。面板上写人话：**"每回合掷 `1D6` 决定能走几步；走完全部步数算一个回合"**。
  下方一句提示："每格的**消耗与权限**由那一格的**道路 / 建筑组件**决定（`cost` / `gate`），不在这里配。"
- **战斗**：
  - **没有 `attacks`**——攻击方式已升级为**技能组件**（左栏「技能」分区）。
    这里只留一句指路：**"这一局用哪些技能、每个技能取哪一维打谁，都在 `技能` 分区里配"**。
  - `stat_dice` 属性结算骰 + `pick_dice` 怪物挑技能骰。
  - `atk_roll` / `def_roll`：**施放方与对抗方各一组**，每组 `add_dice`（可留空）/ `mult`（可留空，留空即不乘倍率）。
- **开箱 `treasure` / 战利品 `loot`**：各一组 `pick`（`algo` = `tiers` 档位表 / `count` 区间）与 `copies`（`fixed` / `value` / `multiplier`）。
- **状态 `state`**：`max_duration` 一个数字框。旁注："**任何状态都不会超过这么多回合**——避免没有解药时被耗死。"
- **商店 `shop`**：默认定价 `price`（`currency` 选一件道具当钱 ＋ `algo` = `fixed` / `value` ＋ 骰子与区间）。旁注："没写定价的商店都用这一套。"
- **事件 `event`**：默认判定骰 `dice`。旁注："**难度值与后果写在事件组件上**（那是内容），这里只给默认骰。"
- **开局职业池**：只列**已启用**的职业；长度 1 = 固定职业，>1 = 开局随机。
- **每个字段旁给一句人话**，把骰子和它的用途绑在一起：
  - 移动 → "每回合掷 1D6 走几格；**走完全部步数算一个回合**（不是每格一回合）"
  - 属性结算 → "登场时掷 1D6 把 `物攻[3~6]` 摇成 `5`，本场固定"
  - 战斗 → "力值 = 物攻 5（已摇定）+ 铁剑(+5) + 技能加成(0)，× 职业 100%，+ 1D4 叠加，× 1D6 倍率"
  - 开箱 → "掷 1D6：1~2 空箱，3~4 一件，5~6 两件；每件再掷 1D6 定 1~3 份"
  - 怪物挑技能 → "掷 1D6 按 `普通攻击 3 : 毒牙 1` 挑，玩家两维都得堆"
- **预览按钮**：每个算法旁给「模拟 10 次」按钮，直接看产出分布（避免"配完了不知道是什么效果"）。

**组件页**（在左栏组件库里选中一条 → 编辑的是**库里的组件定义**）：

- 公共：名称、图标（Emoji）、描述、标签 `tags`、来源徽章（`预设` / `自建`，只读、由 id 派生）、
  `预设` 条目带「恢复默认」（拿 id 去内置预设表取原始定义覆盖回来）。
- 本局状态：启用开关（仅非地图件）＋ 铺设次数 / 被引用次数（只读，说明它在本局算不算内容）。
- **怪物**：**6 个属性的区间**（`hp` / `mp` / `patk` / `matk` / `pdef` / `mdef`，属性结算输入）、
  **`attack_weights` 技能权重表**（**从已启用技能里多选 + 各自权重**，
  旁边提示"掷 1D6 按 `普通攻击 3 : 毒牙 1` 挑，玩家两维都得堆"）、
  可选 **`effects`**（命中玩家时施加，**用与消耗品同一套控件**）、
  可选 `atk_roll` / `def_roll` / `stat_dice` 覆盖、`point_reward`（打赢给几点）、可选**战利品池**（`source: ids|filter`）+ 可选覆盖 `pick` / `copies`。
  > 界面上给个**档位对照**："小怪 `hp 6~12` / 精英 `hp 24~40`"（§6.1.1），并提示可用 `tags: [精英]` 标注。
- **技能**（§4.8.3）：**选一维 + 选个对象 + 加个效果**，五个下拉/数字框：
  - `dim` **基准维度**（6 属性下拉）→ `target` **作用对象**（`opponent` 打人 / `self` 对己）
  - `vs` **对手拿哪一维对抗**（`auto` / `none` / 具体维）→ `bonus` **技能加成**（数字，默认 0）
  - `apply` **力值作用到哪**（`hp` / `mp` / `none`，默认 `hp`）
  - `cost` 施放成本（默认免费；给法术填 `{ mp: 3 }`）
  - `effects` 附带效果（与消耗品同一套控件，挂 buff / debuff）
  > **面板上直接写人话预览**，让人一眼看出这是"打人"还是"救人"：
  > - `dim: patk` + `target: opponent` → **"用物攻打对方 `pdef`，伤害 = max(1, 力值 − 对方物防)"**
  > - `dim: matk` + `target: self`   → **"不对抗，回自己 力值 点 `hp`"**
  > - `apply: none` + `effects: [力量祝福]` → **"不对抗，给自己挂 3 回合 力量祝福（物攻 +2）"**
  >
  > **编辑器不认识"火球术""治疗术"这些词**——它只显示"取哪一维、打谁、挂什么"。
  > **技能页底部还有一块「这一局里谁能学到它」**：列出所有指向它的 `learn_skill`（技能书 / 事件 / 商店），
  > 一个都没有时标黄提示"**已启用，但没有任何地方能学到**"（§5.7）。**技能没有"谁会"这个属性**——
  > **"谁学会"是游玩态数据，编辑器不管**（§4.8.3）。
- **职业**：`base_stats`（6 个属性的**初始属性**，数字输入）+ `free_points`（**开局自由点数**，数字输入）
  ＋ `buffs` 百分比（力值链③）＋ `tags` ＋ **`inventory_size`（背包格数，数字框 ＋「无限」勾选）**
  ＋ **`starting_items`（初始道具多选，只列已启用道具）**——**没有属性区间、也没有 `skills`**。
  > 面板上给三句人话：①"这个职业开局给 **25 点**自由点（想给 300 也行）"；
  > ②"把点堆在 `matk` 会被 ×1.3，堆在 `patk` 会被 ×0.8——**职业决定怎么分才不亏**"；
  > ③"**职业只给先天的牌面，不给技能**——它从哪儿学本事，是这一局里的事（§4.8.3）"。
- **道具**：kind 切换 → 装备（槽位多选 + **6 属性** `modifiers` 加值，力值链②）
  / 消耗品（`usable` + **`effects` 混合列表**，**五选一 `op`**：`add_stat` 改数值 / `add_tag` 挂状态 /
  `remove_tag` 解状态 / **`learn_skill` 学会技能** / **`forget_skill` 忘掉技能**，§4.8.10）。
  > `add_tag` 行必填 `duration`（超过 `state.max_duration` 会被夹到上限），可再勾"每回合结算"填 `per_turn`，
  > 或填 **`modifiers`**（持续期间改属性，如"力量祝福 物攻 +2"）。
  > **`learn_skill` 行选一个已启用技能，旁边实时显示它的人话预览**——"学会：用物攻打对方 `pdef`"。
  > **这就是"技能书"**，也是"后天发育"的唯一载体（§4.8.3）。
  > **消耗品、技能、怪物、事件四处的 `effects` 用的是同一个控件。**
  > 一行一个效果，右侧一个「＋ 加一条效果」按钮。
  > 道具的 `tags` 框旁注："**给编辑器筛选用**（比如 `货币`），引擎不认识这个词。"
- **建筑**：`encounter` **五选一**（`empty` / `treasure` / `monster` / `event` / `shop`），
  **面板只显示选中行为对应的块**——这就是"构建面板终于有逻辑"的落点：
  - `empty` → 只有 `cost` / `gate` / `point_reward` / `desc`
  - `treasure` → 奖励池（`source: ids` 手选 / `filter` 按条件筛，只列已启用项，可设权重）
    ＋ 可选覆盖 `pick` / `copies` ＋ 勾选"宝箱怪物"展开 `mimic`
  - `monster` → 怪物池（同上结构）
  - **`event`** → **门槛 `gate` ＋ 判定 `check`（骰子 / 加值属性 / 目标值）＋ 后果 `on_success` / `on_fail` ＋ `once` 勾选**
    - 门槛复用道路那套标签控件（`tags` / `mode` / `on_missing`），**标签反查提示也共用**
    - 后果块是一个可增删的列表，每项可选 `text` / `cost` / `point_reward` / `grant` / `effects`
    - **判定下方实时显示必成 / 必败区间**（§5.7）
  - **`shop`** → **上架池 `stock`（与奖励池同一套选择器）＋ 定价 `price`（货币下拉 ＋ 固定价 / 掷骰定价）**
  - 通用：`cost` / `gate`（§4.5）＋ `point_reward`
  > 每个选择器旁边实时显示**算出什么**：
  > 奖励池"掷 1D6：1~2 → 空箱，3~4 → 1 件，5~6 → 2 件；每件再掷 1D6 定份数"；
  > 怪物池"命中 12 只，掷 1D6 按权重抽 1 只"；
  > 事件判定"当前加值 8：需掷 ≥ 7，命中率约 58%"；
  > 商店定价"红瓶：每件掷 1D6 → 5 ~ 15 枚 `gold`"。
- **道路**：名称 / 图标 / 描述 ＋ **消耗 `cost`**（步数 / 血量 / 法力三个数字框，步数默认 1）
  ＋ **权限 `gate`**（标签输入，回车加一个；`mode` any/all；`missing` block/penalty；`penalty` 三个数字框）。
  > **不放"铺设（画线）"按钮**——那是模式 3，入口唯一在模式条。
  > 面板上给一句对照："`step: 1` 正常；`step: 2` 难行；`step: 0` 不耗步"。
  > 权限框旁边**实时列出现在哪些已启用组件带这些标签**——"`火抗`：火抗鞋 ✓ / 炎魔甲 ✓"，
  > 一个都没有时标黄提示"目前没有任何装备带 `火抗`，这条路走不通"，避免造出死路。
- **装备 / 职业**：除 `modifiers` / `buffs` 外，还有 **`tags` 输入框**，旁注
  "这些标签用于**通行权限匹配**（§4.5.2）"，并实时反查"带 `火抗` 可以让玩家通过：火焰山 ×2 处"。

**实例页**（选中地图上的节点）：

- 坐标、类型、引用的组件名；`[编辑该组件定义]` 快捷跳转到组件页。
- 建筑：宽 / 高（格）。
- 操作：复制该节点 / 删除该节点。
- 若引用的组件已被删除 → **标红提示**并给出"换成别的组件"快捷操作。

> 这里的编辑**直接改库**，所有用到它的局一起生效（§4.7）。想保住原版就先用 `⋯ → 复制成新组件` 派生一条再改。

### 5.7 校验与提示（每张图）

| 项 | 规则 | 违反时 |
|---|---|---|
| 起 / 终点 | 每图恰好各一个 | 图层面板行显示红点；导出前给 toast 提示，**不阻塞导出**（不把用户锁死） |
| 建筑多格 | 不与其它节点重叠 | 放置时**直接替换**被压住的节点（计入一步撤销） |
| 引用完整性 | `reward_pool` / `monster_pool` / `stock` / `price.currency` / `mimic.monster` / `class_pool` / `starting_items` / **`learn_skill` / `forget_skill` 的 `skill`** / **`attack_weights` 的键** / 事件 `grant` 只能指向已存在且**已启用**的组件 | 右栏标红 + 快捷修复；悬空引用导出时自动剔除并提示 |
| **技能指向失效** | 某个 `learn_skill` / `forget_skill` / `attack_weights` 指向**已停用 / 已删**的技能 | 标红 + 快捷修复（换成别的技能）。**停用的技能不被任何书 / 怪物引用**——它们的世界里不存在这一招（§4.8.3） |
| **技能无法获得** | 这一局**没有任何途径**能让玩家学到某个已启用技能（既没有技能书、也没有事件给、商店也不卖） | 标黄提示："`火球术` 已启用，但**没有任何地方能学到它**——要不要放一本技能书 / 让某个事件教它？"。**不阻塞导出**（也可能是故意留给纯怪物的技能） |
| **技能自相矛盾** | `target: self` 却写了 `vs:` 具体维；`vs: none` 却指望有伤害；`apply: none` 且 `effects` 为空（**这技能什么都不做**） | 编辑器标黄说明后果，并给一句建议（如"`apply: none` 且没有 `effects`，这个技能放出来没有任何效果"） |
| **池筛空** | `source: filter` 的条件可能筛出 0 项 | 建筑 / 怪物池 / 商店上架池旁实时显示命中数；命中 0 时标黄提示"这个池是空的"（导出前再提示一次） |
| **权限死路** | **道路 / 建筑 `gate.tags`、事件 `gate.tags`** 里的标签**没有任何已启用组件带** | 编辑器标黄："没有任何已启用装备 / 职业带 `火抗`，这条路走不通"；**不阻塞导出**（用户可能是先铺路、装备还没做） |
| **事件必成 / 必败** | 事件判定按当前配置算出的命中率是 100% 或 0% | 必成 → 提示"这个判定对当前配置是白送的"；必败 → 标黄"**现在做这个纯属浪费时间，先提升属性 / 换装备**"。**不阻塞导出** |
| **状态无上限** | `effects.add_tag` 的 `duration` 缺失或超过 `state.max_duration` | `duration` **必填**，缺失时禁止保存（状态必须有限期）；超过上限时**直接夹到上限**并提示 |
| **商店缺货币** | `price.currency` 指向的道具没启用，或它在全图里没有任何产出 | 标黄："`gold` 没有出现在任何奖励池 / 事件产出里，玩家买不起东西" |
| **背包容量** | 职业的 `inventory_size` 小于开局要发的道具条目数 | 提示但不拦（设计者可能故意做"精简背包流"） |
| 道路引用 | 地图上的 `road` 节点必须带 `ref` | 缺失时右栏标红；旧档里没有 `ref` 的路节点**回退到默认 `cost: { step: 1 }` 且无 `gate`**，不报错 |
| **"清单"一键自检** | 构建页提供一个 **「清单」按钮**，一键跑上面 **全部 K1~Kn 校验**并**汇总成一张清单**（哪些通过、哪些标红 / 标黄、各自定位） | 让构建者在导出 / 试玩前**一口气查漏补缺**——比逐条散在面板里更省心；不阻塞导出，只是汇总视图 |

> **「清单」按钮**是 §5.7 所有校验的"总开关"：它不引入新规则，只是把 K1~Kn 的结果集中展示，构建者一眼看到全图的健康度。

## 6. MVP 范围：构建闭环

### 纳入
- A. **脚手架**：React+TS+Vite，栅格布局骨架（§5.1）
- B. **信息架构**：**组件库（预设 + 自建）→ 游戏内容（启用 + 铺设）** 打通（§4.0 / §5.0）
- C. **左栏**：图层块（多地图管理，§5.2）+ **组件库面板**（单一列表、分区折叠、筛选、徽章，§5.3）
- D. **画布**：网格 / 十格粗线 / `[0,0]` / 平移缩放 / 6 个操作模式 / 框选批量删除 / 校验（§5.4 / §5.5）
- E. **属性编辑**：右栏三页（组件 / 实例 / **规则**）；奖励池 / 怪物池（`ids` / `filter`）+ 可选覆盖 `pick` × `copies` + mimic（§5.6）
- F. **消耗与权限**：道路 / 建筑可编 `cost`（含 `mp`）+ `gate`；装备 / 职业可编 `tags`；编辑器提供**双向反查**（§4.5 / §5.6）
- G. **6 属性体系**：`hp` / `mp`（资源）+ `patk` / `matk` / `pdef` / `mdef`（能力）；装备 `modifiers`、消耗品 `effects`、怪物 `stats` 全部按 6 属性走（§4.0.1）
- H. **前置配置 `rules`**：完整可编辑并写入 `.pmod`——`move.dice`、`combat` 的 `stat_dice` / `pick_dice` / `atk_roll` / `def_roll`、
  `treasure` / `loot` 两套抽取算法、**`state.max_duration` / `shop.price` / `event.dice`**、`class_pool`；**字段清单严格等于 §4.8.6（共 13 项），不多一个**
  > **注意没有 `combat.attacks`**——攻击方式已升级为技能组件（见 K）。
- I. **职业＝先天**（§4.2.3）：职业可编 `base_stats`（初始属性）+ `free_points`（开局自由点数）+ `buffs`（优劣百分比）
  + **`inventory_size`（背包格数）** + **`starting_items`（出生家当）**——**职业不给技能**；
  怪物 / 建筑可编 `point_reward`（打赢 / 开箱给几点）（§4.2.3 / §4.2.4 / §4.8.8）
- J. **五种建筑行为**：`empty` / `treasure` / `monster` / **`event`** / **`shop`**——右栏**按选中行为只显示对应的块**（§4.4 / §5.6）
- K. **技能系统**（§4.8.3）：技能是**组件库第七类**，字段 `dim` / `target` / `vs` / `bonus` / `apply` / `cost` / `effects`；
  编辑器**只用下拉与数字框**把"取哪一维 + 打谁 + 挂什么"配出来，并给人话预览
- K2. **后天学技能**（§4.8.3 / §4.8.10）：`effects` 支持 **`learn_skill` / `forget_skill`**，
  于是**技能书就是一件普通消耗品**——**推箱 / 事件 / 商店 / 战利品，凡能给道具的地方都能给技能，零新增通道**。
  **技能无职业限制**：法师能学盾击、战士能学治疗术；玩家开局只有保底对 `basic_attack` ＋ `basic_magic`
- K3. **技能可获取性校验**（§5.7）：已启用但**没有任何途径能学到**的技能 → 编辑器标黄提示（不阻塞导出）
- L. **事件系统**：门槛 `gate` ＋ 判定 `check` ＋ 后果 `on_success` / `on_fail` / `once`；编辑器**实时显示必成 / 必败区间**（§4.8.9 / §5.7）
- M. **状态与持续效果**：`effects` **五种 `op`**（`add_stat` / `add_tag` / `remove_tag` / **`learn_skill`** / **`forget_skill`**）；状态带 `duration`（有上限）、
  `per_turn`（每回合增减）、**`modifiers`（持续改属性，进力值链 ②）**；**tag 进能力集合**（§4.8.10）
- N. **商店**：上架池 `stock`（与奖励池同构）＋ 定价 `price`（货币 = 一件道具，复用 `rollRange` 掷骰定价）（§4.8.11）
- O. **背包容量**：职业 `inventory_size`（默认 50，`0` = 无限），按条目数算（§4.2.4）
- P. **回合引擎**：*一次交锋*（技能 + 对手反击）与 *一次移动*（走完全部步数）各算一回合；**道具不占回合**（§4.8.0）
- Q. **数值标定**：预设数值全部落在 §6.1.1 的基线内（预设职业总量约 35 点 / 小怪低区间 / 精英高区间）
- R. **序列化**：导出 / 导入 `.pmod`（自包含组件快照 + `rules`，round-trip 无损，§3.3）
- S. **内置预设**：见 6.1

### 6.1 内置预设最小清单（开箱即玩）

- **技能**（第七类，**全套七条刚好把"取哪一维 × 打谁 × 挂什么"演示完**，§3.1 有完整 yaml）：
  `普通攻击`（`patk`/`opponent`/0 加成）、`普通法术`（`matk`/`opponent`/0 加成，**`cost` 同样为空**）、
  **`治疗术`（`matk`/`self`/`apply: hp`——只改 `target` 就从打人变救人）**、
  **`力量祝福`（`self` + `apply: none` + `modifiers`——对自己上增益）**、
  **`虚弱诅咒`（`opponent` + `apply: none` + 减益——对对手上 debuff）**、
  `盾击`（`patk` + `bonus`，给骑士）、**`毒牙`（伤害 + 挂 `中毒`）**
- **小怪**：哥布林（`hp [6,12]`，`point_reward: 1`，`attack_weights: { basic_attack: 3, basic_magic: 1 }`）、
  史莱姆（`hp [6,10]`，`point_reward: 1`，只会 `basic_attack`、抗魔法）
- **精英怪**：哥布林王（`hp [24,40]`，`point_reward: 5`，`tags: [精英]`，带战利品池，会 `basic_attack` + `basic_magic`）、
  伪装宝箱（`hp [18,28]`，`point_reward: 3`，`tags: [精英]`，带战利品池）
- 道具：铁剑（weapon, `patk +5`）
- **恢复道具**：红瓶（`self hp +5`）、蓝瓶（`self mp +5`）—— 量级按基线，各约 1/6 预算
- **能力件**：火抗鞋（`tags: [火抗]`，脚槽）、小船（`tags: [渡河]`，手槽，`patk -1`）、**撬锁工具（`tags: [撬锁]`，手槽）**
  —— 让"火焰山 + 火抗鞋""河流 + 小船""石门 + 撬锁工具"开箱即玩就能碰出来
- **状态用品**：御火符（`add_tag: 火抗, duration: 3`——**临时通行**）、解毒剂（`remove_tag: 中毒`——**解药**）
- **货币**：金币（`tags: [货币]`，`usable: []`）—— 商店的钱，靠奖励池 / 事件产出
- 建筑：宝箱屋（treasure + mimic + `pick: tiers` 含空箱档 + `copies: multiplier`，`point_reward: 1`）、
  怪物房（`monster_pool` 池里放哥布林 + 史莱姆，**不是写死一只**）
- **事件建筑**：上锁的石门（`event`，`gate: [撬锁]` + `check: 2D6 + patk ≥ 15`；成功给 2 点 + 红瓶，
  失败掉 3 血并挂 `扎伤` 3 回合）—— 把"门槛 ＋ 判定 ＋ 后果"三件套演示一遍
- **商店建筑**：流浪商人（`shop`，`stock` 按标签筛消耗品，`price: 1D6 → 5~15 枚金币`）
- **会下毒的怪**：毒牙哥布林（`attack_weights: { poison_bite: 1 }`，
  **技能 `poison_bite` 自带 `effects: [中毒]`**）—— 演示"怪物会下毒"＋"解毒剂能解"的闭环，
  且**靠的是技能，不是怪物身上的特殊字段**（§4.8.3）
- **道路：小路（`step: 1`）、沼泽（`step: 2`）、河流（`gate: [渡河]` + `block`）、火焰山（`gate: [火抗]` + `penalty hp: 5`）**
  —— 四条路刚好把"纯消耗 / 硬权限 / 软权限"三种形态各演示一遍
- **职业**：骑士 / 法师，各带 `base_stats`（初始属性）+ `free_points: 25` + `buffs`（优劣）+ `starting_items`（家当）：

| 职业 | `base_stats` | `free_points` | `buffs` | `starting_items` | `inventory_size` |
|---|---|---|---|---|---|
| 骑士 | `{ hp: 5, mp: 0, patk: 3, matk: 0, pdef: 2, mdef: 0 }` | `25` | `{ hp: 110, patk: 120, pdef: 110, matk: 80 }` | `[red_potion]` | `50` |
| 法师 | `{ hp: 3, mp: 4, patk: 0, matk: 3, pdef: 0, mdef: 2 }` | `25` | `{ hp: 90, matk: 130, mdef: 120, patk: 80 }` | `[blue_potion, scroll_of_fireball]` | `30` |

> **职业之间只差"先天的牌面"，不差"会什么"**：法师出生带一本《火球术》——
> 但那只是**家当**，能丢能卖，**不是"法师专属技能"**。他要是把书扔了、去捡《盾击》，那他就是个战士（§4.2.3）。
- **技能书**：`scroll_of_fireball`（`learn_skill: fireball`）——**后天发育的载体**，放在宝箱屋的奖励池里、商店的货架上、或事件后果里都行。

> 两个预设职业的 `base_stats` 总和分别是 10 / 12，加上 `free_points: 25` 后总量约 35~37——
> **这就是 §6.1.1 那把尺子的来源**。想要更硬核的局，把 `free_points` 调小即可；**这是职业设定，引擎不管**。

### 6.1.1 数值标定基准（预设职业的尺子）

**这把尺子来自预设职业，不是引擎硬规则**：预设职业的 `base_stats` 总量约 10，`free_points: 25`，
所以开局玩家大约有 **35 点属性**可分（§4.2.1）。1 点 = 1 属性值，所以：

| 对象 | `hp` | `mp` | `patk` | `matk` | `pdef` | `mdef` |
|---|---|---|---|---|---|---|
| **玩家**（预设职业约 35 点） | 5 ~ 30 | 0 ~ 25 | 0 ~ 30 | 0 ~ 30 | 0 ~ 30 | 0 ~ 30 |
| **小怪** | `[6, 12]` | `[0, 2]` | `[2, 4]` | `[0, 2]` | `[1, 2]` | `[1, 2]` |
| **精英怪** | `[24, 40]` | `[4, 8]` | `[6, 10]` | `[4, 8]` | `[4, 6]` | `[4, 6]` |
| **装备**（普通 / 强力，单维加值） | 0 / +2 | 0 / +3 | +1~2 / +4~6 | 同左 | 同左 | 同左 |
| **消耗品**（单次 delta） | 红瓶 +5 | 蓝瓶 +5 | — | — | — | — |

- **尺子在玩家这边**：一件强力装备 `+5` ≈ 1/7 的点数预算；超过它就该是"传说"级别。
- **怪物不在同一把尺子上**：它是**区间**且**小怪 / 精英跨度很大**（`hp` 从 6 到 40）。
  想让某只怪"难缠"，加宽区间或抬高档位即可——**不需要新字段**。
- **`point_reward` 是成长曲线**：预设里小怪 1 点 / 精英 5 点。玩家打完一张图的收益大致可以推算，
  这就是"变强"的节奏。
- 这只是一张**参考基线**，不是硬约束。你完全可以把预设职业的 `free_points` 改成 300，
  那时**这张表就作废了**——**这是你的设计自由**。

> 开箱时有**两件独立的事**，别混：
> ① **系统预设**（上面这批）在新用户首次打开时**播种一次**进组件库（标 `预设`），此后就是用户的资产；
> ② **新建一局游戏**时，项目是**空的**（一张空地图 + 空背景）——需要什么就从库里勾选启用 / 铺到图上；
> 若想开箱即玩，提供"新建 → 示例局"入口，一次性把上面这批**启用 + 铺一张示例地图**。

### 6.2 验收标准
1. **对齐**：顶栏、左栏、中栏、右栏四条边在任意窗口宽度下都落在同一条栅格线上；面板无自带 margin。
2. **图层**：左栏能看到全部地图，可切换 / 新建 / 重命名 / 排序 / 删除；顶栏不再有地图 Tab。
3. **可辨识**：任一组件都能一眼看出**库身份**（`预设` / `自建`）与**本局状态**（`已启用` / `未启用`、`已铺设 ×N` / `未铺设`、`被引用 ×N`）；非地图件不会被误以为能拖到地图上。
4. **操作模式**：6 个模式各自行为与 §5.4 表一致；"铺路"只有一个入口；`Esc` 在任意模式都能干净退回「选择」。
5. **框选批量**：拖框选中范围内全部节点后，可一键批量删除，且只占**一步**撤销。
6. **奖励算法**：宝箱屋能配 `reward_pool`（`source: ids` 手选 / `source: filter` **按条件筛整个组件库**，可带权重）
   ＋ `pick`（`tiers` 档位表含空箱档 / `count` 数值区间）＋ `copies`（`fixed` / `value` **数值** / `multiplier` **倍率**）；
   面板上能直接读到"掷 1D6：1~2 空箱，3~4 一件，5~6 两件"这类预览。**没有 `all`**：件数永远被 `|池|` 夹住。
7. **力值链可验证**：一次施放的**本力值 / 对方防值**都能拆开看到
   **已结算属性值 ＋（装备加值 ＋ 状态加值 ＋ 技能 `bonus`）＋ 职业百分比 ＋ 骰子叠加 ＋ 骰子倍率** 五环，
   不是"只有骰子点数"；换装备 / 挂状态 / 换职业 / 换个技能会立刻反映到力值上。
7a. **技能就是"取一维 + 打谁"**：用**同一个技能编辑器**（五个下拉/数字框）能造出这五类，且**不改一行代码**——
   `普通攻击`（`patk`/`opponent`/0 加成）、`治疗术`（**只把 `target` 改成 `self`**）、
   `力量祝福`（`apply: none` + `modifiers`）、`虚弱诅咒`（`opponent` + 减益）、`毒牙`（伤害 + 挂 `中毒`）。
   **编辑器不认识"火球术""治疗术"这些词**——它只显示"取哪一维、打谁、挂什么"。
7b. **两种技能走两条路**：`target: opponent` 会**对抗、会落空**（不命中则 `effects` 也不生效）；
   `target: self` **不对抗、不落空**，但**仍然掷骰**（骰子决定治疗 / 加成的量）。
7c. **技能不绑职业**：把某职业的 `starting_items` 改成不含技能书、或干脆删空——**他不会因此少会任何技能**；
   把一本《盾击》放进宝箱屋，**法师开箱照样学会**；`forget_skill` 又能把它拿走。
7c2. **"存在"与"谁会"是两件事**：技能页能**反查**"哪些书 / 哪些怪物在用我"，但**不显示"谁会"**（那是游玩态数据）；
   一个技能都没启用的世界里，玩家只有保底对 `basic_attack` ＋ `basic_magic`。
7c3. **"法师练成战士"能跑通**：法师把点数全砸 `patk` + 学到 `shield_bash` + 抢到铁剑，**确实能当战士打**——
   但 `buffs.patk: 80` **永远不消失**（先天的牌面改不了，这正是"顶着 debuff 努力向前"）。
7c4. **技能书就是道具**：把 `scroll_of_fireball` 放进奖励池 / 事件 `grant` / 商店 `stock` 三处任一，
   玩家都能学会——**没有任何一处需要为"教技能"新增通道**。
7d. **回合定义可验证**：掷出 3 步走 3 格**只 tick 一次状态**（不是 3 次）；一次交锋结束 tick 一次；
   **用道具不 tick**——同一场战斗里连嗑两瓶药，状态剩余回合数**一点不减**。
7b. **6 属性贯通**：`mp` 能在五处一致工作——分配点数能加它、法术 `cost` 扣它、蓝瓶回它、地形 `cost` 扣它、怪物 `stats.mp` 有它。**不允许出现"半套 mp"**。
7c. **两边的属性来源不对称**：玩家属性来自 职业 `base_stats` ＋ 分配（**不被骰子改**）；怪物属性来自 `stats` 区间**登场摇定**。
7d. **小怪 / 精英可辨**：预设里两者 `stats` 区间档位明显不同；精英靠 `tags: [精英]` 标注，怪物池能 `filter` 出来。
7e. **点数由职业决定、规则由引擎决定**：把某职业的 `free_points` 改成 `300` 能直接生效（**引擎不拦**）；
    但"1 点 = +1""不可洗点""余点保留"这三条**改不了**（是硬规则）。
7f. **战斗能加点**：怪物 / 建筑上的 `point_reward` 在结算时把点数加进玩家的剩余自由点，
    且**溢出到下个场景仍然有效**（不是临时加点）。
8. **规则可配**：右栏「规则」页的字段与 §4.8.6 清单**严格一致（共 13 项，不多一个）**，且**没有 `combat.attacks`**；
   硬规则（§4.8.0）只读展示、不给开关；
   每个字段旁有人话预览，如"每回合掷 1D6 走几格，**走完全部步数算一个回合**"、
   "力值 = 物攻[3~6] 摇出 5 + 铁剑(+5) + 技能加成(0)，× 职业 100%，+ 1D4，× 1D6 倍率"。
9. **来源派生**：**七大类**（怪物 / 道具 / 建筑 / 道路 / 职业 / 技能 / 背景）都能自建，
   且「预设 / 自建」徽章**判定方式完全相同**——没有哪一类多一个字段。
10. **消耗与权限可配**：道路 / 建筑能编 `cost`（步数 / 血量 / 法力）与 `gate`（标签 + `any|all` + `block|penalty` + `penalty`）；
    装备 / 职业能编 `tags`；编辑器里能**双向反查**——"这条路要 `火抗`，谁带这个标签？""这双鞋的 `火抗` 能过哪些路？"
11. **标签驱动、不写死**：造一条 `gate.tags: [飞行]` 的路 + 一件 `tags: [飞行]` 的装备，**不改一行代码就能走通**——
    编辑器不认识"飞行""渡河""火抗"这些词。
11b. **事件能跑通**：造一个 `encounter: event` 的建筑，能配 `gate`（标签门槛）+ `check`（骰子 / 加值属性 / 目标值）
    + `on_success` / `on_fail` / `once`；编辑器**实时显示命中率与必成 / 必败**——
    把目标值调到必败时会提示"**现在做这个纯属浪费时间**"。
11c. **状态闭环**：中毒能挂上（带 `duration`）、每回合掉血、**解毒剂能解**、`duration` 到点自动消失；
    且 `duration` 超过 `state.max_duration` 时被夹到上限；**造不出永久状态**。
11d. **临时通行**：吃御火符获得 `火抗` 3 回合，期间能过火焰山，3 回合后过不去——
    **全靠状态 `tags` 进能力集合，引擎不写死任何标签**。
11e. **商店能跑通**：造一个 `encounter: shop` 的建筑，配 `stock`（按标签筛）+ `price`（掷骰定价）；
    能验证"**货币就是一件普通道具**"——整个系统里不存在独立的货币字段。
11f. **背包上限生效**：把职业 `inventory_size` 设成 `1`，捡第二件**不同**道具时被拒绝并提示；
    同种道具叠加仍占 1 格；设成 `0` 则不限制。
11g. **五种行为面板分明**：同一栋建筑切换 `encounter` 五选一时，右栏**只显示对应的块**（不把奖励池 / 事件 / 商店糊在一起）。
11h. **跑团立场可验证**：编辑器里**找不到**"难度评估""平衡性警告""多结局""条件通关"这类入口（§1.1 / §7.4）。
12. **round-trip**：导出 `.pmod` → 重新导入，启用集合、铺设节点、地图顺序、组件定义与 **`rules` 全部一致**。
13. **持久化**：刷新页面数据不丢失。

## 7. 后续阶段规划（非 MVP，仅记录）

### 7.0 应用架构与路由约定（MVP 基础）

- **默认主页 = 游玩页**：打开 `xxx.com`（根路径 `/`）直接进**游玩**，玩家无需经过构建界面就能玩。
- **构建页走独立 path**：`xxx.com/build` 才是**构建 / 编辑器**入口（组件库、地图铺设、规则配置、§5 那一套）。
- 两者是**同一应用的两个路由**，不是两个站点；游玩页加载 `.pmod` 开玩，构建页产出 / 编辑 `.pmod`。
- 理由：游玩是产品的主场景，构建是作者工具——默认落到游玩，作者才需要主动进 `/build`，避免每次打开都先看到编辑器。

### 7.1 游玩态
- 去掉网格线，保留每 10 格细坐标参照线
- **开局职业**：按 `rules.class_pool` 随机或固定；属性以该职业的 `base_stats` 起步（§4.2.3）
- **属性加点**（§4.2.2）：界面给 6 个属性各一个"+"，旁边显示**剩余自由点**（开局 = 职业的 `free_points`）；
  **随时可回来加**（战斗外 / 战斗中都能加）；**没有"重置"按钮**（不可洗点是有意的）
- **点数会持续进账**：打赢怪 / 开箱按 `point_reward` 加到剩余自由点（§4.8.8），所以"现在加什么"是持续决策
- **硬规则照 §4.8.0 执行**：正交四邻、不可斜走、可原路返回
- **开局技能栏**：只有**保底对 `basic_attack` ＋ `basic_magic`**（内建，两个 `cost` 都为空）——**职业不给技能**（§4.2.3）。
- **开局家当**：按职业的 `starting_items` 塞进背包（**那是道具，不是本事**；技能书也只是道具）。
- **学技能**：读到技能书 / 事件教你 / 商店买到 → **技能进技能栏（永久）**，存进 `.psave`；
  `forget_skill` 会把它拿走。**"已学会"是进度，不是场景**（§3.3）
- **回合 = 一次"推进时间"的动作**，只有两类（§4.8.0）：
  - **一次交锋**：玩家【点攻击】结算技能 → **怪物【电脑掷骰】反击一次** → 整次交锋 = 一个回合（见 §4.8.3 两回合结构）。**状态在回合【开始】先判存活、再 tick 一次**，不在结束
  - **一次移动**：掷 `rules.move.dice` 得 N 步 → **一次走完（中途可停）→ 走完才算一个回合**。**同样在回合【开始】tick 一次**（移动时踩到的场景 buff / 身上 debuff 也在开头结算）
  - **使用道具不占回合、不 tick**——随时可用，**这是它比技能强的地方**（也是中毒扣到 0 仍能先吃药救活的关键）
- **移动按 §4.8.4 执行**：每格 **权限检查 → 扣消耗 → 结算该格**（含该格的 building 遭遇）
- **技能按 §4.8.3 执行（6 步）**：选技能 → 查成本 → 算本力值 → 判定（`target: self`/`vs: none` 时跳过）
  → 作用到 `apply` 指定的那一维 → 逐个执行 `effects`
  - **选技能前先查 `cost`**：不够就把按钮置灰（§4.8.3），够则扣掉再结算
  - **`target: self` 的技能不对抗、不落空**，但仍掷骰（骰子决定治疗 / 加成的量）
- **力值按 §4.8.2 力值链算**：已结算属性值 + （装备 `modifiers` ＋ 状态 `modifiers` ＋ 技能 `bonus`）× 职业 `buffs`% + 骰子叠加 → × 骰子倍率
  - 玩家侧属性 = 分配值（全程不变）；怪物侧属性 = 遭遇开始时摇定一次
- 踩到 `building`：`treasure` → 按 `rules.treasure` 掷骰定件数 / 份数后揭晓；`monster` → 先 `resolveMonster` 抽怪摇属性再打；
  `event` → 走 §4.8.9；`shop` → 走 §4.8.11；`mimic` → 先按 `chance` 判定伪装
- **战利品**：战斗胜利后按 `rules.loot` 抽取（池取自怪物 `reward_pool`，可带权重）
- 装备穿戴（含多槽 / 挤占规则）、消耗品在对战 / 前进时使用（红瓶回 `hp`、蓝瓶回 `mp`）
- **事件按 §4.8.9 执行**：踩到 `encounter: event` → 先查门槛 `gate`（不满足按 `on_missing` 处理）→
  需要判定就掷 `check.dice` 并算手艺值 → 走 `on_success` / `on_fail`（展示文本 / 扣资源 / 给点 / 给道具 / 挂状态）
- **商店按 §4.8.11 执行**：踩到 → 按 `stock` 上架 → 每件价格由 `price` 掷定 → 玩家用 `currency` 指的那件道具付款
- **状态按 §4.8.10 执行**：**每回合【开始】先判存活、再 tick**（走完一次移动 / 打完一次交锋都算一个回合，tick 都在其开头）——把每个状态的 `duration` 减 1、
  按 `per_turn` 结算增减、按 `modifiers` 参与力值链，归零自动移除；**本回合中刚挂上的状态要到下回合开始才首次 tick**。
  状态 tag **进能力集合**，所以"御火符"能顶一阵 `火抗`、力量祝福能顶 3 回合物攻 +2
- **背包按 §4.2.4 执行**：拾取时按 `{ id, count }` 条目数检查 `inventory_size`（**同一种道具算 1 格**），满则拒绝并提示

### 7.2 骰子系统
- 掷骰与判定明细展示：让人看到完整链条，如
  `怪物物攻：区间[2~4] → 掷1D6=5 → 4（本场固定）`
  `本力值 = 4 + 装备 0 + 状态 0 + 技能 0 = 4，× 职业 100% = 4，+ 1D4=2 → 6，× 1D6→1.5× = 9`
  `玩家物防 = 分配 5 → 5` → `命中（9 ≥ 5），伤害 = max(1, 9−5) = 4`
- **`target: self` 的技能要另写一条线**：`治疗术：本力值 7（物攻…不对抗） → 回自己 7 点 hp`
- **法术要显示 `mp` 流水**："消耗 3 `mp`（剩 2）"；**道具不消耗回合，要用另一种颜色标出来**
- UI：转盘 / 幸运转盘等形式，点击投掷；合适时机提供合适骰子
- 掷骰历史可回放

### 7.3 存档与分享
- `.pmod` 静态场景；`.psave` 单独存游玩进度（**已学会的技能栏**、背包与穿戴、加点与剩余点、已揭晓奖励、骰子结果、位置、身上的状态），可重开多周目
- 导入/导出两份文件
- **组件库单独导入 / 导出**（把整个库存成一个文件带走、跨设备同步）——与 `.pmod` 分开，因为库是跨项目的资产（§4.0）
- **`.pmod` 加 `version` 字段**：格式一旦再变，靠它做迁移提示（现在是"没写 = 初版"）

### 7.4 明确不做（含理由，防止以后又当新需求提）

| 不做 | 理由 |
|---|---|
| **多结局 / 条件通关 / 剧情分支树** | **这是跑团，不是剧情 RPG**（§1.1）。跑团是未知的自由探索和玩家自己定下的未来；走到终点就是完成游戏，**用任何方式到都算** |
| **难度评估 / 平衡性警告** | **编辑器不下定义**（§1.1）。不同的设计本身就是各自的特色玩法 |
| **纯概率门**（"必须掷出 6 才能撬锁"） | 那不叫玩法，叫浪费时间。事件判定的正解是**门槛（标签）+ 手艺（属性/装备抬高基数）**，并把**必成 / 必败**标出来（§4.8.9） |
| **货币系统 / 背包独立系统** | 货币就是**一件普通道具**，背包就是**职业上的一个数字**（§4.2.4 / §4.8.11）。不发明第二套机制 |

### 7.5 技能系统：已落地 + 后续扩展方向

> **技能已经做了**——但它**没有被做成"每个技能一套剧本"**，而是被收敛成
> **"取哪一维属性 + 打谁 + 附带什么"**（§4.8.3）。所以它**没有侵蚀骰子模型**：
> 判定仍然只有一条力值链、一个命中公式、一个伤害公式。

**落地形态回顾**

| 项 | 结论 |
|---|---|
| 技能是什么 | **组件库第七类**（§4.0），可自建、可启用，进 `.pmod` |
| 技能决定什么 | `dim`（取哪一维）+ `target`（打谁）+ `vs`（对手拿哪一维防）+ `bonus` + `apply` + `effects` |
| 玩家技能从哪来 | **后天学的**：技能书（`learn_skill` 消耗品）/ 事件后果 / 商店 / 战利品（§4.8.3）。**职业不限定技能** |
| 失去 | `forget_skill` 能拿走技能——**环境和运气真的会把你的本事夺走** |
| 怪物技能从哪来 | **`attack_weights` 的键**（§4.1）——**主角有怪物就有** |
| 不占地图格 | 是。**和道具同类**（非地图件），必须显式启用 |
| 保底 | **默认模板角色**开局技能栏 = **保底对 `[basic_attack, basic_magic]`**（两个 `cost` 都为空）；**默认模板下永远不会"一个技能都没有、打不了架"，也不会"没蓝等死"**。**保底对是模板默认安全网，作者可在设计中移除 / 改 `cost`（自创角色不受影响）** |
| 代价 | 施放 = **一次交锋 = 一个回合**（所以"治疗术"比"红瓶"费力，但量更大，§4.8.0） |

**后续可以往上加的东西（都不破坏现有结构）**

| 想加的 | 怎么加（不新增判定） |
|---|---|
| **冷却** | 技能上再加 `cooldown: N`——用完数 N 个回合才能再放。**规则层只多一个计数器** |
| **使用次数限制** | `charges: 3`——用完需要补充（比如靠道具恢复） |
| **连续技 / 蓄力** | 技能上写 `requires: { tag: 蓄力 }`——**复用状态 tag 作前置条件**，和 `gate` 同一套逻辑 |
| **范围 / 多目标** | 加 `targets: n`（打 N 个）或 `shape`（十字 / 直线）——**只在选目标那一步展开，判定仍是一对一** |
| **技能改乘数而非加数** | 在 `effects` 里加一个 `op: mult_modifier`（作用在力值链 ③ 职业百分比的旁边）——**不是新判定，只是多一个修饰点** |

- **纪律不变**：任何新加的字段，都必须能回答"**它在哪一步生效、用哪颗骰**"。
  回答不上来的，就说明它想把骰子拆成"每个技能一套流程"——**那时候要把方案打回来重做**。

| **配置纪律** | **配置里出现的每个字段都必须是代码已实现的**；不给"本来就该如此"的东西做开关（`move.allow_back` / `move.diagonal` 全删）。有疑问的字段一律不写 |
| **硬规则** | 正交四邻移动、不可斜走、可原路返回；**一回合 = 一次推进时间的行动（一次交锋 / 一次移动走完全部步数）**；`target: opponent` 时 `本力值 ≥ 对方防值` 命中；伤害 = `max(1, 本力值−防值)`、治疗 = `本力值`；**1 点=+1 / 不可洗点 / 余点保留**；技能要付自己的 `cost`；**任何状态必须有 `duration` 且不超上限**（§4.8.0） |
| **状态必有上限** | 任何状态都必须带 `duration`，且不超过 `state.max_duration`（默认 10）。**不存在永久状态**——没有解法的状态就是死局（§4.8.10） |
| **点数给多少 = 职业设定** | `ClassDef.base_stats`（初始属性）+ `ClassDef.free_points`（开局自由点）**都是职业自己的字段**。**不设上限**——`free_points: 300` 完全合法（§4.2.3） |
| **分配规则 = 硬规则** | **1 点 = 该属性 +1**；可分配到 6 属性任意项；**任意时刻**都能加；**不可洗点**；**剩余自由点保留**。这一层引擎写死（§4.2.2） |
| **点数会持续进账** | 怪物 / 建筑上的 `point_reward`（默认 0）在结算时把点数加进剩余自由点——**这是玩家变强的主渠道**，固定值不掷骰（§4.8.8） |
| **属性来源两侧不对称** | **玩家 = `base_stats` ＋ 分配出的确定值**（不能被骰子改）；**怪物 = `stats` 区间登场摇定**（有波动）。玩家可控、敌人随机——故意的（§4.0.2 / §4.8.2） |
| **小怪 / 精英** | **不加字段**：靠 `stats` 区间拉开档（小怪 `hp 6~12` / 精英 `hp 24~40`），精英再打 `tags: [精英]`，怪物池直接 `filter: { tags: [精英] }` 就能做精英房（§4.1 / §6.1.1） |
| **`mp` 是正式属性** | 两条资源之一：玩家能分配点到它、**有成本的技能消耗它**（如 `cost: { mp: 3 }`；**保底对 `basic_attack` / `basic_magic` 都不花 mp**）、蓝瓶回它、地形 `cost` 能扣它。**要么没有 mp，要么成套**——现在是成套（§4.0.1 / §4.8.3） |
| **消耗 vs 权限** | 道路 / 建筑有**两个正交维度**：`cost`（消耗：步数 / 血量 / 法力）与 `gate`（权限：标签匹配）。**消耗只让路变贵，权限才决定能不能过**——两者任意组合（§4.5.1） |
| **标签驱动通行** | `gate.tags` 对 `capabilities = ⋃(穿戴中装备.tags) ∪ 当前职业.tags` 做匹配（`any` / `all`）；不满足时 `block`（走不进去）或 `penalty`（能走但加罚）。**引擎不认识"渡河""火抗"这些词，用户造新标签就自动有新区块**（§4.5.2 / §4.5.3） |
| **能力的三个来源** | `capabilities = ⋃(穿戴中装备.tags) ∪ 当前职业.tags ∪ **身上状态.tags**`。装备是**长期**钥匙（5 个槽位有限，"带火抗鞋就带不了小船"正是玩点）；状态是**临时**钥匙（御火符顶 3 回合）。**同一个 `tags` 字段身兼三职**（§4.3 / §4.5.2 / §4.8.10） |
| **`cost` / `gate` 是地图件公共字段** | 道路和建筑**共用同一套**：建筑加 `gate` 就是一扇上锁的门，机制完全复用，不另发明（§4.4） |
| **力值合成链** | `力值 = floor( ( (已结算属性值 + 装备 modifiers + **状态 modifiers** + **技能 bonus**) × 职业 buffs% + 骰子叠加 ) × 骰子倍率 )`。**属性 / 加值（加法环：装备＋状态＋技能）/ 职业（乘法）/ 骰子（叠加 or 倍率）四环全在链上，不是只看骰子**（§4.8.2） |
| **技能决定维度** | `skill.dim` 决定"取哪一维属性当基准"，`skill.vs` 决定"对手拿哪一维对抗"（`auto` 物理族对物理族、法术族对法术族）。**引擎不再写死"物攻→物防、魔攻→魔抗"**（§4.8.3） |
| **基础积木只有三个** | `rollRange`（骰点→区间取值）、`rollSteps`（骰点→档位倍率）、`rollSum`（骰点直接相加）；全篇不另起第二套公式（§4.8.1） |
| **技能 = 取一维 + 打谁** | 技能是**组件库第七类**，只回答三件事：**`dim`（取哪一维属性）／ `target`（打谁）／ `effects`（附带什么）**。**攻击、治疗、增益、诅咒全是这三种选择的组合，不是四套代码**（§4.8.3） |
| **两个 0 加成基准** | `普通攻击`（`patk`/`opponent`/`bonus: 0`）与 `普通法术`（`matk`/`opponent`/`bonus: 0`）——**纯粹拿属性值打人，技能只是载体**；**两者 `cost` 都为空（保底对）** |
| **`auto` 自动配对** | `dim = patk` → `vs = pdef`；`dim = matk` → `vs = mdef`。**引擎不再写死"物攻→物防"**，那只是两个预设技能的选择 |
| **技能来源** | **玩家 ← 后天学**（技能书 `learn_skill` / 事件 / 商店 / 战利品）；**怪物 ← `attack_weights` 的键**（键就是技能 id）。**职业不限定技能**，**默认模板角色**开局只有保底对 `basic_attack` ＋ `basic_magic`（§4.8.3，作者可移除） |
| **skill 的两个分支** | `target: opponent` **对抗、会落空**（不命中则 `effects` 也不生效）；`target: self` **不对抗不落空，但仍掷骰**（骰子定治疗/加成的量） |
| **战斗骰子** | `stat_dice` 属性结算骰；`pick_dice` 怪物挑技能骰；`atk_roll` / `def_roll` **施放方与对抗方各一组力值骰**（`add_dice` / `mult` 可省）。**没有 `combat.attacks`**（§4.8.3 / §4.8.6） |
| **回合 = 推进时间** | 只有两类行动算一回合：**① 一次交锋**（玩家【点攻击】＋ 怪物【电脑掷骰】反击，§4.8.3）**② 一次移动**（掷骰得 N 步，**走完全部才算一个回合**）。**状态与地形 `cost` 在回合【开始】先判存活、再 tick 一次**（§4.8.0） |
| **移动为什么算整次** | 若"走一格 = 一回合"，摇 6 就 tick 6 次、摇 1 只 tick 1 次——**摇 6 反而更亏**，掷骰失去意义 |
| **道具不占回合** | 使用道具是**回合内的自由动作**，不推进时间、不 tick——所以嗑药随时可用。**这是它比技能强的地方** |
| **技能占回合** | **施放任何技能 = 一次交锋 = 一个回合**——所以"治疗术"花一回合、"红瓶"不花，**道具即时但量小、技能费力但量大**（§4.8.10） |
| **技能有成本** | 技能自己的 `cost`（如 `{ mp: 3 }`）——**选它之前先查，不够就选不了**；`mp` 不进力值链，它是"入场券"。`cost` 省略 = 免费（§4.8.3） |
| **技能两侧不对称** | **玩家自己选**（从**自己学到的**技能栏里挑，有取舍）；**怪物掷 `pick_dice` 按 `attack_weights` 随机**——否则玩家只堆一维防御就无敌（§4.8.3） |
| **职业＝先天** | 职业只给 **`base_stats`（属性起点）+ `buffs`（优劣百分比）+ `inventory_size`（背包）+ `starting_items`（家当）**。**没有 `skills`**——**技能一律后天学**（§4.2.3） |
| **先天改不了、后天自己选** | `buffs` 的百分比**永远生效**（法师 `patk: 80` 一辈子打八折）。**"顶着 debuff 努力向前"就是靠这一条**——你可以用后天的选择去对抗先天发到的牌，但**抹不掉它** |
| **技能书 = 消耗品** | 技能靠 `op: learn_skill` 传播。**因为书就是道具，所有现有"给东西"的机制自动都能给技能**——奖励池 / 事件 / 商店 / 战利品，一处都不用改（§4.8.3 / §4.8.10） |
| **学过 ≠ 状态** | 学会技能是**永久的**（只能被 `forget_skill` 拿走）；状态是**限时的**（必带 `duration`）。**两者不是一回事**（§4.8.10） |
| **技能的"启用"≠"谁会"** | "启用" = 这一局世界里**存在这一招**；"谁会"是**游玩态数据**（进 `.psave` 不进 `.pmod`）。未启用的技能不能被学、不能被怪物用（§4.8.3） |
| **怪物属性登场摇定** | **怪物**登场时用 `stat_dice` 把 6 属性区间摇成具体值，**本场固定**；**玩家不摇**（`base_stats` ＋ 分配）。战斗中的随机性只来自力值链的 ⑤叠加 / ⑥倍率（§4.8.2） |
| **怪物不写死** | 怪物房用 `monster_pool`（池 + 权重 + 掷骰抽），**单只 = 单元素池**；抽到后再摇它的属性（§4.8.5⑥） |
| **奖励算法** | 池（组件上）：`source: ids` 手选 / `source: filter` 按条件筛整个组件库，条目可带 `weight`。算法（前置配置）：`treasure` / `loot` 各一套 `pick`（`tiers` 档位含空箱 / `count` 区间）+ `copies`（`fixed` / `value` / `multiplier`）；**件数恒被 `\|池\|` 夹住**（§4.8.5） |
| **没有 `all`** | `pick.algo: all` 已删除——池来自 filter 时会把上百件全倒给玩家。要"全给"就写显式 ids 给个大 `n`（§4.8.5 ④） |
| **移动** | `rules.move` **只有 `dice` 一个字段**：每回合掷它定步数。其余是硬规则（§4.8.4） |
| **组件覆盖** | 怪物可覆盖 `atk_roll` / `def_roll` / `stat_dice` / `reward_pool` / `pick` / `copies` / **它的技能表 `attack_weights`**；建筑可覆盖 `reward_pool` / `monster_pool` / `pick` / `copies` / **`event.check`** / **`stock`** / **`price`**。**技能与消耗品不覆盖配置**——它们的内容本身就是字段（§4.8.7） |
| **建筑有五种行为** | `encounter: empty / treasure / monster / **event** / **shop**`。**给东西 / 打架之外，终于能"提要求"和"做交易"**（§4.4 / §4.8.9 / §4.8.11） |
| **事件 = 门槛 + 手艺** | ① `gate` 标签门槛（**能不能碰**）；② `check` 判定（**做不做得成**）。两层都可省，**全省 = 纯叙事块**。判定复用力值链，所以**提升属性 / 换装备能提高成功率**（§4.8.9） |
| **骰子是核心，不是运气** | 编辑器必须把**必成 / 必败区间**算出来摆在眼前：必成提示"白送"，必败提示"现在做纯属浪费时间，先去提升属性"。**不做"必须掷出 6"这种纯概率门**（§1.1 / §4.8.9） |
| **状态 = 标签 + 回合数** | `{ tag, duration, per_turn? }`；每回合 tick 一次；`duration` 必填且不超上限。状态 tag **进能力集合**，所以"临时通行"成立（§4.8.10） |
| **商店不发明货币** | **货币就是一件普通道具**（`tags: [货币]` 只是给编辑器筛选用），"捡钱"就是普通产出。商店 = `stock`（上架池，与奖励池同构）+ `price`（复用 `rollRange` **掷骰定价**），形态与宝箱屋并列（§4.8.11） |
| **背包 = 职业的一个数字** | `inventory_size`（默认 50，`0` = 无限），按 `{ id, count }` **条目数**算，同一种道具占 1 格。它是**内容**（所以不同职业可以背得不一样多），(§4.2.4) |
| **技能已落地（第三轮）** | 技能被收敛成"**取哪一维属性 + 打谁 + 附带什么**"（§4.8.3），**不新增判定**——仍是一条力值链、一个命中公式、一个伤害公式。**冷却 / 蓄力 / 范围多目标只是后续扩展方向**，都不破坏现有结构（§7.5） |
| **职业＝先天、技能＝后天** | **`ClassDef.skills` 删除**。职业只给先天的牌面：`base_stats` + `buffs` + `inventory_size` + `starting_items`。**技能一律后天学**（技能书 / 事件 / 商店 / 战利品）——**角色是先天发到的牌，路子是自己走出来的**（§4.2.3 / §4.8.3） |
| **保底对** | **默认模板角色**技能栏含 `basic_attack` ＋ `basic_magic`，两个 `cost` 都为空（免费安全网）。**"打不了架"与"没蓝等死"两种死局在默认模板下被堵死**；免费 ≠ 无差别——差别在 `dim`（取哪一维），先天的 `buffs` 百分比照样起作用（§4.8.3）。**作者可在设计里移除 / 改 `cost`，这是玩法的一部分** |
| **技能的学习与失去** | 学会靠 `op: learn_skill`（**技能书就是一件普通消耗品**——所以所有"给东西"的机制自动都能给技能，零新增通道）；`op: forget_skill` 能**夺走**技能。**学会是永久的，状态是限时的**（§4.8.3 / §4.8.10） |
| **跑团哲学** | **不做多结局 / 条件通关 / 剧情分支树**——跑团是未知的自由探索，走到终点就是完成，**用任何方式到都算**（§1.1） |
| **编辑器不下定义** | **不做难度评估、不做平衡性警告**。引擎只校验"会不会卡死"（引用悬空 / 死路 / 必败），**不评判好不好玩**（§1.1） |
| **布局对齐** | 全页**一层** padding + 唯一间距 token；**面板一律不许自带 margin**；顶栏不换行 |

## 9. 部署（GitHub Pages）

- **纯静态 SPA，无后端、无服务端能力**。所有数据走 `localStorage` + 浏览器文件导入/导出（`Blob` 下载 / `<input type="file">` 读取），不依赖任何服务器接口。
- 构建：`npm run build` 产出 `dist/`（HTML/JS/CSS/字体），可直接静态托管。
- **base 路径**：Vite `base` 设为仓库项目页路径（如 `/<repo>/`）或自定义域；用项目页必须配置，否则资源 404。
- **路由**：优先单页（用视图状态切换 Build/Play，不用 URL 路由），从根本避免 GH Pages 深链 404；若确需路由用 `HashRouter`。
- **依赖边界**：仅使用能**打包进静态产物**的库（React / Vite / Zustand / lucide-react / 解析库）。不使用任何需要运行时服务器的组件、SSR、服务端存储、外部 API。
- **字体**：手写体优先**自托管**（`.woff2` 放进仓库 `/public/fonts` 并用 `@font-face` 引用），避免运行时依赖外部 CDN，也保证离线可用；如接受外部 CDN 也可用 Google Fonts，但非必须。
- 可选：`.github/workflows/deploy.yml` 用 GitHub Actions 构建并发布到 `gh-pages` 分支（纯配置，不引入服务器）。

## 10. 视觉风格（纸张 + 手绘）

- **整体基调**：暖色纸张（米黄 / 羊皮纸），模拟纸纹与手绘。
- **纸纹**：内联 SVG `feTurbulence` 噪声滤镜做颗粒质感（data URI 背景），叠加轻微暖色渐变；无需外部图片资源。
- **手绘线条**：边框 / 分隔 / 网格线用 SVG 位移滤镜（`feTurbulence` + `feDisplacementMap`）做出轻微抖动的不规则手绘感；或 CSS 不规则 `border-radius` + 微小旋转。避免引入 rough.js 等额外库（除非后续确认）。
- **字体**：标题 / 正文用手写体；拉丁文用 Caveat / Patrick Hand 类，中文用手写体（如马善政 / 龙藏 / 字芒行等），自托管。
- **图标**：lucide 矢量图标可套同一手绘滤镜柔化；自定义 / 内容继续用 Emoji。
- **网格**：构建态网格线呈手绘铅笔线，每 10 格加粗且略带颜色深浅变化；游玩态去网格、留细坐标参照线（同样手绘风）。
- **组件放置**：地图上的建筑 / 怪物以"贴在纸上的手绘便签 / 涂鸦"观感呈现（轻微阴影 + 不规则边）。
