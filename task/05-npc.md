## E0 数据模型与类型（§4.9 / §4.4）

- [x] `NpcDef`：`EntityBase`（`id` / `name` / `icon` / `tags` / `desc`）＋ `dialogs: Record<string, DialogNode[]>`（**方案名 → 根节点数组**）
- [x] **只有一个结构，没有任何判别联合 —— `DialogNode` 就是全树的唯一类型**：
  ```ts
  interface DialogNode {            // 根层数组的元素与任意深层的 items 元素「都是它」
    result?: string                 // 仅当本条是某个 items 的元素（玩家选项）时才生效；根层不写
    message: string[]               // 唯一必填：NPC 台词，逐条展示
    dice?: string                   // 本层 items 的命中骰；不写 ＝ 这一层的选项直接点选
    hit?: string                    // 父层写了 dice 时本条的命中区间；非骰子选择时不需要
    items?: DialogNode[]            // 后续选项；缺省 / 空 ＝ 说完就结束
    give?: string[]                 // 赠予道具 id（可重复 ＝ 多份）；没有赠予时不需要
  }
  ```
  - **不区分根节点与子节点**：`items` 的元素与根层数组的元素**是同一个类型**（§4.9.2「只有一个结构」）；**`type: 'chat' | 'prop'` 判别与 `DialogItem` / `DialogChatItem` / `DialogPropItem` 全部作废**（旧包里的 `type` 字段**忽略**）
  - **必填只有 `message`**：`result` / `items` / `dice` / `hit` / `give` 五个**全部可省**（赠予道具的记录同样有台词 —— 这正是取消"单独道具项类型"的原因）
  - **`give` 与 `items` 可并存**：先结算 `give`，再按 `items` 决定继续还是结束（§4.9.2 结构约束）
  - **道具清单叫 `give`、不叫 `items`**（§8.3 设定 8）：`items` **永远只表示"后续选项"**（同一结构的数组）；道具清单是**字符串数组**（道具 id，可重复 ＝ 多份）—— 两者不共用一个 key
- [x] `Rules` 新增 `talk: { dice: Dice }`（缺省 `1D6`）；`DEFAULT_RULES` 同步，**配置项总账 13 → 14 项**（§4.8.6）
  - **V1 冻结口径里写死的「13 项」要一起改（别只改 `04-editor.md`）**：`src/types/project.ts` 的 `Rules` 注释；`src/build/inspector/RulesPage.tsx` 的注释与常量 **`RULES_FIELD_COUNT = 13`**（清单 / 校验按它算总数）；`src/build/RulesScreen.tsx` 的注释与 `<span class="badge">13 项</span>`；`src/build/TopBar.tsx` 按钮 `title`；`src/build/__tests__/buildApp.test.tsx` 的「整局规则面板（13 项 ＋ 模拟 10 次）」用例名。[`01-build.md`](./01-build.md) 属 V1 史实，**已就地标注「Phase E 后为 14 项」、不改写**
