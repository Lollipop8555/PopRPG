# PopRPG

**单人跑团（Solo TTRPG）的网页实现。**

一个人，一个浏览器，就能开一场冒险。地图、怪物、道具与规则都由你写下来，然后亲自走进去。

## 一局游戏如何展开

```mermaid
flowchart TD
    A["铺开一张地图"] --> B["摆上怪物、道具与房屋"]
    B --> C["写下这一局的规则"]
    C --> D["掷骰前行"]
    D --> E{"前方是什么"}
    E -->|怪物| F["进入战斗"]
    E -->|事件与机关| G["就地解决"]
    E -->|宝箱| H["打开才知道"]
    F --> I["结算，继续前行"]
    G --> I
    H --> I
    I --> J{"到终点了吗"}
    J -->|还没有| D
    J -->|到了| K["走进下一张地图"]
```

上半程是搭台，下半程是走进去。搭台时你说了算，走进去之后——怪物、宝箱与事件当场揭晓，那一局才真正开始。

## 亲手搭起一个世界

```mermaid
mindmap
  root(("这一局的世界"))
    地图与道路
      道路从哪里经过
      何处是死路
    房屋与机关
      迎客送礼的屋子
      做买卖的商人
      上锁的石门
    怪物
      在何处等候
      带什么战利品
    道具与技能
      药水与装备
      技能书
    规则
      判定与战斗
      移动与奖励
```

- **地图由你铺陈**：道路从哪里经过，房屋落在何处，怪物在何处等候，宝箱藏在哪个角落。
- **怪物、道具与技能都可以自己设定**：这一局的判定、战斗与移动规则，也同样由你决定。
- **想要的内容大多能亲手添进去**：迎客送礼的屋子、做买卖的商人、伪装成宝箱的怪物，都可以加进地图。
- **难度由你的设计决定**：地图上若有走不通的地方，会提醒你；至于这一局好玩与否，由你拿捏。

## 一个人的冒险

- **掷骰前行**：每回合掷骰决定步数，在地图上行走；遭遇怪物便进入战斗。
- **六项属性自由分配**：生命、法力、物攻、魔攻、物防、魔防——战士也可以主修魔攻，法师也可以主修生命。
- **技能不绑职业**：战士也能放火球，法师也能学治疗。技能书是一件寻常道具，拾到便能修习，也可以丢掉或卖掉。
- **每一道难关都有钥匙**：火焰山配火抗鞋，河流配小船，石门配撬锁工具——解开谜题，寻找通过的方法。
- **地形各有各的通过方式**：沼泽拖慢脚步，火焰山灼烧生命，河流拦住去路。
- **准备得愈充分，掷骰所能左右的分量便愈小**：属性、装备、职业与状态都计入判定。
- **每一场交锋都留有结算**：胜负出在哪一步，回头看得分明。
- **宝箱里装着什么，只有打开才知道**：药水、装备、金币，或是一只伪装成箱子的怪物。
- **抵达终点，这一场便算完成**：此后还能接着走进下一张地图。

## 游戏流程拓扑（V2.3 设计）

> V2.3 引入**全局状态池**后的完整流程拓扑。**回合是全篇唯一的时间轴**——一切按回合结算。

```mermaid
flowchart TD
    subgraph BUILD["① 构建（作者搭台）"]
        B1["铺地图 · 摆组件"] --> B2["写《规则》Rules<br/>移动 / 交锋 / 判定 / 状态"]
        B2 --> B3["写《状态池》Pool<br/>变量声明 ＋ 回合判定 checks"]
        B3 --> B4(["导出 .pmod"])
    end

    subgraph SETUP["② 开局播种"]
        S1["载入 .pmod"] --> S2["播种状态池<br/>引擎空间（六维 / 步数 / 位置 / 道具件数）→ 作者空间"]
        S2 --> S3["装载回合判定<br/>按来源分批、批内拓扑排定"]
    end

    B4 --> S1
    S3 --> START(["站在起点 start"])

    subgraph TURN["③ 回合循环（世界心跳）"]
        T1["回合开始：一批回合判定，按来源自然排序"]
        T1 --> P1["① pmod 作者业务判定 checks<br/>批内别名拓扑 · 匿名后置"]
        P1 --> P2["② state 状态 tick<br/>per_turn 增减 ＋ duration − 1"]
        P2 --> P3{"③ engine 基础判定（强制最后）<br/>玩家 hp ≤ 0 ?"}
        P3 -->|存活| ACT{"本回合行动（二选一）"}
        ACT -->|"掷 move.dice 得步数"| STEP["移动一格<br/>① 权限 gate → ② 扣 cost"]
        ACT -->|"进入交锋"| F1["玩家攻击回合<br/>选技能 → 查 cost → 力值链（读池）→ 判定 / 作用 / effects"]
        STEP --> CELL{"③ 结算该格"}
        CELL -->|"道路"| ROAD["tags 判定 → 门锁 pool 判定 → missing / penalty"]
        CELL -->|"建筑"| BLD["① 门锁 pool 判定 → ② NPC 触发 / 对话（if-else ＋ pool）"]
        CELL -->|"怪物格"| F1
        BLD --> ENC{"建筑 encounter 行为"}
        ENC -->|treasure| TRE["开箱：池 ＋ 抽取 → give / pool"]
        ENC -->|event| EVT["事件：门槛 gate ＋ 手艺 check → on_success / on_fail"]
        ENC -->|shop| SHOP["商店：定价 → 买 / 卖"]
        ENC -->|monster| F1
        ENC -->|mimic| MIM{"chance 判定"}
        MIM -->|宝箱| TRE
        MIM -->|怪物| F1
        ENC -->|empty| EMPTY["无事"]
        ROAD --> DONE["该步结算完"]
        TRE --> DONE
        EVT --> DONE
        SHOP --> DONE
        EMPTY --> DONE
        F1 --> F2["怪物反击回合<br/>pick_dice 选技能 → 力值链（读池）→ 玩家【防御】"]
        F2 --> DONE
        DONE --> REACH{"站上终点格？"}
        REACH -->|"否，还有步数"| STEP
        REACH -->|"否，步数用完"| REND["回合结束"]
        REACH -->|"是"| CLEAR(["抵达终点：本图完成"])
    end

    START --> T1
    P3 -->|"hp ≤ 0"| LOSE(["败北 · 本局结束"])
    CLEAR -->|"还有下一张地图"| NEXT["起点接上一张终点"]
    NEXT --> START
    CLEAR -->|"全部走完"| FINISH(["本局完成"])
    REND -. "推进时间" .-> T1

    FREE["自由动作：用道具<br/>不占回合 · 不 tick · 不推进时间"]
    FREE -. "回合内随时可用" .-> ACT
```

### 组件通信时序（V2.3）

> 组件之间"谁在什么时候跟谁说话"用**时序图**表达：**纵轴 = 时间**（自上而下），**横轴 = 参与者**——每条生命线就是一条泳道。
>
> **结构原子**：每一次交互都是 **`交互物 → 读状态池 → 用户交互 → 写状态池`**——**一切基于状态**。下面这张图就是把这条原子展开成一回合。

```mermaid
sequenceDiagram
    autonumber
    participant S as 状态池 · 唯一真值
    participant E as 引擎 · 回合判定
    participant P as 玩家
    participant X as 交互物（道路 / 建筑 / 怪物 / 技能 / 道具）

    Note over S,X: 交互原子：① 读池 → ② 用户交互 → ③ 写池

    rect rgb(240, 248, 255)
    Note over E,S: 回合开始 · 一批回合判定（按来源自然排序）
    E->>S: [1] pmod 业务判定 checks：拓扑排序，匿名最后
    Note over E,S: 例（用户设定）：上一回合打怪写入了经验 → 本回合"命中"判定 → 写 engine-points<br/>升级设定 → 加点 → 写 属性值
    E->>S: [2] state tick：per_turn 增减 ＋ duration − 1
    E->>S: [3] engine 基础判定（强制最后）：读 engine-hpValue
    end

    opt engine-hpValue ≤ 0
        E-->>P: 败北 · 本局结束（归零不触发任何池事件）
    end

    E->>P: 交出行事权
    P->>E: 掷 move.dice 得步数
    E->>S: 写回本回合步数（引擎键）

    loop 每一步（一次一格）
        P->>X: 走进这一格（交互物就位）
        X->>S: ① 读池：门锁 pool 判定 / 读当前值
        alt 交锋（怪物格）
            P->>X: ② 用户交互：选技能
            X->>S: 力值链读池：属性① ＋ 装备② ＋ 职业%③ ＋ 状态 mod④ ＋ 骰⑤⑥
            X->>S: ③ 写池：扣 hp / 扣 mp / 挂状态 / 记战利品
        else 道路 / 建筑
            P->>X: ② 用户交互：对话选项 / 买 / 卖 / 事件判定
            X->>S: ③ 写池：give / pool / effects
        end
        X->>E: 该步结算完毕
    end

    Note over P: 自由动作：吃药 / 用道具<br/>同一套原子（读池 → 写池），不占回合 · 不 tick
    P->>E: 回合结束（时间 +1，不再 tick）
    E-->>E: 回到回合开始
```

**怎么读**

- **结构原子**：每一组"交互物 → 池"的箭头都是 **读池 / 写池** 两拍，中间夹一次**用户交互**。内容侧从不直接改数，一律经池——所以状态池是**唯一真值**。
- **力值链本身也读池**：`属性① ＋ 装备② ＋ 职业%③ ＋ 状态 mod④ ＋ 骰⑤⑥` 全是从池里取。攻击与反击走**同一条链**，只是取不同维度。
- **死亡判定在回合开始，不在回合结束**：它是 `engine` 内置基础判定，在"一批回合判定"里**强制最后**执行——先跑 `pmod`（含用户的经验 / 升级设定）与 `state` tick，最后才判 `engine-hpValue ≤ 0`。
- **经验 / 升级不是引擎机制，而是 `pmod` 回合判定**：上一回合打怪写经验入池 → 本回合 `pmod` 的"命中"判定 → 写 `engine-points` / 属性值。引擎只保证它**每回合开始按来源排一次**。
- **自由动作不占时间轴**：`Note over P` 标出吃药 / 用道具随时可插，走的还是同一套"读池 → 写池"，不 tick、不推进时间。
- **出口**：`opt engine-hpValue ≤ 0 → 败北` 在回合开始判；`站上终点格 → 本图完成`在"逐格走"内循环里判，此处省略以保可读。

### 责任泳道（flowchart 子图版 · 全渲染器兼容）

> **为什么不用 `swimlane-beta`**：那是 Mermaid v11.16+ 才有的 beta 图表类型，GitHub 与 VS Code（11.12）等渲染器都还不认，会直接渲染失败。
> **为什么不用 PlantUML**：GitHub 原生 Markdown 只支持 `mermaid` / `geoJSON` / `topoJSON` / `ASCII STL` 四种图表语法，**不含 PlantUML**。下面这版用 `flowchart` + 顶层 `subgraph` 伪装泳道，**任何支持 Mermaid 的渲染器都能预览**。

**横向 = 时间**（一回合从左到右），**纵向 = 四条泳道**。

```mermaid
flowchart LR
accTitle: 一个回合的时间线与四条泳道
accDescr: 横向为时间，纵向为引擎、玩家、地图内容、状态池四条泳道；跨泳道箭头即责任交接
    subgraph LANE1["引擎 · 时序"]
        T0["回合开始<br/>一批回合判定<br/>pmod → state → engine"]
        T5["回合结束<br/>推进时间"]
    end

    subgraph LANE2["玩家 · 行动"]
        A1["掷 move.dice<br/>得本回合步数"]
        A2["逐格走<br/>一次一格"]
        A3["交锋：选技能<br/>力值链读池 → 判定"]
        A4["自由动作<br/>吃药 / 用道具"]
    end

    subgraph LANE3["地图内容 · 触发"]
        C1["道路<br/>tags → 门锁 pool"]
        C2["建筑<br/>NPC 对话 → encounter"]
        C3["怪物<br/>力值链读池 → 攻 / 反击"]
    end

    subgraph LANE4["状态池 · 全局"]
        K1["读 / 写池键<br/>写入即通知登记处"]
    end

    T0 -->|"轮到玩家"| A1
    A1 --> A2
    A2 -->|"走进道路格"| C1
    A2 -->|"走进建筑格"| C2
    C2 -->|"遇敌，转交锋"| C3
    C3 -->|"轮到玩家出招"| A3
    C3 -->|"结算完毕"| T5
    C1 -->|"结算完毕"| T5
    T5 -. "下一回合（时间 +1）" .-> T0

    T0 -. "读 / 写池键" .-> K1
    A3 -. "耗蓝写池" .-> K1
    A4 -.-> K1
```

**泳道对照**

| 泳道 | 谁 | 在这一回合里做什么 |
|---|---|---|
| 引擎 · 时序 | 引擎 | 回合**开始**整批判一次（基础判定强制最后）；回合**结束**推进时间 |
| 玩家 · 行动 | 玩家 | 掷骰得步数 → 逐格走 →（遭遇怪物）选技能；**吃药随时可做** |
| 地图内容 · 触发 | 道路 / 建筑 / 怪物 | 走进去的那一下**就地**判定与结算（门锁 pool、NPC 对话、encounter、交锋） |
| 状态池 · 全局 | 状态池 | 四条泳道都读它、都可能写它；写入即通知关心它的使用处 |

- **一回合 = 一条从左到右的横线**：`回合开始 → 掷骰 → 逐格走（含触发）→ 回合结束 →（下一回合）`。
- **只有两条泳道推进时间**（引擎的回合开始 / 回合结束）；玩家行动与地图触发都发生在这一回合**之内**。
- **自由动作不占横线**：吃药 / 用道具随时插进来，不推进时间、不 tick。
- **两个出口不在这张图里**：**败北**在"回合开始"的引擎泳道判出、**抵达终点**在"逐格走"里判出——见上面时序图的 `opt` 与第一张拓扑图的 `LOSE` / `CLEAR`。

### 闭环与边界

- **闭环**：`回合开始（一批回合判定）→ 本回合行动 → 回合结束 → 下一回合开始`——除下面两个出口外，流程永远回到"回合开始"。
- **两个出口**：① **抵达终点** → 走进下一张地图（起点自动接上一张终点；全部走完即本局完成）；② **玩家 `hp ≤ 0`** → 在回合开始的 `engine` 基础判定里判死 → **败北**。
- **回合判定只有一批**：`pmod` 业务（作者设定先执行）→ `state` tick → `engine` 基础判定（**强制最后**）；没有独立的"存活判定步"，也没有独立的"状态 tick 步"。
- **缓冲靠自由动作**：`hp` 降到 `0` 只在回合**开始**判死，本回合内仍可**随时吃药**（不占回合）；次回合 `state` tick 的"回血 / 掉血"对冲后才判死——上个回合吃过药，下个回合就死不掉。
- **自由动作与触发判定不占回合**：用道具，以及门锁 / 对话 / 建筑的所有**触发判定**，都在回合内**就地结算**，不推进时间、不 tick。
- **不会卡死**：保底技能免费（没蓝也能打）；状态必有 `duration` 上限（不存在永久状态）；依赖缺名只忽略该条、成环按声明顺序兜底。
- **观察即时**：池键一写入即通知登记处，正在展示的对话按新值**即时重算当前层**。
